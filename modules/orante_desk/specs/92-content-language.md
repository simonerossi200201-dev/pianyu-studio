# 规格 92 · 第一次运行问语种：提示词交给 ChatGPT 翻，粘回来就生效

日期：2026-09-24。用户原话：「用户第一次登入进来的时候，多加一个步骤，问问他们是哪个语种的，
然后再把所有的描述语整理起来，一次性显示给用户，提示让用户把这些描述语丢给 ChatGPT，
让 ChatGPT 改成他们所选择的语种的版本，格式保持不变，再重新粘贴回来。」

## 为什么不在软件里直接调翻译

提示词里全是「不要念出来」「把这句话念完整」「【镜头】…」这类拍摄指令，
机器直译很容易把指令本身翻坏，而翻坏了只会在出片时才暴露。
交给用户那边的 ChatGPT，他能一眼看出哪句不对、当场让它改。
**Orante 只负责两件事：把要翻的东西一条不漏地摆出来，以及粘回来时守住格式。**

## 清单长什么样

```
# ===== Orante 提示词语种包 v1 =====
# 目标语种：Español
# 共 58 条
（给 ChatGPT 的 6 条规则：不改编号行、保留 <<< >>>、保留 {占位符}、
  保留【标签】结构、指令按目标语种自然表达、只输出清单本身）

[[3]] tail.情绪
<<<
人物的情绪是温暖而恳切的……
>>>
```

- 定位键是**点路径**：`tail.情绪`、`camera.安静运镜_多样.常规[0]`，写回时按这个路径塞回原结构。
- 两档范围：**关键部分 58 条**（决定片子里的人说什么语言、怎么说：desc / tail / camera /
  接片接龙 / 问题句模板…），**全部 145 条**（再加扩图机位库——讲摄影机怎么摆的，翻不翻都不影响成片语种）。
- **`problem.patterns` 永远不导出**：那是拿来匹配问题句的正则和短语，翻了就认不出来了。

## 粘回来时守什么

1. **只认编号行和 `<<< >>>`**。ChatGPT 在前后加的寒暄照样忽略。
2. **少贴几条没关系**：贴回来几条就应用几条，其余保持原样。长文被截断就分两次贴。
3. **占位符不许丢**：`{原话}`、`{start}` 这些是程序要替换的变量，少了就整条拒收并写明原因——
   这类错误如果放过去，成品提示词会变成一句半截话。
4. 空正文、认不出来的定位键，同样跳过并列出来。
5. **应用前自动备份**，而且只备份第一次（第二次翻译前的那份已经是译文了，留着原文才有意义）。
   一键「还原成改之前」。

## 入口

- **第一次运行向导第 5 步**（填完 Gemini Key 之后）：选语种 → 复制清单 → 粘回来 → 完成。
  选「保持现在这样」直接完成。
- **以后随时重来**：② 多模态 面板左上角「按语种改提示词」卡片，同一套东西，外加「还原」。
- 设置里记的是 `content.lang`（成片语种），和界面语言 `ui.lang` 是两回事，互不影响。
