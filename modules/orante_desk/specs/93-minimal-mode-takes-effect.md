# 规格 93 · 极简模式要立刻生效；不说话的任务不许带说话指令

日期：2026-09-24。用户报：没有文案的任务开了极简模式，成品提示词里照样是运镜卡、
比例锁、画质锁、情绪，最后还跟着一句「人物只需要准确说出下面这一句英文…」——
后面根本没有台词，再下一行又是「画面中的人物全程不说话」。

## 查出来的两件事

**① 段上存着上一轮拼好的提示词，改了设置也不会重拼。**
`segment.prompt_final` 一旦拼好就一直用（91 号加的快照让它更稳，本来就是为了
"跑到一半别人换套装不影响这一轮"）。但**两轮之间**改了极简模式 / 积木开关 / 提示词块 /
套装 / 语种包，也不会重拼——用户看到的就是"开关白开了"。
在他机器上按当前开关重新拼一次，出来的正是他要的（描述语 + 静音提示两段），
说明拼装逻辑本身没问题，**问题在于用的是旧的那一份**。

**② 没有文案时，「说话指令」这一块本来就不该加。**
那一块的原文是「上文所有内容都是拍摄指令，一个字都不要念出来；人物只需要准确说出
下面这一句英文，把话说完整说准确，一字不差，嘴型对齐…」，紧接着却没有台词，
下一行还写着「全程不说话」。两句互相打架，模型多半照样张嘴——这正是之前那批
"不说话的视频还是会开口"的片子的病根之一。

## 改法

### A. 提示词世代（`prompts.rev`）

- 任何一次提示词写入都 +1：`prompts._cfg_set` / `_cfg_reset` 统管所有可编辑块、
  积木开关、极简模式；套装应用（`preset.apply_suite_group` 的 prompts / coverage 两组）
  另外显式 +1；语种包走 `prompts.set_block`，自然也在内。
- 拼提示词时在段上记 `prompt_rev`。
- `generate()` 开跑时取一次 `prompt_rev0`，整轮都拿它比：
  - 段上的 `prompt_rev` **对不上开跑那一代** → 作废重拼（这就是极简模式立刻生效的地方）；
  - 跑到一半别人改了提示词，当下的世代变了，但比的是 `rev0`，**这一轮不受影响**
    （91 号的保证原样保留）；
  - `prompt_locked`（手写提示词）永远不动。
- 换图 / 换描述语照旧由 91 号的 `prompt_snap` 管，两条互不干扰。

### B. 不说话就不发"说话指令"

`flow_shots.build_prompt(no_copy=True)` 时，**无论开关怎么设**，都跳过「说话指令」
和「音色锁」——这两块是冲着台词去的，没有台词就只剩自相矛盾。
（情绪等其它块不动：它们也管表情，想去掉用极简模式或单独关。）

### C. 顺带修好的一个坑

套装的 prompts 组原来会把 `prompts.*` **所有**行一起带走 / 覆盖 / 清空，
里头混着三个程序自己的状态：`prompts.rev`（世代号）、`prompts.switches_before_minimal`
（极简模式前的开关快照）、`prompts.lang_backup`（92 号语种包的出厂备份）。
换一次套装，语种包的"还原成改之前"就没了，世代号还会倒回去。
现在这三个键进了 `preset.PROMPT_INTERNAL_KEYS`，既不进套装也不被套装覆盖。

## 验收

`tools/test_spec93.py`（11 条）：不说话 + 开关全开也没有「说出下面 / 嘴型对齐 /
一字不差」；有台词的一字不少；极简模式下只剩描述语 + 静音提示；
四类提示词改动都会让世代 +1（开关 / 极简 / 改块 / 恢复默认）、套装应用也 +1；
存着的旧提示词按世代作废重拼、同一代不重拼、手写锁定不受影响；
快照会把过期那几段重新拼好并盖上新世代；跑到一半改提示词不影响本轮；
套装不许吃掉三个内部状态键。

`tools/test_spec85.py::test_default_switches_byte_identical_to_backup` 仍然全绿：
它比对的四个用例都是有台词的，B 只改 `no_copy=True` 的路径。
