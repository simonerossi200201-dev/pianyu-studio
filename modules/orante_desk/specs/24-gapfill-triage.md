## 分三档，不要一锅端

`gapfill` 解析出的每一条 `gap` 加一个 `tier` 字段：

| tier | 判定规则 | UI |
|---|---|---|
| `real` | 见下面「交叉印证」，或实义词 ≥ 6 个 | 红色，**默认勾选** |
| `maybe` | 实义词 3~5 个，且该段落盘校验是 ok | 黄色，默认不勾选，可展开 |
| `note` | **去掉成对括号里的内容**、去掉纯标点/数字/`:`/`-` 之后，剩下的实义词 < 3 个 | 灰色，**折叠起来**，默认不勾选 |

「实义词」= 去掉括号内容后按空白切分、且至少含一个字母的词。
`(John 8:34-35)` 剥掉括号后剩 0 个 → `note`。
`(John 8:34-35) 16:13)` 同理 → `note`（残缺的括号也要能处理：**未配对的 `)` 及其左边到行首
的内容一并当注释剥掉**）。
`There is only one God.` → 5 个实义词 → 先判 `maybe`，再看交叉印证。

抽屉顶部显示 `真缺 3 · 待确认 1 · 注释 3`，`note` 那一档折叠在一行
「3 条是括号里的经文出处，不用重生 ▾」后面，点开才看得到。

## 交叉印证（这一节是重点）

Orante 手里有**第二个独立证据源**：21 号做的落盘校验（首帧 aHash + sha256）。
两边对同一段的结论合起来看，才是可信的判断：

| 清单说这段的文案缺了 | 落盘校验说这段 | 结论 | tier |
|---|---|---|---|
| 缺 | `wrong_clip` / `dup` | **真缺**：这段的成片被别人的顶掉了 | `real`，并在行尾注明「该段落盘校验也判为拿错」 |
| 缺 | `ok` | 片子是对的，但话没讲全 —— 可能是模型漏念、也可能是 ASR 在接缝处漏词 | `maybe` |
| 不缺 | `wrong_clip` / `dup` | 内容碰巧被别的段覆盖了，但**文件名和内容对不上**，重拼时顺序会乱 | 单独列一档「文件对不上」，也要能一键重生 |

T0013 拿来验：`134~173→s004`、`307~356→s008`、`454~465→s011` 三条都能在落盘校验里
找到 `wrong_clip`，直接升 `real`；`197~199→s005` 剥括号后是空的，落 `note`；
s006 和 s010 虽然不在缺失清单里，但落盘校验判它们 `wrong_clip`，要出现在「文件对不上」那一档。

**最后抽屉里应当勾好 5 段：s004、s006、s008、s010、s011。** 这就是本次的验收基准。
