## 1. 为什么现在五分之四都长得一样（先看懂再动手）

现在的 24 条提示词由 `prompts.py::_line()` 拼出来，问题不在措辞，在**结构**：

**① 只有一个变量在动，而且是最弱的那个。**
`_HEAD` 写死了「保持上传图像中的人物形象服装和**动作**都不变」。
所以 24 行里唯一在变的是**相机**。同一个人、同一个姿势、同一个背景，
换个裁切比例，模型给你的当然是几乎同一张图。

**② 那个变量自己还在打架。**
`_HEAD` 说「动作不变」，后半句又说「更换人物的**朝向**」——
朝向本来就是姿态的一部分。指令自相矛盾时，生成模型的默认行为是**保守，即保持原样**。
所以连朝向都经常没换成。

**③ 景别三档之间差得太少。**
24 个组合里 21 个是中景 / 中近景 / 近景，只有 3 个全身。
腰以上、胸以上、肩以上——这三档在画面上就是「差不多大小的半身像」。

**④ 角度没有量化。**
「略微仰拍」「略微俯拍」没给度数，模型普遍理解成「几乎平视」，三档角度实际塌缩成一档。

**⑤ 每一行互相不知道对方存在。**
每条都是独立地「从原图变一点」，没有任何「要和已经生成的那些不一样」的约束，
结果必然一起收敛回原图附近。

**⑥ `_TAIL` 那一长串形容词**（"高清真实色彩漂亮清晰好看真实的获奖级别的画质"）
几乎不带信息量，只会稀释前面真正的机位指令的权重。

> **结论：光靠扩充机位表解决不了。**
> 用户给的 12 个机位里，真正在「相机位置」上不同的只有 5 种
> （正面 / 右四分之三 / 左四分之三 / 正侧 / 低机位）加一档距离变化（环境全景），
> 其余差异都是裁切。**必须让人物动作同时变成一个变量，才能真正拉开差距。**
> 这也正是用户自己判断的方向。

## 2. 新的库：`orante/legacy/coverage_library.json`

已经在仓库里了。结构：

    { "head": "...", "tail": "...",
      "cameras": [ {id,name,class,front,rank,text} × 12 ],
      "actions": [ {id,name,phase,rank,text} × 12 ] }

**`rank` = 画面里看得见多少**：`1` 只看得见脸 / `2` 上半身 / `3` 手也在画面里 / `4` 全身。

**配对规则（必须照做）**：

    合法  ⟺  0 <= camera.rank - action.rank <= 1

道理很简单：**画面里看不见的动作等于没改**。近景只有脸，配「双手在胸前」毫无意义；
全景配「眉头微收」也看不出来。按这条规则算出来是 **78 个合法组合**（现在实际只有 6 个左右）。

`class`：`A` 主力 / `B` 侧面 / `C` 空间 / `D` 收尾。
`phase`：`start` / `develop` / `hold` / `resolve`（动作周期，第 4 节用）。

**成品提示词 = `head` + `camera.text` + `，` + `action.text` + `tail`。**
注意 `head` 里**已经没有「动作不变」**了，改成「长相、发型、五官、服装、配饰、场景、
背景陈设、光线色调都完全不变」——该锁的锁死，该放的放开，不再自相矛盾。

`_HEAD/_TAIL/_SHOT/_ANGLE/_FACE/_COMBOS/_line/EXPAND_DEFAULT/REFILL_DEFAULT` 这一整套删掉，
`prompts.get_block("expand")` 改成读这个 JSON。用户在 ② 多模态里编辑的也是这个 JSON
（两张表，可加行可删行），沿用 spec 29 做好的自动保存。

## 3. 选哪些机位：均匀覆盖，不分等级

扩图的目的是**把图池铺开**，不理想的图用户回头删掉就行。所以**不做类别配额、不做正面比例限制**
——分级挑选反而会把选择面收窄，重新制造雷同。

选法就一条：**在 78 个合法组合里均匀轮转，同一轮不重复。**

    1. 把所有合法 (机位, 动作) 组合列出来。
    2. 优先挑「本轮还没用过的机位」里、「本轮还没用过的动作」的那些组合；
       两个维度都轮完一遍，才允许开始复用。
       —— 目的是让每个机位、每个动作都尽量露一次，而不是随机撞运气。
    3. 同一轮里 (机位, 动作) 这个二元组绝不重复。
    4. 跨轮次（同一个任务多次扩图）也记下用过的组合，优先挑没用过的。

`class` 和 `front` 这两个字段**仍然写进 JSON 并写进图片元数据**（第 4 节要用），
但**这一步不拿它们做任何过滤**。

### 所有可调的东西都要开放出来

这个软件要发给别人用，别人的人物、题材、风格都不一样。所以：

- **机位表和动作表**在 ② 多模态里以两张可编辑的表格呈现：
  每行可以改文字、改 `rank` / `class` / `phase`，可以**加行、删行、上下移动**。
  加一个「恢复默认」按钮（恢复成 `coverage_library.json` 里打包的那份）。
- 表格上方一行说明，把 `rank` 的含义和配对规则用人话写清楚
  （`1 只看得见脸 / 2 上半身 / 3 手也在画面里 / 4 全身；相机 rank 减动作 rank 在 0~1 之间才配得上`）。
- 编辑后**立刻保存**（沿用 spec 29 的自动保存），并且**进预设文件**（spec 26 的 `prompts` 分组里
  加上这个库）。
- 界面上实时显示 `当前合法组合：78 个`，用户加删行时这个数字跟着变 —— 
  让他一眼看出自己改完之后覆盖面是变宽了还是变窄了。
- 提示词的头尾（`head` / `tail`）也要能编辑，不要写死在代码里。

## 4. 动作周期：把标签写进 manifest，留给编排用

扩图这一步产出的是**图池**，真正决定「第几段用哪张」的是 ③ 编排。
所以「Start → Develop → Hold → Resolve」这个周期**横跨两步**，本规格只做前一半：

**扩图时给每张图打标**，写进 `manifest.images[]`：

    {"p": "p07", "file": "images/p07.jpg",
     "cov": {"camera": "04", "camera_name": "右前四分之三中景", "class": "B",
             "action": "03", "action_name": "右手抬起", "phase": "develop"},
     ...}

② 多模态的图卡上把 `04 右前四分之三中景 · 右手抬起` 显示出来（小号灰字），
用户一眼就能看出图池的覆盖面够不够。

**编排那一半**（按 phase 沿段序推进、A 类打底 B 类点缀、每 6~8 段插一个 C、
结尾用 D）留到下一份规格，本次只要**保证标签写对**。
但顺手做一件便宜的事：spec 30 的「间隔排列」升级一条——
相邻两段**不仅不能是同一张图，也尽量不要是同一个 `class`**（改不动就跳过，不报错）。

## 5. 生成时就把雷同的挡掉（这条是效果的保证）

光换提示词不够，要有闭环。复用 `orante/services/verify.py` 里现成的
`ahash_image()` / `hamming()`：

1. **先测基线**。写 `tools\cov_similarity.py`：给一个任务的 images 目录，
   两两算 aHash 汉明距离，打印距离分布（最小/中位/直方图）和「距离 < T 的图对占比」。
   **先拿 T0014 现有的图跑一遍，把结果写进报告** —— 这是改之前的基线，
   也是定阈值 `T` 的依据（不要拍脑袋定，按实测分布挑一个能把明显雷同的那一簇切出来的值）。
2. **生成时拒收重生**：每张图落盘后算 aHash，和该任务图池里已有的每一张比。
   最小距离 < `expand.dup_dist`（默认取第 1 步测出来的 T）→ **判为雷同**：
   删掉这张，换一个还没用过的 (机位,动作) 组合重生，最多重试 2 次。
   日志写 `✗ p09 和 p04 太像（距离 7），换 06×08 重生`。
   两次都不过就留下并标黄，不要卡死整个流程。
3. `expand.dup_dist` 放进设置页，用户能调。

## 6. 验收（要有数字，不能只说「感觉好多了」）

1. `tools\cov_similarity.py` 对 **T0014 改之前的图**跑一遍 → 报告里贴出距离分布
   和雷同对占比（预期会印证用户说的「五分之四雷同」）。
2. 用新库对同一个任务重新扩 12 张 → 再跑一遍 → **雷同对占比要降到 20% 以下**，
   距离中位数要明显上升。两组数字并排贴进报告。**这是本规格唯一的硬指标。**
3. 打开这 12 张肉眼看：
   - 至少出现 4 种明显不同的相机位置（正面 / 左右四分之三 / 正侧 / 低机位或全景）
   - 至少出现 4 种明显不同的手部或表情状态
   - **背景、服装、人物长相 12 张完全一致**（该锁的没被放开）
   - 没有一张是分屏 / 拼贴 / 三联图（这是老问题，回归确认一次）
4. `manifest.images[].cov` 每张都写全了；② 多模态的图卡上能看到机位名和动作名。
5. 在 ② 多模态里删掉两个机位、加一个自己写的机位 → 界面上「当前合法组合」的数字跟着变，
   下一轮扩图确实用上了新加的那个机位，删掉的没再出现。
6. ② 多模态里改一行机位文案 → 立刻保存（spec 29 的自动保存），重开软件还在。
7. 跑一次 refill（补位）→ 确认 spec 29 那句 `refill_clause` 仍然被插进去了，没被这次改动弄丢。
