## 1. 提示词改了存不住（bug）

### 现象
用户在 ② 多模态里改了描述语提示词 / 运镜规则 / 结语，重开软件发现改动没了。

### 根因（两条，都要修）

**(a) 前端要手点「保存」，而切块/切任务会静默覆盖。**
`ui/js/panels/gemini.js` 每一块下面都有一个 `saveDesc / saveExpand / saveRefill /
saveCamera / saveTail` 按钮（第 453、467、481、495、522 行）。textarea 里的文字只在
点了那个按钮之后才 POST `/api/prompts`。而第 363、369 行的两个 watch：

    watch(() => ui.promptBlock, (v) => { ...重新拉取... });
    watch(tid, () => { ...重新拉取... });

**只要切一下提示词块、或者在下拉里换个任务，就把 textarea 重新灌成服务端的值**——
用户刚敲的字当场消失，而且没有任何提示。这就是「改了存不住」的真身。

**(b) `PROMPT_FORMAT_VERSION` 升级会静默清掉用户存过的 expand / refill。**
`orante/services/prompts.py::_migrate_once()`：版本号一涨，就
`_cfg_reset("prompts.expand")` / `prompts.refill`，**用户手写的 24 行提示词直接没了**，
不备份、不提示。现在 `PROMPT_FORMAT_VERSION = 5`，以后每涨一次就再吃一次。

### 要做的

**自动保存，不要再依赖那个按钮：**

- textarea `@input` 去抖 **800ms** 自动 POST；`@blur` **立即** POST。
- 维护 `dirty` 标记。**切块、切任务、切面板、关窗口之前，先 `flush()` 把没存的存掉**，
  再做原来的重新拉取。`beforeunload` 也要 flush。
- 每块标题右边显示状态点：`● 未保存` / `✓ 已保存 14:32` / `⟳ 保存中`。
- `Ctrl+S` 强制立刻保存当前块。
- 原来的「保存」按钮**保留**（有人习惯点），但不再是唯一入口。
- 保存失败要红字提示并保住 textarea 里的文字，**绝不回滚成服务端的旧值**。

**迁移不许静默丢东西：**

`_migrate_once()` 改成：清掉之前先把用户的值抄到 `prompts.<name>.bak.v<旧版本>`，
并写一条 `prompts.migrate_notice`。② 多模态打开时若有这条 notice，顶部显示一条可关闭的横幅：

    你的「扩图提示词」因为格式升级被重置了。旧的还在 → [查看] [恢复] [知道了]

「恢复」= 把备份写回 `prompts.expand`。横幅点了「知道了」就清掉 notice。

## 2. 「扩图提示词」和「补槽位提示词」合并成一块

### 分析：确实是重复的

两块的默认值都由 `prompts.py::_line()` 生成，同样的 24 个「景别 × 角度 × 朝向」组合，
**唯一差别是 `refill=True` 时在句子中间多插一句**：

    mid = "并且构图必须和上传图像明显不同，" if refill else ""

触发点确实是两个（`expand` = 图池不够时批量扩；`refill` = 被拒的 pX 用新图覆盖同名文件），
**但提示词正文 96% 一样**。维护两份 24 行清单，改了一份忘了另一份，是必然会踩的坑。

### 改法

- **只保留一块 `expand`**，界面上就叫「扩图提示词」。
- 新增一个短设置 `prompts.refill_clause`，默认就是那句
  `并且构图必须和上传图像明显不同，`。界面上「补槽位提示词」那一整块换成**一行输入框**，
  标题「补位时额外加的一句」，下面一行灰字说明：
  「补位是用新图顶掉被拒的旧图，所以要强调构图必须和原图明显不同。清空则和普通扩图一样。」
- `_prompt_block(refill)` 改成：永远取 `expand` 那一块，`refill=True` 时把
  `refill_clause` 插到 `_HEAD` 之后（和现在 `_line()` 里 `mid` 的位置一致）。
  **列表模式下逐行插入**，注释行（`#` 开头）跳过。
- `REFILL_DEFAULT` 常量删掉，`EDITABLE` / `READABLE` 里去掉 `"refill"`。

**迁移**（必须做，别把用户已有的东西弄丢）：
- 用户改过 `prompts.refill` 而**没**改过 `prompts.expand` → 把 refill 的内容搬到 expand，
  逐行去掉那句 `并且构图必须和上传图像明显不同，`，并把它填进 `refill_clause`。
- 两个都改过 → 保留 expand，把 refill 存进 `prompts.refill.bak`，横幅告知用户
  「补槽位提示词已经并进扩图提示词，你原来那份在这里 [查看]」。
- 两个都没改过 → 什么都不用做。

## 3. 「跨任务队列」：一个接一个把描述语写完

### 需求
② 多模态的下拉里有一堆任务，用户现在要一个一个手动切过去点生成。
希望有个开关，开了之后软件自己排队，把所有还缺描述语的任务依次写完。

### 界面
② 多模态顶栏（任务下拉右边）加一个开关按钮 **「跨任务队列」**。
关着的时候就是现在的行为。打开时按钮下方出现一条队列条：

    跨任务队列  ●开   队列 3 / 7 · 正在 T0016 李星辰v03 · 已写 12/18 张   [暂停] [跳过这个] [停止]

### 行为
1. 打开时扫描**当前工作区里所有没进回收站的任务**，挑出「有主体图、且至少一张主体图
   的 `desc` 是空」的，按 ① 任务表格的行序排成队列（不是按 id，用户排的顺序才是他的意图）。
2. 一个任务一个任务地跑 `describe`。**同一时刻只跑一个任务**（用户要的是「有条不紊」），
   任务内部的多张图仍然按 `ai.max_workers` 和接口池并发。
3. 已经写好描述语的图**跳过**，不重写、不烧额度。
4. 某个任务失败（没图 / 接口全挂 / 报错）→ 记下来，**继续下一个**，不要整条队列停掉。
5. 全部跑完弹一条汇总：`7 个任务 · 成功 6 · 失败 1（T0019：没有主体图）`，
   失败的列出来可以点进去。
6. 「暂停」= 当前任务跑完就停在那儿，再点继续；「跳过这个」= 停掉当前任务的 job 进下一个；
   「停止」= 清空队列。
7. 队列状态要**跨面板保活**：用户切到 ③ 编排去干别的，队列继续跑；
   顶栏给一个小小的进度指示（和现有 Job 指示放一起）。
8. 队列本身不占账号锁（describe 走的是 AI 接口池，不是 Flow/Grok 账号），
   所以可以和出片同时进行 —— 但要**尊重 `ai.max_workers` 总上限**，别把接口池打爆。

### 接口

    POST /api/queue/describe/start   body {"only": ["T0016","T0017"]} 或 {}  # 空 = 自动扫
    POST /api/queue/describe/pause   body {"on": true|false}
    POST /api/queue/describe/skip
    POST /api/queue/describe/stop
    GET  /api/queue/describe         → {on, paused, done, total, current, results:[...]}

进度用现有的 SSE 广播（`events.emit`），别让前端轮询。

## 4. 验收

1. 在描述语提示词里敲几个字，**不点保存**，切到「运镜规则」再切回来 → 字还在，
   状态点显示 `✓ 已保存`。重启 Orante → 还在。
2. 同上，改完直接关窗口 → 重开还在。
3. 手工把 `settings` 里的 `prompts.format_version` 改成 4，重开 Orante →
   顶部出现迁移横幅，点「恢复」能把旧的扩图提示词拿回来。
4. 「补槽位提示词」那一块变成一行输入框；跑一次 refill，日志里打印实际用的提示词前 60 字，
   确认那句「并且构图必须和上传图像明显不同」在正确的位置。
5. 造 3 个缺描述语的任务，开「跨任务队列」→ 依次跑完，中间切到 ③ 编排队列不中断，
   已写好的图没有被重写（看日志的 token/请求数）。
6. 把其中一个任务的图删光，再跑队列 → 那个任务失败，队列**继续**跑完剩下的，最后汇总里点得进去。
