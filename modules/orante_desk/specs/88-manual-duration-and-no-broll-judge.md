# 规格 88：时长用户手选、准备阶段不判空镜、切套装不拦生成

日期：2026-09-23。承接 84（时长/画幅）、13（空镜提前到准备）、86（简单任务）、87（同账号拼单）。
本号把 0922 临时放开的几处限制固化成规则，并补上放开之后必须有的保险。

## A. 准备阶段不再判空镜（不调 Gemini）

**为什么**：一张图一次 Gemini 调用，几十张图要等很久；而且景别优先的判法常把横屏主体图判成空镜，
任务直接卡在「没有主体图」。用户自己一眼就能分辨，机器没必要代劳。

**规则**
- `prepare` 下完图后不再调 `broll.screen`：全部图 `role="主体"`，清掉 `broll_check` / `broll_reason`，
  按 `broll.renumber` 连号 `p01…`，日志写「图全部收下，不判空镜（哪张是空镜自己标）」。
- `describe` 也不再额外问「是不是空镜」那一题（那是每张图又一次调用）。只认已经标好的 `role`：
  标着空镜的照旧搬进 `空镜头/`。
- `broll.screen` / `broll.judge` 保留（手动批量判、老任务复算用），但不在自动流程里调。
- 用户改 role 的路子不变：多模态面板改 `role`，或把文件拖进 / 拖出 `空镜头/` 再同步。

## B. 没文案的任务可以拿空镜头出片（0922 放开，保留）

`split.clip_images()`：没文案时按图拆段用**全部**图（主体 + 空镜），只排除文件缺失 / 被拒的。
`generate` 对没文案的任务不再拦「配了空镜图」。有台词的口播照旧拦——空镜没有人脸，开口说话没意义。

## C. 时长：有文案的任务也能手选（改 84）

84 原来的规则是「有文案 → 时长只能按语速自动」。现在改成：

| 任务 | ① 任务表「时长」留空 | 手选了某一档 |
|---|---|---|
| 没文案 | 引擎默认（Flow 8 / Grok 10，可在设置里改） | 每段都是这个秒数 |
| 有文案 | 按语速自动（原 84 规则，逐段定档） | 按这一档的字/词上限拆段，**每段都是这个秒数** |

- 档位仍只认 `caps.DURATIONS`：Flow 4/6/8，Grok 6/10/15。
- 手选时的拆段上限取该档的配置：Flow 用 `dur_4s/6s/8s_max_words`，Grok 用 `dur_6s_max_chars` /
  `max_chars_10s` / `max_chars_15s`。
- Flow 只在标点处断句，遇到断不开的长从句会超量：照样按用户选的秒数出片，但日志给一行
  「⚠ 有 N 段超过 X 秒能念完的量……」。
- 时长列里留着这个引擎不支持的旧值（换过账号）时，有文案的任务不报死：警告一行，这一轮按语速自动。
- 前端：时长列一律可编辑，下拉第一项是「自动（按语速）」/「自动（按 N 秒）」，选了就显示「N 秒」。
  工具栏「设置时长…」也对有文案的行生效。

## D. 切套装不再拦生成（0922 放开，保留）+ 提示词开跑定稿（新增）

- `suites.switch` 去掉 `jobs_active` 拦截：两个窗口各用各的套装、各用各的账号，互不打扰。
  同账号的排队由账号锁管，不在这里拦。
- **保险**：`generate` 开跑时先 `snapshot_prompts()`，把这一轮要提交的段的提示词按当前套装定稿
  （写进 `prompt_final`，并记下 `prompt_snap` = 图号+文件+描述语摘要）。
  中途别的窗口换套装，影响不到已经开跑的这一轮。
  定稿之后图换了（补图 / 借图 / 描述语重写）→ `prompt_snap` 对不上，按新图重拼。
  接片 / 接龙每段要看前一段尾帧，只能现拼，不定稿。

## E. Grok 没有拒图（0922 放开，保留）

Grok 不像 Flow 会拒图，「找不到 post / 下不到片子」不是图的问题。所以 Grok 任务：
失败用**原图**再交一次（`grok_retry` 最多 1 次），不标 blocked、不换图、不补图；
以前误标的 blocked 在重生时收回。
