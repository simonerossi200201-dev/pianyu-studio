## 这是什么

一个**套装** = 一整套"做某种风格的片子"所需要的配置。存多套，右上角一键切换。

用户的原话：*"有的时候生成影片是完全不同的风格，就可以通过直接切换模板套装来快速有效地实现。"*

软件现在自带的那一整套描述语，就是**默认套装**。

## 心智模型：你永远在某一个套装"里面"工作

**这一条决定了整个功能的正确形状，先立住再往下看。**

套装不是"把当前配置打个包存起来"，而是**你正在使用的那份配置本身**。
顶栏那个 `● 默认套装` 显示的就是"我现在在哪一份里工作"，像文档标题一样。

所以正确的顺序是：

    新建套装「温暖布道」 → 自动切进去 → 在里面改提示词、换卡片、调账号
                                        ↑ 改的每一下都直接属于这个套装

**不是**"先改一通，再想办法存成一个新套装"。后者会让人不知道自己刚才改的东西到底属于谁，
也会出现"我以为在改新的，其实把默认套装改坏了"这种事。

（`⋯` 菜单里仍然保留一个<span class="btn-ref">另存为新套装…</span>，给"改完了才想起来要分家"那种情况用，
但它**不是主路径**，主路径是先新建再改。）

## A. 套装装什么 —— 这张表就是全集

| 组 | 内容 | 默认勾选 |
|---|---|---|
| `prompts` | 提示词全部块：描述语 / 运镜 / 固定结语 / 问题句子库 / 补位句 / upscale / bridge / bridge_single / chain，以及**情绪预设**当前选的是哪个 | ✓ |
| `coverage` | 扩图覆盖库（机位 + 动作 + 头尾） | ✓ |
| `desc_cards` | 换图卡片（68 号那四张 + 自建的） | ✓ |
| `gen` | 生成相关参数：`generate.mode`、`split.*`、`track.*`、`expand.*`、`flow.image_model_key` | ✓ |
| `accounts` | **账号的选用**，见下面那条重要说明 | ✓ |

### 账号这一组，只记"用哪几个"，不记账号本身

用户说"也可以把账户全部换掉"。但账号里带着 Chrome 登录态，**不能跟着套装复制来复制去** ——
那会变成几份登录态互相覆盖，一定出事。

所以：**账号仍然是全局唯一的一份**（在账号抽屉里管理），套装记的是：

- 哪几个账号 `enabled`
- 各引擎的默认账号是谁
- `engine.flow.model` / `engine.*.max_concurrent`
- 扩图默认账号（66 号那个）

切换套装 = 把这几项改过来，**登录态一个都不动，切换是瞬间的**。
套装里引用的账号如果已经被删了 → 切换时跳过它并在汇总里点名，不报错。

### 明确不进套装

任务 / 工程 / `gemini.api_key` 和接口池（那是账号级的，不该跟风格走）/
`workspace.*` / `ui.*`（界面偏好是人的习惯，不是风格）/ `setup.done`。

## B. 存哪

两张新表（`db.py` 里照现有写法建）：

    suites        id TEXT PK      -- S001…
                  name TEXT       -- 用户起的名字，唯一
                  note TEXT       -- 一句话备注，可空
                  color TEXT      -- 色卡里挑的一个色，用于识别和转场
                  builtin INTEGER -- 1 = 出厂那份
                  sort INTEGER
                  created TEXT
                  updated TEXT

    suite_data    suite_id TEXT
                  grp TEXT        -- prompts / coverage / desc_cards / gen / accounts
                  payload TEXT    -- JSON，**直接用 preset.py 现成的分组序列化产物**
                  PRIMARY KEY(suite_id, grp)

当前生效的套装记在 `settings` 的 `suite.current`。

### 出厂套装

首次启动（或表为空）时，把**当前配置**原样存成一份 `name="默认套装"`、`builtin=1` 的套装，
`suite.current` 指向它。这样任何人第一次打开就已经站在一个套装里，不存在"没有套装"的状态。

出厂套装**可以改、可以改名**，但**不能删**；改乱了可以<span class="btn-ref">恢复出厂内容</span>
（只重置它的内容，不影响别的套装）。

## C. 界面

### 入口

顶栏右上角，放在**版本号右边、账号按钮左边**：

    ● 默认套装 ▾

- 前面那个圆点是套装的颜色。
- 点开是一个**面板**（不是下拉列表——套装是有分量的东西，值得一个面板）。

### 套装面板

    ┌──────────────────────────────────────────────────┐
    │  模板套装                            [ + 新建套装… ] │
    │                                                  │
    │  ┌────────────────────┐  ┌────────────────────┐  │
    │  │ ● 默认套装    使用中 │  │ ● 温暖布道          │  │
    │  │ 出厂的那一套          │  │ 柔和眼神、掌心朝上    │  │
    │  │ 提示词 9 块 · 卡片 4 张│  │ 提示词 9 块 · 卡片 7 张│  │
    │  │ 账号 3 个            │  │ 账号 2 个            │  │
    │  │ 上次用 今天 14:20     │  │ 上次用 9 月 12 日     │  │
    │  │              ⋯      │  │            切换  ⋯   │  │
    │  └────────────────────┘  └────────────────────┘  │
    └──────────────────────────────────────────────────┘

- 卡片式，一行两张（窄屏一张）。当前使用中的那张：主色描边 + 右上角「使用中」角标，**不显示切换按钮**。
- 每张卡 `⋯` 菜单：重命名、改颜色、复制一份、导出为 `.orpreset`、删除（出厂那份没有删除）。
- 底部：<span class="btn-ref">从预设文件导入为套装…</span>

### 新建套装（主路径）

弹一个对话框：

    新建套装
    名字   [ 温暖布道                    ]
    备注   [ 柔和眼神、掌心朝上            ]  （可空）
    颜色   ● ● ● ● ● ● ● ●
    内容从哪来
      ( • ) 复制当前套装「默认套装」        ← 默认
      (   ) 复制别的套装  [ 下拉 ▾ ]
      (   ) 出厂默认内容（回到软件自带的那一套）
                              [ 取消 ]  [ 创建并切换 ]

- 按钮就叫<span class="btn-ref">创建并切换</span>，点完**直接切进新套装**（走 D 节那套转场动画）。
  创建完停在原地不动是错的——用户建它就是为了要在里面改东西。
- 切进去之后，顶栏显示 `● 温暖布道`，此后在 <span>②</span>多模态 改的提示词、
  <span>③</span>编排 的参数、新建的换图卡片，**全部自动属于这个套装**（按 D 节的回写规则）。
- 名字重复 → 当场提示，不让建。

### 另存为新套装（次要路径）

在 `⋯` 菜单里。把**当前配置**存成一个新套装，并切过去。
适用于"我在默认套装里改了一通才意识到应该分家"——这时候还会多问一句：
「原来的『默认套装』要恢复成改动前的样子吗？」勾上就把改动带走、原套装回滚，不勾就两边都留着改动。

## D. 切换：先保住现在的，再换

### 切换前必须做的两件事

1. **把当前套装的内容回写一遍。** 你在界面上改的每一下，改的都是"当前套装"的内容
   （见开头的心智模型），但那些改动此刻还在 `settings` / `prompts` 这些活表里。
   所以切换的第一步是把它们存回当前套装这一行，否则切走就丢了。
   - 这个行为要**在界面上说明白**：切换确认框里写一行「切换前会先把你现在的改动存回『默认套装』」。
   - 设置里给一个开关 `suite.autosave_on_switch`，默认**开**。关掉的话切换前会问"当前套装有改动，要保存吗？"
2. **检查有没有任务正在生成。** 有活跃 job → **不让切**，提示「有 N 个任务正在生成，
   提示词现在换掉会影响正在出的片子。先停下来再切。」给一个跳到 <span>④</span>生成 的链接。

### 转场动画（用户明确要求"设计得好看漂亮一些"）

总时长约 **900 ms**，`prefers-reduced-motion` 下全部跳过、直接切：

1. **0–180 ms**：套装面板里其余卡片向外淡出缩小，选中那张**轻微放大并居中**。
2. **180–520 ms**：以那张卡片的中心为圆心，一个该套装颜色的圆形遮罩 `clip-path: circle()`
   从 0 扩散到盖满全屏（`cubic-bezier(.65,0,.35,1)`）。遮罩不是纯色——用该颜色到透明的径向渐变，
   中心亮、边缘透，像一层光。
3. **~400 ms**（遮罩最满的时候）：在屏幕中央显示套装名 + 颜色点，字号大、字距宽，
   **这一刻底下悄悄完成数据切换和各面板重载**。
4. **520–900 ms**：遮罩向外淡出（不要收回圆心，那会让人以为撤销了），套装名跟着淡出。
   界面露出来时已经是新的。

切换完成后 toast：`已切到「温暖布道」`，如果有跳过的账号，第二行列出来。

### 切换之后必须重载的

提示词各块、扩图覆盖库、换图卡片、账号列表和各处的账号下拉、生成方式下拉、
<span>③</span>编排 的参数。**报告里逐个确认**，漏掉一个就会出现"界面显示的是旧的、实际用的是新的"这种最难查的 bug。

## E. 和 26 号预设的关系（别搞混，也别重写）

| | 预设 `.orpreset` | 模板套装 |
|---|---|---|
| 用来干嘛 | **跨机器搬运**：换电脑、重装、发给别人 | **本机内快速切换**多套风格 |
| 形态 | 一个加密文件 | 数据库里的若干条 |
| 含登录态 | 可以带 | **从不**带 |
| 含 API Key | 可以带 | 不带 |

**序列化代码只有一份**：套装的存 / 取 / 导出 / 导入全部调 `preset.py` 现成的分组函数。
写一条 grep 断言：`suites.py` 里不出现自己拼 JSON 的分组逻辑，全都是调 `preset` 的。
套装导出就是生成一个普通的 `.orpreset`，能被 26 号的导入流程正常读。

## F. 接口

    GET    /api/suites                    → {current:"S001", items:[{id,name,note,color,builtin,counts:{prompts,cards,accounts},used_at}]}
    POST   /api/suites                    body {name,note,color,from:"current"|"<suiteId>"|"factory", groups:[…]}
                                          # 新建。from 决定内容来源；建完由前端接着调 switch
    POST   /api/suites/{id}/switch        → {ok, skipped_accounts:[…], reloaded:[…]}
    PATCH  /api/suites/{id}               body {name?,note?,color?}
    POST   /api/suites/{id}/duplicate
    POST   /api/suites/{id}/save-current  # 把当前配置存回这个套装（切换前自动调的就是它）
    POST   /api/suites/{id}/restore-builtin   # 仅出厂那份
    DELETE /api/suites/{id}
    POST   /api/suites/{id}/export        body {password, path}   → 走 preset 的导出
    POST   /api/suites/import             body {path, password, name}  → 导入成一个新套装

`switch` 在有活跃 job 时返回明确的错误码和人话，前端据此拦下来。

## G. 测试 `tools/test_spec76.py`（**先设 ORANTE_DATA**）

- 空库启动 → 自动生成「默认套装」，`builtin=1`，`suite.current` 指向它。
- 改一块提示词 → `save-current` → 再读回来，改动在套装里。
- 新建 `from:"current"` → 新套装内容和当前一致；改新套装的提示词，**旧套装不受影响**（互相独立，不是引用）。
- 新建 `from:"factory"` → 内容是出厂默认，和当前被改过的套装**不一样**。
- 新建 `from:"<别的套装id>"` → 内容等于那个套装。
- 名字重复 → 被拒，错误文案含「已经有叫…的套装」。
- 切换：A 改提示词但不保存 → 切到 B（`autosave_on_switch` 开）→ 再切回 A，**那个改动还在**。
- `autosave_on_switch` 关 → 切换接口返回"当前套装有改动"的标志，前端该问用户。
- 有活跃 job 时 `switch` 被拒，错误文案含「正在生成」。
- 套装里引用的账号被删 → 切换成功，`skipped_accounts` 里点名，不抛异常。
- 账号的**登录态目录**在切换前后逐字节不变（算目录 sha256 比对）——这条最重要。
- 出厂套装不能删（DELETE 返回错误）；`restore-builtin` 只重置它自己。
- 导出一份套装 → 用 26 号的导入流程能读进来。
- grep 断言：`suites.py` 里没有自己拼分组 JSON 的代码，全走 `preset`。
- 回归：`python -m pytest tools/` 全过，`test_spec26` 不回退。

## 验收

1. 右上角出现 `● 默认套装 ▾`，点开是套装面板，里面一张「默认套装」卡，标着"使用中"。
2. 点<span class="btn-ref">+ 新建套装…</span>，起名「温暖布道」、挑个颜色、内容选"复制当前套装"，
   点<span class="btn-ref">创建并切换</span> → 转场动画走完，顶栏变成 `● 温暖布道`。
   **然后**去 <span>②</span>多模态 把固定结语整块改掉、情绪预设切到「温暖」、建几张换图卡片 ——
   这些改动全部落在「温暖布道」里。
3. 切回「默认套装」：转场动画走完之后，<span>②</span>多模态 里的提示词、情绪预设、
   换图卡片**全部变回原来的**。再切到「温暖布道」，又全部变回去。
4. 在「温暖布道」里改一句提示词**不另存**，直接切到「默认套装」，再切回来 —— **那句改动还在**。
5. 一边有任务正在生成时点切换 → 被拦下，提示里说明原因并给了去 <span>④</span>生成 的入口。
6. 切换前后打开账号抽屉：**登录态没丢**，不需要重新登录。
7. 导出「温暖布道」为 `.orpreset`，在另一台机器上用向导的"我有预设文件"导入，提示词和卡片都在。
