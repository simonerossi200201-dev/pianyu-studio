## 这是什么

用户只给**一张图**。

    起头图 ──描述语──▶ s001 ──尾帧──▶ s002 ──尾帧──▶ s003 ──尾帧──▶ … ──▶ s0NN

每一段的首帧就是上一段的尾帧，一段接一段画下去，目标是**一镜到底**的观感。

它和「锚点+接片」的区别：那个是主片锁身份、接片当过渡，检查严；这个是**所有段都是接片**，
而且**检查要松**。用户原话：

> 不需要严格的检测尾帧是否和上个视频相同，只要能确定这个尾帧不是严重的穿帮问题就没关系。
> 不能因为尾帧生成的第二个视频和尾帧不像就把这个视频给拒了，这是不可以的。
> 中间某个尾帧的效果不好，那也可以扩图重新生成视频。它只是一种生成视频的方式，不要要求太死板。

**这一段是本规格的最高原则。** 任何「像不像」的判定都只能是黄旗，不能是红灯，不能作废片子，
不能停链条。

## 复用什么（别重造）

52 号已经把「单图起于上一段尾帧」这条路修好了：`stage_bridge_start()` 从上一段尾帧写 `01_首帧_start.jpg`，
`BRIDGE_PROMPT_SINGLE` 是延续提示词，`ref_kind == "tail"` 走 `_first_frame_ref`。
**尾帧接龙 = 每一段都走这条路**（Flow 和 Grok 都是单图 i2v，Flow 不再传结束帧）。
尾帧抽取（`scan_tail_candidates` + `pick_sharpest`，最后 3~8 帧取最锐）原样复用。

## A. 模式定义

- `pipeline.MODE_CHAIN = "tail_chain"`，进 `MODES`。`mode_of` / `set_mode` / `resolve_gen_mode` /
  `remember_mode` / `parse_gen_mode` / `mode_switch_hint` 全部认得它。
- 任务级（54 号）和段级（56 号）都能选。段级默认「跟随任务」；一段改成 `first_frame` 就是
  「从这一段起换张图重新起头」——**下一段仍然从这一段的尾帧接**，链条不断。
- 段的 `role` 在这个模式下统一是 `"chain"`（不是 anchor / bridge），`role_word` 显示「接龙」。
- manifest 加 `chain: {start_image: "p03", desc_policy: "auto"|"always"|"never", reuse_dist: 18,
  upscale_every: 5}`。

**起头图**：`chain.start_image`。默认取任务图池里 `expand_ref` 勾着的第一张；没有就取 p01；
界面上必须能换（见 F）。

## B. 提交顺序：严格串行

`iter_ready` 在 chain 模式下只放行**一段**：编号最小的、状态为 planned 且上一段已 collected 并且尾帧文件存在的那一段。
s001 的「上一段」视为已就绪（参考 = 起头图）。

- 并发上限在这个模式下等于 1（每个任务）。**界面上要写明白**：「尾帧接龙是串行的，一段做完才能做下一段，
  N 段大约要 N × 单段时长」。别让用户以为 5 个并发白白闲着是 bug。
- 多个任务并行不受影响，各走各的链。

## C. 参考图与描述语

### C1. 参考图

`sg["chain"] = {"ref_kind": "start"|"tail", "ref_from": "p03" | "s004", "ref_file": "...", "ref_note": ""}`。

- s001：`ref_kind="start"`，文件就是起头图。
- s(n)：`ref_kind="tail"`，文件是 `tails.tail_path(d, n-1)`。
- **D 节判定「严重穿帮」时**，`ref_from` 退到最近一个没被标严重的尾帧，再退到起头图，`ref_note` 写明为什么退。

### C2. 描述语：变化不大就沿用，变了才重写

每段提交前决定这段的「画面描述语」（就是现在从图池 `im["desc"]` 取的那一份）：

    dist = aHash(本段参考图, 上一段实际用的参考图)
    desc_policy == "never"   → 沿用上一段的描述语
    desc_policy == "always"  → 对本段参考图调 Gemini 重写
    desc_policy == "auto"    → dist <= chain.reuse_dist(默认 18) 沿用，否则重写

- 重写走一个新的 `describe.describe_file(job, d, path, ...)`，内部复用 `describe_one` 的提示词和解析，
  只是对象是一个文件而不是图池里的 `im`。结果存 `sg["chain"]["desc"]`，同时记 `desc_src: "reuse:s003" | "gemini"`。
- 沿用时把上一段的 `chain.desc` 原样复制过来（s001 用起头图 `im["desc"]`）。
- 日志每段一行：`· s005 描述语沿用 s004（尾帧距 9）` 或 `· s005 尾帧变化较大（距 27），已重写描述语`。
- `reuse_dist` 默认 18：52 号实测单图起片首帧距 0~7，同一镜头连续两段的尾帧通常在 10~20，
  超过 25 基本是换了景。报告里贴一次真实任务的距离分布再定稿。

### C4. 画质衰减的补救：每 5 段自动提一次清

尾帧是从视频里截的，视频又是从上一张尾帧生的，一代代传下去画质必然递减。
所以每 `chain.upscale_every`（默认 5）段，下一段起头之前先把参考尾帧**提升画质**一次：

    s001 s002 s003 s004 s005 ──s005 尾帧提清──▶ s006 … s010 ──s010 尾帧提清──▶ s011 …

- **直接调 66 号的例程**（同一个函数、同一个账号解析、同一个 `prompts.upscale`、同样的三道闸）。
  不许在 chain 这边复制一份逻辑；66 号改了阈值这里要自动跟着变。
- 提清的对象是 `tails.tail_path(d, n)` 那张尾帧文件，**不是图池里的图**；提清后写回同一路径，
  旧尾帧走 `tails.archive_old_tail`（现成的 `_old` 归档），`sg["chain"]["tail_upscaled"] = {from, to, dist, acc}`。
- 三道闸有一道没过 → **用原尾帧继续**，日志一行 `⚠ s005 尾帧提清没过闸（原因），s006 用原尾帧`，
  链条不停、不重试。提清失败永远不是阻塞。
- 提清的账号 = 66 号 `resolve_account_id`（跟着扩图账号走）。
- 计数按**实际生成成功的段**数，失败重试不算；段级改成 `first_frame` 换图起头的那一段，计数归零重数
  （新图本来就是高清的）。
- 手动入口：H 节尾帧一览里每张尾帧都有「提清这一帧」按钮，点了就对这张尾帧跑一次同样的流程，
  之后从它接的段照常。
- `upscale_every` 在 ④生成 的 chain 设置行里可改（0 = 关掉自动提清）。

### C5. 每张尾帧都留档，不许覆盖丢失

现在 `tails/` 目录 + `archive_old_tail` 已经在做归档，chain 模式下把它坐实：

- 每段的尾帧文件 `tails/s005.jpg` 永远存在（直到任务归档）；重生 / 提清产生新尾帧时旧的进 `tails/_old/`，
  `TAIL_OLD_KEEP` 在 chain 模式下提到 **10**（一镜到底的任务反复修，3 份不够回溯）。
- 尾帧文件的元数据（锐度、对上一段参考的距离、`tail_severe`、是否提清过、被哪一段用作起头）都记在
  `sg["chain"]` 里，H 节的界面直接读 manifest，不另存一份。

### C3. 提示词

新可编辑块 `prompts.chain`，默认：

    画面从上传图片的这一刻自然延续：{start}。
    镜头保持当前的运动趋势，人物保持同一身份、同一位置，讲话不中断，不切镜、不跳剪、不淡入淡出。

`{start}` 用 `tail_pose` 文字（`_pose_text`），没有就用描述语第一句。
之后拼常规成品提示词（台词、运镜、收尾块），和 52 号 `wrap_bridge_prompt` 的拼法一致。

## D. 校验：只拦「严重穿帮」，其余一律放行

### D1. 片子本身永远不因为「不像」被作废

`verify.after_download` 里，`mode == tail_chain` 的段：

- 首帧 vs 参考图的距离**照算、照记**（`sg["chain"]["head_dist"]`），**不进 `wrong_clip`，不 `_apply_void`**。
  距离 > `DIST_SOFT`（16）标黄，仅此而已。
- `_thresholds_for(seg)` 对 chain 返回 `(None, DIST_SOFT)`：红线为 None 表示「没有红线」。
  写测试：给一个距 60 的片子，段状态仍是 collected，文件仍在 `clips/`，`fail_count` 不涨。
- 仍然生效的硬性检查只有这些（它们和「像不像」无关）：`is_real_mp4`、时长在合理范围、
  `_rejected` 地址不收、拿错邻居的片（`url_matches_post` 那一路）。

### D2. 尾帧「严重穿帮」的定义（就这三条，别加）

抽完尾帧后判定，命中任一条 → `sg["chain"]["tail_severe"] = "<原因>"`：

1. **几乎是纯色/黑场**：像素标准差 < 8（整张图算灰度 std）。
2. **糊到没法当首帧**：所有候选帧 Laplacian 方差都 < `TAIL_MIN_SHARP / 3`（=20）。
3. **画面里没有人**：`inspect_tail` 明确返回没有人物（不是「近景」「出画一点」，是**没有人**）。
   `inspect_tail` 拿不到结论 → 不算命中。

**不算严重的**（明确写进代码注释，防止以后有人手痒）：脸小、侧脸、近景、in_frame=false、
眼睛闭着、嘴半张、和上一段构图不同、光线变了、手势变了。这些全是黄旗或者干脆不标。

### D3. 严重了怎么办：链条不停

- 这一段照收、照算完成。
- **下一段的参考图退级**（C1）：用最近一个没被标严重的尾帧；都没有就用起头图。
- 检查台里这一段标黄、写原因，给「重生这一段」和「换图起头」两个按钮。
- 日志：`⚠ s006 尾帧几乎黑场，s007 改从 s005 尾帧接；s006 可到检查台重生`。

### D4. 段失败（引擎拒、超时、多次重试用尽）也不能卡死链条

`MAX_AUTO_REFILL` 用完仍失败的段：

- 标 `failed`，**但下一段照常放行**，参考图按 D3 退级，日志写清楚。
  这是 58 号「跑到完」的精神在这个模式下的体现：宁可中间缺一段让用户补，不能整条链停在那里等。
- 用户补上那段（重生 / 换图起头）后，**不自动级联**后面的段（见 E）。

## E. 修复：用户说了算，不自动级联

55 号在锚点模式下有「尾帧变了就级联打回后面的段」。**chain 模式下关掉它。**
用户重生了 s004，尾帧变了，s005 之后已经做好的段**不动**，只在检查台把 s005 标黄：
「上游 s004 尾帧已变，这里可能有跳变」，旁边一个按钮「从 s005 往后重跑」，点了才级联。

单段的修复入口（都是现成的，确认在 chain 模式下都能用）：

- **重生**：从它记录的 `chain.ref_file` 重新生成（参考图不变）。
- **换图起头**（56 号段级模式改 `first_frame` + 选图池里一张，或者先 66 号扩图再选）：
  这一段从新图起，下一段从这一段的新尾帧接。
- **检查台「通过」**：黄旗清掉，不影响任何东西（本来也没拦）。

## F. 界面

### ④生成

生成方式下拉第三项：

    尾帧接龙   一张图起头，每段从上一段尾帧接着画（串行，N 段≈N×单段时长）

选中后下面多一行：

    起头图  [p03 ▾]     尾帧描述语  ( • ) 变化大才重写   ( ) 每段都重写   ( ) 一直沿用
    每 [5] 段自动把尾帧提一次清（0 = 不提）

- 起头图下拉列图池里状态 ok 的图，带缩略图。
- 三个单选对应 `desc_policy`。默认「变化大才重写」。
- 鼠标悬停说明：「不会因为画面不像上一段就拒片；只有黑场 / 全糊 / 没有人才会标黄并换参考」。

### ⑤收片：「尾帧一览」

用户的用法是：**视频全部生成完之后，先把尾帧从头到尾翻一遍，画面有没有问题一眼就知道，
不用一条条打开视频看。** 所以要一个专门的快速浏览界面，不是把缩略图塞进现有表格。

⑤收片 顶部加一个按钮「尾帧一览」（chain 模式下默认高亮；其他模式也能用，只是意义小些）。
点开是一个覆盖层：

    ┌──────────────────────────────────────────────────────────────┐
    │  尾帧一览 · T0022 · 共 12 段          [◀ 上一张]  s005 / 12  [下一张 ▶]   ✕   │
    │                                                                │
    │                       （大图：s005 的尾帧，尽量占满）                       │
    │                                                                │
    │  s005 尾帧  1080×1920  锐度 142  距 s004 参考 9  ✓ 提清过（864→1728）        │
    │  [ 重生 s005 ]  [ 换图起头 ]  [ 提清这一帧 ]  [ 标记有问题 ]                  │
    │                                                                │
    │  ▪▪▪▪■▪▪▪▪▪▪▪   ← 底部一排缩略图，当前高亮；黄旗的带角标                      │
    └──────────────────────────────────────────────────────────────┘

- 快捷键：`←` `→` 翻页，`Esc` 关，`空格` 在「尾帧」和「本段首帧」之间切换（看衔接），
  `Home` / `End` 到头尾。翻页要快，缩略图预加载。
- 每张下面那行信息全部来自 `sg["chain"]`（C5）。黄旗（`tail_severe` / 距离 >16 / 上游尾帧已变）
  在缩略图上打角标，翻到时下面用一句人话写原因。
- 「标记有问题」= 现有的 `review.set_mark`，标完在 ⑤ 的表格里和手动标记一样，方便一览完统一重生。
- 「重生 s005」「换图起头」「提清这一帧」都调现成/本规格的接口，点完覆盖层不关，等 job 跑完那张缩略图自己刷新。
- 缩略图和大图地址带 `?v=mtime`，尾帧换了立刻能看到新的。

### 检查台（bench）

chain 模式每段一行：`上一段尾帧 | 本段首帧 | 距离 | 尾帧状态`。
距离只显示数字，>16 黄，**没有红**。`tail_severe` 有值 → 黄 + 原因 + 「重生」「换图起头」。
上游尾帧变了 → 黄 +「从这里往后重跑」。

### ③编排

chain 模式下图轨只对 s001 有意义。段表里 s002 之后的「图」列显示 `← s001 尾帧` 这样的灰字，
不可拖图、不可钉图（改段级模式为 first_frame 之后才恢复）。

## 验收

1. 新建一个任务，只放一张图，④生成 选「尾帧接龙」，起头图选它，开跑：
   日志逐段出现 `s001 起于 p03` → `s002 起于 s001 尾帧（距 6，描述语沿用）` → …，
