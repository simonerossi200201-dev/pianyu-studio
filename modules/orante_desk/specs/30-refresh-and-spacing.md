## 1. 全局刷新

### 为什么要
本地文件动过（换了片子、重生出了新片段、手动删了东西），或者界面莫名其妙卡住，
现在只能重启软件。**重启一次要重连 Chrome、重开 4 个窗口，代价太大。**

### 位置和长相
顶栏 `● 账号 6` 的**左边**，一个圆形箭头图标按钮（⟳），和旁边的点式按钮同一套样式。
Tooltip：`全局刷新（F5）· 右键深度刷新`。

- 点击 → 图标旋转，完成后短暂变 ✓（0.8s）再变回来。
- 快捷键 `F5` 和 `Ctrl+R`（输入框聚焦时不触发）。
- **SSE 断线时这个按钮变琥珀色**，tooltip 变成
  `实时连接断了，点一下重连` —— 界面「卡住」十有八九就是 SSE 断了，
  这个提示比什么都管用。

### 浅层刷新（点一下）
1. **先 flush** 当前面板所有未保存的编辑（复用 spec 29 的 flush，提示词、表格单元格都算），
   绝不能因为刷新把用户刚敲的字冲掉。
2. 重新拉 `store`：tasks / jobs / accounts / settings / queue。
3. 重新拉当前面板自己的数据（收片 → `/api/tasks/{tid}/review`，编排 → 配图轨，等等）。
4. **重扫当前任务目录下的文件**：clips / images 的存在性、大小、mtime。
   这一步是「本地文件动过」的关键 —— 后端 `review._seg_payload` 等已经在读盘了，
   确保这次调用不吃任何缓存。
5. 强制视频元素重载：给 `<video>` 的 src 加 `?v=<mtime>` 查询串（不要用随机数，
   否则每次刷新都重下几百 MB）。图片同理。
6. 重连 SSE（如果已断）。

### 深度刷新（右键 → 菜单）
浅层的全部，外加：
- 清掉 `data/ahash-cache.json` 里 size/mtime 已经对不上的条目，重跑一次轻量校验。
- 重新探测每个账号的 Chrome 端口是否存活（`chrome.port_alive`）。
- 清掉进程内的 `_CACHE`（`verify.py` / `checks.py` 里的那几个）。
- 完成后 toast 报一句 `深度刷新：重算 3 段首帧 · 账号 2/4 在线`。

### 接口

    POST /api/refresh   body {"deep": false, "tid": "T0013"}
    → {ok:true, tasks:N, files_rescanned:N, ahash_dropped:N, accounts_alive:"2/4"}

## 2. 编排「间隔排列」

### 需求
`一张图撑 N 段` 解决的是「一张图连着用几段」，但用户有时想要的是
**「同一张图可以重复用，只是不要连着用」**。现在没法表达这个意思。

### 界面
③ 编排工具栏，放在 `起伏 ±` 和 `单位` 之间，一个开关按钮 **「间隔排列」**，
**默认开**。Tooltip：`同一张图不会用在相邻两段（钉住的段除外）`。
状态跟着任务走，存进 `manifest.track.no_adjacent_repeat`；
全局默认存 `settings` 的 `track.no_adjacent_repeat`（默认 `true`）。

### 算法（`orante/services/arrange.py::_run_plan` 之后加一道后处理）

开着的时候，在 plan 出结果、`trackmod.apply` **之前**扫一遍：

    for i in 1..n-1:
        if rows[i].p == rows[i-1].p:      # 和前一段撞了
            换掉 rows[i]

换的规则，按顺序试：
1. 候选 = 当前图池里 **既不等于前一段、也不等于后一段** 的图。
2. 候选里优先挑**距离上一次被用最远**的那张（沿用现有 plan 的「最近未用」逻辑，
   别自己另发明一套）。
3. 该段被**钉住**（`track.pins` 里有）→ **绝对不动**，改动前一段或后一段里没被钉住的那个。
4. 前后两段都被钉住、或者图池里只有 1 张能用 → **跳过**，记一条 warning：
   `s007 和 s008 都钉了 p03，间隔排列改不动`。
5. `一张图撑 N 段`（hold）**优先级更高**：hold≥2 时，同一张图本来就该连着占 N 段，
   这时「间隔排列」只管**不同组之间的边界**（第 N 段和第 N+1 段不能是同一张），
   不要把组内拆开。这一条别搞反了。

跑完在 job log 和界面统计里报一句：`间隔排列：改了 4 段，2 处改不动`。

### 和已有规矩的关系（别破坏）
- 钉住 / 限定图池的段永远优先，间隔排列不许覆盖用户的手动指定。
- 只有点「预演」或「应用」时才重排；**不许因为打开这个开关就自动重排整条轨**
  （用户明确说过：只有「换一批」才该重来）。打开开关只是改设置，
  下次预演/应用时生效，界面上灰字提示一句 `下次预演时生效`。

## 3. 验收

1. 收片面板打开着，在资源管理器里手动删掉一个 clip → 点刷新 → 那一段变「缺片」，
   不用重启。再把文件放回去 → 再点刷新 → 恢复正常。
2. 在提示词框里敲字不保存，直接按 F5 → 字被存下来了，没有丢。
3. 手动断掉 SSE（后端重启一下）→ 刷新按钮变琥珀色，点一下恢复实时更新。
4. 右键 → 深度刷新，toast 报出重算了几段、几个账号在线。
5. 一个 9 段任务，图池只有 3 张，`一张图撑 1 段`，开「间隔排列」→ 预演结果里
   **没有任何相邻两段是同一张图**。
6. 同上但把 s004 和 s005 都钉成 p03 → 预演能跑完，warning 里点名这两段改不动，
   **钉住的段没有被动过**。
7. `一张图撑 3 段` + 间隔排列 → 组内仍然是连着 3 段同一张，
   只有第 3 段和第 4 段的交界处保证不同。
