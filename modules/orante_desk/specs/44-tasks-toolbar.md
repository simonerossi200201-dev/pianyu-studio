## 1. 「从 Google Sheet 粘贴」到底多不多余

**不多余，但名字骗人，而且和隔壁按钮重复。** 查清楚是这样：

| 入口 | 走哪条路 | 行为 |
|---|---|---|
| 「从 Google Sheet 粘贴」按钮 | `POST /api/tasks/parse` | **追加**新行，服务端做列识别 |
| 「导入 csv / xlsx」按钮 | **同一个** `POST /api/tasks/parse` | 追加新行，只是来源是文件 |
| 表格里 `Ctrl+V` | `applyPaste()` | 按当前选区**就地覆盖**，纯位置映射 |

所以：

- 前两个按钮**是同一个功能的两个入口**（文本框 vs 文件），白占两个位置。
- 它和 `Ctrl+V` **不是**一回事（追加 vs 覆盖、列识别 vs 位置对应），
  但「从 Google Sheet 粘贴」这个名字让人以为就是 `Ctrl+V` —— 28 号做完之后表格本来就能直接
  从 Google Sheet 粘贴，名字和实际能力对不上，看着当然多余。

### 改法：合成一个「导入…」

工具条上只留一个 **`导入…`**。点开一个对话框：

    ┌─ 导入任务 ──────────────────────────────────── ✕ ┐
    │  来源：  (•) 粘贴文本    ( ) 选择文件               │
    │  ┌──────────────────────────────────────────┐   │
    │  │ （从 Google Sheet / Excel 整块复制过来粘这里） │   │
    │  └──────────────────────────────────────────┘   │
    │                                                  │
    │  识别到 34 行 · 列对应：                            │
    │   第1列→任务名  第2列→文案  第3列→图片来源           │
    │   第4列→任务类型  第5列→账号  第6列→时长   [改…]     │
    │  ☑ 跳过第一行（看起来是表头）                        │
    │                                                  │
    │          [取消]              [追加 34 行]          │
    └─────────────────────────────────────────────────┘

- **列对应预览**是这条路存在的理由 —— 它比 `Ctrl+V` 多出来的价值就在这儿，
  要让用户一眼看见。每一列的下拉可以手动改成别的字段或「忽略这一列」。
- 选文件那一档沿用现有 `onFile`（`.csv/.txt`；`.xlsx` 仍然提示不支持）。
- 按钮文字统一叫 **`追加 N 行`**，明确是追加不是覆盖。
- 旧的 `tasks.paste` / `tasks.import` 两个 i18n key 保留不删，新增 `tasks.import_dlg.*`。

## 2. 工具条规格统一

现在这一排是这样（这就是"乱糟糟"的来源）：

    btn(从 Google Sheet 粘贴) btn(导入 csv/xlsx) [btn(+ 行…) + 裸 input] 
    btn(舒适) btn.sm(重置列宽) btn(删除选中) btn.primary(保存表格)

四个毛病：

1. **尺寸不一致** —— 「重置列宽」是 `btn sm`，混在一堆 `btn` 里，自己矮一截。
2. **裸输入框** —— `+ 行…` 旁边那个 `.tg-add-n` 是个光秃秃的 `input`，高度、圆角、边框都和按钮对不上。
3. **宽度参差** —— 中文标签从 2 字（舒适）到 14 字（从 Google Sheet 粘贴），按钮宽度跟着文字跑。
4. **没有分组** —— 7 个按钮一字排开，看不出哪些是一类；「重置列宽」这种低频项和「保存表格」并列。

### 新排布

    任务          [导入…] │ [+ 行 3] [舒适] [⋯] │ [删除选中]  [保存表格]
                  └ 数据 ┘  └─── 表格操作 ───┘   └─ 危险 ─┘ └─ 主操作 ─┘

- 组与组之间：10px 间距 + 1px `var(--rule)` 竖分隔线；组内 6px。
- **所有按钮同一规格**：高 30px、左右 padding 12px、圆角 6px、字号 13px、
  `white-space:nowrap`。**工具条里禁止再出现 `btn sm`**。
- **最小宽度 64px**，让「舒适」这种短标签不至于缩成一小块。
- `+ 行` 和数字框做成一个 **segmented 控件**：外面一个 30px 高、6px 圆角的容器，
  内部左边是按钮、右边是 40px 宽的数字输入，中间 1px 分隔线，
  输入框自己 `border:0; background:transparent; height:100%`，**看起来是一个整体**。
- **`⋯` 溢出菜单**（收低频项，工具条立刻清爽）：`重置列宽` / `导出选中为 TSV` / `只看已选`。
- **`删除选中`**：平时是普通幽灵态，**只有真的选中了东西才变红**（`--bad` 描边），
  避免一排红色一直扎眼。
- **`保存表格`**：42 号做完自动保存之后，它已经不是主操作了
  （这个面板的主操作是底部的「开始准备」）。改成**次级按钮 + 状态点**：

      ● 未保存   ⟳ 保存中   ✓ 已保存 14:32

  点一下仍然立刻保存。**不要再用 `primary` 实心样式**，把实心让给底部的「开始准备」。
- 「重置列宽」那个硬编码的中文文字和 `title` 走 i18n，别留裸中文。

### 窄窗口

工具条总宽不够时（小于约 720px），按这个顺序折叠进 `⋯`：
`舒适` → `+ 行` → `导入…`。`删除选中` 和保存状态点**永远留在外面**。

## 3. 验收

1. 工具条截一张图放进报告：所有按钮**同高同圆角**，没有 `btn sm`，`+ 行` 和数字框是一个整体。
2. 组之间有竖分隔线，`⋯` 里有三项且都能用。
3. 没选中时「删除选中」是灰的普通样式；选中后变红。
4. 「保存表格」不再是实心主按钮，旁边有状态点，改点东西后依次出现
   `● 未保存 → ⟳ 保存中 → ✓ 已保存 HH:MM`（42 号的自动保存）。
5. 「导入…」对话框：粘一段 Google Sheet 的 34 行 → 显示「识别到 34 行」+ 列对应，
   改一列映射 → 追加后那一列进了改后的字段；勾掉「跳过第一行」→ 变成 35 行。
6. 选文件那一档：`.csv` 正常，`.xlsx` 仍然提示不支持。
7. 把窗口拖到 700px 宽 → `舒适`、`+ 行`、`导入…` 依次进 `⋯`，
   「删除选中」和保存状态点还在外面，工具条不换行、不溢出。
8. `Ctrl+V` 就地覆盖的行为**完全没变**（28 号的粘贴测试全过）。
9. 回归：`node tools\test_spec28.mjs`、`python tools\test_spec28_ui.py`、
   `test_spec31_ui.py`、`test_spec33_ui.py` 全过；41 / 42 / 43 各点一遍没退。
