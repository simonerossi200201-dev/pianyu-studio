## 先说清楚：后端已经会了，缺的是让人知道、让人好填

`images.py` 文件头第 2 行写着「图片来源：**本地文件夹/单文件**、Google Drive 文件夹/单文件、http(s) 直链」。
`classify()` 第一件事就是 `Path(raw).is_dir()`，`fetch()` 里有 `local_dir` 分支，
`_copy_local` 用 `shutil.copy2` 把图拷进 `任务目录/images/pNN.ext`。

**所以在「图片来源」里直接填 `D:\素材\0920` 现在就能用。** 用户不知道，是因为：

- 那一列长得就像个链接框，没有任何地方说可以填路径；
- 填错了（路径不存在、里面没图、图在子文件夹里）**在点「开始准备」之前完全没有反馈**，
  要等 Job 跑起来失败才知道；
- 没有「浏览…」按钮，得自己去资源管理器复制路径；
- `_list_local_dir` 只扫**顶层**（`iterdir()`），素材放在子文件夹里就是 0 张，而且**不说为什么**。

本规格把这一层补齐，并加上用户要的「移动」。

## A. 单元格实时认出来源，并当场体检

「图片来源」单元格左边加一个小徽章，输入时实时判别（防抖 400 ms）：

| 徽章 | 什么时候 | 右边补充信息 |
|---|---|---|
| `☁ 网盘` | Drive 链接 | 文件夹 / 单文件 |
| `🔗 直链` | 其它 http(s) | — |
| `📁 本地` | 路径存在且是文件夹 | **`· 24 张`**（实时扫出来的数量） |
| `📄 本地` | 路径存在且是单个图片文件 | — |
| `⚠` 红 | 路径不存在 / 认不出 | `找不到这个文件夹` |
| `⚠` 黄 | 文件夹在但顶层 0 张 | `顶层 0 张，子文件夹里有 18 张` + 一键包含 |

- 扫描走新接口 `POST /api/images/probe-source  {"src":"…"} → {kind, ok, n, n_deep, note, sample:[前 4 个文件名]}`。
  **只数不拷**，要快；同一个路径 60 秒内的结果缓存住，别每敲一个字就扫一次磁盘。
- 网盘链接**不要**在这里联网去数（慢，还可能触发限流），只判别类型。
- 鼠标悬停徽章 → 小浮层显示前 4 个文件名，让人确认自己指对了文件夹。

## B. 填路径要省事

1. **「浏览…」按钮**：单元格右侧一个文件夹小图标，点了弹系统的文件夹选择框
   （后端照抄 `server.py` 里现成的平台分支写法），选完把路径填进去。
2. **拖放**：从资源管理器直接把一个文件夹拖到这个单元格上 → 自动填。
   拖的是一堆图片文件 → 取它们**共同的父文件夹**填进去，并 toast 一句
   `已填入它们所在的文件夹（24 张）`。
3. **粘贴**：现在 `LINK_PREFER_FIELDS` 会把粘贴内容当链接处理。
   粘贴的要是一个 Windows 路径（`X:\…` 或 `\\…`），别当链接，原样填进去。
4. 路径两端的引号照旧自动去掉（`classify` 已经在做，确认前端别抢先处理坏）。

## C. 子文件夹：要么用上，要么说清楚

`_list_local_dir` 现在只扫顶层。改：

- `fetch` 的 `local_dir` 分支支持 `recursive`（默认 **关**，保持现在的行为不变）。
- 递归时复用 `list_library_files`(185) 那套 `os.walk` 写法：跳过 `_` 和 `.` 开头的目录，
  **深度上限 3 层**，同样按自然序排。
- 递归开关记在任务行上（`meta.image_src_recursive`），由 A 节那个「一键包含子文件夹」置位。
- 顶层 0 张且子文件夹里有图，**又没开递归** → `fetch` 要报人话错误，
  不是拿 0 张图继续往下跑：`这个文件夹顶层没有图片，子文件夹里有 18 张——在「图片来源」那一格点「包含子文件夹」`。

## D. 复制 / 移动 —— 默认复制，理由写在界面上

用户说「直接本地移动过去就可以了」。**但默认仍然用复制**，原因要在界面上讲明白：

> 移动是不可逆的。素材文件夹要是你的图库（而不是只放这次要用的），移走之后原地就没了；
> 而且同一批图想再开一个任务（换个文案重做）就找不到了。
> 二十几张图复制一下就是一两秒，省下的那点时间换不来这个风险。

三档，放在设置 → 工作区，单元格右键菜单里可以按行覆盖：

| 档 | 行为 |
|---|---|
| **复制**（默认） | 原文件原地不动 |
| **复制并标记** | 拷完把源文件改名加 `【已使用】` 前缀 —— 和 Drive 那边 `images.rename_on_drive` 对称，一眼看出哪些用过了，文件还在 |
| **移动** | `shutil.move` 搬走。**第一次选这档时弹一次确认**，讲清楚不可逆；确认过就记住，不再烦 |

- 移动 / 标记失败（文件被占用、只读、权限）→ **降级成复制并继续**，日志一行说明原因，
  **绝不因为搬不动就让整个准备失败**。
- 跨盘移动用 `shutil.move`（它自己会退化成拷贝+删除），别自己写。
- 日志把档位写出来：`本地文件夹 24 张（复制，原文件保留）` / `（移动，原文件已搬走）`。

## F. 测试

### `tools/test_spec81.py`（**先设 ORANTE_DATA**）

- `classify`：`D:\x`（存在的目录）→ `local_dir`；不存在 → 抛 `OranteError` 且文案含「认不出」；
  带引号的路径 → 去掉引号照常识别；UNC 路径 `\\\\srv\\share\\x` 走 `local_dir`（用 monkeypatch 假装存在）。
- `probe-source`：本地目录返回真实张数和前 4 个文件名；顶层 0 张但子目录有 → `n=0, n_deep=18`；
  路径不存在 → `ok:false` + 人话 note；Drive 链接 **不发网络请求**（打桩断言 requests 没被调）。
- 递归：`recursive=False` 只拿顶层；`True` 拿到 3 层内的全部，跳过 `_`/`.` 开头的目录，自然序正确
  （`2.jpg` 排在 `10.jpg` 前面）。
- 顶层 0 张 + 子目录有图 + 没开递归 → `fetch` 抛人话错误，**不是**静默拿 0 张。
- 三档模式：
  - 复制 → 源文件还在，`images/p01.jpg` 存在，两边 sha1 相同；
  - 复制并标记 → 源文件改名带 `【已使用】`，内容不变；
  - 移动 → 源文件不在了，目标在；
  - 移动时源文件被占用（打桩让 `shutil.move` 抛）→ **降级成复制**，源文件还在，日志含「降级」，
    准备**没有失败**。
- 非图片文件、`.` 开头的文件被跳过，且日志里报了跳过几个。
- 同一个本地文件夹连开两个任务：`used_images` 计数正确，第二个任务照常拿到图。
- 回归：`python -m pytest tools/` 全过，`test_images` / `test_spec46` 不回退。

## 验收

1. 在「图片来源」那一格直接粘一个本地文件夹路径：**立刻**看到 `📁 本地 · 24 张`，
   鼠标停上去能看到前几个文件名。
2. 点单元格右边的文件夹图标，弹出系统选择框，选完自动填好。
3. 从资源管理器把一个文件夹拖进那一格 → 直接填上。
4. 故意填一个不存在的路径 → 当场红字，**不用等到跑起来才知道**。
5. 素材放在子文件夹里 → 黄字提示「顶层 0 张，子文件夹里有 18 张」，点一下包含，数字变 18。
6. 点「开始准备」→ 体检对话框把好的坏的分开列出来，只准备好的那几个。
7. 跑完：图都在 `任务目录\images\` 里按 p01、p02 编好号，**原素材文件夹原封不动**。
8. 把模式切到「移动」→ 弹一次不可逆的确认 → 确认后再跑，源文件确实被搬走了。
