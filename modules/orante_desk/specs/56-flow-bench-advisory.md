## 为什么要改

跨度闸是 37 号设计的，当时的前提是「一条接片拍坏了就白烧一次额度」。那个前提对 Grok 成立
（52 号之后是单图接片，慢且占账号），**对 Flow 不成立**——用户的 Flow 是无限刷。

更要紧的是判据本身站不住：**跨度大的接片，它的对照组不是「完美接片」，是「硬切」。**
跨度 5 的意思是这一跳要从近景走到全景，Flow 拿尾帧当首、下一张锚点图当尾，照样插得出一段过渡，
只是动作幅度大。不拍它，那儿就是一刀硬切——38 号 A/B 量过，硬切跳变值 49/115/84。
**一条不完美的接片，好过它要替代的那一刀。** 现在这个闸的实际作用是：
以「过渡不够漂亮」为由，拦住那个本来能让这一刀变好看的东西。

T0017（Flow，32 段）现在 28 处要人工决策，其中大部分红色还**换不动锚点**
（`auto_swap_anchor` 第 464 行：下一段主片已 collected/submitted 就放弃），
等于逼用户手挑图。这是软件在给用户造工作量。

## 要做的

### A. Flow：跨度闸降级成「事后复查」，不拦生成

- `pipeline` 新增 `gate_mode_of(m, sg) -> "block" | "advise"`：
  Flow 接片 → `"advise"`；Grok 接片 → `"block"`（保持现状，那边每条确实贵）。
  判据复用 `_is_grok_engine` / `grok_bridge_is_single`，别另起一套。
- `"advise"` 下：
  - `refresh_bridge_ready` 不再因为 `g > GAP_ENQUEUE` 就把 `bridge_ready` 压成 False；
    跨度照算、照写 `gap_score` / `gap_why`，只是不参与放行判断。
  - `wait_reason` 里那条 `等 sXXX 收片（跨度 N，检查台）` 改成普通的 `等 sXXX 收片`——
    上一段没收片当然要等，但**不再因为跨度而多等一道人工**。
  - `cascade_after_anchor` 第 842 行那条 `keep` 的跨度条件在 advise 下不生效
    （55 号的尾帧指纹检查**仍然生效**，那条是防拿错，不是防不好看）。
- **真正拍不成的仍然拦**，不分引擎：尾帧没抽出来、`face_ok` / `in_frame` 为 False。
  这些拍出来必废，拦住省的是无用功，不是审美。

### B. 检查台改成复查清单

- `bench_level` 在 advise 下：跨度 ≥4 **不再是红**，降成黄并标 `跨度 N（已放行，拍完复查）`；
  红只留给上面那几条「拍不成」和 53 号的三个计数器超限。
- 检查台列表加排序：**首帧距 > 跨度 > 段号**，最可能有问题的排最前。
  已收片的接片直接显示成品第一帧，和上一段尾帧并排——这才是复查该看的东西。
- 加「全部放行」按钮（含红色），二次确认写明
  `跳过 N 处跨度检查，拍完请到 ⑤ 收片复查`。确认后逐条 `passed = True` 并 `_kick_generate`。
- **`swap_all_red` 不许再给没换成的项盖章。** 现在第 397 行无条件 `mark_acted(sg)`，
  于是 `auto_swap_anchor` 返回 None（换不动）的项也解锁了放行按钮，等于允许你
  盲放一条什么都没修的接片。改成**只有 `r` 非 None 才 `mark_acted`**。
- `swap_all_red` 跑完返回并在界面上显示汇总：`换成 N 个，换不动 M 个（下一段主片已收片）`。
  现在点完一句反馈都没有。

### C. 生成方式下放到「段」：每一段都能单独选单图首帧还是首尾帧接片

这其实就是 `role` 已经在做的事——`anchor` = 单图首帧，`bridge` = 首尾帧接片——
只是现在它被叫做「角色」，藏在 ④ 的链条图里，用户看不出它和任务级那个
「逐段首帧 / 锚点+接片」是同一个选择的两个层级。**统一成一套话术，下放到段。**

| 层级 | 控件 | 作用 |
|---|---|---|
| 任务（54 号） | ① 任务表「生成方式」列 | 决定这个任务**初始**怎么分角色：逐段首帧 = 全是单图；锚点+接片 = 奇数主片偶数接片 |
| **段（本规格）** | ③ 编排 / ④ 链条 / ⑤ 收片 上的小切换 | 单独把某一段改成 **单图首帧** 或 **首尾帧接片** |

- 两级用**完全相同的两个词**：`单图首帧` / `首尾帧接片`。不再出现「主片 / 接片」这种
  只有我们自己懂的内部说法（`role` 字段名不改，改的是所有面向用户的文案和 i18n）。
- 段级控件**只在任务是「锚点+接片」时可用**；任务是「逐段首帧」时整列置灰，
  tooltip `这个任务是逐段首帧，每段都单独起头`。别去支持「逐段首帧任务里混一条接片」，
  `is_anchor_mode` 一关整套接片机制都是停的，混着只会出怪事。
- 后端就是现成的 `pipeline.toggle_role`，不用新写判定逻辑；
  新增 `bench.set_seg_mode(tid, s, mode)` 包一层：`mode` 取 `single` / `bridge`，
  和当前一致就直接返回，不一致就 `toggle_role` + 下面的重拍流程。
  路由 `POST /api/tasks/{tid}/seg-mode`。

**改完要连带做的事**（这是「一键」的核心，缺了就等于让用户自己收拾）：

1. 已收的旧片挪 `clips/_弃用`，`status` → `planned`，`gen_id` / `error` / 53 号那三个计数器清零；
2. `rebuild_bridge_links` + `stamp_waits`——下一段若是接片，它的尾帧来源变成本段，
   本段收片后 `after_collect` 自动重抽尾帧，55 号的指纹检查接得上，不用人管；
3. 改成 `单图首帧` 时这段用的就是它自己的配图 `sg["image"]`（锚点模式下本来就分好了，
   只是没用上），不用重新配图；
4. `_kick_generate`。

**入口三处，文案带代价说明**：

- ⑤ 收片每张卡片——**用户真正看到难看片子的地方**，最重要的一处。
  切到单图时小字 `这一段不再和上一段连贯，改用 pXX 单独起头`；
  切回接片时小字 `这一段会从 sNNN 的尾帧接上`。
- 检查台该行同样一个。
- ④ 链条上的节点：点击切换（现在就是这个行为），但把 tooltip 换成新话术。

**可逆**，两个方向都是同一个动作。被手动改过的段在链条上标个小记号，
和任务模式自动分的区分开，悬停 `手动改成单图首帧`。

### D. 检查台的图太大，一屏放不下

现在每一项的图是写死的大尺寸，看一条要滚半天，28 条滚到手酸。复查清单的前提是
**一屏能扫过好几条**，不然排序做得再好也没用。

- **三档密度**，和 ① 任务表的「紧凑 / 舒适」同一套话术和同一套 CSS 变量
  （spec 33 已经有 `--grid-density`，这里加 `--bench-thumb`，别另起一套）：
  `紧凑`（一屏 ≥6 条）/ `舒适`（≥3 条，默认）/ `大图`（1 条铺满，用来抠细节）。
- **另加一个无级缩放滑杆**，40%~200%，和三档联动（拖滑杆时三档高亮消失）。
- **快捷键**（弹层获得焦点时生效，写进检查台顶部的 `?` 提示里）：

  | 键 | 作用 |
  |---|---|
  | `-` / `=` | 缩小 / 放大一档（10%） |
  | `0` | 回到 100% |
  | `1` `2` `3` | 紧凑 / 舒适 / 大图 |
  | `J` / `K` 或 `↓` / `↑` | 上一条 / 下一条（滚动自动跟随，当前条高亮） |
  | `空格` | 放行当前这条 |
  | `S` | 对当前这条自动换锚点 |
  | `F` | 当前这条改单图首帧重拍（C 节那个动作） |
  | `Enter` | 当前这条放大到「大图」看，再按回到原档 |
  | `Esc` | 关掉检查台 |

- 密度和缩放值**记住**（`config` 里存，跟着预设走，不用 localStorage——
  26 号的预设导出要能带上）。
- 图片用 `object-fit: contain` + 固定高度的容器，缩放只改容器高度，别让不同宽高比的图
  把行高撑得参差不齐——现在滚起来累，一半是这个原因。
- 顶部固定一行「第 N / 共 M 条」和当前筛选（全部 / 只看红 / 只看黄），列表区单独滚动，
  别整个弹层一起滚。
