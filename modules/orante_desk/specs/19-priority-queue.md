## 一句话需求

> 不同账号可以同时渲染，互不影响；同一个账号的多个任务必须一个一个排队。
> 默认自动排序，用户可以手动插旗提高优先级。旗子是彩色的、带序号，序号没有上限、
> 可以重复——不同账号可以同时用同一个序号，同一个账号内部才比大小。

## 语义（已定死，界面照着做就行）

| 概念 | 规则 |
|---|---|
| 旗子序号 | `tasks.priority`，整数 `0..999`。`0` = 自动（没插旗）。`≥1` = 手动插旗，**数字越小越优先**（旗1 最先跑）。 |
| 重复 | 完全允许。同账号内同号时按**发号顺序**（Job 号 J00098 的 98）先到先得。 |
| 跨账号 | 序号的作用域是**单个账号**。A 账号的旗1 和 B 账号的旗1 同时跑，互不相干。 |
| 自动 vs 手动 | 插了旗的一律排在「自动」的前面；「自动」之间按发号顺序。 |
| 不抢占 | 旗子只管排队。已经在跑的任务不会被打断——改小旗子只影响它**下一次**排队。 |
| 中途改 | 排队中改旗子，**1 秒内**生效，会当场插到队伍前面。这是后端保证的，界面改完调一次接口就行。 |
| 作用范围 | 所有「占账号」的 Job：`generate` / `regenerate` / `refill` / `expand`。Grok 任务借 Flow 号扩图时，排的是**被借那个号**的队。 |

## 后端：已完成（0907，Claude 改的，别再动）

- `orante/db.py`：`tasks` 加字段 `priority INTEGER DEFAULT 0`；新表 `account_waiters`
  （谁在等哪个账号，带 `prio`/`seq`/心跳）；`account_locks` 加 `prio`。加了 `_migrate()`，
  老库自动补字段。
- `orante/locks.py`：抢锁不再是「谁手快谁赢」。要抢的人先在 `account_waiters` 报到，
  **只有队头才拿得走锁**；队头 = 按 `(旗子序号, 发号顺序)` 排第一。排序时旗子是
  **当场从 tasks 表读的**，所以中途改旗立刻算数。等待者心跳 1 秒一次，30 秒没心跳就
  从队里清掉（进程被杀不会堵死队伍）。持有者心跳 20 秒，90 秒没动静可被接管（原有行为）。
- `orante/scheduler.py`：进程内的队列也从「先进先出」改成按 `(prio, seq)` 挑；
  `Job.to_dict()` 多了 `prio` 字段。
- `orante/tasks.py`：`set_priority(tid, n)`、`bump_top(tid)`（置顶：同账号最小旗子是 3
  就插 2；已经是 1 就把同账号插了旗的整体 +1，自己占 1，相对顺序不变）。
- `orante/server.py`：两个新接口。

### 接口

    POST /api/tasks/{tid}/priority   body {"priority": 0..999}  或  {"top": true}
    → {ok:true, priority:<改完的号>}     顺带广播 SSE `tasks.changed`

    GET  /api/queue
    → {ok:true, queue: {
         "A001": {
           "running": {"job_id":"J00098","task_id":"T0010","prio":1,"since":1757...},
           "waiting": [ {"job_id":"J00101","task_id":"T0013","label":"generate","prio":1,"seq":101},
                        {"job_id":"J00099","task_id":"T0011","label":"generate","prio":9999,"seq":99} ]
         }, ... } }

`prio: 9999` = 自动。`waiting` **已经排好序**，第 0 个就是下一个要跑的，界面直接用，别自己再排。

> ⚠️ 这个接口才是**跨窗口**的真相。前端 `store.jobs` 只有本窗口的 Job；用户会同时开
> 4 个 Orante 窗口，08 规格里那句「排队中（前面还有 N 个）」用 `store.jobs` 算是**错的**，
> 本次要改成用 `/api/queue` 算。

## 要做的界面

### 1. 旗子本体（做成一个小组件，两个面板共用）

新建 `ui/js/parts/flag.js`（`ui/js/parts/` 已经有别的组件，照着它们的写法注册全局组件；
记得在 `ui/index.html` 里按现有顺序加 `<script src>`）。

- 形状：一面小旗。**内联 SVG**，不要用 emoji（跨平台画风不一）。旗杆细竖线 + 三角旗面，
  整体 16×18px。序号写在旗面上（≤2 位数字）；≥100 的号旗面放不下，就写在旗子右边一个
  小 `mono` 标签里。
- 颜色：按序号取色，同号同色。`COLORS[(n - 1) % 10]`：

      1 #ff5f56  2 #ff9f43  3 #ffd166  4 #4ade80  5 #2dd4bf
      6 #60a5fa  7 #818cf8  8 #c084fc  9 #f472b6  10 #a3e635

  旗面用该色实心 + 同色 30% 的柔光（`filter: drop-shadow`），旗杆用该色 60% 亮度。
  暗色底上要够亮，别糊在背景里。
- 自动（`priority === 0`）：**空心灰旗**（只描边 `#6b7280`，不填色），不写数字，
  hover 时透明度提到 1。它要看得出「可以点一下插旗」，但绝不能比彩旗抢眼。
- 正在跑的那个任务的旗子：轻微飘动动画（`@keyframes flag-wave`，旗面 `transform: skewY`
  在 ±2.5° 之间，2.4s ease-in-out 无限循环）。排队中的：呼吸式 opacity 0.55→1，3s。
  其余：静止。**`prefers-reduced-motion` 时全部静止**。
- 无障碍：`<button>` 包起来，`:title` 写 `t('prio.tip.flag', {n})` / `t('prio.tip.auto')`。

## 验收（自己跑一遍，写进报告）

1. 三个任务挂在同一个账号，分别插旗 3 / 自动 / 1 → 点「全部生成」，
   执行顺序是 旗1 → 旗3 → 自动。**同一时刻只有一个在跑**。
2. 两个不同账号的任务都插旗1 → 两条进度条**同时**在动。旗子颜色一样，不冲突。
3. 一个任务在跑、两个在排队时，把最后那个改成旗1 → 1 秒内顶栏队列顺序就变了，
   当前这个跑完后先跑它。**正在跑的没有被打断**。
4. 开两个 Orante 窗口，各提交一个同账号的任务 → 两个窗口的顶栏都显示**同一份**队形，
   排队那个的行内写着「前面还有 1 个（T00xx 在跑）」。
5. 旗子浮层在窗口右下角打开时不溢出屏幕。
6. `prefers-reduced-motion: reduce` 下旗子不动。
7. 任务面板改旗子 → 切到生成面板，旗子是新的（靠 `tasks.changed` 事件）。
