## 背景 / 问题
1. **扩出来的图全都雷同。** 根因在 `expand.py`：`EXPAND_PROMPT` / `REFILL_PROMPT` / `EXPAND_SENTENCE` 写死在代码里，而且每次把景别钉死成 `SHOTS` 里的一个词（「近景侧面」「中景略俯」…），句式是「只改变拍摄距离和角度：近景侧面」。参考图本来就是近景侧面时，模型就原样复制。用户要的是：**告诉模型必须换距离和角度，但不指定换成哪个**，让它自己选，并明确要求和参考图不同。
2. 这些提示词用户在界面上**看不到、改不了**，没法调试。
3. 点了「多镜头扩图」后界面没有任何进度反馈，不知道有没有提交。

## 一、提示词进 prompts 体系，铺开可编辑
1. `prompts.py` 新增两个块：`expand`（扩图）和 `refill`（补槽位），默认值进默认提示词 JSON（和 desc/camera 同一个文件），`all_blocks()` 返回它们，`GET/POST /api/prompts`、`/api/prompts/reset` 自动支持。
2. `expand.py` 改成 `prompts.get_block("expand")` / `get_block("refill")`；删掉写死的 `SHOTS` 轮换和 `{shot}` 替换。保留一个**兜底句**（Gemini 挂了用）：「同一个人物，同样的服装、发型、姿态和表情，换一个明显不同的拍摄距离和角度，背景延续原图环境。」
3. 新的默认 `expand` 提示词（措辞可润色，规则不能丢）：
   > 看这张参考图，写一句中文生图描述，不超过 70 字。要求：同一个人，同样的服装、发型、姿态和表情，背景延续原图环境。**必须换一个和参考图明显不同的拍摄距离和角度**——先看清参考图现在是什么景别、什么朝向，然后选一个不同的（距离：特写/近景/中景/全景；角度：正面/四分之三侧/侧面/略俯/略仰；也可以换到人物另一侧），并把你选的距离和角度自然地写进句子里。不要加人名、品牌、字幕、引号。只输出这一句。
   `refill` 同理，多一句「不要复制原图构图」。
4. **同一轮里多张之间也要不一样**：`gen_images(..., n=per_round)` 一次生 n 张用的是同一句，n 张自然雷同。改成：每张参考图这一轮**问 Gemini 一次，让它一口气给 n 句**（json_mode，`{"variants":["…","…","…","…"]}`，要求 n 句的距离/角度两两不同），然后每句各生 1 张（`gen_images(prompt_i, ref, n=1)`）。Gemini 失败时退回「一句生 n 张」。提示词块里用 `{n}` 占位。
5. **多模态面板**（gemini.js）左栏在「运镜规则」下面加两个折叠块：「扩图提示词」「补槽位提示词」，和描述语提示词同样的编辑/保存/恢复默认交互。编排面板的扩图横条上加一个小链接「提示词…」，点了跳到多模态面板并展开「扩图提示词」块。
6. 日志里每张图记：`参考 p02 → 变体 3/4：<整句>`，方便对照结果调提示词。

## 二、实时进度卡
### 后端
- `jobs.py` 的 Job 加 `progress` 字段：`{"phase": str, "done": int, "total": int, "current": str, "items": [...]}`，提供 `job.set_progress(**kw)`（合并更新、线程安全、写内存即可不必落盘）。`/api/jobs` 和 `/api/jobs/{jid}` 响应带上它。
- `expand()` / `refill()` 在每个节点更新：
  - 开始：`phase="connect"`，`current="连接 Flow（账号 xxx）"`
  - 每张参考图：`phase="prompt"`，`current="参考 p02 · 问 Gemini 写 4 句"`
  - 每次提交生图：`phase="gen"`，`current="参考 p02 · 变体 2/4 · 已提交，等 Flow 出图"`；出图后 `done += 1`，并往 `items` 追加 `{"p": 新编号 或 null, "thumb": 相对路径, "role": "主体|空镜|被拒", "ref": "p02", "variant": 2}`
  - `total` = 目标张数 − 现有主体+待审（即还差几张）；被拒不计 done 但 items 里记一条 `被拒`。
  - 结束：`phase="done"`。
- Flow 引擎的 `gen_images` 里现有的 `self.log("  ✎ 生图 …")` 保留。

### 前端（track.js 编排面板）
- 点「多镜头扩图」后，扩图横条原地变成一张**进度卡**（不弹窗、不遮住配图轨）：
  - 左：圆环进度（SVG，`done/total`，中间大字 `3 / 6`），跑动时环上有一段柔和的旋转高光；
  - 中：两行字——第一行 `phase` 的中文（连接 Flow / 写描述 / 生图中 / 判空镜 / 完成），第二行 `current`；下面一条细进度条；
  - 右：`items` 的缩略图排成一行（每出一张就从右侧滑入，主体绿边、空镜灰边、被拒红边+斜杠，hover 显示它的整句提示词），最多显示 8 张，多了折成 `+N`；
  - 右上角小按钮「停止」（调 `/api/jobs/{jid}/cancel`）和「日志」（展开这个 job 的日志文本，`GET /api/jobs/{jid}/log`，每 2 秒刷新）。
- 轮询：复用 store.jobs 的刷新；如果 store 现在刷新间隔 > 1.5 秒，扩图跑动期间把这个 job 单独按 1 秒轮询 `/api/jobs/{jid}`。
- 完成后：卡片停 3 秒显示「✓ 扩了 N 张，待审 M 张」，然后恢复成横条并刷新图片行；如果有待审图，横条上提示「有 M 张待审，去多模态面板留/弃」。
- 提交失败（`POST /api/jobs` 抛错、或 job 一开始就 failed）：卡片红色，显示错误原话（OranteError 的 message + hint），不要只 toast 一下就没了。
- 补槽位（refill）用同一张卡。

## 验收
1. 多模态面板能看到并修改「扩图提示词」，保存后 `data/` 里的 prompts 配置有它；「恢复默认」有效。
2. 对一个 5 张图的任务点扩图：进度卡立刻出现「连接 Flow」，随后每张出图缩略图滑入，圆环从 0/1 走到 1/1（目标 6 − 5 = 1）；日志里每张有整句变体。
3. 把 `expand.min_images` 临时改 9 再跑：同一轮 4 句变体互不相同，出的 4 张图景别/角度肉眼可见不一样。
4. 跑动中点「停止」能停，卡片显示「已停止」。

## 三、用户指定参考图（哪几张图拿去扩）
**问题**：现在 `expand()` 自动拿所有 ok 主体图轮着当参考，用户根本不知道上传的是哪张、扩散思路从哪来。

1. **编排面板**：图片行的每张主体图卡片右上角加一个小圆形勾选（「参考」），默认**只勾第一张 ok 主体图**（通常是最正的那张）；可以多选。空镜 / blocked / 待审图不可勾。勾选状态存 manifest `im["expand_ref"] = true`（`POST /api/tasks/{tid}/image/{p}` 已有，加这个字段的白名单）。
2. 扩图横条改成：`图片只有 5 张，建议扩图 · 参考：p02、p03 ▾ [多镜头扩图 (用 Flow)]`——「参考：…」是一个小下拉/弹层，里面列出所有可选主体图缩略图 + 勾选，和卡片上的勾同步；一张都没勾时按钮禁用并提示「先勾一张参考图」。
3. `expand(job, target, refs=None)`：只用勾了 `expand_ref` 的图当参考（没有任何勾就退回旧逻辑=全部 ok 主体图，并在日志里说明）。轮次分配不变：目标差几张就在这些参考图之间轮流。
4. 进度卡上「当前」那一行明确写 `参考 p02 · 变体 2/4`，右侧 items 的每张缩略图角上标它的参考编号，鼠标放上去也能看到。
5. `refill`（补槽位）**不受这个影响**——补的是被拒的那张 pX，参考就是它自己，保持现状。

验收补充：
5. 只勾 p03 跑扩图，日志和进度卡里所有变体都写「参考 p03」；一张都不勾时按钮灰。
