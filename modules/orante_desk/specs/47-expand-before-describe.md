## 现象

③ 编排显示「没有已写描述语的任务」，下拉框是空的、进不去。
而**扩图按钮就在 ③ 编排里**。于是变成一个死结：

    想扩图 → 必须先进 ③ 编排 → 必须先写描述语
    扩完图多出 N 张新图 → 新图没有描述语 → 回 ② 多模态再写一遍

用户想要的顺序是合情合理的：**下图 → 扩图把图池铺够 → 一次性写描述语 → 编排配图轨**。
现在这个顺序做不到，而且第一遍给原始图写的描述语，扩图之后有些原图会被弃用/替换，**白写**。

## 根因

`ui/js/panels/track.js` 开头：

    const ST_ORDER = ['draft','prepared','described','arranged','generating','collected','finished'];
    return ST_ORDER.indexOf(st) >= ST_ORDER.indexOf('described');

③ 编排要求任务状态 **≥ described**。而扩图（`expandAcc` / `expandBtnLabel` / `expand_done`）
恰恰长在这个面板里。

**这个门槛是多余的。** 查了 `arrange.py::_run_plan`：配图轨用的是图的 `role`（主体/空镜）、
`pins`、`pools` 和段数，**从头到尾没有用过 `desc`**。描述语只有在
`prompts.build_final_prompt`（出片时）才用得上。
所以「没写描述语就不能配图」这条限制，拦错了地方。

## 要做的

### A. 扩图搬到 ② 多模态（③ 也保留入口）

扩图属于「把图准备好」，天然是第 2 步的事 —— ② 多模态本来就管图的 `role`、管描述语、
左侧面板里已经有「扩图覆盖库」。

- **② 多模态**「主体图 · N」那一行右边，加一组按钮：`重扫目录`（46 号）、**`扩图…`**。
  点开的对话框和 ③ 里现在那个一致（选账号、张数、进度），逻辑**复用 `expand.py`，不要抄一份**。
- **③ 编排**里的扩图按钮**保留**（配图不够时就地补图更顺手），两处指向同一个服务。
- 扩图完成后自动跑一次 46 号的**静默重扫**，新图当场进图库、编号对齐。

### B. ③ 编排的门槛降到 `prepared`

    return ST_ORDER.indexOf(st) >= ST_ORDER.indexOf('prepared');

没写描述语的任务**照样能进、照样能配图轨、照样能预演和应用**。
选中这类任务时，面板顶部出一条**提示条**（不是拦路）：

    这个任务还没写描述语，配图可以先做；出片前需要补上。  [去写描述语]

按钮直接跳 ② 多模态并选中这个任务。

### C. 把完整性检查挪到真正需要它的地方

「描述语齐了没」这件事**只在出片前才要紧**，所以检查点挪到 ④ 生成：

- ④ 生成面板里，主体图有缺描述语的任务，行尾标一个琥珀色 `缺 3 张描述语`，
  **「生成」按钮置灰**，悬停说明原因 + 一个「去补写」的跳转。
- 后端 `generate.py` 开跑前再兜底检查一次，缺就抛 `OranteError` 点名是哪几张图，
  **不要跑到一半才发现**。

### D. 扩图之后只补写新增的那几张（这条最省事）

不管用户选哪个顺序，**描述语都不该写两遍**：

- `describe` 服务已经支持「只给缺 `desc` 的图写」。确认扩图产生的新图
  `desc` 为空、`pose` 为空，跑描述语时**自动跳过已经写好的**（看日志里的调用次数验证）。
- ② 多模态顶部显示 `3 张新图还没描述语 [只补这 3 张]`，一键补写。
- 任务已经是 `described` 时又扩了新图 → **状态不回退**（spec 25 的单调性已经保证），
  但这条提示要出来，别让用户以为已经齐了。
- spec 29 的「跨任务队列」也要认这种情况：扫的是「有主体图缺 `desc`」的任务，
  已经 `described` 但有新图的同样排进去。

### E. 节点栏的灯要说实话

底部 ①②③④⑤ 那排节点灯现在只反映 `status`。改成：**只要这一步能进，灯就亮**。
③ 的灯在 `prepared` 之后就该亮（现在要等 `described`）。
鼠标悬停在灯上显示「还缺什么」，比一句空荡荡的「没有已写描述语的任务」有用得多。

## 验收

1. 新建任务，只跑完「开始准备（下图 + 拆段）」**不写描述语** →
   ③ 编排下拉里**能看到它**，能选中，配图轨能预演、能应用；顶部出现提示条和「去写描述语」按钮。
2. 同一个任务，在 ② 多模态点 `扩图…` → 能跑，跑完新图进图库、编号对齐（46 号的重扫生效）。
3. 扩完图再点「写描述语」→ 日志里的多模态调用次数 **等于新图张数**，
   已经写过的一张都没重写。
4. 先写描述语、再扩图 → ② 顶部出现 `N 张新图还没描述语 [只补这 N 张]`，
   点一下只补新的；任务状态**没有从 described 退回去**。
5. ④ 生成里，缺描述语的任务「生成」按钮是灰的，标了 `缺 N 张描述语`，能跳去补写；
   强行调后端接口也会被拦住并点名哪几张图。
6. 底部 ③ 的节点灯在 `prepared` 之后就亮了；悬停能看到还缺什么。
