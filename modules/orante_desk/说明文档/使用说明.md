# Orante 制片台 · 使用说明

双击 `Orante.bat`，浏览器会自己打开 <http://127.0.0.1:9400>。
第一次运行会建 `.venv` 并装 fastapi + uvicorn，之后就是秒开。

关掉那个黑窗口 = 关掉服务。

---

## 这一版能做什么

开新批 + 全部生成 + 配图轨编排 + 看图运镜 + 复查 + 重生 —— 从表格那个「零」一直到收片。Orante **不自己生成任何视频**，也不自己拼提示词：
它算出你要的配图轨，交给流水线自己的函数写进 manifest；
要出片时腾出位置，把流水线原有的命令原样跑起来。

**台账只读。** Orante 不改 `Grok台账.json`，也不改 `manifest.json` —— 那两份是
各自流水线的唯一真值，动了就等于凭空多出第三份真相，0826 那次错乱就是这么来的。
你在界面上打的标记单独存在 `data\marks.json`。

左边自动列出两套流水线里所有的批次：

- **Grok 批次** ← `AAA\Grok\<日期>\Grok台账.json`
- **Flow 长文案** ← `0-长文案\数据\<分表>\<日期>\Tik00N\manifest.json`

点进去就是按段号排好的视频墙。

## 键盘

| 键 | 作用 |
|---|---|
| `J` / `K`（或 `←` `→`） | 上一段 / 下一段 |
| `空格` | 播放 / 暂停当前段 |
| `1` `2` `3` `4` `6` `8` `0` | 倍速，`0` = 12×。默认 **4×** |
| `M` | 静音开关。**默认带声音** |
| `A` | 连播开关。**默认开**：一段放完自动跳下一段，一路看到底 |
| `F` | 完成当前任务（没缺片、没失败、没未处理标记时），归入「过时」 |
| `,` / `.` | 上一帧 / 下一帧（收片墙当前卡片；按住 Shift 一次一秒） |
| `X` | 标记这一段要重生 |
| `E` | 展开 / 收起提示词 |
| `C` | 复制当前段的成品提示词 |
| `V` / `P` | 在资源管理器里选中这段的**视频** / **原图** |
| `Esc` | 全停 |

一次只播一个，不会几十个视频一起转把机器拖垮。

### 关于声音和倍速

声音默认是开的，跟着倍速一起走。但要说清楚一件事：

**4 倍以上，语音已经听不清了**，只能听出「有没有声音」。这是时间拉伸本身的限制，
不是播放器的问题。所以别指望靠 12× 听出口型对不对 —— 12× 是拿来**扫画面**的。

「这一段是不是没声音」这件事，交给体检去查，比耳朵准：

- **没有音轨** —— 直接读 mp4 的 box 树，看有没有 soun 轨。零成本，必查。
- **音频只有 x.xs / 画面 y.ys** —— 音轨比画面短三成以上就报。这是 Flow 那边
  常见的失败形态：画面出满 15 秒，人只说了 6 秒。
- **整段静音 / 声音很轻** —— 用 ffmpeg 的 volumedetect 量平均响度，
  ≤ −50 dB 判静音，≤ −38 dB 判过轻。一条 10 秒的片子约 0.1 秒，47 段约 5 秒。
  找不到 ffmpeg 就自动跳过这一条（查找顺序与 `grok_pipe.find_ffmpeg` 一致）。

## 顶栏

- **运行体检** —— 落盘四查：缺片、空文件/过小、时长与档位不符、两段是同一个视频（md5）。
  47 段大约 3 秒。查出来的直接标在卡上。
- **筛选** —— 全部 / 有问题 / 已标记 / 缺片。
- **大小** —— 一屏 3、5、7 列。找穿帮用小图扫，确认细节切大图。
- **重生清单** —— 把「已标记 + 缺片」导成一张表，P2 会直接拿它去跑重生。

## 提示词框

展开后**第一块就是成品提示词** —— 真正提交给 Grok / Flow 的那一整段字，不是零件。
右上角有「复制」，按 `C` 也行。下面几块（英文段 / 运镜卡 / 描述语 / 音色）是它的
组成部分，压暗显示，方便对照着看是哪一块写坏了。

标题右边会写清楚这一段是怎么来的：

- **台账原文** —— Grok 铺页那一刻实际粘贴的原文，从 `Grok台账.json` 里直接取，最忠实。
- **现算** —— 这一段还没提交过（或者是 Flow，manifest 里本来就不存提示词），
  按**当前**的卡库和描述语现拼一遍。用的是流水线自己的
  `flow_shots.build_prompt()`，不是另写一份 —— 拿 0830 那批逐段比对过，
  现算结果与台账原文**逐字节一致**。

> 现算是按「当前卡库」拼的。所以老批次展开时，如果 `flow_shots.json` 后来改过，
> 你看到的会与当年提交的略有出入 —— 那是**下次重生时会用的**版本，不是历史记录。
> 想看历史记录，看标着「台账原文」的那些。

**只读**：拼提示词时不会往素材目录里写运镜卡文件（`cards_for()` 会写，所以没用它，
改用 `read_shot_file` / `shot_cards`）。

## 开新批（左边栏「＋ 开新批（从表格开始）」）

这是「零」。表格就是你领任务的那张表，12 张分表的链接、gid、存图目录、切分上限
全部读自 `core\config*.json` —— Orante 一个 id 都不写死。

### 两条线，别走错

| | 长文案 | Normal |
|---|---|---|
| 什么料 | 一篇长稿，切成几十段 | 一图一文案 |
| 分表 | 只能是 Flow / LUCA 系 | 12 张都行 |
| 跑什么 | `core\longtik_newbatch.py --sheet LUCA-1 --lane TIK-L1` | `core\表格自动下载器.py --auto`（Grok 分表）<br>`core\flow_table_auto.py --auto`（Flow/LUCA 分表） |
| 等价的 bat | `★★1-开新批（扫表+下图+拆分）.bat` | `启动-表格自动.bat` |
| 预演 | 有，`--dry` | **没有** —— 下载器本身不带 |

选错了会被拦住（拿 Grok 分表跑长文案会直接说「请用 Normal 这一条」）。

### 参数

- **泳道** 从 `0-长文案\lanes.json` 读。D 系（账号冻结）和 TIK-G-STEFANO（预留）
  在下拉里是禁用的，选不中。
- **不生成描述语**（`--no-desc`）—— 描述语这一步最慢也最容易失败。
  勾上先把图和文案拿下来，描述语回头用 `Longtik-描述语.bat` 单独补。
- **只做某几组**（`--only`）—— 填 `Tiktok_01,Tiktok_03` 之类，试水用。
- **切分档位**（只有 Normal 这条线有）：
  Grok 分表选 10s（≈170 字）或 15s（≈250 字）；
  Flow / LUCA 分表选松紧 —— 标准 20 词 / 紧 18 词 / 松 22 词，
  和 `启动-表格自动.bat` 的菜单一字不差。

### B 列要不要填 —— 看这张分表开没开「自动认组」

长文案扫表有两种认组方式，界面上选完分表就会写明是哪一种。

**自动（LUCA-1 已开，阈值 150 词）**

B 列**什么都不用填**。判据是：**C 列英文 ≥ 150 词，而且 J 列有链接** → 这一行就是一个组。
一行一组，J 列那个网盘文件夹里的图全归它，自动列出、自然排序。

- 表头那一行、以及所有短文案，都会被当成「太短/没图」直接跳过，**不再整批拒绝**。
- 手填的 `Tiktok_01` 仍然优先，而且连续几行填同一个号还是会合成一组 —— 老写法没废。
- 阈值写在分表配置里（`core\config_luca1.json` 的 `tiktok_min_words`）。
  Normal 一条通常 20~40 词，长文案 200 词以上，150 卡在中间，两边都不容易误判。

**手动（其余 11 张分表still 是这个）**

B 列只认三种值（规则在 `core\sheet_filter.py`）：`Tiktok_01`（正则
`^tiktok[_\-\s]?(\d+)$`，大小写不限）、`normal`、空。**其他任何值 → 整批拒绝**。
一组 = 连续若干行填同一个 `Tiktok_NN`。

> 注意 `Tik001` 不是给你填的 —— 那是流水线**发给你的**组号。你填 `Tiktok_01`，它回你 `Tik001`。
> 表头那一行的 B 也会被扫，所以手动模式下 `B1` 不能是「中文内容」这种列名。

**要给别的分表也打开自动认组**：在它的 `core\config_<key>.json` 里加一行
`"tiktok_min_words": 150`。不加就是老行为，一个字节都不变。

> 扫表其实有**两个**扫描器：`longtik_router.scan_groups` 负责分组，
> `表格自动下载器.fetch_sheet_rows` 负责扁平行对照（`flat_check`）。
> 两边都读 B 列、都会因为「不认识」整批拒绝，所以自动认组必须两边一起改 ——
> 只改一边的话，分组过了、对照那一关照样把你拦下来。

**开跑前先点「先扫表（只读）」** —— 跑 `longtik_router.py --sheet LUCA-1`，
只读扫一遍打出每行怎么判的、收了几组、每组几张图，什么都不落盘。

### 「已存在 TikNNN，跳过」然后报 manifest 不见了

组名每一批都从 `Tiktok_01` 重新数，但 `组登记.json` 里的登记是**永久**的。
所以上一批的素材归档搬走之后，登记那条还在，脚本会说「已存在 Tik001，跳过建组」，
下一步去读早就不在盘上的 `manifest.json` → 整组 `No such file`。

0831 把 `longtik_newbatch.existing_gid()` 收紧成两条（备份 `.bak-0831-stale`）：

- **目录不在了就不算存在** —— 登记那条留着当记录，但不再拿它挡路，直接发新号。
- **文案指纹对不上也不算存在** —— 同一个组名换了一篇新文案，以前会被当成同一组，
  新文案悄悄套用旧的 `manifest.json` 和旧的 `src.txt`；现在会另起一组。

两条都只是把「算存在」判得更严，**本来该复用的仍然复用**（重跑还是幂等的）。

### 脚本停下来问话怎么办

流水线里不少脚本会停下来问一句 ——「以上 2 个组来自分表 LUCA-1，确认无误就回车开始」、
拼接成片的三选一、submit 的确认……子进程没有终端，光按键盘是送不进去的。

所以任务日志下面有一条 **「脚本在等你回答」** 的输入框，脚本一开口它就自己冒出来：
直接按回车 = 确认，输 `n` = 取消，输 `1`/`2`/`3` = 选项。送进去的内容会以 `> xxx`
记在日志里，回头能看清当时答了什么。

开新批那边另有一个 **「跳过脚本的二次确认（--yes）」** 复选框，
嫌每次答一遍烦就勾上。不勾的话它会停下来把组列一遍再问 —— 那一眼其实挺值。

### 几件要知道的事

- 长文案有自己的锁（`0-长文案\.newbatch.lock`），一次只许跑一个。
  界面开局就查，被占了会直接告诉你。
- `表格自动下载器.py` 本体是个 tkinter 程序，只有带 `--auto` / `--retry` /
  `--reuse` 才走无界面分支。Orante 一律加 `--auto`，**绝不去驱动它的窗口**。
- 第一次跑会走 Google OAuth，浏览器会弹出来让你授权一次，之后 `core\token.json` 里有。
- 缺一张图整组不开工 —— 这是长文案流水线自己的规矩，不是 Orante 加的。

跑完左边栏就会出现新批次，接着往下走「编排」。

## 全部生成（左边栏「▶ 全部生成（提交出片）」）

0905 接进来的。以前这一步只能在 `0-长文案` 里双击 bat，现在界面上也有了 ——
跑的是同一条命令、同一份锁、同一个日志文件，两边完全等价，混着用也没关系。

```
0-长文案\core\longtik_runall.py [--lane TIK-D1] [--gid TikNNN]
                                 [--skip Tik004,Tik006]
                                 [--collection <URL或id>] [--dry]
```

**面板上有什么**

- **泳道** —— 只列 `lanes.json` 里 `engine=flow` 的。停用的选不动。
  换泳道会立刻重读这条泳道的组和出片去向。
- **只跑某一组** —— 留空 = 这条泳道的全部组。
- **跳过哪几组** —— 逗号分隔，对应 `--skip`。
- **手动指定合集** —— 留空就好。优先级是「手动 > 分表配对 > 泳道兜底」，
  平时靠分表自动配对（`core\flow_config_<分表>.json`），填这一栏是临时改道用的。
- **组表** —— 每组的总段 / 已提交 / 待提交 / 被拒。灰掉的组读不到
  `manifest.json`，脚本会直接跳过。
- **出片去向** —— 把最终解析出来的 collection id 直接写在脸上。
  开跑前扫一眼这一行，比什么检查都管用。

**要知道的几条**

- **可以随时取消。** 已提交的段不会丢 —— 脚本靠 `manifest.json` 里的段状态
  判断，`submitted` / `collected` 的下次自动跳过。取消之后再点「开跑」
  就是从断点续跑，不会重复出片。
- **一次只跑一个任务。** 和「重生」共用同一条规矩：两个任务抢同一个 Chrome
  必乱。要两条泳道真并行，还是开两个黑窗口（`★ 长文案总控.bat`）。
- **脚本自己也有锁**（`TIK-L1` 用 `.runall.lock`，别的泳道用
  `.runall-<泳道>.lock`），超过 15 分钟没心跳就当上一个崩了。
  界面会把锁的状态和上次心跳时间显示出来，不用去翻文件。
- **组和泳道是绑死的。** 拿 TIK-D1 的浏览器提交 TIK-L1 的组，片子会跑进
  错的合集。`--gid` 本身不拦这个，Orante 在这里拦了。
- **`--dry` 只算不连浏览器**，会把待跑清单和预计时长打出来。心里没底就先点它。

跑完接着走「复查」看片墙，缺的走「重生」。

## 配图轨编排（顶栏「编排…」，只对 Flow 长文案的组开放）

Grok 批次是一图一文案，配图在 `vNN.txt` 那一层，没有轨可编。

### 它替换掉了什么

流水线现在的配图是 `longtik_plan.py` 里的一行：

```python
p = p_subject[subj_count % len(p_subject)]
```

取模轮转 —— **每段必换，顺序永远 p01→p02→…→p01**。不是随机，是最死板的一种规律。
编排台把它换成三段式：

| | |
|---|---|
| **钉区** | 你在色条上框选、指定用哪张图。图钉死不动 |
| **中段** | 洗牌袋抽图，一张连撑 `hold ± 起伏` 段（也可以按秒） |
| **空镜** | 不碰，仍旧走流水线自己的空镜编排 |

洗牌袋而不是取模：把图池洗乱依次取用，取空再洗。分布仍然均匀，但不呈周期。

### 怎么用

1. **缩略图条** —— 点一下让一张图进 / 出全局图池。被 Flow 拒过（blocked）和文件不在的图
   带 `×`，进不了池子。
2. **色条** —— 一格一段，颜色 = 用哪张图。点一下选中，按住 Shift 点第二下选一整段范围。
   底部黑线 = 钉住的段，顶部蓝线 = 限定过图池的范围，斜纹 = 改不了的段。
3. **选中之后**：`钉住用 pNN`（你的邀约文案就钉在这儿）、`限定图池`
   （这段范围只在你挑的几张里抽 —— 就是「批量选中一些图让它随机选」）、
   `取消钉住` / `清除限定`。
4. **一张图撑几段** 滑杆，`起伏 ±` 控制块长的随机幅度，单位可切成秒。
5. **预演** —— 纯计算，不碰盘。顶上直接告诉你：换图 43 → 16 次，一张撑 9s → 23s。
   不满意点 **换一批** 换个随机种子重排；同一个种子出同一条轨，
   所以你看到的预演和写下去的一定一致。
6. **应用到 manifest** —— 逐段调流水线自己的 `longtik_plan.patch_segment`。
   它会把 `role` 和文件名 `TikNNN-sNNN-pNN.mp4` 一起改对，
   再重生 `TikNNN.txt` / `TikNNN_shot.txt`。

### 什么时候用

**开新批、切分完、提交之前。** 那时候所有段都是 `planned`，全都能改。

已经出过片的组（`submitted` / `collected`）改不了 —— 这是 `patch_segment` 自己拦的，
不是 Orante 拦的：段都提交过了还改配图，盘上的 mp4 会和 manifest 对不上。
真要重排，先在「重生」里把那些段打回 planned。

## 看图运镜（顶栏「运镜…」）

### 为什么要分三层

直接让 AI 写运镜句子，它会写出画面里根本没有的东西：

> 「摄影机升到**高过人头**的位置」→ 模型于是在前景摆几个人头，好让镜头有得可高过。
> 「两侧的**舞台灯光**依次向后退去」→ 凭空造出一排灯。

这不是模型不听话 —— 是提示词里**确实写了那些名词**。所以分工改成：

| 层 | 谁做 | 做什么 |
|---|---|---|
| **测量** | Gemini | 只回档位，一个字散文都不要 |
| **拼句** | 程序 | 句子从白名单模板里拼，模型碰不到句子 |
| **体检** | 程序 | 再扫一遍成品，画面里没有的物体名词一律打回 |

模型物理上没有机会把想象出来的东西写进提示词 —— **它压根不产出句子**。

### 测图

点「测图（跑 Gemini）」。会弹出独立的 `desc Chrome` —— 这是复用
`longtik_desc.GeminiPage`，一行 API 调用都没有重写。它解决的是最麻烦的那件事：
Key 是 HTTP-referrer 锁定的，裸 urllib 会 403，所以调用必须在
`描述语生成器.html` 页面里发出，referer 才对得上。429 退避和重试也是它自带的。

模型只准回这一份 JSON：

```
shot_size 远景|全景|中景|近景|特写      facing   左|右|正面|背面
room_left / room_right 窄|中|宽         headroom 紧|中|宽
depth 浅|中|深                          level    平视|略仰|略俯
people 整数    crowd 真/假    seated 真/假
```

不在选项里的值一律收敛成默认值，读不出 JSON 就报错，**绝不猜**。
结果按图片 sha1 缓存在批次目录的 `_镜头测量.json`：图没换过就不重量，不白烧额度。
每量完一张立刻落盘，中途崩了已量的不丢。

### 拼句

景别、余量、纵深、人群，四道一起卡：

| 景别 | 允许 | 不许 |
|---|---|---|
| 特写 | 极缓微推、轻微横移、浮动、拉开 | 再推进 |
| 近景 | 微推、推一档（纵深够才行）、拉开、横移 | 推成大特写 |
| 中景 | 推一档、拉开、横移、弧行 | — |
| 全景 / 远景 | 推一档、横移、弧行、下降 | 直接推成特写 |

- 左右**余量窄的那一侧不往那边走**；
- 头顶**紧**只能升不能降；
- 测出 `crowd` 就只剩沿人群外缘的弧行和横移，**不穿插**；
- 测出 `seated` 就补一句「人物坐在原位不起身」。

**不重复**用的是运镜指纹 `(主轴, 方向, 起幅景别)`，不是比字符串 ——
「向前推成近景」和「略带偏移地向前推成近景」是两条文本、同一个运动，
只比字符串抓不出来。约束：相邻 3 段指纹互不相同，同一指纹整批尽量不超过 2 次。

### 写卡

| 通道 | 写到哪 | 什么时候能写 |
|---|---|---|
| Flow | `patch_segment` 写进 manifest 的 `shot` | 只有 `planned` 的段 |
| Grok | `vNN_shot.txt` | 随时 |

Grok 的运镜卡是独立文件，只在下一次铺页时被读，改它不影响已经出好的片子
（那些的原文存在台账的「完整提示词」里）。写出去的文件**不带卡库指纹**，
所以 `flow_shots.read_shot_file` 会把它当人工卡原样保留、不覆盖。
想退回流水线自己的卡：删掉那个文件。

### 怪异镜头是怎么来的（0901 复盘）

0831 那批 Tik010：一位坐在沙发上、被几个听众围着的老太太，30 段里 9 段拍成了
从背后绕过肩膀、摇臂下降两米半、「人物一边说一边横向走动」——人根本没站起来过。

查下来是两件事叠在一起，都在 `longtik_plan.assign_shots`：

1. **它直接 `_pool(shots, eye, scene, 阶段)` 取卡，绕过了 `flow_shots.shot_cards`
   里的安静模式分支。** 也就是说 `运镜模式 = 安静` 对长文案这条线**从来没生效过**，
   一直在用老池子里的摇臂 / 轨道 / 绕行 120 度。
   （我之前说过「那些旧卡在安静模式下跑不到」—— 那句话对 Normal 那条线成立，
   对长文案不成立。是我看漏了。）
2. **`shot_cards` 里有一条「坐姿 + 睁眼 → 按闭眼池取卡」的保护，`assign_shots` 没有。**
   睁眼池每张都写着「摄影机随人物同步跟随」，人不起身，模型就会自己把人拽起来走两步。

0901 已修（备份 `longtik_plan.py.bak-0901-quiet`）：安静模式开着时改从
`安静运镜_多样` 池取卡，并补上坐姿保护。另加一条剪辑约束 ——

> **换图那一段**可以用会改变景别的卡（反正下一段本来就是新画面）；
> **同一张图往下连的段**只用「全程不推近、景别不变」那几张。
> 靠方向变化（左移 / 右移 / 缓慢弧行 / 升降）出变化，起幅落幅都还是原画框，
> 怎么剪都不会跳。

实测 Tik010：30 段用 5 张不同的安静卡、相邻不重复、体检零命中。

### 已经出片了才发现镜头不对，怎么补

**一个按钮：「重生…」→ 勾中那几段 →「换卡 + 重生」。**
它按顺序做完三件事：打回 planned（旧片进 `片段\_弃用\`）→ 把这几段的运镜卡
换成安静卡 → 提交、下载、改名补全。

旁边两个是拆开用的：

- **「只打回，不提交」** —— 打回并换好卡，但不提交。想先自己看看卡、
  或者顺手改改文案时用；改完再点「换卡 + 重生」。
- **「直接重生（不换卡）」** —— 只重摇一次，提示词一个字不动。
  只有在你确认卡本身没问题、纯粹是模型这一次发挥失常时才用。

> **0901 踩过的坑**：这三步以前是分开的，结果点了「开跑」（那时候不换卡），
> 旧片挪走了、新片也生成下载了，但提示词一个字没改 —— 等于拿同一句话再摇一次，
> 出来还是那个怪镜头。所以现在合成一个按钮。

### 重生之后要用的是新的那条，不是旧的

打回重做之后，Flow 合集里同一个 title 下会有两条：原来那条和新生成的那条。
收货时两条都会下下来，一条拿正名 `Tik010-s005-p01.mp4`，另一条排 `-b`。

`longtik_collect.build_plan` 以前按 createTime **正序**排，
于是**最老的那条拿到正名**，`apply_collected` 又固定取第 0 条 ——
manifest 指向的就成了旧片。实测 0831 那批：manifest 指向的文件与挪进 `_弃用`
的旧片 md5 完全一致，等于白重生一次，而且不报任何错。

0901 改成**倒序：最新的一条永远拿正名**（备份 `longtik_collect.py.bak-0901-newest`）。
单 take 的段没有任何区别，只有重做过的段会受影响 —— 那正是要的行为。

### ★★3 报一串 No such file 还退出码 1

`longtik_finish.all_groups()` 以前把登记表里所有组都算上，包括素材早已归档搬走的。
0901 改成目录不在了就不进名单（备份 `.bak-0901-stale`）。

### 镜头语言的四条硬规矩（0901 全量重写）

实拍反馈里，这四类说法会直接把画面拍坏。`flow_shots.json` 里 136 张卡
**全部重写过**（备份 `flow_shots.json.bak-0901-plain`），一条都不许再出现：

| 不许写 | 为什么 | 改成 |
|---|---|---|
| 「由全景**收成/收到**近景」 | 「收」被理解成圆环往里收拢 → 出来是圆形转场，不是推进 | 「镜头缓慢地朝人物向前靠近一点」 |
| 「**手持稳定器**」「**摇臂**」「轨道」「滑轨」 | 器材名会被真的画进画面，穿帮 | 只说「镜头」 |
| 「沿**弧线绕行** 90 度」「**环绕**」 | 出来是各种奇怪的形状类切换 | 只用直线：靠近 / 退开 / 左右平移 / 升降 |
| **英文段** | 对出片没意义，还多一份被念出来的风险 | 全部删掉 |

另外两条：

- **景别词一个都不写进句子。** 景别只用来决定「这张图能选哪种运动」
  （特写不能再靠近、纵深浅不能推），决定完就不写了。
- **全部用正面表述。** 不写「不要转场」——句子里一旦出现「转场」两个字，
  模型照样可能给你来一个。改成正面说「全片是一整段连续拍下来的画面，
  从第一帧到最后一帧不中断」。

现在的卡长这样：

```
【镜头】全片是一整段连续拍下来的画面，从第一帧到最后一帧不中断。
镜头缓慢地向画面左侧平移。运动轻微柔和、匀速平稳，幅度很小，
但不是完全不动的固定镜头。人物始终留在画面中间，画面的边框和构图保持不变。
```

**同一张图连着好几段时，只用不改变远近的卡**（平移 / 升降），
起幅落幅都是原画框，怎么剪都接得上；换图那一段才允许靠近或退开。

### 扫一遍卡池

不需要测图、不烧任何额度：把 `core\flow_shots.json` 里 136 张卡整个扫一遍。
报告分三档，别混着看：

- **器材词**（摇臂 / 轨道 / 滑轨）—— 拍摄器材永远不在画面里，一定要改；
- **凭空参照物**（人头 / 头顶上方 / 高过）—— 拿画面里没有的东西当参照物；
- **景物词**（舞台 / 灯光 / 桌椅 / 车窗）—— 要看场景。
  卡在 json 里的位置就说明了场景：`围绕` 池里的卡提到那一圈人是本来就该提的，
  `车内` 池里提车窗也一样，这些不算问题。

报告会标出哪些卡在**当前的「安静模式」下真正会被用到** ——
旧卡池里的问题再多，跑不到就不急。

## 重生

顶栏「重生…」打开右侧抽屉。候选 = **已标记 + 缺片**，默认全选，可以逐个点掉。

### 通道

| 批次 | 可选 | 干了什么 |
|---|---|---|
| Grok | **用 Grok 重生** | 把选中的旧片挪进 `视频输出\_淘汰\<时间戳>\`，再跑 `grok_pipe.py 跑` |
| Grok | 改走 Flow | 暂时接不上，见下 |
| Flow | **用 Flow 重生** | `longtik_gate.redo_many(shelf=True)` 打回 planned，再跑 `longtik_finish.py --gid` |
| Flow | **Flow 跑完，仍缺的改走 Grok** | 同上 `+ --grok`，Flow 补完还缺的交给 TIK-G-SIMONE。**会烧 Grok 额度** |

Grok 那边为什么只挪文件、不改台账：`grok_pipe` 判待办的依据是
「状态不是已下载/已验收，**或者文件不在**」。文件挪走它自己就认出来了，
台账一个字节都不用动，铺页→提交→锚点是全新一轮，旧 postId 会被覆盖。
挪走的旧片留在 `_淘汰\` 里，随时能翻回来。

### Grok 批次改走 Flow —— 暂时接不上

这不是懒得做。`接力救援.py` 干的就是这件事，但它要**粘表格链接**重新拉 C 列文案，
再按 Flow 的 110 字规则重拆（Grok 是 170），是另一套交互。
反方向（Flow 组走 Grok）之所以现成，是因为 `longtik_finish --grok` 本来就带这条路。

### 预演

「预演」只算不动：列出会挪走哪些文件、落到哪个文件夹、要跑的**完整命令**。
那条命令是可以直接拷进黑窗口手动复现的 —— 行为一模一样。

拦路的会红着写在最上面，最常见的一条是 **Grok 调试端口没开**：
先双击 `启动-Grok全流程.bat` 选账号，把带调试端口的 Chrome 拉起来，再回来点重生。
被拦住时**一个文件都不会动**。

### 任务

点「开始重生」之后，脚本作为子进程跑起来，输出实时贴在下面，可以取消。
日志同时落在 `data\logs\`。跑完自动刷新这一批。

**同时只允许一个任务** —— 两个任务抢同一个 Chrome 会互相打架。

为什么用子进程而不是 import 进来：脚本崩了不会把 Orante 一起带走；
它们本来就是命令行程序，断点续跑、日志格式都是按这个设计的；
出事了你能拿同一条命令手动复现。
