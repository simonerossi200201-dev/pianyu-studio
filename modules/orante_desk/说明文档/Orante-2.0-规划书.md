# Orante 2.0 · 总体规划书

日期：2026-09-06　　作者：Claude（方向把控）　　执行：Grok 4.6（PowerShell）+ Claude 审核

---

## 0. 一句话结论

**保留 Python 后端 + 本地网页前端这条路，但把它做成"一个文件夹拷走就能用"的桌面软件；Flow 这条线彻底放弃「找按钮」，改走 Flow 自己的内部接口（tRPC），从根上治好前端改版就失效的病。**

Grok 和 Flow 两条引擎共用一套任务模型（任务 → 分段 → 每段一张图 + 一句成品提示词），配图轨、重生、多镜头扩图、审核……全部只写一遍，两边都能用。

## 1. 我看到的现状（调研结论）

### 1.1 现有资产盘点

| 位置 | 规模 | 价值 |
|---|---|---|
| `下载图片\core\` | 29 个脚本，约 19,000 行 | Grok 全流程（grok_pipe 2,941 行）、表格下载器、拆分、描述语、运镜卡库（flow_shots.json 136 张卡）、视频体检——**这些逻辑是踩过坑的真金白银，必须原样继承** |
| `0-长文案\core\` | 24 个 longtik_* 模块，约 13,900 行 | 长文案流水线：扫表 / 下图 / 切分 / 配图计划 / 提交 / 回收 / 闸门 / 拼接送 AutoSub |
| `Orante\` | 5,700 行 | 已有的制片台：视频墙、体检、配图轨、看图运镜、重生、开新批、全部生成 |
| 描述语生成器.html | 80 KB | Gemini 描述语提示词 v7、预设管理、Key 存 localStorage（Key 是 HTTP-referrer 锁定的） |

**结论：不是重写，是"重组 + 补缺 + 换掉一根断了的腿（Flow 提交）"。**

### 1.2 现在的硬伤

1. **Flow 提交靠 DOM 找按钮**。0905 日志：`模型列表里没有 Veo 3.1 - Lite`、面板显示「8 秒」而本地想要 4s/6s、进度卡片数不出来（页面数到 1 / 本地记账 5）。luca 账号中文界面、dong 英文界面，aria-label 全不一样，只能中英双写硬撑。Flow 一改版就全军覆没——这条路走不长。
2. **Grok 只支持"一段长文案 = 一张图"**，没有配图轨、没有重生、没有多图编排。
3. **表格依赖 Google Sheet + OAuth**：12 张分表的 id、gid、列号写死在 `core\config*.json`，分发给别人要先教他建表、授权、改配置——学习门槛极高。
4. **绝对路径遍地**：`lanes.json`、`config*.json`、`flow_config*.json` 里全是 `D:\0_Dev\...`，`ffmpeg`、ASR 模型也指到 `D:\0_Dev\AutoSub_v6`。拷到别的机器一步都动不了。
5. **固定结语 / 情绪 / 禁令 / 问题句子（"wait for 7 seconds then type Amen"）藏在 `flow_shots.json` 和脚本里**，普通用户找不到、改不了、换语言更改不了。
6. **配置文件爆炸**：config_×12、flow_config_×12、lanes.json、组登记.json、flow_done/flow_submitted 一堆几 MB 的 json——同一件事有三处真值。
7. **21 个 .bat + 一个 tkinter 下载器 + 一个 FastAPI 9300 + 一个 FastAPI 9400**，入口太多。

### 1.3 「其他人做的」Flow 批量生成扩展（v1.0.6，0905 发布）—— 能借鉴什么

这是一个 Chrome 扩展（Manifest V3），代码整体做了 RC4 字符串混淆，但结构看得清：

**值得学的三点**
- **不碰按钮，直接拦网络请求**：`transformers/flow.js` 劫持了 `window.fetch` 和 `XMLHttpRequest`，从 Flow 的 tRPC 响应里直接读出 `mediaGenerationId`、`mediaStatus`、成片 URL。解码出来的接口名有：`video:batchAsyncGenerateVideoText`、`…StartAndEndImage`、`…ReferenceImages`、`media.fetchCheckAsyncGeneration…`、上传走 `/fx/api/…?name=` form-data。**这正是 Flow 改前端也不受影响的原因**——它盯的是接口，不是界面。
- **页面内嵌电子表格**（打包了 Handsontable）：列是 图片 / 首帧 / 尾帧 / 文本 / 语音 / 数量 / 预设 / 状态，用户像填表一样填任务。和你"内置表格"的想法一致。
- **防止标签页休眠**（`disablePageFreeze.js`）：Web Locks + WebRTC 心跳 + 标题闪动，三招齐上保证后台标签不被 Chrome 冻结。我们的长时间批量提交也该加上。

**它的缺陷（正是 Orante 的机会）**
- 只能在**一个已登录的 Flow 标签页里**跑，一次一个账号，没有多账号调度、没有并发编排。
- 只做「提交 + 下载」，没有文案拆分、没有 Gemini 描述语、没有配图轨、没有体检、没有重生、没有拼接。
- 代码混淆，出问题没法自己修；商业授权的 Handsontable 用在分发软件里有法律风险。
- 表格填的是**每条视频的提示词**，用户还是要自己把长文案拆好、一段一段贴，本质上没解决"长文案对多图"。
- Chrome 扩展分发要用户开开发者模式手动加载，普通人上手并不轻松。

## 2. 技术选型（回答"网页端还是独立软件、用什么语言"）

### 2.1 结论表

| 层 | 选择 | 理由 |
|---|---|---|
| 后端 | **Python 3.11+，FastAPI**（延续现状） | 19k 行现成逻辑全是 Python；Playwright 在 Python 下最成熟；Windows/Mac 一份代码 |
| 前端 | **Vue 3 + Vite，纯静态打包进后端**（不用 CDN、离线可用） | 现在 2,000 行原生 JS 的 index.html 已经到了上限；节点栏、表格、配图轨、多面板需要组件化。Vue 心智负担最低，Grok 写起来也快 |
| 表格 | **Tabulator（MIT）** 或 **RevoGrid（MIT）** | 支持从 Google Sheet 直接 Ctrl+V 粘贴 TSV、单元格下拉、列校验、右键菜单、导入 csv/xlsx，免费可分发。不用 Handsontable（商业授权） |
| 外壳 | **pywebview**（原生窗口包住本地网页） | 双击即开一个独立软件窗口，不是浏览器标签；Windows 用 Edge WebView2（系统自带），Mac 用 WKWebView，**同一份代码**。找不到 WebView 时自动退回到默认浏览器打开 |
| 浏览器自动化 | **Playwright（Python）连 CDP** | 继承现状；每个账号一个独立 Chrome Profile + 独立调试端口 |
| 分发 | **便携文件夹**：`Orante\`（Windows 附带 embeddable Python，Mac 附带一个 `Orante.command`）+ 首次运行自动 `pip install` | 不做安装程序，拷给谁都能用；所有路径以 `Orante\` 根目录为基准的相对路径 |
| 数据 | 每个任务一个文件夹 + `manifest.json`（沿用长文案已有格式扩展），全局用 **SQLite 一个文件**记任务表/账号/设置 | 不再有 12 套 config、几 MB 的 flow_submitted.json |

### 2.2 相对路径 & 跨设备的硬规矩

- 代码里只有一个根：`ROOT = Path(__file__).resolve().parent`，**其余一律 `ROOT / "..."`**。
- 用户数据（工作区、账号、Key、Chrome Profile）默认在 `Orante\workspace\`，用户可在设置里改到任何位置，配置里存的是**用户选的那一个绝对路径**——这是唯一允许出现绝对路径的地方，因为它是用户自己选的。
- 所有外部程序（ffmpeg、Chrome）走「自带 → 环境变量 → 系统常见位置」三级查找，找不到就在 UI 里明确告诉用户缺什么、去哪下。
- 文件名、目录名不做任何 Windows 独有假设（大小写、反斜杠、`\\?\`），用 `pathlib` 全程处理。
- Python 依赖锁死版本（`requirements.lock`），首次运行按平台自动装 Playwright 的 Chromium 或直接用系统 Chrome。

## 3. 界面：底部节点工作流

底部一条窄窄的节点栏，从左到右五个节点，点谁切到谁；每个节点下有一颗小灯（灰=未开始 / 蓝=进行中 / 绿=完成 / 红=有问题），一眼看出一批任务走到哪了：

```
 ① 任务   ──▶   ② 多模态   ──▶   ③ 编排   ──▶   ④ 生成   ──▶   ⑤ 收片
 填表、选账号     Gemini 描述语      配图轨         批量提交       视频墙/体检/重生/拼接
 下图、拆段       运镜、问题句       图片排序       多账号并发     过时/回收
                 多镜头扩图         缺图补生成     右键开/停
```

### ① 任务面板

- **内置表格**，首行是**注释行**（灰底、不可编辑，写清这列填什么）。
- 列：`任务名` · `文案` · `图片来源`（单张直链 / 网盘文件夹链接 / 本地文件夹）· `任务类型`（下拉：长文案 / 短文案）· `账号`（下拉：列出所有 Flow 与 Grok 账号）· `时长偏好`（可留空用默认）· `状态`（只读）。
- **完全兼容 Google Sheet**：从 Sheet 里选中区域 Ctrl+C，到 Orante 表里 Ctrl+V 即可；也支持导入 `.csv/.xlsx`；老用户可以保留"从表格链接导入"（走现有 OAuth 下载器），但**不再是必需**。
- **账号管理**在右上角一个抽屉里：「+ 添加 Flow 账号」「+ 添加 Grok 账号」，填个名字就行，点「登录」弹出这个账号专属的 Chrome 让你登一次，以后不用再登。数量不限，每个账号一条独立通道，互不影响。
- **拆段规则**在设置里明文可调，默认沿用现值：
  - Flow：145 字上限 / `dur_4s_max_words=8`、`dur_6s_max_words=13`，其余 8s，付费模型可选 10s。
  - Grok：≈170 字→10s、≈250 字→15s，6s 档按现脚本的阈值。
- **点「开始」前先弹出一次「这批数据存到哪」**：选一个根目录后，自动按 `根\2026-09-06\A\`、`\B\`……建版本文件夹，永不覆盖。默认记住上次选择。
- 下载规则不变：单张图用过标 `【已使用】`，再用标 `【已再次使用】`……（沿用 `used_files.json` 的逻辑，改为随工作区存放）。
- 短文案 + 网盘文件夹 = 随机挑一张；长文案 + 网盘文件夹 = 全部下载、编号 `p01…pNN`、自然排序。

### ② 多模态面板（Gemini）

- 每个用户填自己的 **Gemini API Key**（存本机，不上传）。既支持普通 Key（直连 REST），也兼容你现在那种 referrer 锁定 Key（走隐藏页面发请求，沿用 `longtik_desc.GeminiPage`）。模型钉 `gemini-3.5-flash-lite`，可在设置里改。
- **全部提示词明文可见、可编辑、可存预设、一键恢复默认**，默认值 = 现在脚本里正在用的那一套（v7 描述语、运镜规则、固定结语、情绪推进、禁令）。分成四块卡片，可展开/收起：
  1. 描述语提示词（身份锁正文 + 音色）
  2. 运镜规则（默认：人物不动、镜头轻微运动；可切"人物可动 / 剧烈运动"预设）
  3. 固定结语（闭眼 / 睁眼 / 空镜三版）
  4. **问题句子库**：用户可无限添加「文案里会出现、必须念出来的指令句」（如 `Stay for 7 seconds and type Amen`），支持任何语言；还有一颗「让 Gemini 扫一遍文案自动补充」按钮，把 AI 找到的句子自动加进库里，你确认即可。
- 面板最下方一块「**最终提交预览**」：选任一段，把程序最终会发给 Flow/Grok 的**完整提示词**原样显示出来，不再有任何隐藏拼接。
- **多镜头扩图**（长文案专用）：图片 < 6 张时自动进入。Gemini 读每张图 → 生成「换景别 / 换角度 / 换距离，人物动作服装外貌不变」的生图提示词 → 提交 Flow 一次出 4 张 → 自动下载 → 进入「待审核」栏，你勾留哪几张。
- **空镜头识别**：无论是下载来的还是新生成的，Gemini 判为「大全景 / 观众席 / 无主角环境」的图，自动挪进 `空镜头\`，不进配图轨，后续单独生成无声 B-roll。

### ③ 编排面板（配图轨）

- 就是现在 Orante 已有的配图轨（钉区 / 洗牌袋 / 限定图池 / 预演 / 换一批），**开放给 Flow 和 Grok 两种任务**。
- 每张图自动重命名为数字 `p01…`，色条每格显示 `p07` 这样的编号，颜色相近也分得清。
- **被拒图片自动补生成**：Flow 报「知名人士 / 违规 / 未成年」时，程序拿同组一张能用的图让 Gemini 写简短描述（强调换景别、角度、距离）→ Flow 生成一批 → **自动左右翻转** → 替换掉那张被拒的图，配图轨里的分配规则、钉区、图池范围**一个字节都不变**（因为替换的是 `p07` 这个"槽位"里的文件，不是重排轨道）。一次不行自动换描述再来，直到补上。

### ④ 生成面板

- 任务列表 = 任务表的每一行；复选框多选；**右键菜单**：开始生成 / 停止 / 重生缺片 / 打开文件夹 / 移到回收站。顶部「全部生成」。
- **调度规则**：每个账号同一时刻只跑一个任务；不同账号并行；一个账号跑完自动接它的下一个任务。任务表里选好的账号就是它的通道，不再询问。
- 实时进度：每段一颗小格（待提交 / 已提交 / 已下载 / 被拒 / 失败），日志抽屉可展开。
- **过时 / 回收**：检测到任务目录下已有「字幕成品」→ 自动归入「过时」；「回收」是手动丢弃区，可恢复。主列表始终只显示在做的。

### ⑤ 收片面板

- 现有视频墙、体检、重生、拼接送 AutoSub 全部保留，**「重生」对 Grok 任务同样可用**（挪走旧片 → 同图同提示词重提 → 下载改名补位）。

## 4. 引擎层：Flow 怎么修、Grok 怎么补

### 4.1 Flow：从「找按钮」改成「调接口」

Flow 前端是 Angular + tRPC。扩展已经证明可以直接和 `flow.google.com/fx/api/trpc/...` 对话。方案：

1. **抓包定型**（我来做）：在你某个泳道的 Chrome 里手动生成一次，用 CDP 的 Network 域把真实请求原样录下来：上传图片（form-data）、`batchAsyncGenerateVideoReferenceImages`（图生视频）、状态轮询、成片 URL。记录字段：projectId、collectionId、model 枚举值、aspect、durationSeconds、seed、referenceImage id。
2. **写 `engines/flow_api.py`**：所有调用通过 `page.evaluate(fetch(...))` 在**已登录的 Flow 页面上下文里**发出（cookie、`x-goog-*` 头、reCAPTCHA token 都由页面自带），我们不伪造任何鉴权。
3. **兜底**：如果某个接口拒绝脚本调用，只在「点开始生成」那一步退回真实鼠标点击，其他全走接口——这也是 0905 你们已经验证过的"真实鼠标点一次"经验。
4. 每个账号的 Chrome 加上防冻结注入（借鉴扩展），后台跑几小时不掉。
5. 保留 `longtik_flow_newui.py` 作为「Plan B 适配器」，接口层出问题时一键切换。

**这样一改，Flow 再换前端，我们只需要重新抓一次包对一下字段，不用再对着中英文按钮名猜。**

### 4.2 Grok：补齐长文案 + 配图轨 + 重生

- Grok 现有 `grok_pipe` 的一段一图逻辑本质上就是「每段一个 (图, 提示词) 作业」——把它的输入从 `vNN.txt` 改为读统一 `manifest.json`，长文案多图就天然支持了。
- 重生 = 挪走旧片 + 让该段回到 planned + 重跑该段，与 Flow 完全一样的按钮、一样的语义。
- Grok 的时长档 6/10/15s 由拆段规则决定，写进每段的 manifest。
- 多镜头扩图、被拒补图这两件"生图"的事，Grok 任务也统一交给某个 Flow 账号（Ultra 不用白不用），在任务表里可以指定「扩图用哪个 Flow 账号」，默认第一个。

### 4.3 统一任务模型（两边共用）

```
Task
 ├─ id, name, engine(flow|grok), account, type(long|short), workspace_dir
 ├─ copy.txt                     原文
 ├─ images/  p01.jpg … pNN.jpg   (已编号；被拒替换直接覆盖同名)
 ├─ 空镜头/                      Gemini 判定的大全景 / 观众
 ├─ manifest.json
 │    segments: [{ s, text, image:"p07", duration: 6, shot_card, desc, prompt_final, status, take_files[] }]
 │    track:    { pins, pools, hold, seed }
 └─ clips/  <task>-s001-p07.mp4  … ；_弃用/ ；字幕成品/
```

`prompt_final` 是提交那一刻的**完整字符串**并落盘——审核时看到的就是发出去的。
