# 蓝图 — 用本地代理取代 Grok Bot

> 依据 2026-10-05 对本机实际文件的查看结果。

## 1. 现有工具盘点：代理能怎么接

| 工具 | 是什么 | 现成接口 | 代理接入方式 | 难度 |
|---|---|---|---|---|
| **CUTORA**（片语 Studio）`D:\0_Dev\CUTORA` | 视频剪辑、自动字幕、批量导出 | ✅ **已有 MCP 服务器**（`cutora_mcp.bat` → `cutora.api.mcp_server`），以及批量 CLI（`CUTORA_CLI.bat` → `cutora.batch.cli`）、本地 API 和任务进度（`api/jobs.py`、`events.py`） | Goose 直接挂 `cutora_mcp.bat`。需要先打开片语 Studio，并在 **设置 → 代理接口** 里启用 | ⭐ 最容易 |

**CUTORA 已经有 MCP，等于有一半已经接好了。**

## 2. ⚠️ 最大的限制：显存只有 16 GB，需要轮流用

| 占用 GPU 的程序 | 大约显存 |
|---|---|
| muse-glimmer | 约 17 GB（本身就放不下） |
| gemma4:12b | 约 8.4 GB |
| ComfyUI MiniMax H3 | 按 16 GB 显卡调过，基本会占满 |
| CUTORA 自动字幕和导出（CUDA） | 数 GB |

**结论：大脑和干活的软件不能同时都放在 GPU 上。** 解决办法：
1. **用"任务队列"思路，代理不需要一直醒着**：它下达任务后让 Ollama 卸载模型（`keep_alive=0`），由监控脚本盯进度，完成或出错时再把它叫醒做判断。
2. 需要它一直在线时，用 **gemma4:12b**（8 GB），把剩下的显存留给 CUTORA。
3. ComfyUI 生成视频时，**代理必须让出 GPU**。

这其实和你现在的 `RUN_GROK_QUEUE.bat` 是同一种模式：队列、锁文件、日志、`_HALT` 停止标记。

## 3. 两个角色，分开配置

### 角色 A：工作代理（取代 Grok bot 的"操作员"部分）
- 主体：**Goose** + muse-glimmer（精确优先）
- 工具：CUTORA MCP、Orante bridge 脚本、rclone、ComfyUI 脚本、Playwright MCP（浏览器、Google Sheets）
- 记忆：`D:\0_Robota\SOP.md` + Goose Recipes

### 角色 B：语言导师（聊天）
- 主体：**Open WebUI** 语音通话模式
- 模型：**gemma4:12b**（对话要快）
- 耳朵：Whisper（本地）；嘴巴：Kokoro（本地，声音自然）
- 设置一个"导师"系统提示：目标语言、纠错方式、难度
- 记忆：Open WebUI 的 Memory 功能（记住你的水平、常犯的错误）

## 4. 坦白说：哪些取代不了

| Grok 原来做的事 | 本地能否取代 |
|---|---|
| 按步骤调用你的工具、看进度、汇报 | ✅ 可以 |
| 读表格、改名、上传、整理文件 | ✅ 可以 |
| 语言陪练对话 | ✅ 可以 |
| **`RUN_GROK_QUEUE` 那种：自主修改 CUTORA / Orante 的大型代码库** | ❌ **基本不行**。28B 本地模型改这种体量的代码，质量和稳定性差距很大，容易改坏 |
| Orante 流水线里作为**视频生成服务**的 Grok / Flow | ❌ 那是云端生成模型，和代理无关；本地能替代的只有 Studio Zero 这条线 |

建议：**日常操作交给本地代理（省下大头费用）**，写代码这类重活保留一个按量付费的方案，偶尔用。

## 5. 实施顺序

1. 安装 Goose，连上 Ollama，开启"每步确认"
2. 接入 **CUTORA MCP**，做第一个闭环：让代理导入 → 字幕 → 导出 → 汇报进度
3. 写 GPU 调度脚本：自动卸载和加载 Ollama 模型
4. 接入 Orante bridge 和 rclone
5. 接入 ComfyUI（Studio Zero）
6. 把完整工作流写进 `SOP.md`，存成 Recipe
7. 配置 Open WebUI 语言导师和语音

## 6. 三层大脑：自动升级，不需要人工切换

本地大脑处理不了的事，**由机器人自己决定交给更强的大脑**，你不用手动切换。

```
           你下达任务（打字 / 语音 / 队列文件）
                        │
              ┌─────────▼─────────┐
              │  调度器 dispatcher  │  ← 自己写的小程序，按规则分派
              └─────────┬─────────┘
       ┌────────────────┼────────────────────┐
       ▼                ▼                    ▼
 第 1 层 本地 Muse     第 2 层 免费云端 API      第 3 层 Antigravity
 （Ollama，免费、私密） （快、强，有频率限制）       （SDK 程序化调用，最强）
 日常操作、调度、       本地卡住时的推理、          写代码、改 CUTORA 和 Orante、
 看日志、汇报           长文档、翻译               复杂排错
```

### 怎么做到"自动"
- **Antigravity 有官方 Python SDK**（`pip install google-antigravity`），可以在脚本里直接启动一个 Antigravity 代理去执行任务，权限可以自己配置。
- 把它包装成本地代理的一个**工具**，例如 `ask_antigravity(任务说明)`。Muse 判断"这是写代码"或"我做不来"时，自己调用这个工具。
- 也可以把 `RUN_GROK_QUEUE.bat` 里的 `grok --prompt-file ...` 换成调用 Antigravity SDK 的脚本，**队列、锁文件、日志、`_HALT` 这些机制都不用改**。

### 升级规则（建议）
| 情况 | 交给哪一层 |
|---|---|
| 调用 CUTORA、Orante、rclone，看进度、汇报 | 第 1 层 |
| 同一步本地连续失败 2 次 | 自动升到第 2 层 |
| 任务涉及修改代码或写新脚本 | 直接交给第 3 层 |
| 涉及私密资料（账号、客户素材内容） | 只能用第 1 层，禁止上云 |

### 第 2 层的候选（非中国公司，**使用前请核实当下的条款和额度**）
| 服务 | 公司 / 所在地 | 说明 |
|---|---|---|
| Google AI Studio（Gemini API）免费层 | Google（美国） | 免费层的数据**可能被用于改进产品** |
| Mistral 免费层 | Mistral（法国，欧盟） | 有免费的试用方案 |
| Groq / Cerebras | 美国 | 推理速度极快，免费层托管的是开源模型 |
| GitHub Models | 微软（美国） | 有 GitHub 账号就能用，频率限制严格 |
| OpenRouter 免费模型 | 美国中转平台 | ⚠️ 免费模型里很多是中国模型，且部分服务商会记录数据，需要逐个挑选 |

> 注意区分两件事："模型是谁做的"和"数据发到谁的服务器"。比如 Qwen 是中国模型，但托管在美国的 Groq 上时，数据不会去中国。你可以自己决定哪种算"排除"。

### 共同的代价
- 第 2 层和第 3 层的数据都会**离开本机，发到云端**。
- 免费层普遍有**频率限制**，而且**可能用你的数据训练模型**。
- Antigravity 的用量受你账号套餐的额度限制，具体以你的套餐为准。
