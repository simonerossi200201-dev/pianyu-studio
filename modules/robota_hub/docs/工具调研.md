# 0_Robota — 本地 AI 代理工具清单

> 目标：用本机 Ollama 模型（muse-glimmer / gemma4），搭一个类似 Grok bot 的"按步骤干活"的本地代理。
> 整理时间：2026-10。**下载前请再到官方页面核对一遍最新信息**，项目更新很快。

## 一、推荐组合（先从这套开始）

| 角色 | 工具 | 用途 |
|---|---|---|
| 🧠 大脑 | **Ollama**（已装） | 本地跑模型，数据不出本机 |

## 三、安全配置清单（必做）

- [ ] 所有工具**只配置本地 Ollama**（`http://localhost:11434`），**不填任何云端 API Key**
- [ ] 尤其**不要**配置中国厂商的在线 API（DeepSeek / 通义 / Kimi / 智谱 等在线接口）
- [ ] 关闭遥测：
  - Open WebUI 环境变量：`SCARF_NO_ANALYTICS=true`、`DO_NOT_TRACK=true`、`ANONYMIZED_TELEMETRY=false`
  - Aider：`--analytics-disable`
  - Cline / Continue / Goose：在设置里找 telemetry / analytics，关掉
- [ ] 代理设为**每一步需要确认**（至少前几周）
- [ ] 只开放一个工作目录给代理（比如 `D:\0_Robota\workspace`），不给整个硬盘
- [ ] 不装来路不明的插件、扩展、技能
- [ ] 让代理上网时，用**Windows 防火墙**限制出站，或者放在 Windows Sandbox / 虚拟机里跑
- [ ] 用 `netstat -ano` 或防火墙日志检查它实际连了哪些地址

## 五、复刻 "Grok bot 工作方式" 的方案

核心原则：**脚本负责干活，代理负责调度和汇报。**

```
D:\0_Robota\
├── README.md          ← 本文件
├── SOP.md             ← 你的操作步骤（代理每次先读这个）
├── scripts\           ← 你的本地脚本
│   ├── 01_xxx.py
│   ├── render_watch.py   ← 渲染进度监控脚本
│   └── ...
├── workspace\         ← 只开放给代理的工作目录
└── logs\              ← 脚本输出日志，代理从这里看进度
```

做法：
1. 把你平时告诉 Grok 的步骤写进 `SOP.md`（模板见同目录）
2. 每个步骤尽量对应一个**能独立运行的脚本**，脚本运行时输出清楚的日志（比如 `进度 45%`、`完成`、`错误: ...`）
3. 对 Goose 说：「读 `D:\0_Robota\SOP.md`，按步骤执行」
4. 稳定之后，把流程存成 Goose Recipe，以后一句话就能触发
