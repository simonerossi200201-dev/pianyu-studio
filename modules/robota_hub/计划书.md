## 1. 目标

| # | 目标 | 衡量标准 |
|---|---|---|
| G1 | **取代 Grok 队列**：自动执行代码修改任务 | `tools\grok-queue.txt` 这类任务能由 Antigravity 跑完，日志、锁文件、停止机制保持一致 |
| G2 | **工作代理**：串联 CUTORA、Orante、右键表格工具（rclone）、Studio Zero | 说一句"跑流程 A"，机器人按 SOP 一步步执行、监控进度、汇报，出错时停下来问你 |
| G3 | **自动升级**：本地处理不了的任务，自动交给更强的模型 | 不需要人工切换；有日志记录每次升级的原因 |
| G4 | **语言导师**：语音对话陪练 | 本地语音识别和语音合成，能纠错，记得你的水平 |
| G5 | **省钱、安全** | 停用 Grok；私密数据不上云；所有操作有日志、能回滚 |

**不在范围内**：替代 Grok / Flow 的云端**视频生成**（那是生成服务，和代理无关）。

## 4. 安全红线（全程遵守）

1. **不改动你现有项目里的任何文件**，除非那个阶段明确需要。改动前先确认 git 状态是干净的，在**新分支**上改。
2. **`RUN_GROK_QUEUE.bat` 和 Grok 相关文件保持原样**，作为备用方案，直到你确认可以停用 Grok。
3. Antigravity 代理**不使用"全部放行"模式**：限定工作目录，禁止删除仓库以外的文件。
4. 私密数据（账号凭据、`rclone.conf`、客户素材内容）**只在本地层处理，不发给云端**。
5. 所有安装来源只用官方渠道（PyPI 官方包、官方 GitHub、官网）。
6. 每个阶段结束都有**验收**；没通过就不进入下一阶段。
7. 涉及安装软件、修改系统设置、修改现有项目时，**先问你**。

## 5. 分阶段实施

### P0 · 准备与基线（约 20 分钟）
**步骤**
1. 建立目录结构，`git init`，写 `.gitignore`（排除 secrets、logs、venv）
2. 用 `uv` 建 `runtime\venv`（Python 3.11 或 3.12）
3. 记录基线：Ollama 版本、显卡驱动、各项目的 git 状态、当前显存占用
4. 设置 Ollama 默认参数：上下文 32K、模型空闲 5 分钟自动卸载

**交付物**：目录 + `logs\baseline.txt`
**验收**：venv 能用；基线文件完整

### P1 · 验证 Antigravity SDK（约 30 分钟）⭐ 关键
**步骤**
1. `pip install google-antigravity`（官方 PyPI）
2. **只读模式**测试：让它列出 `D:\0_Robota` 里的文件并做总结
3. 确认登录方式：用的是不是你的 Ultra 账号？需不需要单独登录？
4. **可写模式**测试：只在 `workspace\sandbox` 里让它新建、修改一个文件
5. 测试权限边界：让它尝试写 sandbox 以外的地方，确认会被拦住
6. 记录额度消耗：测试前后各看一次用量面板
7. 测试故意触发错误、超时，记录报错格式（用于后面识别"额度用完"）

**交付物**：`robota\agy_task.py`（单任务执行器）+ `logs\P1_sdk_report.md`
**验收**：能用程序启动 Antigravity 代理完成一个可写任务，权限边界生效，额度消耗清楚
**风险**：SDK 不支持订阅登录、只能用 API key → 改用 CLI 方案或计费 API；会先跟你确认再继续

### P2 · 替换 Grok 队列（约 1 小时）
**步骤**
1. 读懂现有队列格式：`tools\grok-queue.txt`、`docs\plan\queue\` 下的 spec、`.stop`、`_HALT`、`_progress.txt`
2. 写 `agy_queue.py`，**完全沿用原有约定**：
   - 逐行取任务 → 记录 git 状态 → 调用 Antigravity 执行 → 再记录 git 状态 → 出队 → 写入 done
   - 单写者锁（加上进程 ID，能识别上次崩溃留下的锁）
   - 支持 `_HALT` 和 `<任务>.stop`
   - **新增**：识别额度用完 → 自动暂停 → 每 30 分钟重试 → 恢复后继续
   - **新增**：单个任务超时保护
3. 写 `RUN_AGY_QUEUE.bat` 作为入口（纯 ASCII，和原来的风格一致）
4. **演练**：用一个临时 git 仓库加 2 个小任务完整跑一遍，包括中途 `_HALT`
5. **实战**：在 CUTORA 的**新分支**上跑 1 个你挑选的真实小任务

**交付物**：`agy_queue.py`、`RUN_AGY_QUEUE.bat`、演练日志
**验收**：真实任务跑完，日志格式和 Grok 版本一致，测试通过情况不比之前差
**达成后**：G1 完成，可以考虑停用 Grok 💰

### P3 · 本地大脑（约 1 小时）
**步骤**
1. 测试 muse-glimmer 的**工具调用稳定性**：设计 10 个标准测试（单个工具、连续多个工具、参数复杂、出错后重试），统计成功率和耗时
2. 同样的测试跑一遍 gemma4:12b 作对比
3. 选主体：
   - 方案 A：**Goose**（现成，支持 MCP 和 Recipes）
   - 方案 B：自己写一个轻量代理循环（Ollama 工具调用 API + MCP），更可控
   - 按测试结果决定；倾向先试 Goose
4. 配置：只开放 `workspace`，每步确认

**交付物**：`logs\P3_local_benchmark.md`，配置好的代理
**验收**：本地代理能稳定完成"读文件 → 跑脚本 → 读日志 → 汇报"的循环

## 8. 风险与应对

| 风险 | 应对 |
|---|---|

# v2 修订（2026-10-05 03:05，根据 P1 结果）

## A. P1 结论
| 项目 | 结果 |
|---|---|
| Antigravity SDK 云端模式 | 需要 Gemini API key → **不采用**（你不想用 Gemini API） |
| Antigravity SDK 本地模式（接 Ollama） | ✅ 可用 → 作为**本地层的代理框架**，不再需要 Goose |
| **Antigravity CLI `agy` 1.2.16** | ✅ 已安装，**已用你的 Ultra 账号登录**；无人值守模式实测 7.7 秒完成建文件任务，输出 JSON（包含 token 用量） |
| `agy` 可用的模型 | Gemini 3.8 / 3.7 / 3.6 Flash、Gemini 3.1 Pro、**Claude Opus 5.5**、**Claude Sonnet 5.5**、GPT-OSS 120B |

`agy` 的关键参数：`-p`（无人值守）、`--output-format json/stream-json`、`--mode accept-edits`、`--sandbox`、`--add-dir`、`--print-timeout`、`--model`、`--effort`、`agy mcp add`。
→ **完全可以替代 `grok --prompt-file`**，而且 Ultra 订阅里就包含 Claude Opus 这一级的模型。

## B. 修订后的大脑分层

| 层 | 大脑 | 费用 | 用途 |
|---|---|---|---|
| **L1 本地** | Ollama：muse-glimmer / gemma4 | 0 | 日常调度、看日志、汇报、私密任务、语言陪练 |

**说明**：L3 已经能用 Claude Opus、Gemini Pro 这一级的模型，而且已经付过钱了。所以 L2 **不是用来补"智力"的**，而是补 **L3 没有的专项能力**，或者在 L3 额度用完时顶上。

## D. 统一接入方式：LiteLLM 网关

实测发现：SDK 的 OpenAI 兼容模式**只能填地址、不能带 API key**。所以加一层本地网关：

```
代理（SDK / 调度器） ──► LiteLLM（本机 127.0.0.1:4000）──► Ollama / Mistral / Groq / Nebius / Meta ...
                         统一管理密钥、自动故障切换、频率限制、用量统计
```
- LiteLLM 是开源项目（MIT 许可），**只在本机监听**，密钥放在 `D:\0_Robota\secrets\`
- 自动切换：某家额度用完或出错 → 换下一家
- 私密任务的路由规则：**只允许走 Ollama**

## E. 原则：按用途接入，不为接而接
每多接一家，就多一个**账号、一份数据外流、一个故障点**。接入顺序按实际价值排：
1. **DeepL**（语言导师，马上能用上）
2. **Mistral**（欧盟通用备份，L3 额度用完时顶上）
3. **Groq 或 Cerebras**（实时语音对话需要低延迟时）
4. 其他的等遇到具体需求再加

**每一家都需要你本人注册账号并申请 API key**，我没法替你注册。你拿到 key 以后放进 `secrets\`，我来负责接入。
