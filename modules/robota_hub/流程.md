# 流程全景 — 本地代理怎么"活过来"

> 只用来理解原理，暂时不需要动手。

## 1. 整体结构

```
        你（打字 / 说话）
              │
   ┌──────────▼──────────┐
   │  耳朵 Whisper（可选）  │  语音 → 文字
   └──────────┬──────────┘
              │
   ┌──────────▼──────────┐      读      ┌──────────────┐
   │   身体 Goose（代理）   │ ◄─────────── │ SOP.md 手册   │  记住你的步骤和习惯
   └──────────┬──────────┘              └──────────────┘
              │ 每一步都问大脑："下一步该干嘛？"
   ┌──────────▼──────────┐
   │ 大脑 Ollama + Muse    │  只负责思考和决定，自己不能动手
   └──────────┬──────────┘
              │ 决定调用某个工具
   ┌──────────▼───────────────────────────────┐
   │  手脚（工具）                              │
   │  ├ 命令行：运行 D:\0_Robota\scripts\*.py   │
   │  ├ 文件：读日志、读结果                     │
   │  ├ 浏览器：Playwright MCP 打开表格          │
   │  └ 软件 API：通过你写好的脚本调用             │
   └──────────┬───────────────────────────────┘
              │ 工具返回结果（日志、进度、报错）
              ▼
        回到大脑判断 → 继续 / 汇报 / 停下来问你
              │
   ┌──────────▼──────────┐
   │  嘴巴 Kokoro（可选）   │  文字 → 语音
   └─────────────────────┘
```

## 2. 一次任务的实际循环

1. 你说："按 SOP 的流程 A 跑一遍"
2. Goose 读 `SOP.md`，把内容交给 Muse
3. Muse 思考后决定：先运行 `01_read_sheet.py`
4. Goose 弹窗请你确认 → 你点同意 → 脚本运行
5. 脚本输出 `完成` → 结果交回 Muse
6. Muse 决定下一步：开始渲染 → 运行 `02_start_render.py`
7. 渲染期间：Muse 每隔一段时间调用 `render_watch.py` 查看进度，并向你汇报 "45%"
8. 出现 `错误` → 按 SOP 规则停下来问你
9. 全部完成 → 汇报总结

**一句话：脚本是手，Muse 是脑，Goose 是把两者连起来的神经，SOP.md 是记忆。**

## 3. 分工原则

| 交给脚本（稳定、可重复） | 交给 Muse（需要判断） |
|---|---|
| 读表格、调用软件 API、导出文件 | 决定下一步做什么 |
| 检查渲染进度、等待 | 看懂日志和报错 |
| 重命名、移动文件 | 遇到意外情况时决定停下还是继续 |
| | 用人话给你汇报 |

脚本写得越完善，代理越可靠，对模型能力的要求也越低。

## 4. 模型选择

| 场景 | 模型 | 原因 |
|---|---|---|
| 代理干活 | **muse-glimmer** | 更大，专门为工具调用和多步任务训练；多步任务里错误会累积，所以准确度比速度重要 |
| 语音闲聊、快速问答 | gemma4:12b | 能完整放进显存，响应更快，聊天时延迟低体验更好 |

## 5. 搭建顺序（以后要做时）

1. 安装 Goose → 连上 Ollama → 选 muse-glimmer，上下文设为 16K 到 32K
2. 开启"每步确认"，只开放 `D:\0_Robota\workspace`
3. 写第一个脚本和 SOP，用一个简单流程试跑
4. 接上 Playwright MCP（浏览器）
5. 写渲染监控脚本
6. 稳定后保存成 Goose Recipe → 以后一句话就能触发
