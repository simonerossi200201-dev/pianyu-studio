## 一、尾音剪不干净，是切点算错了，不是模型不够好

现场取的就是你给的那条：`Tik012-s001-p04.mp4`，文案 *…prayed only once a year*。

转录缓存里 whisperX 的原话是：

```
… ['once', 3.789, 3.950] ['a', 4.110, 4.151] ['year', 4.251, 4.532]
  ['to', 4.633, 4.753] ['sod', 4.834, 5.738]
```

模型**没有错**：它把该剪掉的 "to sod" 认出来了，起点 4.633s 也压得很准
（音频包络显示声音是 4.59s 抬起来的）。

错的是下刀的规则。老代码只有一行：

```python
b = min(dur, t1 + tail_pad)      # 词尾 4.532 + 尾部余量 0.35 = 4.882
```

4.882s **正好落在 "to" 的中间**。成品里就留下 0.25 秒的半个音，接上下一段
必然跳。同一批里 s007 的 "too lord" 也是一样的死法。

所以**不需要换更大的模型**——换成 large 也只会把 "to sod" 转得更准一点，
而切点还是 4.882。这条余量是固定的，只要片段结尾有东西，它就一定剐得到。
（更糟的是那种 ASR 根本不转的半秒气音／"an"，模型再大也转不出来，
只能靠听音量。）

## 二、新规则：从词尾往后走，声音一回来就在它之前切

新增 `refine_tail` / `refine_head`，判据是**相对 + 绝对两条同时成立**：

* 相对：比这段静音的最低点高出 `EDGE_RISE = 9 dB`；
* 绝对：同时高过本片噪声底（第 5 百分位）`EDGE_ABS_MARGIN = 12 dB`。

两条都满足才算「声音回来了」，然后在抬升点前 `EDGE_GUARD = 20ms` 下刀。
只用相对判据的话，室内底噪自己抖 10 dB 就会把切点提前，每段都会莫名变短——
所以必须加绝对那条。

**一路安静到尾部余量为止的，切点和老版本一个数都不差。** 这一点是刻意的：
不该动的段一段都不许动。

### 实测（你那 18 段，尾部余量仍是 0.35）

```
Tik012-s001   0.000-4.882  →  0.000-4.570   ← "to sod" 整个切掉了
Tik012-s007   0.000-5.528  →  0.000-5.230   ← "too lord" 整个切掉了
其余 16 段    完全不变
```

接缝处的电平（10ms 一格，dB）：

```
老：-25 -26 -26 -25 -27 -36 -94 | -21 -17 -16    ← "to" 响着被硬切断
新：-17 -23 -28 -34 -38 -40 -43 | -21 -17 -16    ← "year" 自然衰减到静音
```

拿不到音频包络时（极端情况）也退化成「不越过下一个词的起点」，仍比老版本干净。

## 三、接缝淡化

`_encode_group` 每段加 **10ms 淡入 / 30ms 淡出**（可在界面关掉）。
淡入故意只做 10ms：片段常常第一帧就开口（s002 的 "and" 在 0.031s），
30ms 淡入会把字头削软。淡出可以长，反正切点已经在静音里了。

## 四、多文件夹

素材那一栏从单行输入框换成列表，四个按钮：

* **添加文件夹...** —— 一次加一个，可以重复点；
* **添加整棵目录...** —— 选 `…\0901\`，自动把下面所有装着视频的子文件夹
  （`Tik012\片段`、`Tik013\片段`…）全加进来，自动跳过 `_stitched` / `_invalid` /
  `_collect` 这些自己产出的目录；
* **移除选中** / **清空**。

上次用过的文件夹会记在 `core\user_data\stitch_naming.json`，下次开对话框直接摆好。

### 成品各回各家

| 东西 | 落点 |
|---|---|
| 成品 mp4、`_asr_cache.json`、`_encoded.json` | **各自素材文件夹**下的 `_stitched` |
| 切点表、拼接报告、缺失文案清单 | 第一个文件夹的 `_stitched`（汇总） |

转录缓存跟着素材走，所以以后单独重跑其中一个文件夹照样命中，不会重转。

组名重复时（两个文件夹里都有 `01` 组），表里第二个改叫 `01(文件夹名)` 只为
字典键唯一，**出片文件名仍然是 `01.mp4`**，而且落在它自己的文件夹里，谁也不
覆盖谁。日志里会写一行提示。

体检（`media_guard.preflight`）改成**逐文件夹各体检各的**——坏文件要隔离进它
自己的 `_invalid`，断号也只有在同一个文件夹里比才有意义——最后合成一份报告。

## 四点五、开头被剪掉（当天补的修复）

现场：`Grok\0901\视频输出\04a.mp4`，文案开头 **WHAT SINS SHOULD CHRISTIANS…**，
成品里 "what sin" 整个没了。同组 `04i` 也一样，开头的 "revelation 3" 没了。

原因不在切口，在更早一步的**词级认领剪枝**：

```
whisperX 听成 sin，文案里是 sins  →  what 落单成了一个 1 词的 run
plan_group_dedup:  big = [r for r in merged if r[1]-r[0] >= 2]   ← what 被扔掉
保留区间于是从 should 才开始 → 开头两个词整个剪掉
```

最阴的一点：`claimed` 记的是剪枝**前**的区间，所以覆盖表认为这两个词"有人讲过"，
**缺失检测一个字都不报**——白丢了还没人吭声。（这是老代码就有的毛病，只是老规则
入点算在 `t0-0.30`，落在 "sin" 中间，听上去是个含混的半个字；精修之后切得干净，
就变成了整句消失，一下子就露出来了。）

两处改动：

1. **孤立短 run 只有"离所有大块都远"时才扔。** 紧挨着大块、中间只隔着
   ≤2 个没人认领的词（ASR 错词）的，留下。留下也不会多挨一刀——
   `_plan_segments` 那边间隔小于 4 个词根本不切。
   判据里"没人认领"是关键：空档里只要有词被别的片段抢走了，那就是真去重，
   合过去会让同一句话在成品里念两遍。
2. **首段的入点一个字都不往后挪**，和精修前完全一样。片段开头前面那点东西
   没有任何"它是废话"的证据，上一个词多半是被听错的正词；把入点卡到它后面
   就是剪掉开头的正词，代价远大于留下半秒杂音。往后挪只在**内部切口**处做，
   那里的间隔是 `_plan_segments` 判过的（≥4 词且 ≥0.8 秒）真废话。

修完在组 04 上实测：

```
04a  [0.813 → 14.795]  →  [0.000 → 14.795]   开头第一个词 = what
04i  [0.883 → 14.880]  →  [0.000 → 14.880]   开头第一个词 = revelation
其余 9 段完全不变，缺失文案：无
```
