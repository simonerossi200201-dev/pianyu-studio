# Q171 · 中央监视器右键：批量蓝绿幕抠像 / 批量开关分屏 / 批量取消（2026-10-06）

Luca：
- 中央监视器里选中一批视频，右键就能批量抠蓝 / 绿幕，并且把全部抠像功能放进子菜单。
- 批量操作不能扎堆把内存、显存、系统资源一下子用爆，性能要做到顶尖。
- 自动抠像默认针对**外部加载的视频**，不针对媒体库视频。需要时可以改成目标图层或媒体库视频。
- 分屏要能批量开、批量关，选中的视频右键可以批量取消分屏。其他功能也一样：能批量做，也能批量取消。

## 右键菜单（选中几条，在任一条上右键）

```
蓝绿幕抠像（N 条）▸
  作用于：外部加载的视频 ▸  ● 外部加载的视频（默认） ○ 媒体库视频（主视频） ○ 两种都要
                            ○ 只抠右键点中的格子 X（分屏时出现，本次打开监视器有效）
  范围内 n 个视频片段 · 已抠 m 个
  自动识别屏幕色并抠像（绿 / 蓝）
  标准绿幕 / 标准蓝幕 / 手机绿幕（压缩严重）
  消除溢色 ▸ 开·只处理边缘 / 开·整个画面 / 强度 弱 中 强 / 关
  边缘 ▸ 收缩一点 / 扩张一点 / 更柔 / 更硬 / 去斑点 +1 / 抠得更狠 / 抠得轻一点 / 边缘恢复默认
  查看 ▸ 合成 / Matte（黑白）/ 原图 / 只看溢色抑制
  复制这一条的抠像设置 / 粘贴抠像设置到选中的 N 条
  遮罩 ▸ 全部开启 / 全部关闭
  AI 抠像 ▸ 开启（用已算好的结果）/ 关闭 / 在主窗口精修这一条
  关闭抠像（保留参数） / 重新开启抠像 / 移除抠像设置
取消分屏（N 条） · 恢复分屏（关掉前的布局）（N 条）       ← 有开着 / 关掉的分屏才出现
分屏布局 ▸ … 关闭分屏 / 恢复关掉前的布局（N 条） / 各种布局
批量取消（N 条）▸ 取消分屏 / 去掉分界线 / 背景填充改回「无」 / 去掉外部背景 / 重置全部格子的平移缩放
                 / 关闭蓝绿幕抠像 / 关闭遮罩 / 关闭 AI 抠像 / 撤销上一步
```

- 「作用于」选什么都会记下来（`batch_key.json`），下次打开还是它。「右键点中的那一格」只在这次打开监视器时有效。
- 以下内容永远不碰：
  - 整幅背景轨；
  - 片头缩略图和片头视频；
  - 锁定的轨道和片段（会跳过并在状态栏说明）。
- 用了节点图的片段：改的是图里的「蓝绿幕抠像」节点（节点图里不认顶层的抠像设置）。图里没有抠像节点就跳过，并说明原因。
- 没抠过的片段，点「消除溢色」「查看」「重新开启」不会凭空生成一份抠像设置。
- AI 抠像需要在画面上点选要保留的人或物，只能一条一条在主窗口里做。菜单里能批量做的是：开启或关闭已经算好的结果，或者直接跳到主窗口精修这一条。

## 性能

| 环节 | 做法 |
|---|---|
| 改参数 | 只改片段上的一个 dict，60 条一次改完不到 0.5 秒（测试里锁死） |
| 撤销 | 新的 `mm.snapshot_fx`：只记片段的 keyer / masks / ai_matte / fx_graph 四样，不深拷整份时间线；一批只算一步撤销 |
| 重画 | 只作废画面，不当场解码。监视器原来的调度器一格一格补，看不见的格子不解码（测试锁死：屏幕外的格子不进解码队列）；抠像在渲染线程里算 |
| 自动识别 | 后台一条低优先级线程。一次只起一个 ffmpeg（Windows 上用低于正常的优先级），只抽一帧并直接缩到 192×192，大约 110 KB。不解整段视频，不占显卡。同一素材的同一时刻只抽一次，本次打开监视器期间都记住结果。全部认完后在界面线程里一次写入，一步撤销。中途可以「停止自动识别」 |
| 识别规则 | 看画面四周一圈（宽度为画面的 18%）：绿多还是蓝多，那一类至少占 30%，而且大部分像素和中位色相差 ≤ 45 才算屏幕（杂乱的彩色画面过不了这关）。取中位数当屏幕色，再套标准绿幕或蓝幕预设 |
| 线程安全 | `layer_fx` 的结果缓存被主画布和监视器渲染线程共用，原来没有加锁，现在加了锁 |
| 绿幕素材解码 | 以前只看第一帧画面正中 8×8，干净的绿幕或黑场开头会被当成「硬解坏了」，整条素材掉到最慢的 ffmpeg 管道解码。抠绿幕的素材恰好全是这种。现在看五块：五块全是同一种纯色才算坏，而且按通道算方差。第一帧像坏了，再看片子 40% 处那一帧 |

## 分屏开 / 关

- 「取消分屏」：关掉选中视频里所有开着的分屏。
- 「恢复分屏（关掉前的布局）」：布局、分界线位置、每格放哪条视频，都和关掉之前一样。关分屏时这些设置本来就没丢，只是 `enabled=False`。
- 两者都是一步撤销。

## 第二轮：阈值（色阶）+ 全自动抠像（每条自己拾色、去掉半透明灰）

Luca 发了两张截图：监视器里是 Matte 视图，很多条背景是一片灰（半透明），有的抠得干净、有的不干净。
他提了三点要求：
- 要有阈值；
- 每条视频按自己的绿幕拾色；
- 自动找到让灰消失的颜色和阈值。

### 为什么有的干净有的不干净

每条视频的绿幕颜色和光照都不一样（亮度、偏黄还是偏蓝、上亮下暗、地上有影子）。标准预设只有一个固定的屏幕色、阈值也不裁，
屏幕色对不准的那些，背景抠出来就是 30%~60% 的灰。在云端用 4 种不同的绿幕 / 蓝幕测试片验证过：预设抠完，背景 100% 的像素都留着灰。

### 全自动抠像（替换了第一轮的「自动识别屏幕色」）

每个片段在后台按下面的步骤做，做完一条立刻在监视器里亮一条：

1. **抽帧**：抽 3 帧（片段的 20% / 50% / 80% 处），长边缩到 360 px。一次只起一个 ffmpeg，用低于正常的优先级，每帧几百 KB。
2. **认屏幕和取色**：先判断是绿幕还是蓝幕，再取这条自己的屏幕色（中位数）。
3. **划出「肯定是背景」和「肯定是人」**：
   - 背景 = 整幅里的屏幕色像素，包括影子和暗角；
   - 人 = 画面中间明显不是屏幕色的像素；
   - 两块都往里收 3 px，避开边缘。
4. **试色**：在这条自己的屏幕色附近，给 R / G / B 各加减（步长 16 → 8 → 4），同时配几档 Key 增益和预模糊。目标是让「人身上最透明的那点」和「背景里最不透明的那点」拉得最开。这就是 Luca 说的「加蓝加红减蓝减红，看灰是不是在消失」，由程序自动搜。
5. **定阈值**：透明阈值落在背景 99.5% 分位之上，不透明阈值落在人身上 0.5% 分位之下。然后继续往两边收，直到「成片的灰」最少。
   - 人身上破洞是硬约束，不允许出现；
   - 人和背景之间一两像素的正常过渡不算灰（半透明区域先往里收 2 px 再统计），所以边缘照样是柔的，头发不会变锯齿。
6. **复查打分**：查背景残留、人身上的破洞、成片的灰，判成「干净」或「可能要看一眼」。最后的状态栏会列出要看一眼的那几条的编号。

云端测试片（4 种屏幕色和光照）的结果：

| | 背景残留的灰 | 人身上破洞 | 一条耗时 |
|---|---|---|---|
| 标准预设 | 100%（背景平均 alpha 0.28~0.62） | 1~10% | — |
| 全自动 | 0% | 2~3%（边缘 3 px 内） | 抽帧约 0.3 s + 计算约 0.3 s |

关于不卡：
- 整批是「一条接一条」做的，不是一起做，同时只有一个片段在计算、一个 ffmpeg 在跑。
- 算好的格子攒 250 ms 再一起重画，不会每条都打断监视器的调度器。
- 同一素材的同一段只算一次；这次打开监视器期间都记住结果，第二次直接套用。
- 整批算一步撤销；中途停止或关窗，已经做好的那部分照样保留，也照样可以撤销。

### 阈值（色阶）：右键菜单里直接拖

- 放在右键「蓝绿幕抠像」子菜单里，形式是 QWidgetAction：上面是这条视频的 Matte 直方图（后台抽一帧来算），下面是黑到白的渐变条和两个把手。
  - 左把手 = 透明阈值，右把手 = 不透明阈值；
  - 被裁掉的两段会压暗，和色阶工具一样，一眼就能看出裁了哪一段。
- 拖动的时候只实时预览右键点中的那一条（只重画这一格）。松手后才对选中的全部写入，并记一步撤销。拖到一半按 Esc 或关掉菜单，预览会还原。
- 两种作用方式：
  - 「一起挪」（默认）：每条按自己现在的阈值挪同样的幅度，自动精调给每条算出来的差异不会被抹平；
  - 「统一成这个值」：所有选中的都设成同一个值。
- 快捷按钮：收紧（±0.05）、大幅收紧（±0.15）、放松、复原。也可以用键盘：←/→ 微调，Shift 加大步长，Alt 调右把手。
