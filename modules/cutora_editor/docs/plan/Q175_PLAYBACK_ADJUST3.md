# Q175 · 播放流畅 + 调整轨第三期（2026-10-06）

## 1. 播放卡：画面跟不上声音

Luca 的反馈：加了调整图层或者标题文字以后，播放时只听得到声音，画面基本不动。

### 原因

播放时，每 33 ms 一次心跳。工作线程只负责合成视频层，**界面线程**要把文字 / 字幕 / 图片 / 调整图层全部重新排版、重新画一遍（每次心跳还要画两遍：一遍是播放头动了，另一遍是新的视频帧到了）。字加了特效、再有一块调整图层时，一遍就要几十到上百毫秒，界面线程被占满，画面跟不上。

还有第二个原因：工作线程那边奉行「只要最新的一帧」——合成慢于请求间隔时，每一帧算完都已经过时，被直接扔掉，结果一张也送不出来。

云端 2 核机器上模拟 4 秒播放（1080×1920 视频 + 3 条标题字 + 镜头模糊调整图层）：

| | 改之前 | 改之后 |
|---|---|---|
| 画面帧率 | 6 fps | 19 fps（Luca 的 i9-13900KF 单核快得多，预计能到满帧） |
| 界面线程每次画 | 中位 49 ms | 中位 2.4 ms |
| 界面卡顿（p95） | 277 ms | 55 ms |

### 做法（暂停时的画面、导出都不变）

1. **播放时整幅画面交给工作线程合成。** 新增 `PreviewEngine.display_frame_at`，视频、文字、字幕、图片、调整图层一次合成完。它走的就是导出的那套叠压，测试里满分辨率时和导出逐像素一致。像素按**屏幕上实际显示的大小**来算，几何和导出完全一样，字在屏幕上一样清楚。画布播放时只做两件事：贴这一张图，再画选中框和安全区。
2. **根据工作线程最近的用时，往前多要一点。** 例如合成一帧要 40 ms，就请求 40 ms 之后那一帧，这样送到屏幕时正好和声音对上。
3. **不再饿死。** 工作线程送出的整幅帧即使已经旧了，播放中照样显示，等于「掉帧但不停帧」。暂停 / 擦洗时的普通帧，如果连续 0.1 秒都没送出过一张，也照样送。
4. **解码出来的整幅帧先缩小再处理（只在预览降分辨率合成时）。** 按屏幕上真正画出来的像素，只做整 2 倍的减半：cv2 的 2× 快速路径，1080×1920 一次不到 1 ms，而且不占 GIL。后面的调色、绿幕抠像、羽化都在小图上做。暂停时按满分辨率合成，不走这条路；导出永远不走。AI 抠像要按源像素对齐缓存，所以不缩。
5. 停下来以后，画布会一直贴最后一张整幅帧，直到普通帧到达，然后回到原来的逐层画法（可以点选、拖动、编辑）。播放中拖画布上的东西或者在画布上打字，也会自动切回逐层画法。
6. 帧率表现在数的是「真正送到屏幕上的新帧」，以前数的是重画次数，偏高。
7. 调整图层形状缓存加了锁（工作线程和界面线程都会用到）；预览工作线程在程序退出时先叫停，测试退出时不会再出现 abort。

## 2. 调整轨第三期

### 描边生成动画（`adjust_layer.stroke_progress / stroke_paths`）

- 边框可以沿形状一笔画出来：
  - 「描边生成 秒」：这一段开头用几秒画出来；
  - 「描边收回 秒」：结尾用几秒收回去；
  - 两者都带缓入缓出。
- 起笔位置有 8 个：四个角和四条边的中点。方向有三种：顺时针、逆时针、从起点向两边同时画。
- 「描边快画完时填充再淡入」：描边画到六成以后，填充才开始慢慢出现；收回时先淡出。
- 实现方式：沿圆角矩形的中线（解析计算直线段和圆弧）取出已画到的那一段折线，用 `QPainterPathStroker` 描成边框的宽度，平头端点、圆角拐点。画满的那一刻和原来的整圈边框完全一样。
- 属性面板在「边框」打开后显示这几项。

### 跟踪连接

- 调整图层本来就放在覆层列表里，跟踪烘焙出来的关键帧（x / y / 旋转 / 缩放）可以直接驱动它。测试验证过：跟踪后马赛克框会跟着走。
- 「AI 跟踪 → 应用到」的目标列表里，调整图层会显示为「调整图层：调整·马赛克」（以前显示成一个空名字的「图片」）。
- 调整图层面板里加了一行说明，告诉用户怎么做跟踪。
- 典型用法：用马赛克或模糊盖住画面里移动的脸、车牌。

### 图层复制、粘贴、搬运

- **时间线 Ctrl+C / Ctrl+V / Ctrl+D（同一条视频）**：粘贴出来的还在调整轨上。
  - 以前从别的视频复制过来、轨道 id 对不上时，会被挂到第一条图片轨上，变成看不见的坏图层。现在会挂到调整轨上，没有调整轨就新建一条。
  - 判断能不能编辑时，看的是调整图层自己那条轨道锁没锁，不再看第一条图片轨。
- **跨视频的图层剪贴板**（时间线、中央监视器、图层面板共用，`layer_transfer`）：调整图层单独算一类「调整图层」。
  - 「素材」：按原时间贴到对方的调整轨（没有就新建）；
  - 「属性」：把形状、纯色 / 效果设置、羽化、遮罩、关键帧刷到对方的第 N 块调整图层上；
  - 两条视频画布大小不同时，坐标、羽化、边框宽度都按比例缩放。
- **中央监视器 / 画布上的覆层复制**（`monitor_model`）：`overlay_kind` 新增 `adjust`。
  - 复制到别的视频时挂到调整轨上；
  - 监视器格子里的调整图层现在点得中、拖得动、能缩放；
  - 同步编辑时，「同一条」按调整图层的序号对应。
- **图层面板**：
  - 调整图层排在最上面，图标是「图层」，缩略图里纯色显示为色块，效果显示为虚线框；
  - 类型筛选里多了「调整」；
  - 调整图层不能拖到图片轨上。

## 3. 全局调整图层：画面变换 + 范围 + 关键帧（Luca 后来补充的需求）

> 「调整条……能直接控制移动位置、缩放大小和旋转角度，同样支持关键帧动画……相当于一个全局的调整图层，只影响它自己的范围（遮罩可以约束）以及它叠压之下的图层的属性」

### 范围

- 「这块形状」：和原来一样。
- 「整个画面」：全局调整图层。框就是整幅画布，遮罩按整幅画面计算，用来收窄范围。这时它在画布上点不中，不会挡住下面的东西，需要在时间线或图层面板里选它。

### 画面变换（`xform`）

- 把它**下面已经合成好的画面**在范围里平移、缩放、旋转，以范围中心为轴。
- 「露出的边」有三种：露黑边、镜像补边、延伸边缘。
- 用法举例：
  - 整个画面 + 缩放：运镜推拉；
  - 整个画面 + 位置关键帧：晃动；
  - 一块形状 + 放大：放大镜；
  - 变换和效果、纯色可以叠着用。
- 实现方式：只反向取样范围外接框里的像素（`cv2.warpAffine`，多线程、不占 GIL）。变换不起作用（缩放 1、其余为 0）时直接跳过，一个像素都不动。

### 关键帧

- 调整图层面板里的这些参数行右边都有秒表，打开就能打关键帧：画面位置 X / Y、画面缩放、画面旋转、效果强度、效果混合、光斑、调色四项、填充不透明度、圆角、边框宽度、边缘羽化。
- 秒表沿用属性面板原来那一套：开 / 关、移动播放头时控件显示那一刻的值、改值时在播放头处自动记关键帧。
- 改值和记关键帧在同一步撤销里。
- 关键帧面板 / 曲线编辑器里显示中文参数名。
- 形状本身的位置、大小、旋转、不透明度，仍由「变换」组和画布手柄控制，也一直能打关键帧；跟踪烘焙出来的也是这些关键帧。
- 预览和导出都通过 `bake_host` 求值，结果一致。

### 导出速度

- 以前只要工程里有调整图层（或者任何「统一叠压」的情况），导出就一律串行合成，多线程合成被关掉。
- 现在只要全部视频只成一段视频带、并且垫在最底下，就照常多线程合成：解码线程依次拍出视频层，N 个合成线程画文字、字幕、图片和调整图层。「上面有调整图层」正是这种情况。
- 这种情况下，解码线程拍出的视频层就等于那一段视频带。不透明的整张图贴到黑底上是原样拷贝，所以和串行逐像素一样。测试用 framemd5 验证：1 线程和 2 线程导出 50 帧完全相同。
- 视频和文字交错叠压（文字压在视频下面）的工程仍然走串行。

## 4. 没做的：局部抠像

调整图层的效果作用在「它下面已经合成好的整幅画面」上。在这上面做抠像，会把背景也抠成透明（mp4 里就是黑的），几乎用不上。

要「只在某个范围里抠」，正确的工具是视频层自己的抠像 + 遮罩：在那条视频的「遮罩」里画出范围，抠像只在遮罩里起作用。这两个功能现在都有。
