## 2. 罗马化 + MMS 对齐

在 `cutora/asr/` 下新建 `romanize.py`：

- `romanize_tokens(tokens: list[str], lang: str) -> list[str]`，按语言罗马化一串词。
- **结果只喂给对齐器，绝不进字幕**。字幕永远用原文。
  这一条要在模块 docstring 里写死，并且有测试盯着。
- 已经是纯 `a-z` 的词原样返回（省开销，也避免 uroman 把英文改坏）。
- uroman 初始化很贵，**进程内缓存一次**。

`cutora/asr/engine.py` 的 `get_align_model` 兜底链（Q108 已经留好接口）：

1. `en` / `it` 冻结模型 —— 现有行为**一个字节不许变**。
2. 该语言的专用对齐器（Q108 的 `exact` 档）。
3. **MMS**：加载 `align-mms`，对齐前把词列表过一遍 `romanize_tokens`。
4. 都不行 → Q108 已经写好的那句人话异常。

对齐结果的时间戳要映射回**原文词**的下标 —— 罗马化后词数可能变，
必须保证一一对应，对不上就退回第 4 档报错，**不许猜**。

## 3. 验收：拿真音频证明它真的对上了

**光看「没报错」不算数** —— Q107 那次就是「没报错但全是假的」。
写 `tests/test_q109_mms_align.py`，并把探针输出贴进报告：

1. **亚美尼亚语**：一段真实音频 + 对应文字。断言
   - 每个词的 `start < end`；
   - 时间戳**单调递增**；
   - **没有任何一个词占掉总时长的 40% 以上**（Q107 那次最后一个词吞掉 82%，
     这条断言当时必红 —— 它就是这次的核心验收）；
   - 首词 start 与末词 end 覆盖音频的 70% 以上。
2. 日语、越南语各一条，同样三项。
3. **英语回归**：走冻结模型那条路，词级时间戳与改前**逐字节相同**。
   这条是护栏，证明兜底链没有污染已经好用的语言。
4. `romanize_tokens` 对纯 ASCII 输入原样返回（对象相等即可）。
5. **字幕不许被罗马化**：跑一次完整拼接（可用假 ASR），
   断言产出的字幕文本是原文，`Հայերեն` 不会变成 `hayeren`。
6. uroman 缺失时的降级：打桩让 import 失败，
   断言 `align_tier` 把这些语言报成 `none` 而不是崩溃。

## 4. 把能力表更新掉

Q108 的 `align_tier()` 里，通用对齐器可用的判据改成实现版：
MMS 在本地 + uroman 可用 → 这 70 种从 `none` 变 `fallback`。

「语言支持情况」那张表的「逐词对齐」列要能显示三档，措辞用大白话，比如：

- `exact` → 「精确（专用模型）」
- `fallback` → 「可用（通用模型，精度略低）」
- `none` → 「暂不支持」

顶部那句总结跟着改成「可转写 100 种；N 种逐词精确，M 种可用」。
**不许把 `fallback` 说成和 `exact` 一样好** —— MMS 是通用模型，精度确实低一些，
用户有权知道。
