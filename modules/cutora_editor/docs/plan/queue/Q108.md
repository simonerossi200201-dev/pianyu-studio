## 1. 对齐能力分级（这是后面所有显示的地基）

`cutora/asr/models.py` 新增 `align_tier(code) -> str`，返回三档之一：

- `"exact"` —— 有**已就绪的专用对齐器**（Q107 数出来是 26 种：en it ca cs de el es eu
  fi fr hu ka lv nl nn no pl pt ro ru sk sl sv tl tr uk）。逐词时间戳准确。
- `"fallback"` —— 只能走通用对齐器。**Q108 阶段这一档恒定为不可用**，
  留好接口给 Q109 接 MMS；判据写成「通用对齐器可用吗」的一个函数，
  Q109 只改那个函数的实现，不动调用方。
- `"none"` —— 转写得出来，但没有任何可用的对齐器 → 拼接做不了。

另加 `language_capability(code) -> dict`，一次给全：
`{"code", "name_zh", "transcribe": bool, "align_tier", "subtitle_tier", "font_ok": bool}`。
`font_ok` 查 `font_script_coverage.json`。**这个函数是唯一的真相源**，
界面、报告、测试都从它取，不许各处各写一套判断。

`Noto_Sans_Ethiopic`、`Noto_Sans_Tamil`、`Noto_Sans_Thai`、`Noto_Serif_Tibetan` 等
**全都在库**（Claude 已核对）。字体加进来之后 `font_script_coverage.json` 没重新生成。

## 4. 拼接支持「自动检测」

（这一节就是 Q107 任务书的第 2 节，原样照做。）

**对齐模型改成用到才加载**：

- `AnalyzeWorker`（`script_stitcher.py:2908` 起）现在收一个已建好的 `get_align`。
  改成收一个**按语言取对齐模型的可调用对象**，拿到第一个片段的语言之后才调用。
  按语言缓存用现成的 `engine._ALIGN_CACHE`（已经是 `(lang, device)` 键），别再造一层。
- 语言为 `auto` 时 `language=None`（`whisper_language_arg` 已经会转），
  从 faster-whisper 的 `info.language` / `language_probability` 取结果。
  - **置信度 < 0.6** → 走现成的 `detect_confirm.py` 让用户确认，不许自己猜。
  - 确认或高置信度之后**把这个语言定给整批**，不要每个片段各检测各的。
- 检测到的语言 `align_tier` 是 `"none"` 时：**在开始切之前就停下**，
  告诉用户检测到什么语言、为什么拼不了、可以怎么办。不许跑到一半才失败。
- 日志写清：检测到什么、置信度多少、用了哪一档对齐器、具体哪个模型。

## 5. 首页下拉：完整目录 + 当场看得见能力

`home_stitch._fill_languages()` 删掉写死的六个，改用 `picker_entries()`：
「自动检测」排第一并**设为默认**，后面按 `common` / `all` 两组。

每一项的标签要带上能力，用 `language_capability()`：

```
英语 · 逐词精确 · 排版完善
亚美尼亚语 · 暂不支持拼接 · 仅字形保证
```

`align_tier == "none"` 的项**置灰不可选**，tooltip 说明原因。
选中项是 `none` 时「开始拼接」不可点，状态行当场说明。

## 6. 「语言支持情况」页 —— 让用户明确知道能做到什么程度

「帮助」菜单加一项**「语言支持情况」**，打开一个非模态窗口，一张可搜索的表，
100 种语言逐行列出：

| 语言 | 代码 | 转写 | 逐词对齐 | 字幕排版 | 字体 |
|---|---|---|---|---|---|
| 英语 | en | ✓ | 精确（专用模型） | 完善 | ✓ |
| 亚美尼亚语 | hy | ✓ | 暂不支持 | 仅字形保证 | ✓ |

- 顶部一句话总结：「可转写 100 种；其中 N 种能做逐词精确对齐，拼接功能可用」。
- 数据一律来自 `language_capability()`，**不许在界面里写死任何名单**。
- 底下一行说明「逐词对齐」是什么、为什么拼接依赖它 —— 用大白话，别写术语。

## 测试 `tests/test_q108_language_capability.py`（要 Qt 的登记进 `qt_isolate`）

每条都要能说明「改之前是红的」：

1. `align_tier("en")`/`("de")` 是 `exact`；`("hy")` 在 Q108 阶段是 `none`；
   未知代码抛或返回 `none`（选一种并写进 docstring）。
2. `language_capability()` 的 `transcribe` 对 100 种全为 True；
   字段齐全；`font_ok` 与覆盖表一致。
3. 覆盖表重建后，那 13 个 script 各自的覆盖字体数**大于 0**
   （若仍有为 0 的，这条测试要精确断言剩下哪几个，不许笼统放过）。
4. 自动检测：假 worker 返回 `info.language="de"`、概率 0.95 →
   对齐模型按 `de` 取，且**整批只取一次**（断言加载函数只被调一次）。
5. 概率 0.4 → 走确认框（打桩断言被调用）；用户改选 `en` 后按 `en` 加载。
6. 检测到 `align_tier == "none"` 的语言 → **在切片开始前**就抛出可读错误，
   断言一个 ffmpeg 都没被调用。
7. 首页下拉第一项是「自动检测」且为当前项；条目数等于 `picker_entries()` 的条数；
   `none` 档的项 `isEnabled()` 为 False。
8. 「语言支持情况」表的行数是 100，且某几行的内容与 `language_capability()` 逐字相同。
