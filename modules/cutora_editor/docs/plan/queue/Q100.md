# Q100 · 背景色块第四种形状：行轮廓（按每行文字各自成块，再整体圆角）

**开工前先读 `docs/plan/reports/Q97.md`（轮廓包裹怎么做的）和 `docs/plan/queue/Q99.md`
（连字与圆角拆分）。本条排在 Q99 之后，用的是同一套蒙版机制。**

## Luca 要的是什么

原话：「还要支持这种按照行的外轮廓的背景形式，而不是仅仅像描边。而且要支持所有的拐角有
圆角效果，也可以支持扩展收缩范围。」附图是竖屏字幕的常见做法：

- 两行文字，**每行各有自己的一块底**，宽度按各自那行的文字宽度走，所以上一块宽、下一块窄；
- 两块上下相接，合起来是一个**阶梯状的轮廓**；
- 所有拐角都是圆的 —— 包括两块宽度不同时接缝处那个**凹角**；
- 底块相对文字可以往外扩、也可以往里收。

这和已有的三种都不是一回事，要新加第四种：

| 现有 | 是什么 |
|---|---|
| `fit_text` | 整段一个矩形，包住全部行 |
| `fixed` | 整段一个矩形，宽高你自己填 |
| `hug_glyphs`（Q97） | 贴着**字形**轮廓，像贴纸 |
| **`line_hug`（本条）** | 贴着**每行的行框**，阶梯轮廓 |

`hug_glyphs` 贴的是字，所以看起来像描边；`line_hug` 贴的是行，是一块一块的底。
**不要把这条做成 `hug_glyphs` 的参数，要新的 `bg.size_mode` 取值。**

## 怎么做

### 1. 行框

`cutora/render/textfx/layout.py` 的 `LineBox` 已经有 `x / y / w / h / baseline`，
直接用，不要另起一套排版。

**每行的框必须等高** —— 附图里两块底一样高。所以**不许**直接用 `LineBox.h`
（那是这一行实际字形的高度，一行全是小写字母就会矮一截，两块底会不齐）。
改成按这一行主字体在 `em` 下的 ascent / descent 取一条固定的带：
`top = baseline - ascent_ref`、`bottom = baseline + descent_ref`。
水平方向用 `x` 和 `x + w`（这一行自己的宽度，所以各行宽度不同，这正是要的效果）。

空行不出框。

### 2. 扩展 / 收缩

复用现有的 `bg.hug_pad_em`（面板名改成「扩展 / 收缩」，它现在叫「包裹厚度」）：

- 把取值范围从 `0–1` 放宽到 **`-0.3 – 1.0`**，默认仍是 `0.18`。
- `line_hug` 下按这个量把每个行框向外等距扩（负值就是往里收）。
- `hug_glyphs` 下**实际生效值夹到 ≥ 0**（往里收会啃掉字形，没有意义），
  这样 Q97 的行为一个像素都不变。
- 老工程没有这个键 → 0.18，和现在一样。

### 3. 合并 + 全拐角圆角

把所有行框**并起来**得到一张阶梯状蒙版，然后用 `bg.radius_em` 把**所有**拐角抹圆，
凸角凹角一视同仁：

- 半径 `r = radius_em * em`。
- 先**开运算**（先腐蚀 r 再膨胀 r）→ 凸角变圆；
- 再**闭运算**（先膨胀 r 再腐蚀 r）→ 凹角（两行宽度不同时的接缝）变圆。
- 腐蚀 / 膨胀都用 `cv2.distanceTransform` 取距离场阈值，**不要用方形 kernel**，
  方核出来的是八边形不是圆角。Q97 的 `_build_hug_mask` 已经是这个写法，照抄。
- **半径要夹住**：`r = min(radius_em * em, 最窄那一行框的高的一半, 最窄那一行框的宽的一半)`。
  不夹的话开运算会把窄行整条吃掉。夹完的实际半径要能被测试读到（暴露个内部函数即可）。

这里**可以**放心用 `bg.radius_em` —— 它本来就是「底块的圆角」，而且行框是大矩形，
不存在 Q97 那种「把字母内部的孔填满」的风险（那次是 Claude 把两件事塞进一个滑条写错了，
见 Q99）。

### 4. 接进现有管线

`cutora/render/textfx/raster.py` 里 `hug_glyph_mask` / `_hug_cache_key` /
`_hug_cover_spec` / `_raster_bg_hug` 这一套原样复用，**只是换一个蒙版构造函数**。
缓存键要带上 `size_mode`、每行的 `x/w/baseline`、`hug_pad_em`、`radius_em` 和 ROI；
和时间、底图无关，同一段预览再导出只算一次。

`cutora/render/textfx/spec.py:1424` 那段 ROI 扩张要把 `line_hug` 也算进去
（`hug_pad_em * em + r`），否则大扩展值会被裁掉。

### 5. 面板

`BG_SIZE_MODE_ITEMS` 加「行轮廓」。`line_hug` 时显示「扩展 / 收缩」「圆角」「偏移」，
藏「宽 / 高 / 内边距」。色块、毛玻璃、纹理、渐变照旧画，只是被这张蒙版裁 ——
四种填充都要能用。

## 测试 `tests/test_q100_line_hug.py`

每条都要能说明「改之前是红的」：

1. **不是一个大矩形**：两行文字，第一行明显比第二行宽。在第一行的垂直中线高度上，
   底块右边缘要明显超出第二行右边缘（差值 ≥ 两行文字宽度差的一半减去 2px）。
   顺带断言整段包围盒右下角那个像素是透明的。
2. **两行等高**：第一行 `ABCDEF`（全大写有上伸），第二行 `aoe`（全小写无上伸下伸），
   两块底的高度差 ≤ 1px。用 `LineBox.h` 实现的话这条必红。
3. **凹角是圆的**：两行宽度不同，接缝处那个内凹拐角上，沿 45° 采一排点，
   alpha 要有一段平滑过渡，而不是直角的阶跃。`radius_em = 0` 和 `0.4` 两种下对比，
   0.4 那次接缝处被填掉的像素明显更多。
4. **凸角是圆的**：`radius_em = 0.4` 时，每一块底的四个外角像素是透明的；`0` 时是实的。
5. **收缩**：`hug_pad_em = -0.1` 时底块宽度比文字包围盒**窄** `0.1 * em * 2`（±2px）。
6. **半径夹住**：把 `radius_em` 调到 `2.0`（远大于行高），底块**仍然存在**
   （非零像素数 > 0），不许被开运算吃光。
7. **四种填充同形**：色块和渐变在同一参数下蒙版形状一致（把渐变函数打成单色后整帧 MAD = 0）。
8. **预览 = 导出**：同一帧 MAD = 0；把缓存查找改成永远未命中，蒙版会被算两次（用来证明缓存真的在用）。
9. **另外三种模式一个字节不变**：`fit_text` 那条帧 md5 仍是
   `8a063bb50cd86a78515f330072ee72a3`；Q97 / Q99 的现有测试全绿。
10. 面板：切到「行轮廓」时宽 / 高 / 内边距藏起来，扩展 / 收缩、圆角、偏移显示；
    json 往返后重开面板值还在。

## 基线

`line_hug` 只是下拉里多一个取值，**不新增行**，所以预期 `ui_golden` 一条都不变。
如果 `u04e` 或别的用例变了，说明面板行数被动到了 —— **停下写 `.stop` 报 Claude，不许重录**。
渲染 golden 不该变（没有 golden 工程用 `line_hug`）。`golden_check` 红了一律停下。
