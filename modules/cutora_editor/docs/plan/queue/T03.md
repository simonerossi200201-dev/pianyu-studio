## 背景（十六报第 1 节）
`render/export_guard.py:361 MEM_PER_WORKER_GB = 1.2`、`:364 MEM_HEADROOM_GB = 3.0`。
按它算 Luca 这台机：`(16.3−3.0)//1.2 = 11` 不限制，`(32−2)//2 = 15` 不限制 → 放行 6 个进程。
**实测**：16.3 GB → 0.15 GB，6 进程吃 16.15 GB，**每进程 2.69 GB，是估值的 2.24 倍**。
用 2.7 重算 `(16.3−3.0)//2.7 = 4` → 内存不会耗尽 → 黑屏和花屏都不会发生。

每进程 2.7 GB 的来源：`init_torch_runtime`（torch+CUDA）+ cv2 解码器 +
画布 1080×1920 的 QImage（`1080×1920×4 = 7.9 MB` 一张，合成/毛玻璃 backdrop/textfx ROI 各一份）
+ 每帧 `bytes(ptr)` 又一次 7.9 MB。源素材只有 704×1280，**画布放大 2.3 倍把每进程内存也放大了 2.3 倍**。

## 要做
1. 导出时采样每个 worker 的**峰值 RSS**，落 `UserData/logs/export/worker_rss.json`。
2. `plan_parallel_export` 取**最近一次实测的 P90**；没有历史数据时保守用 **3.0**。
3. 按画布像素量缩放：`per_worker = base × (canvas_px / (1080*1920))`，**下限 1.5**。
4. 体检日志把「估值来自实测 / 来自保守默认」写清楚，并打印 `workers` 是被哪一条限制住的。
