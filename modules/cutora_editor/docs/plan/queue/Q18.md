## 这一批的共同根因（Claude 已在 2026-09-18 逐条核实，不要重新推理，也不要推翻了事）

`cutora/render/textfx/spec.py:642` 的 `from_style()` **只读 `style["fx"]` 和 `font_family`**，别的什么都不读。
我对整个 `cutora/render/textfx/` 目录逐个 grep 过这些 v1 扁平键：

| 键 | textfx 里的引用数 |
|---|---|
| `color_text` / `color_high` | 0 |
| `border_width` / `color_outline` / `opacity_outline` / `use_stroke` | 0 |
| `shadow_blur` / `color_shadow` / `opacity_shadow` | 0 |
| `use_box` | 0 |

也就是说：**面板里任何还在写 v1 扁平键的控件，都是死控件** —— 不是偶尔失效，是按构造不可能生效。
九报（BUG-20~24）诊断过、开过 T32「面板重构」的药方，**T32 从来没做**，所以今天全爆出来了。

另外 `cutora/ui/widgets/dock_panels.py:173-180` 的 `_fx()` 帮手：

```python
widget = getattr(panel, attr, None)
if widget is None:
    return          # ← 控件不存在就静默跳过，不报错不打日志
```

这是**静默失败目录第 18 条：引用一个不存在的控件，帮手静默跳过**。

### 2. 通用像素锁（本任务的核心产出）
新增 `tests/test_t18_no_dead_controls.py`：

```
对面板里每一个可见控件：
    1. 构造基准 style（用 lyrics-scroll 之外的任意包）
    2. 渲染一帧 → md5_a
    3. 把该控件设成一个"明显不同"的值
       （枚举取下一项、数值取范围中点或最大值、颜色取 #FF00FF、开关取反）
    4. collect() 出 style → 渲染同一帧 → md5_b
    5. 断言 md5_a != md5_b
```

- 渲染走 `ExportRenderer.render_frame`（导出口径，不是预览），画布 720×1280，固定字体、固定 t。
- 允许一个显式豁免清单 `DEAD_CONTROL_ALLOWLIST`，每一项必须写明理由（例如「只影响 ASR 不影响像素」）。
