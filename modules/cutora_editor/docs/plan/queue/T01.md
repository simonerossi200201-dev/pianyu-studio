## 背景（读 `docs/plan/reports/通宵十六报_导出花屏_黑屏_自动保存全死.md` 第 5 节）
`textfx/pipeline.py:296` 每次画字幕都调 `_fill_word_hits(event, layout, ...)`，
`:222-245` 往**字幕段字典本身**写 `event["_adv_word_hit"] = [{"rect": QRectF(...), ...}]`，
而 `event` 就是 `task["segments"][i]`。于是每渲染一帧就往工程数据里塞 QRectF。

Ctrl+S 没事：`project_io._rj_json_safe` 丢弃下划线开头的 key，且 `main_window._write_project_json`
还带了 `ProjectEncoder` 把 QRectF 转数组。
自动保存必炸：`core/autosave.py:66 write_snapshot` 用**裸 `json.dump`**，两道防线都没有。

后果三层：① 自动保存从来没成功过，`.autosave.json` 一次都没写成；② BUG-15 其实没修好
（它就是调这个必抛的 `_autosave_now(force=True)`，你的测试能过是因为测试里字幕段从没被渲染过）；
③ 关闭软件 `exit code 3` 就是这个未捕获异常炸的。

## 要做
1. `_autosave_now` 走**和 Ctrl+S 同一条序列化路径**（`serialize_render_task` / `_rj_json_safe`），不许自己 `json.dump`。
2. 把 `ProjectEncoder` 挪到 `cutora/core/safe_json.py`，**存工程和自动保存共用同一个**。
3. **治本**：`_fill_word_hits` 不许往共享的字幕段字典里写运行时缓存，改成写旁路表
   （按 seg 索引，和 `hit_records` 放一起）。运行时缓存混进数据模型就是这次的病根。
   改完确认 `canvas._get_sub_word_hits` 仍能读到（shift+点选词不许坏）。
4. 自动保存失败必须**可见**：状态栏红字 + 日志，不许只在控制台打 traceback。
5. 退出路径：`closeEvent` 里的自动保存包在 try 里并记录，不许让异常把退出码变成 3。
