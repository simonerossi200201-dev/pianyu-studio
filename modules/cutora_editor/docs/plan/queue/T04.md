## 背景（十六报第 2 节）
内存跌到 0.15 GB → Windows 极限换页 → WDDM 显示驱动拿不到可分页内存 →
**驱动超时被系统重置（TDR）→ 屏幕黑一下再回来**，黑两次就是两次重置。
TDR 摧毁了正在跑的 5 路 NVENC 会话 —— 这就是 5 个花屏的直接来源。
现在的采样门槛是「连续两次低于 1.5 GB」，等它动作时已经 0.15 GB，**是事后报警不是预防**。

## 要做
1. 导出期间监控可用内存：
   - **低于 2.0 GB**：**暂停派发新 worker 并挂起已排队任务**（不是继续跑），状态栏说明原因；内存回到 3.0 GB 以上再恢复。
   - **低于 1.0 GB**：把所有还没开始的任务立刻转为**串行**执行。
2. `NVENC_MAX_SESSIONS` 默认 **5 → 3**，设置里可调（说明：给桌面合成器留余量，避免驱动重置）。
3. 这两条都要写进导出前体检的日志，让用户看得见。

## 门禁
- `test_guard_pauses_below_2gb`：注入内存读数序列 `[8, 5, 1.8, 1.8, 4]` → 在 1.8 那两拍**没有新 worker 被派发**，回到 4 之后恢复
- `test_guard_serializes_below_1gb`：注入 `0.9` → 未开始的任务全部转串行
- `test_nvenc_sessions_default_three`
- golden 十二例 + UI 六例不变
