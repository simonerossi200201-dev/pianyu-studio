## 规矩

- **每一条都要回答「谁是对的」：测试还是代码。** 不许为了变绿去改断言、放宽阈值、加 skip。
  如果判断测试本身过时了（比如断言旧字面量），改测试要在 `.ok` 里写清理由，并证明新断言仍能抓住它原本想抓的缺陷（故意改坏一次）。
- **SettingsDialog 那条要从用户视角验证**：修完之后写一条测试，真的打开设置对话框、切换每一个页签、关掉，
  断言没有异常、没有 `RuntimeError: ... already deleted`。
- 做不完的，在 `.ok` 里逐条写「为什么还红、谁该修、用户会看到什么」。
