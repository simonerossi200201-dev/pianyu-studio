## 仍存在的问题

1. **单次阻塞仍 520ms。** 报告自己写的「after」里，心跳缺口最大 **521.8 ms**，超过测试门禁 400 ms
   ——而门禁原本建议 200，被放宽了。测试用 eventFilter 量、报告用心跳量，两种量法不一致。
2. **Luca 工程的 ffprobe 反而变多了**：从 16 次变 **20 次**，探的还是工程里没有的 `t0035-*` 文件；
   主线程 ffprobe 合计从 579 变 **909 ms**。报告没解释。
3. **ffprobe 仍是一个接一个串行**，只在等待时 `processEvents`（`media/probe_cache.py:206-222`）。
4. **探测失败的 None 也会持久化**（`probe_cache.py:64-69`）：只要超时一次，这个文件就**一直显示离线**，直到 mtime 变。
5. `_probe_video_has_alpha` 每次打开 .mov/.webm/.gif 都额外跑一次 ffprobe，**不走缓存**。
6. 进度条只有 8→10→45→80 几档（`command_bodies.py:98-109`），探测期间不显示 N/M。
7. 没量**热缓存**下再次打开的数字——而「打开最近项目」正是热缓存场景。
