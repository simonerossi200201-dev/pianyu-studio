# Q67 · GIF 帧率和隔行、大文件导入、代理真正生效

**开工前先读 `docs/plan/queue/_RULES_FOR_EVERY_TASK.md`，尤其第八节：每做完一个子项就提交。**

接在 Q61（资产放到时间线能看见）之后。这一条让透明素材「完美支持」——Luca 的原话。

## 1. GIF 帧率写死 10fps

`media/animated.py:151` `-framerate 10`。`gifdecode.py` 解析 GCE 时**没读帧延时**，
常见 20–50fps 的 GIF 会**慢 2–5 倍**播放。
**做法**：`decode_gif_rgba` 返回每帧延时；按延时生成可变帧率（或用 concat demuxer 带 duration）。

## 2. 隔行 GIF 画面错行

全文件搜不到 0x40 标志位或 interlace 处理。**做法**：按 GIF89a 规范的四遍隔行顺序重排行。

## 3. GIF 解码冻界面

LZW 纯 Python 实现、所有帧一次存成列表（`gifdecode.py:75-170`），整个解码在 UI 线程同步执行（`main_window.py:4346`），
大 GIF 会冻住界面几十秒。缓存文件还写在**用户源文件旁边**（`animated.py cache_path_for`）。
**做法**：挪进 QThread 加进度；缓存挪到用户配置目录下的缓存区。

## 4. 代理永远用不上

`ensure_alpha_proxy(sync=False)` **固定返回 None**（`media/alpha_proxy.py:221`），
所以 `rec["preview_path"]` 从来没写进 item.json（`user.py:136`），而 `place_on_timeline` 只认这个字段。
从文件系统拖进来的路径（`main_window.py:4535`）也不设 preview_path。代理还和原件同分辨率，没缩小。
代理线程在非 GUI 线程里调 `statusBar().showMessage`——**违反 Qt 线程规则，有崩溃风险**。

**做法**：
- 代理完成后**通过 Qt 信号回主线程**，回写 item.json 和已在时间线上的 `MediaSource.preview_path`。
- 代理缩到预览分辨率（长边 ≤ 1280），编码用 ProRes 422 Proxy 带 alpha 的 4444 变体或 qtrle，**不用 libvpx 全分辨率**。
- 所有 UI 调用走信号，不许在工作线程里碰 widget。

## 5. ProRes 4444 的 alpha：预乘两次、12bit 压 8bit、预乘太慢

- 一律按直通 alpha 再预乘（`readers.py:97-99`）。达芬奇导出时如果勾了「预乘 alpha」，**就会预乘两次，边缘发黑**，没有开关。
- 预乘是 1080p 全尺寸 numpy float32 运算，每帧几十毫秒，正好卡在 Q11 规定必须串行的解码上。

**做法**：在 ffmpeg 滤镜链里做 `scale=目标尺寸` + `premultiply=inplace=1`，别在 Python 里做。
读流的 `alpha_mode` 元数据判断直通/预乘；读不到时在资产属性上给一个「Alpha：直通 / 预乘」的选择，默认直通。
