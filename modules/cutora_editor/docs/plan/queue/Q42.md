# Q42 · SliderSpin 从来没接过线（P0，最高优先级）

**开工前先读 `docs/plan/queue/_RULES_FOR_EVERY_TASK.md`。**

## 事实

`cutora/ui/widgets/inspector.py:245-256`：

```python
def minimumSizeHint(self) -> QSize:
    h = max(...)
    return QSize(INSPECTOR_SLIDER_MIN + INSPECTOR_FIELD_GAP, h)
    self.slider.valueChanged.connect(self._from_slider)   # ← return 之后
    self.spin.valueChanged.connect(self._from_spin)       # ← 永不执行
```

这两句在 `return` 后面，**永不执行**。全仓库再无第二处连接 `_from_slider` / `_from_spin`。

后果：`SliderSpin` 的滑条和数值框从未互相连接，`SliderSpin.valueChanged` **从未发射过**。
`fx_fields.py:206,217` 的 `spin.valueChanged.connect(lambda ...: _on_fx(p))` 接在一个永不发射的信号上。
`SliderSpin` 在 `fx_fields.py` 和 `property.py` 共实例化 **13 处** ——
检查器里所有带滑条的数值参数，拖滑条都没反应。

Q25 的五条门禁测试全部测几何与静态属性，没有一条测行为，所以这个控件整体失效仍然全绿。

## 要做的

1. 把那两句 connect 移进 `__init__`，位置在 `self.slider` 和 `self.spin` 都构造完之后。
2. 检查 `_from_slider` / `_from_spin` 的互相触发有没有死循环保护（`blockSignals` 或 guard 标志）。
   接上线之后这两个槽会互相触发，现在没接线所以这个问题从未暴露过。
3. 确认 `SliderSpin.valueChanged` 的发射时机：拖动过程中连续发射还是松手才发射。
   连续发射会让每个中间值都触发一次重渲染 —— 如果 `_on_fx` 很贵，加 `setTracking(False)`
   或在 `_on_fx` 侧做节流，但**不要用「拖动时不更新预览」来省事**，Luca 要的是实时反馈。
4. 顺手查一遍全仓库还有没有同形状的死代码：`return` 语句之后还有语句的函数。
   用 AST 扫 `cutora/`，把结果写进 `.ok`。

## 验收

- `tests/test_q42_sliderspin.py`：
  - `test_sliderspin_two_way`：`sp.slider.setValue(n)` → `sp.spin.value()` 跟随，
    且 `sp.valueChanged` 真的发射（用 `QSignalSpy` 或闭包计数）；反向同理。
  - `test_sliderspin_no_feedback_loop`：连续 setValue 20 次，断言信号发射次数等于 20，
    不是 40（互相触发翻倍）也不是 0。
  - `test_sliderspin_drives_fx`：**走真面板**，拿一个用 SliderSpin 的 fx 参数
    （例如 `stroke.width_em`），改滑条 → `collect()` 出来的 fx 里那个值真的变了
    → 再走 `ExportRenderer.render_frame` 出帧，**像素真的变了**。
    这一条是重点：光断言 dict 变了不够，Q19~Q22 的教训就在这。
  - `test_no_unreachable_code`：AST 扫 `cutora/`，任何函数里 `return` 之后还有语句 → 失败。
- golden 十二例 + UI 六例：**必须不变**。这个改动会让一批以前不生效的控件开始生效，
  如果 golden 变了，说明某条 golden 的录制值本来就依赖「这个控件是死的」——
  那是重大发现，**写 `.stop` 停下报 Luca，不要自己重录**。
- 全量 `pytest tests -q`。
