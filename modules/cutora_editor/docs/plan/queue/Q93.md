# Q93 · 三个使用中发现的问题：文本背景没有宽高、字幕拖动跳到顶部、字幕不吸附

**开工前先读 `_RULES_FOR_EVERY_TASK.md`、`_RULES_UI_OWNERSHIP.md`。每做完一个子项就提交。**

## 1. 文本工具的背景没有宽度 / 高度

> Luca：文本工具里面，打开背景，现在这个背景它没有宽度高度的条件功能了，这很难用的。

**先查清楚是丢了还是从来没有**：`git log -S` 找 `adv_bg_w` / `adv_bg_h` / `advanced_textbox_w` 的历史。
今天的情况是：字幕（v1 样式）在「高级文本框」里有框背景宽 / 高（`frame_renderer._draw_adv_textbox_bg` 读 `adv_bg_w` / `adv_bg_h`），
而文本覆层走的是 fx 的 `bg`（`cutora/render/textfx/spec.py:_parse_bg`），只有 `pad_em`，盒子永远裹着文字。报告里写明结论。

**要做的**：给 fx 背景加尺寸控制，预览与导出同一条路径。

- 新增 `bg.size_mode`：`fit_text`（默认，今天的行为）/ `fixed`。
- `fixed` 时新增 `bg.width_px`、`bg.height_px`（画布像素，0 = 用文字尺寸），以及 `bg.offset_x`、`bg.offset_y`（相对文字盒中心）。
- 老工程没有这些键 → 走 `fit_text`，**渲染结果逐字节不变**（写测试）。
- 面板：「背景」段里加「尺寸」下拉 + 宽 / 高 / 偏移四个数值框，`fixed` 时才显示（用 Q83 的行跟随字段显隐规则）。
  按 `_RULES_UI_OWNERSHIP.md`：只加控件接信号，不改行高 / QSS / dock 宽度。
- 字幕面板那套 `adv_bg_w` / `adv_bg_h` 保持不动，别顺手统一。

**验收**：`fit_text` 与改前逐字节相同；`fixed` + 宽高 = 指定像素（误差 ≤ 1px），预览与导出 MAD < 0.01；面板改值 → 预览立刻变 → 存盘 → 重开还在。

## 2. 自动字幕跑完后，拖动字幕会瞬间跳到顶部

> Luca：自动字幕运行完之后，鼠标拖动字幕的时候，字幕会瞬间移动到顶部。

在 `cutora/ui/canvas.py` 约 2169–2187 行：拖动字幕走 `resolve_style_geometry` 读出当前位置，加上 `dx/dy` 再 `set_position_px`。
**怀疑**：自动字幕跑完后 `style` 里没有 `pos_x/pos_y`（或者是百分比 / 另一个锚点），`resolve_style_geometry` 回落到了默认值，
于是第一次拖动不是「当前位置 + dx」，而是「默认位置 + dx」——看起来就是瞬间跳走。
**先复现**：写一个测试，跑完自动字幕（可以用打桩的 ASR 结果）后模拟按下→移动 (0, 0)→松开，断言位置**一点都没变**。修前必红。

修的时候要点：
- 拖动的基准必须是**画面上当前真正画出来的位置**（和渲染读的是同一个来源、同一个锚点），不是「解析后的默认值」。
- 自动字幕写回样式时不许把已有的 `pos_x/pos_y` 抹掉；本来就没有的，第一次拖动要以当前渲染位置为准落笔。
- 一次拖动一条撤销。

**验收**：`test_q93_sub_drag_zero_delta_is_noop`（修前必红）、`test_q93_sub_drag_after_asr_keeps_position`（跑完 ASR 拖 (30, 20)，位置正好加 30/20，导出帧同步）。

## 3. 拖字幕时画布吸附不起作用（拖图片是好的）

同一段代码：图片 / 覆层分支在移动前调用了 `_calc_snap`（约 2387 行）修正 `dx/dy` 并画参考线，**字幕分支没有走这一步**。
把字幕（含高级文本框模式）接进同一套吸附：用字幕当前渲染包围盒当 `rect`，吸附画布的左 / 中 / 右、上 / 中 / 下六条线，
阈值沿用 `_snap_threshold`，参考线照画，按住 N 临时关吸附（Q69 已有）。

**验收**：`test_q93_sub_snaps_to_center`（把字幕拖到距中心 8px，松手后正好在中心，误差 ≤ 0.5px；关掉吸附则不动）、
`test_q93_sub_snap_guides_drawn`（拖动中有参考线像素）。图片的吸附行为不许变（现有测试仍绿）。
