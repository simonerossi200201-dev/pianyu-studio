# Q65 · 高亮色重新建模：一个控件只管一件事

**开工前先读 `docs/plan/queue/_RULES_FOR_EVERY_TASK.md`。**

Luca 已经报过两次高亮色不起作用。Q51 修好了主路径（当前词确实会换色），也加了「换字色 / 词底方块」两个勾选
（`subtitle_style.py:350-357`）。但**颜色的归属还是错的**，用户会在几个地方撞墙：

## 现在的问题

1. **默认配置下，词底方块的颜色跟提示对不上。** 两个勾选默认都开（`spec.py:377-378`），`tint_also=True`
   （`word_fx.py:317`），颜色取 `spec.bg.color`——背景色块的色 `#0B1A33`（`word_fx.py:321`）。
   提示却写「未点过弹力色则回退到高亮色」。**取消「换字色」，底块颜色又跳到高亮色——一个勾选改了另一个功能的颜色。**
2. **高亮色被锁在灰掉的「配色方案」段里。** 这段默认灰，打开它只解除灰显、不写值（`subtitle_style.py:1626-1628`）。
   用户改高亮色得先拨一个对输出毫无作用的开关。重开工程时 `is_on` 只看 fill（`:1603`），改过高亮色也会重新锁上。
3. **当前词如果是关键词，换字色直接失效。** `word_fx.py:265-267`：`skip_tint = run.emphasized → return`。
4. **一个控件叫「高亮色」，同时管两件事**：当前词 + 关键词强调。提示自己承认「关键词强调也用这套颜色」（`fx_fields.py:798`）。
   这违反了我们刚立的规矩「一个词只能管一件事」。
5. 卡拉 OK 扫过不支持渐变。

## 正确做法

**数据**：
```
fx.follow_word = {
  tint: {enabled, type, colors, angle},            # 当前词字色
  box:  {enabled, color, alpha, pad_em, radius_em, offset_y_em}   # 当前词底块
}
```
与 `fx.emphasis.*`（关键词强调）**彻底分开**。旧键迁移过来。

**界面**：「跟随单词」一个段，里面两个子段「当前词字色」「当前词底块」，**各带开关、各有自己的颜色控件，都在本段内**。
「配色方案」段只保留字色，**去掉那个纯 UI 锁**（Resolve 的填充段没有开关）。
「关键词强调」的颜色控件回到「自动着色」段里，叫「强调色」。

**渲染**：优先级写死为「子段自己的颜色 → 产品默认」，**不再回退到 `bg.color` 或 `emphasis.color`**。
当前词恰好是关键词时，「当前词优先」。`tint_run_ltr` 支持渐变（卡拉 OK 扫过渐变）。
