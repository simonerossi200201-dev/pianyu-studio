## 背景（十六报第 3 节）
`render/parallel.py:181` 注释写明「本进程在**每个视频开始前**读一次」，`:221` `if use_gpu and not degraded_once: read_degrade(...)`。
Luca 这次是 **6 个视频 / 6 个进程，每进程 1 个**，降级指令是在**编码进行中**发出的，
每个 worker 早就过了那个检查点。所以日志里这两行**是假的**：
```
[Guard] 已发出降级指令（gpu_off）：… 已关闭 GPU 加速并降低编码线程
[Guard] 自动降级：… 已关闭 GPU 加速并降低编码线程
```
**什么都没关**，5 路 NVENC 一路没停，然后被 TDR 打断。

## 要做（二选一，都要有测试）
**A. 让它中途能生效**：worker 每 N 帧（建议 60）检查一次 flag；收到降级就
   **干净地收尾当前文件**（正常 close stdin + wait），把该视频标记为「需 CPU 重做」进 `failed`，
   由串行阶段用 libx264 重做。**绝不允许在同一个文件里换编码器。**
**B. 至少别撒谎**：日志改成「已请求降级，但 N 个视频正在编码中，本次不生效；将在下一个视频生效」。

建议做 A，并保留 B 的诚实文案作为 A 不适用时的兜底。
