## 背景
ffmpeg CPU 只有 5%，编码器有的是余量，瓶颈是**单线程合成**。
这是拿到「至少快一倍」的结构性手段，而且**输出逐字节不变**，比改玻璃像素安全得多。
注意：这和 `render/parallel.py` 现有的「多任务并行」不是一回事，是**单个视频内部的并行**。

## 要做
N 个工作单元各合成一段时间的帧（同一套 `frame_at`），**按序**送回主线程写进**同一个** ffmpeg 管道。
默认 `workers` 由 CPU 核数定，但**输出必须与串行逐字节相同**。

## 门禁（硬）
- `workers=1` vs `workers=4` 输出 **md5 完全相同**，锁到 **g08 / g10–g18 / g19-2 / g19b-2 全部十二例**
- golden 十二例哈希不变
- 贴墙钟；目标：T023 工程导出 ≤ T08 基线的一半
- 内存：并行合成不许让每进程 RSS 超过 T03 的估算值，否则 T03/T04 的保护会被击穿 —— 一并量出来
