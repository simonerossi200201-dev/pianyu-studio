## 现象（Luca，带截图）
`字幕文本 → 句子` 分页**始终**显示「还没有字幕。先自动字幕，或在「文案」里贴原文再对齐。」，

## Claude 已经查到的（别重复查，从这里往下走）
1. `TranscriptPanel.segments()`（`cutora/ui/panels/transcript.py:453`）只读**一个地方**：
   ```python
   return list(self.task().get("segments") or [])
   ```
2. `TranscriptPanel.reload()` 在整个仓库只有**一个调用点**：
   `command_bodies.py:1390 _refresh_task_view(idx)`，而且外面套着 `if idx == self.curr_idx`。
3. `_refresh_task_view` 的调用点有 7 个，其中与用户路径相关的两个是
   `main_window.py:4679 on_click`（切换媒体/打开工程最终走到这）和
   `main_window.py:9319 on_align_done`（ASR 完成）。**所以刷新路径看上去是通的。**
4. 于是最可能的根因是 **`task["segments"]` 本身是空的，字幕其实活在时间线的 subs 轨上**。
   佐证：`on_align_done` 里有 `ensure_subs_track_for_segments(task_now)`（segments → 轨道），
   而 2026-09-18 拼接出来的 6 个 `stitched.asproj.json` 全都是 `segments: []` 但有 subs 轨。
   **这是 BUG-13 没修干净的另一半：真源从 `task["segments"]` 漂到了轨道，读端没跟。**

## 要做

### 1. 先量，不要先改（结论进 `docs/plan/reports/T29_句子页真源.md`）
在这五条路径各打一条日志，打印 `len(task["segments"])` 和 subs 轨上的字幕条数：

| 路径 | 怎么触发 |
|---|---|
| 打开工程 | `project.open` |
| 切换媒体条目 | `on_click` |
| ASR 完成 | `on_align_done` |
| 拼接导入 | `_import_stitch_timeline_projects` |
| 撤销 / 重做 | `push_undo` 之后 |

五行数字贴进报告。**哪一条出现「轨道有 N 条、segments 有 0 条」，哪一条就是断点。**

### 2. 定真源，两边不许各存一份
二选一，在报告里说明选哪个和为什么：

- **A（推荐）**：subs 轨是唯一真源，`task["segments"]` 降级为**派生视图**。
  `TranscriptPanel.segments()` 改成从轨道读；所有写字幕的地方只写轨道。
- **B**：`task["segments"]` 是唯一真源，轨道是派生。那 `ensure_subs_track_for_segments` 要变成
  单向同步，且任何改轨道的操作都要写回 segments。

**不许「两边都写、谁先谁后看运气」** —— 那就是今天这个 bug 的来源。
选定之后在 `docs/plan/PROTECTED_INVARIANTS.md` 里加一行不变量。

### 3. 空状态要说实话
即使修好了，空状态文案也要能区分三种情况，不许都显示同一句：
- 真的没有字幕 → 「还没有字幕。先自动字幕，或在「文案」里贴原文再对齐。」（现状）
- 有字幕但读不到（真源不一致）→ 「检测到时间线上有 N 条字幕但读取失败」+ 一个「重新载入」按钮 +
  **同时往日志里落一条 error**。这一条就是「落档不许静默」：这次的 bug 之所以拖了这么久，
  正是因为读不到和没有长得一模一样。
- 当前没有选中任何媒体条目 → 「先在媒体库里选一个条目」

### 4. 顺手修掉 reload 的隐形早退
`reload()` 开头有 `if self._reload_guard: return` 和「有卡片在编辑中就 return」。
这两条**在 segments 从 0 变 N 时不许生效**（否则用户正在某个卡片里打字时跑完 ASR，列表永远不刷新）。
加一个 `force=True` 参数，`on_align_done` 用 force。
