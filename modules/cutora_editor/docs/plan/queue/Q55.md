# Q55 · 转场三件事：素材不够时不许发黑、手柄拖时长、转场库扩容

**开工前先读 `docs/plan/queue/_RULES_FOR_EVERY_TASK.md`。**

## 用户原话

> 转场库做的也挺不错的，就是**视频转场的种类有些少**，比如像是**突进**这种类型的转场也没看到，
> 还有其他一些高级转场也没看到，请你多设计添加更多的高级的转场。
>
> 另外这个转场的持续时间我希望可以**直接在时间线上拖动转场的左边和右边的手柄**就可以控制了。
>
> 还有一个很重要的问题，就是**当视频长度不够的时候，视频之间转场的过程会出现半透明画面半黑的情况**，
> 这种情况也必须要避免。可以给他加一个功能，就是转场时候**使用两个视频的首尾帧进行自动延长视频长度**
> 以避免转场过程中出现画面发黑的情况。除非视频本身有足够的片段剩余出来用于转场，
> 否则就自动使用首尾帧来解决发黑的问题。

## 三件事，按重要性排序

---

### 一、素材不够时的发黑（这是出片质量问题，最要紧）

**现象的成因**：交叉转场需要两条片段在时间上重叠。重叠区里，
A 片段要播它出点**之后**的帧、B 片段要播它入点**之前**的帧（业内叫 handle / 余量）。
源素材没有这段余量时，取不到帧就合成了空（透明/黑），
于是混合结果 = 半透明画面叠在黑上 —— 正是用户描述的「半透明画面半黑」。

**要做的：自动冻结帧延长（freeze-frame handle）**

1. 先查清楚现在到底怎么处理余量不足的：
   `cutora/model/seams.py`、`cutora/render/anim_engine.py`、`render_worker.py` 的转场合成处、
   `preview/engine.py`。**把那段「取不到帧时发生了什么」的代码找出来贴进 `.ok`。**
2. 余量判定：对每条参与转场的片段，算出它在源素材里**还剩多少帧可用**
   （A 的出点到源尾、B 的入点到源头）。
3. 余量够 → 照常用真实帧，**行为完全不变**（这一点必须有测试锁住，
   不能为了修发黑把本来正常的转场也改了）。
4. 余量不够 → 用该片段的**首帧 / 尾帧冻结**补齐缺口。A 用它的最后一帧持续，
   B 用它的第一帧持续。**绝不允许出现透明或黑。**
5. 部分够 → 先用真实帧，用完再冻结，不要一刀切。
6. **预览和导出必须是同一条路径。** 这个项目已经在 preview≠export 上翻过四次车。
7. UI 上给一个可感知的提示：时间线上这段转场标记为「冻结补帧」
   （一个小图标或斜纹），让用户知道这里不是真实素材。**不要弹窗打断。**

**验收**
- `test_q55_no_black_when_handles_short`：造两条只有 10 帧的视频，
  放一个 20 帧的交叉转场，逐帧导出，**断言每一帧的最小亮度都不为 0、alpha 全为 255**。
  现在必红。
- `test_q55_enough_handles_byte_identical`：余量充足的转场，
  改动前后导出**逐字节相同** —— 证明没有误伤正常路径。
- `test_q55_freeze_uses_correct_frame`：断言 A 冻结的是它的尾帧、B 冻结的是它的首帧
  （比像素，不是比调用）。
- `test_q55_preview_matches_export`：同一帧，预览和导出比 MAD。

### 二、在时间线上拖转场的左右手柄改时长

现在转场时长只能在面板里填数字（`property.py` 的 `ov_transition_dur` 一类）。

要做：
1. 时间线上转场对象的**左右两侧各一个手柄**，命中区 ±4px（和现有切缝命中一致，
   `timeline/widget.py:831 _hit_seam_at` 是现成的参照）。
2. 拖左手柄 = 改转场起点（即转场变长/变短，中心不动还是左边不动，要选一个并说明）；
   拖右手柄同理。**拖动时实时预览时长变化**，松手才落命令。
3. 走命令层，**一次拖动 = 一次 undo**（参照 `Q16` 的图钉批量 undo 做法）。
4. 拖到超过可用余量时：接第一件事的冻结补帧，**不要拒绝拖动**，
   但手柄要有视觉反馈（比如超出部分画成斜纹）表示「这段是冻结补的」。
5. 最小时长保护：不许拖成 0 帧或负数。

**验收**
- `test_q55_drag_handle_changes_duration`：模拟按下-移动-松开，
  断言 `TransitionItem` 的时长变了，且 `serialize_render_task` 的 JSON 里数值对得上。
- `test_q55_drag_one_undo`：一次拖动之后 undo 一次，JSON **逐字节**回到拖动前。
- `test_q55_drag_beyond_handles_marks_freeze`：拖超余量，断言该转场被标记为冻结补帧。

### 三、转场库扩容

现有：`render/anim_engine.py:214-226 AUDIO_TRANSITION_LIBRARY`（音频 11+5），
视频转场库在同文件附近。**先把现有的清单列出来写进 `.ok`**，再补。

用户点名要**突进（push in / 猛推）**。除此之外补这些类别，每类至少两三种：

- **推移类**：推入（上下左右四向）、推出、对推
- **缩放类**：突进（快速推近 + 轻微运动模糊）、拉远、缩放溶解
- **擦除类**：线性擦除（可调角度）、圆形擦除、时钟擦除、百叶窗
- **变形类**：旋转溶解、翻页、立方体旋转
- **光学类**：白闪、黑闪、曝光溶解、光晕溢出（bloom）、色散/RGB 分离
- **模糊类**：方向模糊转场、径向模糊转场、散景溶解
- **数字感**：故障（glitch）、像素化溶解、扫描线

要求：
1. 每一种都是**纯函数**：给两帧 + 进度 t (0..1) + 参数，返回一帧。
   便于测试，也便于预览和导出共用。
2. 每一种在转场面板里要有**动的缩略预览**（现有 `transition_panel.py:38 TransitionThumb`
   已经有 QTimer 动画机制，照它做）。
3. 每一种都要有方向 / 强度 / 缓动参数，不要做成一个写死的效果。
4. 命名给用户看的，不要暴露内部术语。
5. **性能**：转场只在重叠区那几帧发生，但那几帧不能成为导出的瓶颈。
   每种转场量一下 ms/帧写进报告，超过单帧预算的要么优化要么标记为「仅导出」。

**验收**
- 每种转场一条像素测试：t=0 时等于 A 帧、t=1 时等于 B 帧、t=0.5 时两者都不等于
  （这条能抓住「实现了但没接上」）。
- `test_q55_all_transitions_have_thumb`：库里每一项在面板上都有缩略图，不许有空白格。
- `docs/plan/reports/Q55_transition_perf.md`：每种的 ms/帧。
