# Q99 · 轮廓包裹：把「连字」从「圆角」里拆出来

**开工前先读 `docs/plan/reports/Q97.md` 和 `docs/plan/queue/Q97.md`。**

## 为什么

Q97 的任务书是 Claude 写的，里面让闭运算半径直接用现有的 `bg.radius_em`。**这是 Claude 写错了**，
Grok 照做没有问题。实际效果见 `docs/plan/reports/img/Q97_hug_radius05.png`：
圆角调到 0.5，闭运算把 `H` 两竖之间的内孔也填满，整块退化成一个纯矩形 ——
「轮廓包裹」的意义正好被抹掉。圆角 0 的形状（`Q97_hug_radius0.png`）是对的。

根子上的问题：「背景矩形的圆角」和「字与字之间连不连起来」是两件事，
不该共用一个滑条。用户为了矩形圆润会把 `radius_em` 调大，那个量级对闭运算来说是灾难性的。

## 要做的事

1. 新字段 `bg.hug_join_em`（面板名「连字」），只在 `size_mode == "hug_glyphs"` 时有意义。
   - 默认 **0.06**，范围 **0–0.15**（em）。不要给更大的上限。
   - 闭运算半径改用它，**不再读 `bg.radius_em`**。
   - `bg.radius_em` 在 `hug_glyphs` 下回到它本来的职责：**不参与蒙版形状**，
     所以「轮廓包裹」时把「圆角」这一行**藏掉**（`fit_text` / `fixed` 下照旧显示）。
2. **再加一道硬上限**，别指望用户自己收着：闭运算半径同时不许超过
   「这一段字形里最窄笔画宽度的一半」。取法：对字形 alpha 做 `cv2.distanceTransform`，
   取字形内部距离场的中位数当作「半笔宽」的稳健估计，闭运算半径取
   `min(hug_join_em * em, 该中位数)`。这样无论滑条怎么拉，字母内部的孔都填不满。
   这个上限算出来的实际半径要能被测试读到（暴露一个内部函数即可，不必上界面）。
3. 老工程：没有 `hug_join_em` → 0.06。已经存过 `hug_glyphs` 的工程形状会变
   （原来读 `radius_em`，现在读新字段）—— 这个功能昨天才做出来，还没有任何工程在用，
   不需要迁移，但要在报告里写明。

## 测试 `tests/test_q99_hug_join.py`

每条都要能说明「改之前是红的」：

1. `hug_join_em` 从 0 调到 0.15，两个字母之间的凹口覆盖像素明显上升（沿用 Q97 那条的量法）。
2. **`hug_join_em` 拉到上限 0.15 时，`H` 内部的孔仍然是通的** —— 取两竖之间正中那一小块，
   背景 alpha 必须接近 0。这条就是 Q97 那张图的反例，是本任务的核心验收。
3. `bg.radius_em` 在 `hug_glyphs` 下从 0 改到 0.5，蒙版**一个像素都不许变**。
4. `fit_text` / `fixed` 两条路径的帧字节仍是 `8a063bb50cd86a78515f330072ee72a3`。
5. 面板：`hug_glyphs` 时显示「包裹厚度 / 连字 / 偏移」，藏「圆角 / 宽 / 高 / 内边距」；
   json 往返后重开面板值还在。
6. 硬上限那个函数：给一段细笔画的字和一段粗笔画的字，细的那段算出的半径必须更小。
