## 现象
「字幕排版里的 字幕范围 左/右 调了不起任何作用。希望改名重新定义为 字幕宽度范围 ——
控制这一行能显示更多还是更少的单词，原来三五个词，调完能放八九个词，调完自动重新断句。」

## 根因
`wrap_left` / `wrap_right` 有**三个写入方**，互相覆盖，用户排最后：

1. 面板（用户调的）→ 写进 `style`
2. `cutora/subtitle/stylepack.py:224-228` 从这两个值**反推**可用宽度
3. `cutora/render/frame_renderer.py:1017-1018` —— **每帧无条件覆盖**：
   ```python
   seg_style['wrap_left']  = padding_x + overscan_x
   seg_style['wrap_right'] = off_w - padding_x - overscan_x
   ```
   而 `pipeline.py:124` 的布局缓存键读的就是被覆盖之后的值。
   → 用户调什么都会被这两行冲掉。**典型的「多个写入方，没有单一真源」。**

## 要做

### 0. 先查清楚一件事
`CANONICAL_STYLE_KEYS` 里已经有一个 `wrap_width_percent`（`stylepack.py:599` 默认 100）。
**先验证它现在有没有生效、和下面要做的是不是同一件事。**
如果是同一件事 → **复用它，不要新增键**，只把面板接上去并修好覆盖问题。
（我倾向于就是同一件事，但没验证，你去验，结论写进 `.ok`，再决定键名。下面暂用 `wrap_width_pct` 指代。）

### 1. 单一真源
`wrap_width_pct`（0–100，默认 86）= 一行字幕可用宽度占**画布宽度**的百分比。

- `wrap_left` / `wrap_right` **退役**（进 `DEPRECATED_UNPAINTED_KEYS`），面板上的「左 / 右」两个输入框连控件一起删。
- 排版计算里，可用宽度 = `canvas_w * wrap_width_pct / 100`，左右居中分配。
- `frame_renderer.py:1017-1018` 改成从 `wrap_width_pct` 算，**只在用户没设过时才用画面边距兜底**。
- 老工程迁移：`migrate_subtitle_style()` 里，若有 `wrap_left`/`wrap_right` 且 `wrap_right > wrap_left + 50`，
  用工程画布宽度折算成 `wrap_width_pct`，然后删掉这两个旧键。

### 2. 面板控件
「字幕排版」段里换成一个滑条：

```
字幕宽度范围   [————●————]  86%      每行约 6 词
```

右侧「每行约 N 词」是**实时预估**：用当前字体/字号/字距量出当前这条字幕的平均词宽，
算 `可用宽度 / 平均词宽`。这是用户判断自己调到哪儿的唯一反馈，**别省**。

### 3. 改完自动重新断句（Luca 特别强调「信号要连清楚」）
滑条 **`sliderReleased`**（不是 `valueChanged`，否则拖动过程中疯狂重排）后：

1. 写 `wrap_width_pct` 进 style
2. 触发一次和「按当前排版重新断句」（`subtitle.relayout` 命令）**完全相同**的路径 ——
   **不要复制一份断句逻辑**，直接调那个命令，走命令总线，可撤销
3. 断句只改**换行位置**，不改任何词的时间戳
4. 状态栏落一条：「字幕宽度 86% → 重新断句，N 条变 M 条」
