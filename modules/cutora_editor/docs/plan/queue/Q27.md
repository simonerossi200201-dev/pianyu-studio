## 现状（Claude 核实）
文本图层走的是**另一套命名空间**：`style_schema.TEXT_LAYER_CANONICAL_KEYS` + `TEXT_LAYER_DEFAULTS`，
键名是 `color / stroke_width / bg_enabled / bg_fill_type / bg_grad_dir / bg_color…`，
和字幕的 `fx` 树**完全平行、互不相通**。
所以字幕这边做出来的毛玻璃、纹理、渐变、真实投影（T21），文本一个都用不上 —— 这正是 Luca 说的差距。

## 要做

### 1. 删掉「图片元素」
从 UI、命令、序列化、测试里**整体删除**，不是隐藏。
删之前先 grep 清楚它的键（`dyn_box_image_*` 一族已经在 DEPRECATED 里了，但文本侧可能另有一套），
把涉及的键一并进 DEPRECATED 并在 `migrate` 里 pop。
老工程里有图片元素的，打开时状态栏提示一次「已移除 N 个图片元素」，**不许静默丢弃**。

### 2. 背景升级到和字幕同一个效果器（本任务的重点）
**不要再写第二套背景实现。** 做法：把字幕的 `BgSpec` + `raster.raster_bg`（含 `glass_thick` 玻璃、
`texture` 纹理、渐变、blend 模式、四边渐隐）**抽成一个与"谁在用"无关的公共背景效果器**，
字幕和文本共用同一份代码、同一组键名。

- 文本侧新增 `fx` 子树（和字幕同构），`bg_*` 一族旧键退役并在 migrate 里折算过去。
- 文本的背景因此立刻拥有：`none / box / glass / texture / bubble` 五种类型、玻璃的
  厚度/折射/倒角/光泽/光线方向、纹理与染色、渐变与高光、五种 blend、四边渐隐。
- **玻璃需要 backdrop**：字幕那边是 `project["_fx_backdrop"]`（`render_worker.py` 每帧灌的）。
  文本图层要走同一条路 —— 确认文本渲染时机拿得到同一张 backdrop，拿不到就**停下写 `.stop` 问 Claude**，
  不要自己发明第二套。

### 3. 描边 / 投影 / 填充也共用
同理，文本的 `stroke_width/stroke_color` → `fx.stroke`；`shadow_*` → T21 的光源投影；
`color` → `fx.fill`（支持渐变和金属）。**一份实现，两个调用方。**

### 4. 富文本编辑
文本框内支持**逐段/逐字符样式覆盖**（选中一段文字单独改颜色/字号/粗细/字体）：
- 数据结构：`text` 之外增加 `runs: [{start, end, overrides:{...}}]`，
  没有 runs 时行为与现在**逐字节一致**（老工程不变）。
- 编辑器：在属性面板里用 `QTextEdit` 承载，工具条给 粗体/斜体/下划线/颜色/字号/清除格式 六个按钮。
- 渲染：`layout` 已经是按 run 组织的（`line.runs`），把 overrides 接进去，**不要另起一套排版**。

### 5. 排版能力补齐（对齐专业软件）
- 段落对齐（左/中/右/两端对齐）、首行缩进、段间距、行距（已有 `text_layout`，接上去）
- 字距 / 字偶距（`tracking_em` 共用字幕那套）
- 竖排文本（中文场景常用）、文字沿路径（**这一条列为欠账，本任务不做**，写进 `.ok`）
- 自动缩放适配文本框（文字超框时按比例缩到框内，或框跟着文字长）
