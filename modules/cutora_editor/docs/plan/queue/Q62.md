# Q62 · 关键帧：拨了没反应的三处 + 两条死掉的渲染路径

**开工前先读 `docs/plan/queue/_RULES_FOR_EVERY_TASK.md`，尤其第八节：每做完一个子项就提交。**

Q31 的核心是对的：`render/keyframe.py` 的 `value_at`、六种缓动、贝塞尔（牛顿迭代+二分兜底）、
OKLCH 最短色相都写对了；视频 clip 的 x/y/scale/rotation/opacity 预览（`canvas.py:1108-1129`）和导出
（`render_worker.py:1454-1502`）都走 `resolve_clip_visual`，真通。**坏在外围。**

## 1. 画布上拖动有关键帧的片段，松手弹回原位

`canvas.py:1698`、`:2169` 只写静态 `clip.x/y/scale`，渲染时被关键帧覆盖，画面弹回原位。文本覆层 `:2131` 同样。
**做法**：参数已启用关键帧时，画布拖动/缩放改走 `keyframe.set`（在播放头时刻打点或更新该点），
即调用 `PropertyPanel._auto_key` 那条路。

## 2. 秒表和数值框不跟播放头走

`_refresh_kf_watches`（`property.py:1293`）只在选中时调用（`:1983`、`:2023`），没接播放头位置信号，
「在关键帧上实心、不在空心」是过期的。`:1993` 读的是静态 `clip.x`，不是 `value_at`。
**做法**：播放头位置信号接到 `_refresh_kf_watches`，同时把数值框刷成 `value_at(t)`（用 blockSignals，别触发写回）。

## 3. 改一个值会给所有已启用的参数都打点

`property.py:1315-1319` 对五个参数都调 `_auto_key`。改 X 会用框里的旧值给 scale 等参数打点，把原来的动画压平。
数值框每跳一下都进一条撤销记录。
**做法**：`on_change_video` 只给 sender 对应的那个参数打点；一次连续编辑（按住滑条拖、spin 连按）合并成一条撤销。

## 4. 字幕的 opacity / scale 关键帧是死的

`frame_renderer.py:1740` 用 `bake_host` 把值写进 `s["opacity"]` / `s["scale"]`，
但 `render/textfx/` 全目录没有任何地方读 style 的 opacity 或 scale（grep 为空）。
**做法**：`textfx/pipeline.draw` 读取并应用 style 的 opacity 和 scale。

## 5. 新式图片覆层的关键帧是死的

`frame_renderer.py:1123`：带 `elements` 的覆层直接 return，交给 `draw_stickers`（`:1510`），
而 `draw_stickers` 没有调 `bake_host`。**时间线上照样画出菱形，用户看得到点、看不到动画。**
**做法**：`draw_stickers` 里调 `bake_host`。

## 6. 切割后右半段动画从头重放

`timeline_model.py:91 split_at` 用 `clone()`，关键帧的 t 没有平移。
**做法**：右半段的关键帧 t 平移 `-(cut - start_t)`，落在右半段范围外的点丢弃，
并在切点处补一个用 `value_at(cut)` 算出的点，保证切割前后画面连续。

## 7. 菱形拖不动

`keyframe.move` 命令写了，UI 从不调用。**做法**：时间线菱形支持左键选中、拖动（调 `keyframe.move`），
粘贴贴到**播放头**而不是被点的那个点（`widget.py:397/418`）。
