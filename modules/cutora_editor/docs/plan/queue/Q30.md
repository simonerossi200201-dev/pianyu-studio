## 现象（Luca）
「多片段时间线上播放，第一个片段有立体声效果，播到第二个片段就没了。怀疑没适配多片段时间线的新形式。」
期望语义：**每条音频在属性面板里有一个「空间立体声」勾，勾上就对这条音频生效，不勾就不生效；
导入进来的音频和带音轨的视频默认勾上；以后加配乐时只给人声勾，配乐不勾。**

## Claude 已核实的三个缺陷（别重新推理，从这里往下走）

### BUG-43 · 预览混音**根本没有**空间立体声（不是第二段没有，是一段都没有）
预览音频走 `cutora/asr/timeline_wav.py` 的 `render_timeline_wav()`。
它的每条 clip 记录由 `_clip_mix_dict()`（该文件 :75）构造，字段只有：
`path / in_t / out_t / start_t / gain_db / speed / fade_in_dur / fade_out_dur / pitch_semitones / audio_role / is_main / loop`
—— **没有任何 spatial 字段**。
而整个文件里 `spatial|reverb|afir|extrastereo` 的出现次数是 **0**（我 grep 过）。
所以预览的 ffmpeg 链里压根没有混响这一环。

连带问题：`preview_audio_fingerprint()`（:149）也不含 spatial 字段 →
**就算以后接上了，改设置也不会让缓存的 preview wav 重算**，表现又会是「怎么调都没反应」。

> Luca 听到的「第一段有」大概率来自 QMediaPlayer 直接播原始视频文件、后续走预览 wav 这两条路径的差异。
> **这一条要量，不要猜**：打日志确认第一段的声音到底从哪条路出来。结论写进 `.ok`。

### BUG-44 · 两条导入路径给了**相反**的默认值
- 正常导入（`main_window.py:4430`）：`_SFX.apply_default_spatial_to_clip(audio_clip)` →
  `spatial_enabled = True`（`sfx_library.py:250`）
- 拼接时间线（`batch/timeline_stitch.py:189`）：**写死** `"spatial_enabled": False, "spatial_amount": 0.0`

同一个软件，两条路进来的音频默认值相反。这就是 Luca 感觉到的「没适配多片段时间线」。

导出侧暂时没暴露，是因为 `spatial.resolve_spatial_for_track()`（`audio/spatial.py:438`）
对 `is_main` / `role == "main"` 的轨走的是 `enabled = default_on or clip_on`，靠全局默认 True 救了回来。
**但只要用户在属性面板碰过任何一条**（`spatial_user_set = True`），那条就只认 clip 上的 `False` —— 永久静音该效果，且用户不知道为什么。

### BUG-45 · 面板那个勾和实际生效逻辑**语义打架**
属性面板的勾（`ui/panels/property.py:811`）读写的是 `clip.spatial_enabled`，
而真正决定生不生效的是 `resolve_spatial_for_track()` 里那三层间接：
`user_set ? clip_on : (is_main ? (default_on or clip_on) : clip_on)`。
所以完全可能出现「勾没打钩，导出却有混响」或者反过来。Luca 截图里的勾就是没打钩的。

## 要做

### 1. 语义改成 Luca 要的那一种（一层，不要三层）
**唯一真源 = 每条音频 clip 上的 `spatial_enabled`。** 删掉 `spatial_user_set` 这个概念和
`resolve_spatial_for_track` 里的三层分支：

```
enabled = bool(clip.spatial_enabled)          # 就这一句
```

全局设置（音效库对话框里那些）只负责**默认值和参数**（预设 / 湿声 / 宽度 / 话筒质感），
以及「导出时默认开启」这个开关只影响**新导入的 clip 的初始勾选状态**，不再在渲染时二次决定。
`audio_role == "sfx"` 仍然强制不上混响（音效本身就是做好的，别二次混响）。

### 2. 三条导入路径统一默认值
凡是新建一条**带音轨的主音频 clip**，默认 `spatial_enabled = True`；**配乐（bgm）默认 False**。
三处都要改成调同一个函数 `apply_default_spatial_to_clip()`，不许各写各的：
- `main_window.py:4430`（正常导入，已经是对的）
- `batch/timeline_stitch.py:189`（**现在写死 False，改掉**）
- `main_window.py:4307`（bgm，保持 False）

老工程迁移：`project_io.py:63` 现在是 `cl.setdefault("spatial_enabled", False)`。
改成按 `audio_role` / `is_main` 给默认值（main → True，bgm/sfx → False），
并且**只对没有这个键的老 clip 生效**（有键的尊重用户的选择）。

### 3. 预览接上混响（BUG-43 的正题）
- `_clip_mix_dict()` 补上 `spatial_enabled / spatial_amount / spatial_preset`
- `render_timeline_wav()` 里逐条 clip 加混响，**复用导出那一份 filter 构造**
  （`audio/spatial.py` 的 `build_hall_reverb_filter`），**不要另写一套** ——
  预览和导出必须是同一个函数，否则又是「预览一个样导出一个样」。
- `preview_audio_fingerprint()` 把三个 spatial 字段加进去，否则改了设置缓存不刷新。
- 性能：卷积混响（afir）对每条 clip 都跑一遍可能让预览 wav 生成变慢。
  **量一下**：拼接时间线 27 条 clip，接上前后 `render_preview_wav` 的耗时，进 `.ok`。
  超过 3 秒就要想办法（比如预览用轻量 IR 或 `aecho` 近似，但**必须在报告里说明预览和导出的差异**，
  不许悄悄用不同算法）。

### 4. 属性面板
- 勾的语义变成「这条音频吃不吃空间立体声」，直白。
- 勾下面的「湿声」滑条：不勾时变灰。
- 多选多条 clip 时支持批量勾 / 批量取消（Luca 以后加配乐就是这个场景）。
