# Q101 · 一个脚本搞定：双击就启动，缺什么自己补，装好自动建桌面图标

**开工前先读 `_RULES_FOR_EVERY_TASK.md`，以及现有的 `CUTORA.bat` / `CUTORA_Install.bat` /
`CUTORA_CreateShortcut.bat` 和 `tools/pack_internal.py`。**

## Luca 要什么

「分发的时候需要用户手动点击安装依赖环境，我希望它就一个脚本，启动的时候默认就是直接启动，
如果依赖环境不完整就直接运行安装依赖环境的脚本，如果用户没有安装 python 就提示用户先把
指定版本的 python 安装好，全部安装好之后就可以直接创建软件的图标在桌面上……
其实它还是一个快捷方式，只不过显示成这个图标。」

Luca 2026-09-24 已定：**只出厚包**（现在这种，包里带 `runtime\python` + `runtime\venv`）。
所以「装 Python / 装依赖」是**兜底路径**，正常用户走不到。

## 现状（先看清楚再动手）

- 厚包里 `runtime\python\python.exe`（3.10.11）和整个 `runtime\venv` 都在，
  **拿到包的人本来就不需要装任何东西**。
- 毛病在 `CUTORA.bat`：它 `import tokenizers` / `import transformers` 失败时
  **停下来叫用户去点 `CUTORA_Install.bat`**，而不是自己去修。这就是 Luca 说的那个手动步骤。
- 每次启动都跑那两条 `python -c "import ..."`，冷启动要好几秒，纯属浪费。

## 要做的事

### 1. 就绪标记，避免每次都体检

在 `runtime\venv\.cutora_ready` 写一行：`requirements.lock` 的 sha256 + 装完时的 UTC 时间。
启动时只比对这个文件和 `requirements.lock` 的哈希，**对得上就直接起，不再 import 探测**。
装完依赖后写，`CUTORA_Install.bat` 成功那一步也写。

`tools/pack_internal.py` 打包时**必须把这个标记一起带上**（venv 是原样打进去的，
标记就在 venv 里，顺带就进去了）—— 但要在打包脚本里**校验它存在且哈希对得上**，
不对就让打包失败，免得发出去一个「标记说就绪、其实没装」的包。

### 2. `CUTORA.vbs` —— 平时零窗口的入口

新文件，放仓库根。逻辑：

1. 检查 `runtime\venv\Scripts\pythonw.exe` 存在 **且** `.cutora_ready` 的哈希对得上。
   - **对得上** → `WshShell.Run` 以**隐藏窗口**方式起
     `runtime\venv\Scripts\pythonw.exe -m cutora`，然后 VBS 自己退出。**全程不闪任何黑窗。**
   - **对不上** → 以**可见窗口**方式起 `CUTORA.bat bootstrap`，让用户看得见进度，VBS 退出。
2. 不做别的事。VBS 里不许写业务逻辑，所有真正的活都在 bat / Python 里。

注意：有些杀软对 `.vbs` 敏感。所以**必须同时保留一个 `CUTORA_console.bat`**，
内容就是可见窗口地跑同一套流程，用于排障和杀软拦了 VBS 时的退路。README 里写明。

### 3. `CUTORA.bat` 重写

一个脚本，带一个可选参数 `bootstrap`。流程：

1. `cd /d "%~dp0"`，算 ROOT。
2. **找 Python**（按顺序，找到就用）：
   a. `runtime\python\python.exe`（厚包正常路径）
   b. 系统 `py -3.10`
   c. `PATH` 里的 `python` 且版本是 3.10.x
   都没有 → **清清楚楚地告诉用户**：需要 **Python 3.10.11（64 位）**，
   给出 python.org 的下载页地址，说明装的时候要勾 "Add python.exe to PATH"，
   装完重新双击这个图标即可。然后 `pause` 退出。**不许只报一句 "venv missing"。**
3. venv 不存在 → 建。
4. `.cutora_ready` 哈希对不上（或用户传了 `repair`）→ **自己执行安装流程**
   （现在 `CUTORA_Install.bat` 的第 2–5 步原样搬过来），装完写标记。
   **不要再叫用户去点另一个 bat。**
5. 起应用：`runtime\venv\Scripts\pythonw.exe -m cutora`。
   `bootstrap` 模式下起完就 `exit /b 0`，让窗口关掉。
6. 首次成功起动后，若桌面上还没有那个快捷方式 → **自动建**（见第 5 节）。
   建过一次就记在用户数据目录里，不要每次都建、也不要用户删了又给他建回来。

`CUTORA_Install.bat` 保留，改成「只做修复」的薄壳：调用同一套流程并强制 `repair`。
**不许两套安装逻辑各写一份。**

### 4. 图标：`Cutora me.png` → `app.ico`

Luca 2026-09-24 确认这张图**不是 Grok 生成的**，可以随包分发。

- 把 `Cutora me.png` 复制成 `resources/brand/app.png`（仓库里用 ASCII 文件名，
  原图留在原处不动）。
- 用 Pillow 生成**多尺寸** `resources/brand/app.ico`，尺寸至少
  `16 / 24 / 32 / 48 / 64 / 128 / 256`，保留 alpha。
  生成脚本放 `tools/brand/icon_from_png.py`，可重复执行、结果确定。
- 同时按现有命名补齐 `icon_16/32/48/64/128/256/512/1024.png`
  —— `tests/test_t02_brand.py:49-51` 那张清单里的文件**一个都不许少**，少了这条测试会红。
  `icon_512_light.png` / `icon_mono_512.png` / `mark_1024.png` 如果原来就有且这次不该换，
  保持原样，在报告里写明哪些换了哪些没换。
- `cutora/core/paths.py` 的 `APP_ICON` / `APP_ICON_PNG` 路径不变，所以窗口图标、
  任务栏图标自动跟着换。

**换图标可能牵动的地方，逐个确认并写进报告**：`tests/test_t02_brand.py`、
`cutora/render/export_guard.py:180`、启动闪屏。
`tools/ui_golden.py --all` 跑一遍：u01/u02 是预览帧、u03e/u04e/u07b/u08b 是面板，
按理都拍不到窗口图标，**预期一条都不变**。真变了就停下写 `.stop` 报 Claude，不许重录。

### 5. 桌面快捷方式

改写 `CUTORA_CreateShortcut.bat`，并让第 3 节第 6 步复用它：

- TargetPath = `%SystemRoot%\System32\wscript.exe`
- Arguments = `"<ROOT>\CUTORA.vbs"`
- WorkingDirectory = `<ROOT>`
- IconLocation = `<ROOT>\resources\brand\app.ico`
- 名字 `片语 Studio`，描述沿用现在那句。

这样双击桌面图标 = 零窗口启动，图标显示成那张图 —— 正是 Luca 要的
「其实它还是一个快捷方式，只不过显示成这个图标」。
