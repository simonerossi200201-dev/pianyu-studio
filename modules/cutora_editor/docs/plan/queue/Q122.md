# Q122 · 收掉剩下的卡顿：拖进轨道的同步探测 + 点选那 400 毫秒

**开工前先读 `_RULES_FOR_EVERY_TASK.md`。前置是 Q110（`aa29358`）：
媒体库导入已经异步化，主线程最长阻塞 4112ms → 82ms，别推倒重来。**

## Luca 的原话

「整个操作过程必须流畅，必须优化软件的性能，减少不必要的、重复的缓存和信号」

## 这一条要收的两块，都是 Q110 自己在报告「没做到」里写明的

### 1. 往时间线轨道上拖一条没导入过的视频，还是同步探测

`cutora/ui/main_window.py` 的 `_drop_video_file` / `_drop_audio_file` 里：

- `MediaSource(path)` 构造时探时长
- `has_audio_stream(path)` 再来一次
- `_probe_video_has_alpha(path)` 又一次

已经导入过的文件会命中 `probe_cache` 的时长缓存，很快；**没导入过的
每条要卡两三次 ffprobe**。Q115 的批量拖放是按返回时长把一批文件首尾
相接排开的，所以拖 10 个新文件 = 20~30 次同步 ffprobe 全压在界面线程。

要求：

- 先建条目（占位时长），探测走 `cutora/media/import_probe.py` 的
  `probe_file_for_import` / `queue_import_probe`（**复用，不许另起一套**），
  回来再就地更新片段时长和后面那些片段的起点。
- 一批文件首尾相接的排法要保住：探测是并行的，但**摆放顺序必须和
  文件名顺序一致**，不能谁先探完谁先排。
- 同一个文件不许被重复探测（import_probe 已经按路径+mtime+size 缓存）。

### 2. 点选一条视频卡 400 多毫秒

Q110 量过：这一顿不是探测，是 `VideoCanvas` 出第一帧 + 样式画廊刷新。

- 先量：写 `tools/_diag/q122_click_profile.py`，量出点选一条视频时
  **界面线程最长一次连续阻塞**，并按调用点分组（画布第一帧 / 样式画廊 /
  属性面板 / 其它）。把原样数字写进报告，这是验收基准。
- 目标：**最长一次连续阻塞 ≤ 150ms**。第一帧可以先出占位或上一帧，
  解码回来再换；样式画廊只刷当前可见的那些缩略图。

### 3. 顺手收掉重复信号（Luca 点名的「不必要的、重复的缓存和信号」）

用第 0 步的探针统计一次**一次用户操作触发了几次全量刷新**
（`refresh_ui` / `timeline.set_data` / `video_canvas.update`），
把同一次操作里重复的合并掉。具体做法你定，但：

- 不许用 `QTimer.singleShot(0, ...)` 到处补刀糊过去；
- 合并要有测试锁住（比如「导入 5 个文件，`refresh_ui` 最多被调 1 次」）。

## 不许做的

- 不许为了快把体检（`media_guard`）或探测删掉 —— 2026-08-23 那次「两个 JPG
  当成 mp4 收进来，最后少了两条成品还一个字没提」的补丁必须还在。
- 不许引新的并发库，线程池用 Qt 自带的那个全局池。
- 不许改 CRF / preset，不许加「快速模式」。
- 不许把探测结果写进工程文件当缓存（工程要能换机器打开）。

## 测试 `tests/test_q122_smooth.py`（要 Qt 的登记进 `qt_isolate`）

1. **拖进轨道不阻塞**：打桩让每次探测睡 200ms，往时间线上拖 5 个新文件，
   断言主线程事件循环最长一次间隔 < 150ms。改之前必红。
2. **顺序不乱**：5 个文件的探测按乱序回调，断言时间线上片段的起点顺序
   仍然是文件名顺序。
3. **不重复探测**：同一个文件拖两次，探测函数只被调用一次。
4. **刷新不重复**：导入 5 个文件，`refresh_ui` 被调用次数 ≤ 1。
5. **体检仍在**：伪装成 .mp4 的 JPG 拖到轨道上，被标出来且不进时间线，
   其余文件照常。
