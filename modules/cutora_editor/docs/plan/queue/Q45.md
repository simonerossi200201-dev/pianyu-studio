# Q45 · 禁用态半灰不灰 + 四态契约（P0）

**开工前先读 `docs/plan/queue/_RULES_FOR_EVERY_TASK.md`。**

## 事实

Q24 要求「关掉的段内容变灰但不隐藏」，实现是 `dock_panels.py:141,149`
`self._content.setEnabled(bool(checked))`。但：

- QSS 里 `QLabel:disabled` **0 条**、`QSlider:disabled` **0 条**、`QToolButton:disabled` **0 条**。
- QSS 显式写死的 `color` 不会被 Qt 的 disabled 调色板自动变暗：
  `QLabel#inspectorLabel { color: fg1 }`（`theme_dark.qss.j2:783`）无条件生效
  → **关掉的段，标签还是全亮**。
- `ColorSwatch.paintEvent`（`inspector.py:405-430`）不读 `isEnabled()`
  → **关掉的段，色块仍是满饱和度原色**。
- `ToggleSwitch.paintEvent` 同样不读。
- QSlider 无 disabled 规则 → **滑块手柄仍是 accent 金色**。

结果：一个「关闭」的段落，实际是输入框变灰了、标签色块滑条全亮。**比全亮还难看。**

## 另外三个状态也不全

- `:hover` 40 处、`:pressed` 8 处、`:focus` 8 处。
- **焦点环只给了文本输入类**（QLineEdit/QSpinBox/QComboBox/QTextEdit 四组）。
  `QPushButton` / `QToolButton` / `QSlider` / `QCheckBox` / `inspectorReset` /
  `ColorSwatch` / `ToggleSwitch` **一个 `:focus` 都没有** —— 键盘走查完全不可见。
- `QToolButton#inspectorReset` 只有 `:hover`，没有 `:pressed`、没有 `:disabled`。
- **`swatchBtn` 在 QSS 里没有任何规则**，`ColorSwatch` 是自绘的，
  grep `enterEvent|leaveEvent|focusPolicy|hover` in `inspector.py` → **零命中**。
  检查器里最显眼的 28×28 控件，鼠标移上去毫无反应。

## 要做的

1. 新建 `cutora/ui/theme/states.py`，对每类可交互控件生成完整四态，禁止手写单态。
2. `:focus` 补齐上面列的七类控件：`border-color: accent` 或 1px outline + 2px offset。
3. `:pressed` 从 8 处补到全部：统一背景 `darken(bg, 0.06)`，**不要位移**（Resolve 不位移）。
4. 禁用态：
   - QSS 补 `QLabel:disabled { color: fg_muted }`、`QSlider:disabled`
     （groove 降到 `line`，handle 从 accent 换 `fg_muted`）、`QToolButton:disabled`。
   - `ColorSwatch.paintEvent` 开头：`if not self.isEnabled():` 以 35% 不透明度混合 bg2 后绘制。
   - `ToggleSwitch.paintEvent` 同样处理。
5. `ColorSwatch` 补 hover：`enterEvent`/`leaveEvent`，hover 时边框换 accent。
6. 过渡动画：`DURATION_MS` 令牌 = 150，但**全 UI 零引用**；
   `collapsible.py:59` 写死 120、`canvas.py:256` 写死 400。改成用令牌，
   并给段落展开/折叠加高度动画（现在是硬切）。

## 追加（2026-09-19，Q42 的遗留）

Q42 把 `SliderSpin` 的滑条和数值框接上了，但它在 `.ok` 里诚实地写了一条没做到的：

> `load_data` 走 blockSignals + setValue 只写 spin，**加载后滑条拇指可停在 0**，
> 直到用户去拖。没改 setValue 去同步滑条，否则 u03d/u04d/u07 静帧拇指会从 0 跳到真值。

用户看到的现象是：打开一个工程，数值框写着 `0.12`，**旁边的滑条拇指却贴在最左边**。
这属于「没有错误但一眼就显得廉价」的那一类，正是这一条任务要解决的东西。

它当时不敢改是对的——改了会让 UI 基线 u03d/u04d/u07 变。**在这一条里一起改**，
因为这一条本来就要动基线、本来就要写 `.stop` 让 Luca 过目。

做法：`SliderSpin.setValue`（以及 `load_data` 那条路径）在写 spin 的同时
用 `blockSignals` 包住 `slider.setValue(...)`，两边都同步，一次信号都不发。

验收：
- `test_q45_slider_thumb_follows_load`：走真面板 `load_data` 一个 `stroke.width_em=0.12` 的工程，
  断言 `sp.slider.value()` 对应 0.12 而不是 0，**并且** `valueChanged` 一次都没发射。
- UI 六例会变（拇指位置），写 `.stop`，在里面说明变的就是拇指位置。
