# Q44 · Q27 在文本侧原样重造了静默失败 #19（P0）

**开工前先读 `docs/plan/queue/_RULES_FOR_EVERY_TASK.md`。**

## 事实

`cutora/ui/panels/property.py:2063-2094 _write_ov_fx` 从 `ov.get("fx")` 起手，
**只更新** `bg.type` / `bg.texture` / `bg.glass_thickness_em` / `fill.colors` / `stroke`。

于是只要一个 text overlay 有了 `fx`（迁移过的老工程，或用户碰过一次面板），
下面这些控件写的扁键，渲染端全都不读：

- 阴影：`ov_shadow_enable / ov_shadow_op / ov_shadow_blur / ov_shadow_spread / ov_shadow_off_x / ov_shadow_off_y`
  （`property.py:2875-2880` 写扁键 → 新路径读 `fx.shadow` → 永不更新。`_write_ov_fx` 全文没有 `fx["shadow"]`）
- 背景：`ov_bg_color / ov_bg_op / ov_bg_rad / ov_bg_pad / ov_bg_pad_x / ov_bg_pad_y /
  ov_bg_fill_type / ov_bg_grad_dir / ov_bg_color2..4 / ov_bg_expand_w / ov_bg_expand_h`
  （`property.py:2862-2874` 写 → `_write_ov_fx` 不回填 → 永不更新）

**Q26 刚刚把这个形状立档成静默失败 #19「面板写的键和渲染读的键各写各的，两边都有代码」，
Q27 在文本侧原样挖了第二个。**

## 还有这些，一并处理

1. **「图片元素」没删干净。** UI 上的段和按钮删了，`text_layer.py:192 strip_image_elements`
   只删子元素；但 `image_element` 整套代码还活着：`ui/canvas.py:447,1474,1653,2170`、
   `property.py:1773-1832,2987`、`render/frame_renderer.py:1589 draw_image_elements`。
   Luca 的原话是「从代码到 UI 都删掉」。
2. **纹理/玻璃只给了三个旋钮。** `property.py:604-616` 只有 `ov_fx_bg_type`（none/box/glass/texture/bubble）、
   `ov_fx_texture`（paper/linen/grid）、`ov_fx_glass_thick`。
   字幕那边已有的玻璃折射/倒角/光泽/光线方向、纹理染色、渐变与高光、五种 blend、四边渐隐
   —— **一个都没接到文本面板**。Luca 要的是「文本也支持字幕里那种高级背景」，
   现在是「支持了三个开关」。
3. **下划线画不出来。** `text_layer_paint.py:127-128` 设 `run.underline = True`，
   `cutora/render/` 里没有任何消费者。工具条的下划线按钮是死控件。
4. **多行富文本 run 偏移逐行错位。** `ui/panels/text_rich.py:208 pos = min(len(text), pos)` ——
   换块（换行）时没有 `pos += 1`，而 `toPlainText()` 每个换行占 1 个字符。
   第一行之后每多一行，runs 的 start/end 就往前错一格。
5. **`text_rich.py:191` 是写死的假分支**：
   `default = editor.currentCharFormat() if False else QTextCharFormat()`。
   因为基准格式永远是空 `QTextCharFormat`，`_overrides_from_format` 会给**每一个 fragment**
   都吐 overrides。结果：用户敲一个字，整段就被写成 runs，overlay 立刻从旧渲染路径跳到新路径。
6. `text_layer.py:280` 的 `_para_spacing` 写进 style 后全仓无人读 —— 面板「段间距」是死控件。
7. `property.py:542-543` `ov_rich_edit_btn.setVisible(False)` 之后全仓无 `show()`。
8. `text_rich.py:188 cursor = QTextCursor(doc)` 定义后未使用。

## 要做的

**先做键路闭合，再做功能扩充。** 两条路线二选一，选了就彻底：

- **路线 A（推荐）**：删掉文本面板上所有扁键控件，全部换成写 `fx.*` 的控件，
  和字幕面板用同一套 `fx_fields.mount_*` 函数。这样文本和字幕天然共享效果器，
  Luca 要的「文本支持字幕里那种高级背景」自动成立，而不是一个个补旋钮。
- **路线 B**：`_write_ov_fx` 补齐全部字段的双向回填。这条路线要写一张
  「扁键 ↔ fx 路径」的映射表，并加测试证明每个控件都在表里。

选 A 的话，`overlay_fx_from_legacy`（`text_layer.py:74-95`）要能把老工程的扁键完整折算过去，
不能只折算一次阴影。

其余 1–8 条按上面列的逐条处理。第 1 条「图片元素彻底删除」要连
`frame_renderer.draw_image_elements`、序列化、canvas 的命中测试一起删，
并加一条测试断言全仓库 grep 不到 `image_element`。
