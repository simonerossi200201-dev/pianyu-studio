# Q107 · 拼接支持全语种：自动检测 + MMS 兜底对齐

**开工前先读 `_RULES_FOR_EVERY_TASK.md`、`cutora/asr/engine.py`（`ALIGN_MODEL_BY_LANG`、
`get_align_model`、`_load_hf_align_model`）、`cutora/asr/models.py`（`align_row_for_language`）、
`cutora/asr/languages.py`（`picker_entries` / `whisper_language_arg`）、
`cutora/ui/detect_confirm.py`，以及 `cutora/ui/home_stitch.py` 的 `_fill_languages`。**

## Luca 要什么

「我希望这个能支持全语种，包括但不限于亚美尼亚语等等。」

## 现状（Claude 已核过，别重新摸一遍）

零件其实都在，缺的是接线：

- `resources/data/languages.json` 有 **100 种语言**（faster-whisper 的全集），
  亚美尼亚语 `hy` 在里面，`script: armenian`、`subtitle_tier: font_only`。
- `resources/fonts/Noto_Sans_Armenian` 已入库，所以亚美尼亚字母**能画出来**。
- `resources/data/align_models.json` 有 **30 条**，其中
  **`align-mms` = `MahmoudAshraf/mms-300m-1130-forced-aligner`**，`language: null`、`enabled: true`，
  而且**已经下载在 `runtime/models/align_mms/`**。这是覆盖 1130 种语言的强制对齐器。
- `cutora/ui/detect_confirm.py`（检测结果确认框）和 `picker_entries()`（完整语言选择器，
  第一项就是「自动检测」）都已经存在，主窗口在用。

**缺的三处**：

1. `get_align_model()` 只认 `ALIGN_MODEL_BY_LANG`（en/it）和
   `align_row_for_language(lang)`。MMS 那一行 `language` 是 `null`，
   所以**永远不会被当兜底选中** —— 没有专用对齐器的语言就直接抛 `FileNotFoundError`。
2. 拼接是**先按选定语言把对齐模型加载好，再开始转写**
   （`AnalyzeWorker` 收的是已经建好的 `get_align` 回调）。选「自动检测」时
   加载那一刻还不知道是什么语言，所以现在根本没法选 auto。
3. `home_stitch._fill_languages()` 把 `en/it/es/fr/pt/de` 六个写死了。

## 第 0 步：先做探针，结果决定后面怎么写（不许跳过）

`MahmoudAshraf/mms-300m-1130-forced-aligner` 是 CTC 强制对齐器。它的词表是
**罗马化**的 —— 官方用法要先把非拉丁文字过一遍 `uroman`。所以在动手之前，
先写一个探针 `tools/_diag/q107_mms_probe.py` 并把**原样输出**写进报告：

1. 用 `whisperx.load_align_model(language_code=..., model_name=<align_mms 目录>,
   model_dir=<同一目录>, device=...)` 分别尝试 `hy`（亚美尼亚，非拉丁）、
   `vi`（拉丁带附加符）、`ja`（日文）三种，记下能不能加载、报什么错。
2. 能加载的话，拿一段真实音频 + 对应文字跑一次 `whisperx.align`，
   看返回的词级时间戳是不是单调、是否落在音频时长内。
3. 结论只可能是三种，照实写：
   - **A. 直接可用** → 按下面第 1–3 节做，兜底链接上 MMS。
   - **B. 需要罗马化** → **停下写 `.stop` 报 Claude**。`uroman` 是新依赖，
     而 `requirements.lock` 是带 `--require-hashes` 锁死的，加依赖要 Luca 拍板。
     不许自己 pip install，也不许把非拉丁语言偷偷降级成「按字符均分时间」。
   - **C. 加载不了** → 同样停下报 Claude，写清报错原文。

## 1. 对齐模型的兜底链

`cutora/asr/engine.py` 的 `get_align_model(language)` 改成一条明确的链，
每一级都在日志里写明走了哪条：

1. `en` / `it` —— 包里冻结的本地模型（现有行为，**一个字节不许变**）。
2. `align_row_for_language(lang)` 且 `enabled` 且已就绪 —— 专用对齐器
   （de/es/fr/pt/nl/uk/cs/ru/pl/hu… 这 30 条里带 language 的那些）。
3. **MMS 兜底**（探针结论是 A 时才做）：拿 `align-mms` 那一行，
   `language_code` 传检测到的语言。加载失败就往下走。
4. 都没有 → 抛一个**人话**异常：说清是哪种语言、缺什么、可以怎么办
   （换一个已备好的语言，或去模型页下载该语言的对齐器）。
   现在那句 `FileNotFoundError("No enabled align model for %s")` 用户看不懂。

`has_local_align_model()` 跟着改：MMS 在本地且可用时，**所有语言都算有**。
它是界面上「这个语言能不能拼」的判据，别让它和实际加载逻辑说两套话。

## 2. 拼接支持「自动检测」

核心改动：**对齐模型改成用到才加载**。

- `AnalyzeWorker`（`script_stitcher.py:2908` 起）现在收一个已建好的 `get_align`。
  改成收一个**按语言取对齐模型的可调用对象**，在拿到第一个片段的语言之后才调用，
  并按语言缓存（`engine._ALIGN_CACHE` 已经是按 `(lang, device)` 缓存的，别再造一层）。
- 语言为 `auto` 时：转写第一个片段时 `language=None`
  （`whisper_language_arg` 已经会把 auto 变成 None），
  从 faster-whisper 的 `info.language` / `language_probability` 拿检测结果。
  - **置信度 < 0.6** → 走现成的 `detect_confirm.py` 让用户确认，**不要自己猜**。
  - 确认或高置信度之后，把这个语言**定给整批**，不要每个片段各检测各的
    —— 同一次拼接里混着不同语言的可能性远小于误判的代价。
- 这一段的日志要写清：检测到什么、置信度多少、用了哪个对齐器。

## 3. 首页那个下拉

`home_stitch._fill_languages()` 删掉写死的六个，改成用 `picker_entries()`：
「自动检测」排第一并**设为默认**，后面按 `common` / `all` 两组，
沿用 `picker_label()` 已有的「· 字幕排版：完善 / 仅字形保证」标注。
下拉宽度和现在一样（`setMaximumWidth(220)` 不动），条目多了就让它自己滚。

选了一个既没有专用对齐器、MMS 也不可用的语言时，「开始拼接」旁边的状态行
当场提示，而不是等跑到一半失败。

## 4. 诚实地标出边界（这一节必须写进报告）

**不许把「全语种」说成无限**。报告里给出一张表，逐条写清：

- 转写的天花板是 **faster-whisper 的 100 种**（`languages.json` 的条数）。
  这 100 种之外的语言，MMS 能对齐也没用 —— 没有转写就没有可对齐的词。
- 这 100 种里，哪些有**专用对齐器**、哪些只能走 **MMS**、哪些**两者都没有**。
- 字幕排版：`subtitle_tier` 是 `complete` 的有完整断行规则，
  `font_only` 的只保证字形画得出来（亚美尼亚语就是这一档 —— `Noto_Sans_Armenian` 已入库）。
  逐个语言去核字体覆盖太贵，**按 script 核一遍**即可：
  `resources/data/font_script_coverage.json` 里每种 script 至少有一个字体覆盖，
  缺的列出来。**不许为了补覆盖去加字体** —— 只有已入库的 OFL/Apache 字体能用。

## 测试 `tests/test_q107_all_languages.py`

每条都要能说明「改之前是红的」：

1. `get_align_model` 的兜底链：打桩让专用对齐器不可用，
   断言它去拿了 `align-mms` 那一行（探针结论是 A 时）。`en`/`it` 仍走冻结路径，
   调用参数与改前逐字相同。
2. 全都没有时抛的是人话异常，消息里含语言名和「怎么办」。
3. `has_local_align_model("hy")` 在 MMS 就绪时为 True，MMS 被禁用时为 False。
4. `whisper_language_arg("auto")` 是 None（现有行为的护栏）。
5. 自动检测：假 worker 返回 `info.language="hy"`、概率 0.95 →
   对齐模型按 `hy` 取，且**整批只取一次**（断言加载函数只被调一次）。
6. 概率 0.4 → 走确认框（打桩断言被调用），用户改选 `en` 后按 `en` 加载。
7. 首页下拉第一项是「自动检测」且是当前项；条目数等于 `picker_entries()` 的条数。
8. 选一个没有对齐器的语言，状态行出现提示且「开始拼接」不可点。
