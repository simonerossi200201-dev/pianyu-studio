# Q82 · 素材存盘缺口：透明通道、代理路径、静音、动图长度

**开工前先读 `_RULES_FOR_EVERY_TASK.md` 和 `_RULES_UI_OWNERSHIP.md`。每做完一个子项就提交。**

## 用户原话

> 不管用户从外部或主界面加载了任何素材，都要在保存工程的时候完整的全部保存到位。

「图片重开就没了」那一条的主因已经由 Claude 修掉（`81131c2`：打开工程时 Q27 的迁移删掉了图片层里的图片）。
但顺着查下去，**GUI 存盘这条路还有一批字段没存**，属于同一类问题：

## 缺口清单（已查清）

用户存盘走 `command_bodies.py:170-172` → `main_window.py:5885 collect_project_data`，加载走 `apply_project_data`。
对照 `project_io._RJ_CLIP_KEYS`（`:360-373`，导出子进程用的那套），GUI 这边漏了：

- **`_serialize_clip`**（`main_window.py:5914-5933`）及加载端（`:6106-6117`）缺：`alpha`、`alpha_mode`、`size_mode`、`fade_top/bottom/left/right`。
- **sources**（`:5982-5988`）只存了 id / path / duration / has_video / has_audio，**缺 `alpha`、`alpha_mode`、`preview_path`**。
  后果：资产库或拖放进来的**透明视频重开后丢透明通道**（`assets/user.py:395-431`、`main_window.py:4611-4623`）。
  这直接违背 Luca 的要求「必须完美支持带透明的 GIF 和达芬奇导出的 mov」。
- **`Track.mute`** 不存盘。
- **`clip._match_target_dur`** 不存盘 → 批量加载放进去的动图 clip 重开后长度缩回。
- **批量加载遇到动图（gif/webp）时**，`script_insert_image.py:905-933` 把它放成**图片轨上的 Clip**，
  但时间线只画图片轨上的 overlay（`widget.py:1926`），渲染也只处理 type=="video" 的轨道（`track_guard.py:135`）
  —— **这种 clip 根本看不见，和存不存盘无关**。改成放到视频叠加轨上（和 Q61 资产库的做法一致）。

## 做法

1. **根治思路**：GUI 存盘和 `project_io` 用**同一张字段表**，不要两份各写各的——这正是这些字段会漏的原因。
   把 `_RJ_CLIP_KEYS` 这类表提到一个共享位置，`_serialize_clip` / `_serialize_track` / sources 都从表里取。
2. 补齐上面每个字段的存与读。
3. 动图改放视频叠加轨。

## 验收（修前必红）

  clip 带 fade 四边和 size_mode、静音轨、`_match_target_dur` 的动图），**走真实存盘命令 → 真实打开命令**，
  逐字段断言相等。

  clip / source / track 的字段集合相同。这一条从结构上防止以后再漏。
- `test_q82_batch_gif_visible`：批量加载一个动图，整帧导出，画面上能看到它。
