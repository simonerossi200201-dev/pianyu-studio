# Q96b · 在 Windows 上复核 Q96（Claude 亲手改的那一批）

**开工前先读 `_RULES_FOR_EVERY_TASK.md`，再读 `docs/plan/reports/Q96.md`。**

Q96（提交 `0b3a7ac`）是 Claude 亲自写的，只在 Linux 隔离环境里验过。
这条任务**只做复核，不做新功能**。

## 要做的事

1. 跑新增的五个测试文件（它们已登记进 `tests/qt_isolate.py`）：

   - `tests/test_q96_scatter_sources.py`
   - `tests/test_q96_scatter_dialog.py`
   - `tests/test_q96_missing_report.py`
   - `tests/test_q96_karaoke_no_words.py`
   - `tests/test_q96_bin_menu_order.py`

2. 跑 `tests/test_t03c_polish.py`（Q96 改了两条逐字断言）、
   `tests/test_cli_describe_compat.py`（Q96 给 `scatter_broll` 只**新增**了 `clips` 一个参数，
   `clips_dir` 的 `required` 和 `desc` 一个字都没动 —— 如果这条红了，说明改动越界了，要改回去）。

3. 跑 `tests/test_q93_bg_size.py::test_q93_bg_fit_text_matches_old_bytes`。
   这条在 Linux 上 md5 对不上（`bd6e16a1…` vs `8a063bb5…`），但把 Q96 的改动摘掉后
   md5 一模一样，所以判定是平台字形栅格差异。**在 Windows 上它必须是绿的**；
   如果在 Windows 上也红，那就是 Q96 引入的，写 `.stop` 报 Claude，不要自己改基线。

4. 跑 `tools/golden_check.py --all`。Q96 的 `layout.py` 改动只在
   「这一段没有逐词时间戳」**且**「这套 fx 里有按词走的动画」时才生效，
   Claude 扫过所有 golden 工程，没有一个命中这个组合，所以预期是 PASS 且 `source_dirty=no`。
   **golden 红了一律停下报 Claude，不许重录。**

5. `tools/ui_golden.py --all`：`u04e` / `u08b` 的变更是 Q93 记下的、还没获批的那两条，
   本条任务里**照旧不许重录**，照抄进报告即可。Q96 没有动检查器布局，
   如果除这两条之外还有别的用例变了，停下报 Claude。

## 允许你改什么

- 如果某条 Q96 新测试在 Windows 上因为**测试自身**的毛病红了（路径分隔符、
  offscreen 平台、`QApplication` 复用之类），可以修测试，但要在报告里写清原因。
- **产品代码一律不许动**。Q96 的产品行为如果在 Windows 上不对，写 `.stop` 报 Claude。

## 收尾

报告写到 `docs/plan/reports/Q96b.md`：每个测试文件的通过条数、
`golden_check` 与 `ui_golden` 的原样输出、以及你改了什么（没改就写没改）。
