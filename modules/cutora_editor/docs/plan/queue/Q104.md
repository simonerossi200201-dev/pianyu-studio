## 版面

`welcome.py` 现在是：品牌行 → 中段两列（左：操作面板；右：最近项目）→ 底部三卡。

新版：**在中段和底部三卡之间，插入一条通栏的「片段智能拼接」带**。

- 中段两列原样保留，只是高度让出来一部分。中段与新带之间用 `QSplitter`（竖向），
  比例存盘，用户可以自己调。
- 新带最小高度 260 px；整页在窗口不够高时可以滚动（现在没有滚动，要补 `QScrollArea`，
  **但不许因此改变现有控件的尺寸策略**）。
- 新带内部横向两块：
  - **左 2/3：投放与清单**
  - **右 1/3（固定 300–340 px）：参数与开始**

### 左：投放与清单

空态：整块是一个圆角虚线框，中间一行大字
「把要拼接的视频或文件夹拖到这里」，下面一行小字
「支持多个文件夹；一个文件夹就是一组」，再下面一排两个次级按钮
「选择文件夹…」「选择视频…」。

拖放要同时吃三种：**单个/多个视频文件**、**单个文件夹**、**多个文件夹**。
（`dropEvent` 里对 `urls` 逐个判断 isdir / isfile，不要只认第一个。）

有内容后变成一张清单表，每行一组：

| 列 | 内容 |
|---|---|
| 组 | 组名（文件夹模式下就是文件夹名） |
| 片段 | 这一组有几条视频 |
| 文案 | ✓ 已有 / ✗ 缺 / — 未粘贴 |
| 来源 | 文件夹名，tooltip 是完整路径 |

表上方一行：「共 N 组 · M 条素材」+「移除选中」「清空」。
行双击 = 在资源管理器里打开那个文件夹（复用 Q96 的 `reveal_in_explorer`）。

### 右：参数与开始

**默认只露这些**，其余收进一个「更多设置」折叠区：

- **分组方式**：分段控件「按文件夹 / 按文件名前缀」。
  **本入口默认「按文件夹」**（这是 Luca 要的零门槛路径）。
  旧对话框的默认不变，仍是按前缀。
- **语言**：下拉（沿用 `cmb_lang` 的取值来源）。
- **「粘贴文案」**大按钮 → 弹出粘贴面板（见下）。按钮上带角标显示「已填 N / 共 M 组」。
- 主按钮 **「开始拼接」**，下面一行状态文字。

「更多设置」里放：尾部留白（`spin_pad`）、裁剪开头空白（`chk_head`）、
切口落在静音处（`chk_edge`）、括号里的经文出处不算缺失（`chk_ignore_refs`）、
以及**仅前缀模式下**才启用的两个命名前缀输入框。

不许把旧对话框那一大堆东西原样搬过来堆在首页 —— Luca 要的是「简约但更好操作」。

### 粘贴文案面板

复用 `PasteTable`（`script_stitcher.py:3433`），**不许重写一个**。
弹出时按当前清单里的组预填「组」这一列，用户 Ctrl+V 一次把 Sheet 那一列贴进来。
关掉后回到首页，清单的「文案」列立刻更新。

## 流程

点「开始拼接」之后：

1. 先跑现有的**拼接前体检**（`StitchDialog._start` 里那段逐文件验头的闸门）。
   不合格的素材照现在的方式拦下来，别跳过。
2. 进度**内联显示**在这一带里（一条细进度条 + 一行当前状态），
   **不要再弹一个窗口**。旁边给一个「详细日志」链接，打开 Q102 的控制台窗口。
3. **有缺漏文案**：把这一带换成结果视图 —— 列出缺哪几组，
   下面两个按钮「打开缺失清单所在文件夹」（复用 Q96 的
   `missing_report_dirs` / `find_missing_report` / `reveal_in_explorer`，**不要重写**）
   和「补好了，重新检查」。**不许**在这种情况下往下走去建时间线。
4. **没有缺漏**：照旧编码 + 建时间线，完成后**切到主编辑窗口**，
   时间线已经拼好、字幕已经在上面 —— 和现在用对话框跑完的结果**完全一致**。

## 最大的风险：不许出现第二套拼接逻辑

旧对话框和新入口**必须共用同一套编排代码**。做法：把 `StitchDialog` 里
「体检 → `AnalyzeWorker` → `_on_analyzed` → 编码 → 建时间线」这条链抽进
`cutora/batch/stitch_session.py`，做成一个不依赖任何具体窗口的对象
（输入：文件夹/文件列表、参数、文案；输出：信号 progress / log / missing / done / failed）。
旧对话框改成调用它，新入口也调用它。

**旧对话框的行为必须一个字节不变** —— 抽取是纯重构，不是重写。
现有那几条拼接测试（`test_script_stitcher_edge.py`、`test_bug06_07_stitcher.py`、
`test_t25_stitch_ux.py`、`test_stitcher_duplicate_sentence.py` 等）必须全绿。

## 第二个风险：别把启动拖慢

`script_stitcher.py` 在模块顶层 `import numpy`、`from cutora.asr.engine import whisperx`
（:46-59）—— 这是几秒级的开销。`welcome.py` **绝对不许在模块顶层 import 它**。
所有对 `script_stitcher` / `stitch_session` 的 import 都写在函数里，
只有用户真的拖了东西或点了开始才触发。

`tests/test_startup_order.py` 是现成的护栏，**再加一条**：
构造 `WelcomePage` 之后，`sys.modules` 里**不许**出现 `cutora.batch.script_stitcher`
和 `whisperx`。
