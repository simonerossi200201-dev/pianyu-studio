# Q110 · 导入和点选不许卡界面：探测挪到后台 + 结果缓存

**开工前先读 `_RULES_FOR_EVERY_TASK.md`。这一条的前置是「不弹黑框」那次扫尾
（`cutora/core/proc.py` 的 `_no_window_run` / `_no_window_popen` 已经铺到全仓，
不要再往回改）。**

## Luca 的原话

「从时间线上导入视频，也是先卡顿一下，再扔两个黑框晃眼，然后才导入进来视频，超级超级慢。
我希望的是，点击导入的瞬间马上导入，软件全程流畅没有丝毫卡顿，也不会弹出任何的黑框来晃眼。」

黑框那一半已经解决（53 处裸 subprocess 全部换成不开控制台的版本）。
**这一条解决剩下的一半：卡顿。**

## 根因（已确认的部分）

导入一条视频和点选一条视频时，软件会**在界面线程上同步**调用 ffprobe / ffmpeg：
媒体探测（时长、分辨率、流信息）、文件头体检（`batch/media_guard.py`）、
时间线缩略图（`ui/timeline/thumbs.py`，**每张缩略图一次 ffmpeg**）、
波形（`audio/waveform.py`）、动图探测（`media/animated.py`）。
外部程序返回之前，界面是真的僵住的。

## 第 0 步：先量，别猜

写 `tools/_diag/q110_import_profile.py`，量出**导入 10 条真实视频**和**点选其中一条**
这两件事各自：

1. 一共起了多少个外部进程，分别是谁、各自耗时多少（按调用点分组）。
2. **界面线程被阻塞的总毫秒数**和**最长的一次连续阻塞**。
   用 `QApplication` 的事件循环打点（比如一个 16ms 的 QTimer，记录实际间隔，
   超过 50ms 的都算一次卡顿并记下当时的调用栈）。
3. 哪些探测是**重复的**（同一个文件被 ffprobe 了几次）。

把原样数字写进报告。**这三个数就是这条任务的验收基准**，改完要再量一遍对照。

## 要达到的目标

- **点击导入的那一刻，界面立刻有反应**：条目马上出现在列表/时间线上，
  哪怕时长、缩略图还是占位符，随后再填进去。
- 导入 10 条视频的过程中，**界面线程最长一次连续阻塞 ≤ 100ms**，
  期间可以正常点别的东西、可以滚动。
- 同一个文件在一次会话里**不许被重复探测**。

## 做法（方向，具体实现你定，但这几条是硬要求）

1. **探测挪到后台线程池**。`QThreadPool` + `QRunnable`，或者已有的 worker 模式 —— 
   **跟现有的 ASR / 导出 worker 用同一套线程管理**，不要再造一个新的并发模型。
   结果通过信号回主线程更新界面。
2. **占位先行**：任务条目先用文件名建出来，时长显示「读取中…」，
   缩略图用一个占位图。探测回来再就地更新，**不许整表重建**（会闪）。
3. **探测结果缓存**：按「路径 + mtime + 大小」做键（`audio/waveform.py` 里
   已有 `file_fingerprint` / `fingerprint_key`，**复用它，不要另起一套**），
   存进 `user_cache_dir()`。同一个文件第二次导入直接命中。
4. **缩略图按需生成**：只给**当前视口里可见的**那些片段生成，滚动到才补。
   现在是一次性全生成。
5. **合并探测**：一次 ffprobe 能一起拿到的信息（时长 / 分辨率 / 帧率 / 流），
   就不要分几次调。第 0 步的「重复探测」那一项会告诉你哪里在浪费。
6. **文件头体检**（`media_guard`）也挪到后台。它现在是导入时逐个文件同步跑的。
   体检没过的条目在列表里标红并说明原因，而不是卡住整个导入。

## 不许做的

- **不许为了快就把体检或探测删掉。** `media_guard` 是 2026-08-23 那次
  「两个 JPG 当成 mp4 收进来，最后少了两条成品还一个字没提」的补丁，它必须还在，
  只是改成后台跑 + 界面上标出来。
- 不许把探测结果写进工程文件当缓存（工程要能换机器打开）。
- 不许引入新的并发库。线程池用 Qt 自带的。
- 不许改 CRF / preset，不许加「快速模式」。

## 测试 `tests/test_q110_import_async.py`（要 Qt 的登记进 `qt_isolate`）

每条都要能说明「改之前是红的」：

1. **界面不阻塞**：打桩让每次探测睡 200ms，导入 5 个文件，
   断言主线程事件循环在整个导入过程中**最长一次间隔 < 100ms**。
   改之前这条必红（5 × 200ms 全压在主线程上）。
2. **占位先行**：导入后立即断言 5 个条目都已存在，且时长字段是占位值；
   等探测信号跑完后再断言时长是真实值。
3. **缓存命中**：同一个文件导入两次，探测函数只被调用一次。
   改 mtime 之后再导入，被调用第二次。
4. **缩略图按需**：时间线里放 50 个片段但视口只看得见 6 个，
   断言生成缩略图的调用次数 ≤ 视口内片段数 + 少量预取（写明预取几个）。
5. **体检仍在**：放一个伪装成 .mp4 的 JPG，断言它被标出来且不进时间线，
   同时**其余正常文件照常导入完成**（改之前是整批卡住或静默跳过）。
6. **回归**：导入完成后 `tasks` 的内容（路径、时长、尺寸）与改前逐字段相同。
