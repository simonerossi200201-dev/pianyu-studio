## 这是什么
里程碑 **T31 调色系统**。和 Q31 关键帧并列的「深水区」第二条。

## 现状
`render/frame_renderer.py` 只有 `blend_mode` 和 `opacity`，**没有任何色彩校正**。
导出管线是 `BGRA numpy → QImage → ffmpeg rawvideo`（见 `PROTECTED_INVARIANTS.md` 第 1、2 条），
调色要插在**合成之后、写管道之前**，而且**不许碰那两条不变量**。

## 要做

### 1. 一级调色（clip 级 + 轨道级 + 工程级，三层叠加）
参数（每层同一组，按 clip → 轨道 → 工程顺序叠加）：

| 组 | 参数 |
|---|---|
| 曝光 | `exposure`（-2..+2 EV）、`contrast`、`pivot` |
| 色彩 | `temperature`（开尔文偏移）、`tint`（绿/品红）、`saturation`、`vibrance` |
| 色轮 | `lift / gamma / gain`，每个是 RGB 三通道 + 亮度，共 12 个数 |
| 曲线 | RGB 主曲线 + R/G/B 三条，各 ≤ 8 个控制点 |
| HSL 限定 | 6 个色相段（红/橙/黄/绿/青/蓝/品红）各自的 H/S/L 微调 |

**实现要点**：
- 全部在 **float32 线性光**里算，进出各做一次 sRGB ↔ 线性转换。在 8-bit sRGB 上直接乘会断色阶。
- 用 numpy 向量化，**不许逐像素 Python 循环**。
- 整条链路合成成**一个 3D LUT（33³）**缓存起来 —— 参数不变时每帧只做一次查表插值，
  这是性能的关键。参数变了才重建 LUT（重建 ~10ms，可接受）。
- 预览和导出**必须用同一个 LUT 构造函数**。

### 2. LUT 支持
- 导入 `.cube`（33/65 级），作为「创意调色」层放在一级之后。
- 强度滑条 0–100%（和原图混合）。
- **只读已入库的或用户自己的 LUT，不内置任何来路不明的 LUT 文件**（许可问题）。

### 3. 示波器（这是专业不专业的分水岭）
预览区可切换：波形图（亮度 / RGB parade）、矢量示波器、直方图。
用缩小到 1/4 分辨率的帧算，**每 3 帧更新一次**，不许拖慢预览。

### 4. UI
按 Q25 的检查器规范。色轮用圆形控件（拖动改色偏、外圈滚轮改亮度），**不是三个滑条**。

## 性能门禁（这条最硬）
调色**关闭**时，导出 ms/帧相对现在涨幅 **< 1%**（关掉就该是零成本）。
调色**开启**时（一级全开 + 一个 LUT），涨幅 **< 12%**。超了就停下报 Claude，别硬上。
贴 720×1280 的实测表进 `docs/plan/reports/Q32_调色性能.md`。

## 门禁
- `test_q32_linear_light`：曝光 +1 EV → 线性光下亮度**正好翻倍**（±1%），不是 sRGB 值翻倍
- `test_q32_lut_equals_direct`：LUT 查表结果与直接逐像素计算的最大偏差 ≤ 1/255
- `test_q32_three_layers`：clip/轨道/工程三层各加 +0.3 饱和 → 结果等于三次叠加，顺序固定
- `test_q32_cube_import`：导入一个已知的 identity `.cube` → 输出与输入逐字节相同
- `test_q32_bypass_is_bitexact`：所有参数归零 → 渲染结果与调色系统上线前**逐字节一致**
- `test_q32_scope_downscale`：示波器用的是 1/4 分辨率帧，且不阻塞预览线程
- golden 十二例：调色默认全关 → **必须逐字节不变**。变了说明 bypass 不干净，停下报 Claude
