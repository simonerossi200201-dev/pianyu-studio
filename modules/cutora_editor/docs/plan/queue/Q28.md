## 要做

### 1. 数据从哪来（不许新开采样线程）
- **播放帧率**：预览已有 `PreviewClock` 和每帧合成入口（`preview/engine.py frame_at`）。
  在合成入口记一个环形缓冲（最近 30 帧的时间戳），帧率 = `30 / (t_last - t_first)`。
  `logs/preview_perf.jsonl` 已经在记预览性能了，**复用它的采样点**，不要新加一套。
- **导出帧率**：`render_worker` 已经每 30 帧 `self.progress.emit(...)`。
  在那里顺带算 `帧数 / 已用秒`，通过一个新信号或 progress 的扩展字段发给 UI。
  并行导出时，各 worker 的进度文件里已经有 `done/cur`，**加一个 `fps` 字段**（和 BUG-41 加 `rss_gb` 同一个地方），
  父进程汇总成总帧率。

### 2. 外观
状态栏最左侧一个小胶囊，**只在有数据时出现**，没数据时完全不占位：

```
 ⏵ 29.9      （播放中，绿色=接近目标帧率，黄色=掉到 80% 以下，红色=低于 50%）
 ⏺ 41.2      （导出中）
```

- 字号用 `font_sm`，颜色用 `ok / warn / err` token，**不许写死颜色**。
- 数字用等宽字体，宽度固定（`min-width` 按 "88.8" 量），避免跳动时状态栏抖动。
- 悬停 tooltip 显示细节：「预览 29.9 fps（目标 30）· 最近 30 帧」/「导出 41.2 fps · 已 1234/5484 帧 · 预计剩余 1 分 42 秒」。
- 数字**每 0.5 秒最多刷一次**（不是每帧），否则状态栏刷新本身会吃掉性能。

### 3. 不许做的
- 不许因为要显示帧率就在渲染热路径里加计时以外的任何东西
- 不许在导出时让 UI 线程去读文件算帧率（走已有的心跳/进度通道）
