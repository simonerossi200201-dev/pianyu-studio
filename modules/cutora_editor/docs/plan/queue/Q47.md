## 为什么要做这一条

这是整次审计最重要的一条。Luca 的原话是「多数时候算是合格，但达不到优秀」。
机制是这样的：

`tests/test_t25_inspector.py:65-83` 的 `test_t25_no_hardcoded_px`，检查范围**硬编码为两个文件**：

```python
for rel in (
    os.path.join("cutora", "ui", "widgets", "inspector.py"),
    os.path.join("cutora", "ui", "panels", "fx_fields.py"),
):
```

正好是 Q25 碰过的两个文件。QSS 模板里 338 个裸 px、`subtitle_style.py`、`property.py`、
`main_window.py` 全部不在检查范围。

`test_t24_toggle_uniform` 的文档字符串写「六个新胶囊与已有四个一致」，
但循环体只遍历 `SIX_CAPSULES` —— 另外 **17 个 `labeled_toggle` 从未被检查**。

**质量成了「上一个任务的局部属性」，不是全局不变量。**
每个任务都合格，应用整体持续漂移 ——
**每一次都合格，是因为每一次的及格线都是现划的。**

## 要做的

新建 `tests/test_ui_invariants.py`，**全部扫描 `cutora/ui/**.py` 与渲染后的 QSS，
不写任何文件白名单**。允许有一张 `KNOWN_EXCEPTIONS` 表，但每一条都要写清理由和到期计划，
并且断言这张表**只减不增**（把当前数量写死，多一条就红）。

| 测试 | 断言 |
|---|---|
| `test_spacing_grid` | 所有 `setSpacing`/`setContentsMargins` 字面量 ∈ {0,1,2,4,6,8,12,16,24,32} |
| `test_no_literal_px_in_qss` | 渲染后 QSS 无非令牌 px |
| `test_radius_closed_set` | 全应用圆角（含 `drawRoundedRect`）∈ 4 个 RADIUS 令牌 |
| `test_type_scale_closed_set` | 所有 `setPixelSize`/`font-size` ∈ 6 级字号 |
| `test_type_hierarchy` | 段标题**实渲染**字号 > 行标签（`QFontMetrics` 实测） |
| `test_control_height_uniform` | 同类控件 `sizeHint().height()` 在所有面板中相等 |
| `test_all_interactive_have_four_states` | 每个可交互类都有 hover/pressed/focus/disabled |
| `test_contrast_all_surfaces` | fg0/fg1/fg2 × bg1/bg2/bg3 + ok/warn/err × bg1/bg2，六套主题全跑 |
| `test_toggle_uniform_all` | 面板里**所有** ToggleSwitch（不是六个），且用令牌而非字面 36/20 |
| `test_theme_switch_repaints_all` | 切每套主题后截图，不存在不属于该 palette 的主导色 |
| `test_no_unreachable_code` | AST 扫 `cutora/`，函数里 `return` 之后不许还有语句 |
| `test_no_dead_written_keys` | 面板写入的键集合 − 渲染读取的键集合 = 空（见下） |

**`test_no_dead_written_keys` 是这一条里最值钱的。** 做法：AST 收集
`cutora/ui/panels/**` 里所有 `self.current_data[k] = ...`、`style[k] = ...`、
`nested_set(fx, path, ...)` 的键/路径；AST 收集 `cutora/render/**` 里所有
`style.get(k)` / `d.get(k)` / `take_known(...)` 的键；断言差集为空。
这一条一次性根除静默失败 #18 和 #19 两类，也就是这个项目反复吃亏的那一类。
