# Q46 · 设计令牌扩容 + 默认主题对比度（P0）

**开工前先读 `docs/plan/queue/_RULES_FOR_EVERY_TASK.md`。**

先说清楚：`cutora/ui/theme/tokens.py` 是一份认真的令牌表，
`theme_dark.qss.j2` 里**硬编码颜色 0 处** —— 这部分不要推翻，要做的是扩容 + 上强制力。

## 事实

**令牌只覆盖一座孤岛。** 全 UI 引用 `SPACE_*/RADIUS_*/FONT_SIZE_*` 共 **20 处**
（其中 8 处集中在 `fps_meter.py` 一个文件）；同期字面量 `setSpacing`/`setContentsMargins`
**157 处**（`property.py` 32、`main_window.py` 30、`subtitle_style.py` 15、`welcome.py` 13……）。
实际在用 **12 种间距值，6 种（2/3/6/10/14/26）不在声明的 8pt 栅格上**。

**QSS 的像素只有 14% 模板化。** 裸 px **338 处**，去掉 73 个 `1px` 边框后，
其余 265 处中 **127 处（48%）不在 4 栅格上**（取值 2/3/5/6/7/10/11/14/18/22/26/30/70）。

**圆角在用 12 种**（0/1/2/3/4/5/6/7/8/11/12/14），令牌只定义 3 种（6/10/14）。
而**用得最多的两种恰恰都不是令牌**：`4px` 17 次、`8px` 15 次；
`RADIUS_CARD`(10) 作为字面量一次都没出现过。**令牌值脱离实际所以被绕过。**

**排版层级是倒置的。** `inspector.py:630` 给段标题设 13px，
但 QSS `:757` `QLabel#dockSectionTitle { font-size: 11px }` 覆盖了它
（Qt 里 QSS 的 font-size 覆盖 setFont），而行标签 `:783` 是 12px ——
**段标题比它自己管辖的行标签还小**，只靠 `font-weight: 600` 撑住。
`UI_INSPECTOR_SPEC.md:46` 承诺的 13px 被 QSS 悄悄推翻，没有任何测试比较这两个值。
字重词汇也是双份：`bold` 12 处、`600` 5 处、`normal` 4 处、`400` 2 处。

**同类控件尺寸各报各的**：方形按钮 20/22/28/32 四种，输入控件 `min-height` 20/22/24/26/28/30 六种，
图标 14/16/18/72 四种。检查器里紧邻的四个元素是四种高度：色块 28、重置 24、段头 28、输入框 22。

**出厂默认主题的对比度是六套里垫底的**（用仓库自带的 `contrast.py` 算的）：

| 配对 | roma-gold（默认） | graphite | midnight-blue |
|---|---|---|---|
| `line` on `bg1` | **1.37** | 1.53 | 1.93 |
| `fg2` on `bg2` | **3.29** | 3.62 | 4.00 |
| `err` on `bg2` | **3.31** | 3.99 | 3.75 |

`line` 在 1.37:1 下**根本看不见**，所以 `UI_INSPECTOR_SPEC.md:53` 承诺的
「段间靠底边细线划分」没有落地，段落是浮空的 —— Resolve 那种「细分隔线分组」的观感缺席。
`fg2` 正是色块旁边那串十六进制小字的颜色（`inspectorHex`），3.29:1。

而守门的 `contrast.py:8-13` 只检 4 对，**全部以 `bg1` 为底**；
`bg2`（输入框/卡片底）和 `bg3`（hover 底）完全不在检查范围 ——
上面所有失败项都发生在 bg2/bg3 上。**门禁被校准成了检查不出真问题的角度。**

**时间线不跟主题走**：`timeline/widget.py:1061-1067` 片段填充硬编码冷色
（`#493955` 紫 / `#3a5a3a` 绿 / `#2f3b4a` 蓝），文字用 `#ffffff` 和 `#e0e0e0`（纯白/中性灰），
而全局 `fg0` 是暖色 `#EFE7DA`。一个自称 "warm black, not pure black" 的暖石色应用，
中间嵌着一块冷蓝紫、打纯白字的时间线。

## 要做的

### 1. 扩容 `tokens.py`

间距承认紧凑档（现在 6px 用了 9 次、2px 用了 7 次，不是纪律差，是**栅格没有合法的紧凑值**）：

```python
SPACE_QUARTER = 2    # 图标与文字、胶囊内缩
SPACE_1  = 4
SPACE_1H = 6         # 合法半步
SPACE_2  = 8
SPACE_3  = 12
SPACE_4  = 16
SPACE_5  = 24
SPACE_6  = 32
```
允许值集合 = `{0,1,2,4,6,8,12,16,24,32}`，10/14/18/22/26/30 一律禁止（就近归 8 或 12）。

行高与控件规格（**当前完全缺失，是「不精密」的首要来源**）：

```python
ROW_H          = 24   # InspectorRow 统一行高
CONTROL_H      = 22   # 所有输入框/下拉/按钮的 min-height，唯一值
CONTROL_H_LG   = 28   # 仅工具栏主按钮
SECTION_HEAD_H = 26
ICON_SM, ICON_MD = 14, 16          # 只留两级
SQUARE_SM, SQUARE_MD = 20, 24      # 只留两级
RESET_PX = 20    # 从 24 降到 20
SWATCH_PX = 24   # 从 28 降到 24，与 ROW_H 咬合
TOGGLE_W, TOGGLE_H = 36, 20
```
模块级 `assert`：`RESET_PX <= ROW_H`、`SWATCH_PX <= ROW_H`、`CONTROL_H <= ROW_H`。

排版拉开层级：

```python
FONT_MICRO = 11; FONT_LABEL = 12; FONT_BODY = 13
FONT_SECTION = 15; FONT_TITLE = 17; FONT_PAGE = 20
W_REGULAR, W_MEDIUM, W_SEMI = 400, 500, 600   # 禁用 "bold"/"normal" 拼法
```
模块级 `assert FONT_SECTION - FONT_LABEL >= 3`。
**并把 QSS 里 `QLabel#dockSectionTitle` 的 `font-size: 11px` 改成 `{{ font_section }}`**，
否则 Python 侧怎么设都无效。

圆角收敛到 4 级，**取当前真实的主流值**（迁移成本最低）：
```python
RADIUS_SM = 3; RADIUS_CTL = 5; RADIUS_CARD = 8; RADIUS_DLG = 12
```

动效：`DUR_FAST, DUR_BASE, DUR_SLOW = 100, 150, 240`，`EASE = OutCubic`。

### 2. 颜色补三个缺口

```python
LINE     = "#524944"   # 旧 #3A302A → 对 bg1 从 1.37 升到 2.01，分隔线终于可见
BORDER   = "#5D5550"   # 新增：控件描边（2.42:1）
FG2      = "#92897F"   # 旧 #7A6F63 → 对 bg2 从 3.29 升到 4.69，hex 标注可读
FG_MUTED = "#7A6F63"   # 旧 FG2 保留，专用于真·禁用态
ERR_TEXT = "#C2736B"   # 新增：错误文字（bg2 上 4.57）
```
六套 palette JSON 都要同步补 `border`/`fg_muted`/`err_text` 三个键
（`_COLOR_KEYS` 会强制校验，漏了直接抛错）。**roma-gold 优先，它是默认且三项垫底。**

### 3. 时间线接主题

`timeline/widget.py:1061-1067` 的片段填充改用 `t.track_video/audio/subtitle` 派生
（同文件 `:102-106` 已经在正确使用轨道色令牌了，片段填充另起一套是遗漏）；
文字从 `#ffffff`/`#e0e0e0` 改成 `fg0`/`fg1`；
悬停边缘 `#F2C14E` 改成 `accent`；`drawRoundedRect(rect, 4, 4)` 改用 `RADIUS_SM/CTL`。

### 4. QSS 生成端强制令牌

在 `tools/build_qss.py`（如果没有就新建）加两道：
- 渲染**前**扫模板源码：出现 `[0-9]+px` 且不在 `{{ }}` 里、值 ∉ {0,1} → 构建失败，报行号。
- 渲染**后**扫输出：`border-radius` ∈ 4 个令牌；`min-height` ∈ {CONTROL_H, CONTROL_H_LG, ROW_H, SECTION_HEAD_H}；
  padding/margin 分量 ∈ 允许集合。

这一条把 338 个裸 px 一次性堵死，而且以后加不进来。

## 追加（2026-09-20）：标签被裁掉一半

用户报的：「有的界面文字被裁切了一半」。根因在这一条的职责范围内。

`inspector.py:790-799`：`setFixedWidth(clamp(row_width * INSPECTOR_LABEL_RATIO, 32, 160))`，
建标签时（`:722-731`）**没有 setWordWrap、没有 elide、没有 tooltip 兜底**，而且 `AlignRight`
—— 超长时 Qt 从**左边**切，于是「毛玻璃模糊强度:」显示成「模糊强度:」。

`main_window.py:2827-2834`：右侧 dock 最小 200 / 最大 420 / 默认 280。
按 12px 字号、汉字 advance 12px 算：dock 280 时标签列只有 69px = 5.8 个汉字，
dock 拖到最小 200 时只有 44px = 3.7 个汉字，**65 条标签里 37 条被裁**。

`INSPECTOR_LABEL_MAX=160` 需要 dock ≈564px 才够得着，**超过 420 的硬上限，是永远达不到的死配置**。

要做：
- 标签列宽改成按**本段最长标签的 `QFontMetrics.horizontalAdvance`** 定（上限仍夹住），
  而不是按行宽的固定比例。中文标签比英文宽得多，按比例算必然裁。
- 统一 `setToolTip(text)` + elide 兜底：真放不下时从**右边**省略并加省略号，不要从左边切。
- 右侧 dock 最小宽从 200 提到 300。
- `INSPECTOR_LABEL_MAX` 和 dock 上限要自洽，不要留一个永远够不着的常数。

验收 `test_q46_label_not_clipped`：用 `QFontMetrics` 逐个量面板上每个标签的
`horizontalAdvance(text)`，断言不超过它实际分到的宽度；dock 取新最小值 300 时也要过。现在必红。

（Q52 也提到这一条，以先落地的为准，两边不要各做一遍。）
