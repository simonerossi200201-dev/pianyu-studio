# Q103 · 拼接新增「以文件夹为一组」分组方式

**开工前先读 `_RULES_FOR_EVERY_TASK.md`，以及 `cutora/batch/script_stitcher.py` 的
`scan_groups`（:773）/ `scan_groups_multi`（:830）/ `build_name_rule` / `find_material_dirs`。**

## Luca 要什么

「增加一个新的模式，就是以『文件夹』作为分组……它跳出了我们之前所说的，必须要让每个视频片段
有同样的前缀才能算是一组，但是如果开启了以文件夹为分组，那就是一个文件夹内的视频都属于一组，
无论文件夹内的视频如何命名、随意命名，都可以视作为一组，这样就不用让用户再大费周折的给视频
文件重命名了。」

这条只做**核心分组逻辑 + 现有对话框 + CLI**。首页那个新入口是 Q104，它依赖这条。

## 现状

`scan_groups()` 靠文件名猜分组：自定义前缀规则 → 纯数字 `01a/01b` → `TikNNN-sNNN-pNN` →
通用兜底 `AUTO_RE`。名字不合这四条里任何一条的文件**直接被丢掉**（`:808-809` 的 `continue`），
用户完全看不到自己的素材去哪了。所以才有「大费周折重命名」这回事。

## 要做的事

### 1. 核心

`scan_groups_multi(folders, group_mark=None, order_mark=None, group_by_folder=False)`
—— 新参数放最后，默认 `False`，**老调用一个字不改，行为一个字节不变**。

`group_by_folder=True` 时：

- 每个文件夹 = 一个组。**不看文件名**，`group_mark` / `order_mark` 一律忽略。
- 组内成员 = 该文件夹**下一层**的视频文件（`VIDEO_EXTS`），
  跳过 `_stitched` / `_invalid` / `_scatter` 这些自产目录（沿用 `find_material_dirs` 里那份跳过名单，
  **不要再抄一份**，抽成一个共用常量）。
- 组内顺序 = 文件名自然序（`_natkey`，`a2.mp4` 排在 `a10.mp4` 前面）。
- **组号 = 文件夹名**。重名沿用现有那套：表里改叫 `名字(上级目录名)`，
  `base_of` 仍是原文件夹名，所以成品文件名和落盘位置不变。
- 没有视频的文件夹**不产生空组**，但要往 `notes` 里写一行
  「<文件夹> 里没有视频，跳过」—— 用户要看得见自己拖进来的东西为什么没出现。

另外新增一个纯函数 `group_by_folder_scan(folder)` 供上面调用和单测，不要把逻辑塞在循环里。

### 2. 现有对话框

`StitchDialog` 里，命名前缀那两栏（`ed_group_mark` / `ed_order_mark`，:3567-3576）旁边加一个
复选框「以文件夹为一组（忽略文件名）」：

- 勾上 → 两个前缀输入框**置灰**（不是隐藏，用户要能看见它们为什么没用了），立刻重扫。
- 这个选择存进 `stitch_naming.json`（和 `group_mark` / `order_mark` 同一份，用
  `save_naming` 那条「只改自己的键，别把别人的冲掉」的写法）。
- **对话框里默认仍是关**。老用户打开还是他熟悉的样子。

文案表格的「组」那一列会变成文件夹名，这是对的，不用特殊处理 —— `parse_scripts`
的归一化（`_norm_key`）已经能吃非数字组号。**但要确认一遍**：拿一个叫
`观众席素材` 的文件夹跑一遍 `parse_scripts`，组号能对上。对不上就改 `_norm_key`，
并在报告里写明改了什么。

### 3. CLI

`cutora/batch/cli.py` 的 `stitch` 那条 OPS_SPEC **只新增**一个参数：

```
"group_by_folder": {"type": "bool", "default": False,
    "desc": "true 时一个文件夹算一组，忽略文件名与前缀规则。文件随便命名也能拼"},
```

**现有任何一条参数的 `required` / `default` / `desc` 一个字都不许动** ——
`tests/test_cli_describe_compat.py` 对叶子值是逐字比对的，改了就红。

## 测试 `tests/test_q103_folder_group.py`

每条都要能说明「改之前是红的」：

1. 一个文件夹里放 `随便起的名字.mp4` / `另一个.mp4` / `a10.mp4` / `a2.mp4`：
   `group_by_folder=False` 时按现有规则只认得出其中一部分（甚至 0 组）；
   `=True` 时是 1 组 4 条，顺序为 `a2, a10, 另一个, 随便起的名字`（自然序）。
2. 两个文件夹 → 2 组，组号分别是两个文件夹名，`folder_of` / `base_of` 各归各的。
3. 同名文件夹在不同上级目录下 → 表里键不冲突，`base_of` 仍是原名。
4. 文件夹里有 `_stitched` / `_scatter` 子目录且里面有视频 → **不算进组**。
5. 空文件夹 → 不产生组，`notes` 里有那一行提示。
6. `group_mark` / `order_mark` 传了值但 `group_by_folder=True` → 结果与不传时**完全一致**
   （证明前缀规则真的被忽略了）。
7. **回归**：`group_by_folder=False` 时，`scan_groups_multi` 对一批老命名
   （`01a/01b`、`Tik001-s001-p01`、`Tik001_v01`）的输出与改前逐字节一致。
   这条是护栏，别省。
8. `parse_scripts` 吃中文文件夹名当组号，能对上。
9. CLI：`--describe` 里 `stitch` 多了 `group_by_folder`，其余参数一字未变
   （跑 `tests/test_cli_describe_compat.py` 即可）。
