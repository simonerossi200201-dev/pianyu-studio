## 这一批的共同根因（Claude 已在 2026-09-18 逐条核实，不要重新推理，也不要推翻了事）

`cutora/render/textfx/spec.py:642` 的 `from_style()` **只读 `style["fx"]` 和 `font_family`**，别的什么都不读。
我对整个 `cutora/render/textfx/` 目录逐个 grep 过这些 v1 扁平键：

| 键 | textfx 里的引用数 |
|---|---|
| `color_text` / `color_high` | 0 |
| `border_width` / `color_outline` / `opacity_outline` / `use_stroke` | 0 |
| `shadow_blur` / `color_shadow` / `opacity_shadow` | 0 |
| `use_box` | 0 |

也就是说：**面板里任何还在写 v1 扁平键的控件，都是死控件** —— 不是偶尔失效，是按构造不可能生效。
九报（BUG-20~24）诊断过、开过 T32「面板重构」的药方，**T32 从来没做**，所以今天全爆出来了。

另外 `cutora/ui/widgets/dock_panels.py:173-180` 的 `_fx()` 帮手：

```python
widget = getattr(panel, attr, None)
if widget is None:
    return          # ← 控件不存在就静默跳过，不报错不打日志
```

这是**静默失败目录第 18 条：引用一个不存在的控件，帮手静默跳过**。

## 现象
「自动着色这里也加上开关；底下的填充、3D 挤出、背景纹理、双字体、弹出散落，这些都加上开关按钮，统一好。」

## 背景
九报第 1 节定过一条规则，只写了没执行：
> 有「启用」概念的段，段头必有胶囊；纯参数段段头无开关但箭头样式一致。

现状：背景色块 / 描边 / 多层扩展描边 / 高亮弹力条有段头开关；
自动着色 / 填充 / 3D 挤出 / 背景纹理 / 双字体 / 弹出散落 / 阴影发光没有 —— 外观割裂。

## 要做
给下面每段加段头胶囊开关。**开关语义必须是「这个 fx 家族生不生效」，不是新加一个布尔键**
（新加布尔键 = 又一个没人读的死键）：

| 段 | 关 → 写什么 | 开 → 恢复 |
|---|---|---|
| 填充 | `fill.type = "solid"` 且 colors 回单色白 | 恢复上次 type / colors |
| 3D 挤出 | `extrude.depth_em = 0` | 恢复上次 depth |
| 背景纹理 | `bg.type` 从 `texture` 切回上一个非 texture 类型 | 切回 `texture` |
| 双字体 | `fonts.emphasis = ""` | 恢复上次 emphasis 字体 |
| 弹出散落 | `scatter.enabled = False`（本来就有布尔键，直接用） | `True` |
| 自动着色 | `emphasis.auto = []` 且 `emphasis.words = []` | 恢复上次列表 |

要点：

1. **「记住上次的值」抽成公共 helper** `SectionToggle(path, off_value, default_on)`。
   T20 的描边开关、BUG-21 的背景开关一起换过去用它。现在是各写各的。
2. 段头开关的外观、尺寸、开金关灰，**六段完全一致**，且和已有的四段一致（沿用 BUG-18 的胶囊控件）。
3. 关掉的段，内容区**变灰但不隐藏**（用户能看见自己之前设了什么）。
