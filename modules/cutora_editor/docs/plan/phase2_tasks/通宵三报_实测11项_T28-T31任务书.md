## 1. 逐项分析

### #1 「时长不符」弹窗 —— 误报，软件的单视频遗留假设撞上了 T06 的检查

**弹窗的意思**：T06 做的离线/时长检查，发现工程 JSON 里记的时长（448.09 s）和 ffprobe 读到的文件时长（15.04 s）不一样，按 Luca 「落档不许静默」的规矩把两个数都摆出来。

**为什么会不一样**：拼接出来的时间线工程还带着两个**单视频时代的字段**：
`task["video"]` = 第一个片段的路径，`task["duration"]` = **整条时间线**的总时长（`timeline_stitch.py:204–222`）。
`offline.py:85–87 inspect_task` 拿 `task["duration"]` 去和 `task["video"]` 的 ffprobe 比 —— 一个是 31 段加起来的 448 s，一个是第一段的 15 s，当然不符。

**结论给用户**：素材没坏、模型没错、算法没错、**不用重新生成、不用挨个检查**。是检查代码用错了字段。
时间线里每个片段的真实时长在 `timeline.sources[*].duration` 里（g19 工程里我核过：8.0 / 4.71…，和文件一致）。

**BUG-11**：`inspect_task` 对 `timeline` 工程只逐 source 比，不比 `task.duration`；弹窗文案改成用户能懂的：「某某片段：工程记录 X 秒，文件实际 Y 秒。工程里的时长已保留，导出按文件实际时长。」加一句「怎么办」。
测试：g19 工程 `inspect_task` → `duration_mismatch == []`；一个 source 故意写错时长 → 只报那一个。

### #2 「批量结果」分页 —— 是 T12c 批量语言识别的结果表，只在批量自动字幕后才有内容

`asr_batch_results.py`：文件 / 语言 / 置信度三列 + 「重跑标黄的行」「重跑纠正过的行」。你从没走过批量语言识别，所以永远空白。

### #4 播放只播第一段、从别处点播放被拉回开头 —— 根因确定

## 2. T28 · 时间线播放引擎（#4，A 档最大的一块）

**目标**：预览 = 时间线。从哪点播放就从哪播，跨片段连续播到时间线末尾才停，画面和导出逐帧一致。

**设计**：
1. **主时钟**：时间线音频代理。把整条时间线的音频混音（`compute_export_audio_tracks` 那条路，48 kHz 立体声）渲染成 `UserData/cache/preview_audio/<工程指纹>.wav`，一个 `QMediaPlayer` 播它，它的 `position()` 就是时间线时间。`asr/timeline_wav.py` 已经会做 16 kHz 版，复用；音频相关编辑（移动 / 修剪 / 增益 / mute / solo）后 debounce 500 ms 后台重生成，生成期间状态栏「音频代理更新中…」，画面照常按时间线时钟走（`_timeline_ms` + `QElapsedTimer` 兜底）。
2. **画面**：`frame_at(t)`：用导出那套解析（`_find_active_clips_in_track_export` / `_get_video_frame_at_time` / `_compute_fit_rect` / 转场合成）—— **同一路径**，不许再写一份预览专用的。每个 source 一个常驻 `cv2.VideoCapture`（池，LRU 8 个），单调前进就顺读，跳变才 seek。
3. **交互**：点时间线任意处 → `_timeline_ms` = 那里，播放从那里起；播到末尾停在末尾（不回零）；J/K/L 照旧；空格切换。
4. **删掉**：`media_player.setSource(task['video'])` 这条主路径、`_using_media_clock` 对单文件的依赖、`media_player.duration()` 当总时长。单视频工程 = 只有一个 clip 的时间线，走同一条路。
5. 字幕 / 覆层 / 贴纸照旧按时间线时间画。

**门禁**：
- g19 工程：从 0 播到底，`_timeline_ms` 单调递增到 29.26 s 后停；点 20 s 再播，从 20 s 起。
- 画面一致：t = 4 / 12 / 20 / 28 s 预览帧 vs 导出帧（`T20a_g19_pair_*` 那种对帧图），平均绝对差 < 2/255。
- 音画同步：代理 wav vs 导出音轨互相关，滞后 < 20 ms。
- 单视频 golden（g08/g10/g11–g18）预览帧 vs 导出帧同样对帧，哈希不变（导出路径没动）。
- 打开 Luca 的 T023 工程，31 段连播不卡（状态栏显示 fps ≥ 24）。

## 4. T30 · 关键帧系统（#11 上半）

**数据模型**
```
keyframes: {
  "<param_path>": [ {"t": 0.0, "v": 1.0, "interp": "linear|hold|ease_in|ease_out|ease_in_out|bezier", "bez": [x1,y1,x2,y2]} ... ]
}
```
挂在 **clip / 覆层 / 贴纸 / 字幕角色样式** 上，`t` 相对该对象自身起点（秒），排序存储。可关键帧的参数：位置 x/y、缩放、旋转、不透明、音量（gain_db）、裁剪、模糊、调色全部参数、字幕字号/颜色/位置。
- `resolve_at(obj, t) -> dict`：无关键帧 = 静态值；一个关键帧 = 常量；多个 = 插值。**preview 和 export 只经过这一个函数**（接在 `resolve_paint_style` 同一层）。
- 命令：`keyframe.set / delete / move / set_interp`，`undoable=True`，锁定轨拒绝。

**UI**
- 属性面板每个可关键帧参数左边一个 ◇：灰=无关键帧、金=当前时间有关键帧、空心金=有关键帧但当前时间不在上面；点 ◇ 在当前时间加/删；改值时若该参数已有关键帧 → 自动记录在当前时间（记录模式 ● 可全局开关）。
- 时间线：选中对象时其下方展开一条关键帧带，◇ 可拖动（改 t）、右键改插值、`Alt+拖` 复制；`[` `]` 上一个/下一个关键帧。
- 关键帧面板（右栏新分页「关键帧」）：当前对象所有参数的列表 + 曲线视图（一个参数一条曲线，可拖手柄；第一版只做线性/缓动，bezier 手柄第二版）。

**门禁**：一个覆层 x 从 0→1080 两关键帧，导出帧 t=0/0.5/1 位置正确（像素定位）；ease 曲线中点 ≠ 线性中点；undo 逐字节；golden 新录 **g22_keyframe_overlay**；无关键帧的所有旧 golden 不变。

## 5. T31 · 调色系统（#11 下半）

**范围（第一版）**：每个视频 clip 一组「调色」参数 + **调整层**（一条特殊轨，作用于其下所有视频轨）。
参数：曝光、对比度、饱和度、色温、色调、高光、阴影、白平衡、LGG 三色轮（lift / gamma / gain）、RGB 曲线 + 亮度曲线、色相/饱和/亮度曲线（HSL 第二版）、暗角、LUT（.cube，用户自带，不内置）。全部可关键帧（T30）。
**实现**：CPU 管线。所有一次映射类操作（曝光/对比/饱和/温度/色调/LGG/曲线/LUT）合成一张 **33³ 3D LUT**（参数变了才重算，缓存键 = 参数哈希），逐帧用 `cv2` 三线性查表；高光/阴影/暗角是空间相关的，单独一步。preview 和 export 同一个 `grade_frame(img, params)`。性能门：1080×1920 单帧 < 8 ms（i5 级 CPU）。
**UI**：右栏「调色」分页：上半色轮三个（拖动，双击复位），下半滑块组 + 曲线编辑器（点加删拖）+ LUT 选择；顶部「对比」按钮按住看原图；示波器（直方图 + 波形，第一版直方图）。每个控件左边关键帧 ◇。
**门禁**：纯灰卡帧：曝光 +1 → 亮度 ×2（±2%）；饱和 0 → R=G=B；温度 +50 → R−B 增大；.cube 恒等 LUT → 逐像素不变；golden 新录 **g23_grade**；旧 golden 不变（默认参数 = 恒等，必须逐像素恒等，测试锁）。
