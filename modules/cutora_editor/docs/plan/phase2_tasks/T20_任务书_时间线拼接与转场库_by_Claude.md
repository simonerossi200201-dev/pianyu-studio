## 1. 那份「缺失文案清单」为什么错：**两个不同的 bug，我在数据里都找到了**

我拉了 `T0035` 和 `T0040` 的 `copy.txt`、`_asr_cache.json`、缺失清单，逐条对。

### BUG-06 · `T0040-s002-p09.mp4`：ASR **把后 5 秒的话丢了**

缓存里这个片段的转写：

```
words: many(0.00–0.74) people use scripture to condemn others(2.42–2.90)
dur:   8.0
```

**片段 8 秒，转写在 2.9 秒就停了。** 「but forget that Jesus also brought grace, mercy, and freedom」正是紧接在「condemn others」后面那半句 —— 它根本没被转写出来。

**这不是猜的。** 缓存里存了这个片段的**音量包络**（每秒 100 个采样），我解出来看：

```
t(s)   平均电平   
 0.0     88   #####################   ← "many"
 1.0     41   ##########              ← "use scripture"
 2.5     50   ############            ← "condemn others"   转写到此为止
 3.4     48   ############            ← 电平和上面一模一样 —— 人在说话
 4.4     39   #########
 5.9     52   #############
 6.4     84   ####################
 7.9     96   #######################
```

**3.4–8.0 秒的电平和 0–2.9 秒完全一个量级。** 人一直在说，ASR 在 2.9 秒放弃了。
Luca 说「它认真读过一遍、这段话就在里面」—— **对，就在里面，是 ASR 把它扔了。**

**候选原因**（要 Grok 复现后定）：
- VAD 在 2.9–3.4 秒的短停顿处切了一刀，**只把第一段送进 Whisper**
- Whisper 提前发了 end-of-text（`condition_on_previous_text` 或长停顿导致）
- 缓存键里的 `|p2` 和 `"deep": 1` —— 如果这是「第二遍 / 只扫某个窗口」的模式，可能只喂了一部分音频

**必须加的自检**（这条比修根因还重要，它防的是整类问题）：
> **转写结束点比音频结束点早 1 秒以上、且之后的包络还有能量 → 判定转写不完整，
> 对剩余部分（或整段、不带 VAD）重跑一次。** 仍然短 → 在报告里标「⚠ 转写可能不完整」，不当缺失。

### BUG-07 · `John 16:13`：经文引用**归一化**没做

`T0035-s021-p03.mp4` 的转写：

```
john 1613 says when he the spirit of truth is come
```

**话在，词也在。** 文案写的是 `John 16:13`，ASR 把「sixteen thirteen」写成 `1613`。
匹配器拿 `16:13`（或拆成 `16` `13`）去对 `1613`，对不上 → 报缺失。

**Luca 的内容里经文引用到处都是**（Luke 13:3、John 8、Matthew 5、John 16:13 全在这两篇里），
**这条不修，每一篇都会误报。**

**修法**：文案侧和 ASR 侧**各自归一化到同一种形式**再比：
`16:13` / `16 13` / `1613` / `sixteen thirteen` / `chapter 16 verse 13` → 同一个等价类。
数字统一（`8` / `eight`），常见缩写（`KJV` / `K J V`）。
**测试**：这两篇 `copy.txt` 里的全部经文引用，逐条断言能匹配上。

### 拼接准确率「再高一档」—— 除了这两条，还有三件

1. **换 `large-v3`**（Luca 已定「用最强的」）。medium/small 丢词更多，BUG-06 那种截断在大模型上也更少
2. **报告分级**：现在只有「缺失」一档。改成三档 —— 「**确实没有片段讲**」/「**有相近转写但没对上**（附最接近的那句 + 片段名）」/「**转写可能不完整**（BUG-06 的自检触发）」。
   Luca 看到第二、三档就能一眼判断是误报，不用自己去听 27 个片段
3. **匹配阈值可视化**：报告里给每个缺失项写出「最接近的候选 + 相似度」。现在是黑箱

## 2. 硬件自动分档（Luca 的新要求）

> 打包把所有模型都带上；运行时软件自己判断这台机器最高能跑什么，保证不卡死不崩溃。

### 2a. 探测（启动时一次，设置里可「重新检测」，结果落盘）

| 探什么 | 怎么探 |
|---|---|
| 有没有 CUDA、几张卡、**每张 VRAM 总量和当前可用** | `ctranslate2.get_cuda_device_count()` + `torch.cuda.mem_get_info()`（没 torch 就 `nvidia-smi --query-gpu=memory.total,memory.free`） |
| 系统内存总量 / 可用 | `psutil.virtual_memory()` |
| CPU 核数 | `os.cpu_count()` |
| 磁盘上实际有哪些模型 | `runtime/models` 清单 |

### 2b. 分档表（写成常量表，不写在代码逻辑里）

| 档 | ASR 模型 | 计算类型 | 最低要求 |
|---|---|---|---|
| **S** | large-v3 | fp16 GPU | VRAM ≥ 6 GB 可用 |
| **A** | large-v3 | int8 GPU | VRAM ≥ 4 GB 可用 |
| **B** | medium | int8 GPU | VRAM ≥ 2.5 GB 可用 |
| **C** | large-v3 | int8 **CPU** | RAM ≥ 8 GB 可用（慢，但准） |
| **D** | medium | int8 CPU | RAM ≥ 5 GB |
| **E** | small | int8 CPU | 任何机器 |

对齐模型同理另一张表。**「最低要求」都留 20% 余量**，不要卡在边上。
数字先按这个，**Grok 在本机实测每档的峰值占用后修正**（用 `torch.cuda.max_memory_allocated`）。

### 2c. 选择与兜底

- 默认「**自动**」：取满足要求的**最高档**；UI 里显示「自动（当前：large-v3 · GPU fp16）」
- 用户可手动指定；指定了超出机器能力的档 → **启动前就警告**，不是跑到一半炸
- **运行时守卫**：捕获 CUDA OOM → 卸载模型 → **自动降一档重跑** → **状态栏 + 日志明说「已从 S 降到 A」**。**不许静默降档**
- ASR 跑在 worker 里，**带看门狗**：单个片段超过 `10 × 时长` 没返回 → 判定卡死，杀掉、降档、重试一次、再不行标错继续下一个。**批量跑一夜绝不能卡在一个片段上**
- 笔记本无独显 → 自动落 C/D/E，UI 明说「本机无 GPU，预计速度 ×N」

### 2d. 测试
- 探测结果**可注入**（mock），六档各一条：给定 VRAM/RAM → 断言选中的档
- 模拟 OOM → 断言降档 + 有通知日志 + 结果仍产出
- 看门狗：注入一个永不返回的 ASR → 断言被杀、降档、批量继续

**这是一刀，编号 `T12f`（挂在 T12 多语种 ASR 下，它是 ASR 运行时的事）。**

## T20 任务书 · 时间线拼接 + 转场库

### 现状（T06/T08/T11 摸底 + 今天看的文件）
拼接器读 `copy.txt` + `clips/*.mp4` → ASR 每个片段 → 匹配 → **`ffmpeg` 拼成 `_stitched/T035.mp4`** → 再导入。
拼完的 mp4 里**片段信息全丢**：不能单独调色、不能改某一段、不能加转场、不能回退。
这是「软件外的一条岔路」，和 T11g 杀掉的 v1 路径是同一种病。

### 目标
点「开始拼接」→ **产出一个时间线工程**：N 个片段按 cutlist 顺序放在**一条视频轨**（链接的音频轨跟着），
每个片段是独立 clip（`source_id` 指向各自 mp4，`in_t/out_t` 来自 cutlist），
片段之间默认硬切、可加转场。**软件外不再产生任何中间视频。**
自动字幕把整条轨当一个视频；媒体库里显示**一个工程**。

### T20a · 拼接器改产出时间线（核心）
- `stitch()` 的输出从「mp4 路径」改成 **`List[ClipPlacement]`**（`source_path, in_t, out_t, start_t, link_audio`）
- 一条命令 `stitch.to_timeline {task_dir}`，`portable=True`（按目录寻址）
- 每个片段**铺满项目画布**（cover），这条从 T21 折过来 —— 720×1280 的素材进 1080×1920 画布必须放大填满
- `cutlist.json` 保留，作为可追溯的中间产物；`_stitched/*.mp4` **不再生成**
- **golden**：新增 `g19_stitch_timeline`，用 T0035 那 27 个片段（拷贝到 golden 夹具，**不要引用 D:\1_PROJECT**）
- **观感对照**：同一份 cutlist，旧路径拼的 mp4 vs 新路径时间线渲的成片，全画布并排静帧三张（开头/中段/结尾）。
  **不要求像素相等**（两条不同的编码链），要求**切点位置一致、画面内容一致**

### T20b · 先还 `seg.id` 的债，再做跨片段 ASR
- **`seg.id` 改稳定 uuid**（挂了两周的 Phase 2 债，现在必须还：多片段时间线上下标寻址一碰 ripple 就错位）
  - 读旧工程：无 id 的段落分配 uuid，落盘后就固定
  - 所有 `seg_id` 参数的命令改收 uuid；旧的下标寻址**只在迁移路径保留**，UI/CLI/MCP 全部走 uuid
  - `portable` 白名单重审：uuid 寻址的段落命令可以变 `True`
- 自动字幕：把时间线**音频轨渲成一条临时 wav**（T07a 的 `compute_export_audio_tracks` 就是入口）→ 跑一次 ASR → 段落时间即时间线时间
- **BUG-06 的自检和 BUG-07 的归一化在这条路径上同样生效**
- **缺词分级（随 T20b）**：≥3 词仍报「缺失」；1–2 词报「疑似缺词」（附前后各 3 词上下文）；报告开头写明阈值。不要把阈值降到 1。

### T20c · 转场库
- **先盘**：`TransitionItem` 模型在（T05e），**渲染器现在到底画不画它**？摸底一句话
- 转场是独立实体（T05e 语义：接缝在就平移，接缝没了就删，永不缩短）
- 第一批 8 个：**交叉溶解 · 黑场 · 白场 · 推（左/右/上/下）· 擦 · 缩放溶解 · 模糊溶解 · 闪白**
  每个带时长（默认 0.35s）和缓动；**不许纯黑**用 `#0B0B0E` 一类的深灰（老规矩）
- 时间线上：拖到两个片段的接缝上放下；右键换类型；拖边改时长
- **golden**：`g19` 加一条带交叉溶解的变体 `g19b`
