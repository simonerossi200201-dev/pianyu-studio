## 2. T35 · 提速研究：为什么慢、慢在哪、怎么至少快一倍

### 2a. 先说结论，再说证据

**自动字幕慢**：拼接器已经对每个片段跑过一遍 ASR + 对齐（`_asr_cache.json`，BUG-06/07 打磨过的词级时间），时间线工程**把这份结果扔了**，把 31 段混成一条 7.5 分钟的 wav 再**从头跑第二遍** ASR + 对齐（`main_window.py:8837-8858`）。三个组就是三遍。这不是"慢一点"，是**整段工作做了两次**。

**导出慢**：解码是顺序读、只在片段边界 seek（`_get_video_frame_at_time` 的 `decode_cursor` 逻辑是对的，我读过），**不是** seek 的锅。最可能是 T21：画布默认 1080×1920，Luca 的素材全是 720×1280 —— 以前「跟源尺寸」导出 720×1280，现在**每帧先放大 2.25 倍再合成再编码**：`SmoothPixmapTransform` 放大 + 2.25 倍像素的 QPainter 合成 + 2.25 倍的 rawvideo 管道 + 2.25 倍编码。其次：毛玻璃每帧要拷一份背景（`_needs_glass` 是按任务判的，不是按帧）；合成和编码在同一线程串行。

### 2b. 规矩：先量，后改

没有数字的优化不许提交。`tools/profile_export.py` / `tools/profile_asr.py`，跑 Luca 的 T023 工程（31 段，7.5 分钟）：

| 导出各阶段（每帧 ms） | ASR 各阶段（s） |
|---|---|
| 解码 read / seek 次数 | 渲 wav（ffmpeg 混音） |
| SAR 修正 + fill 缩放 | 模型加载（是否每组重载） |
| 视频层合成 | ASR 推理 |
| 字幕/覆层 raster（缓存命中率） | 对齐 |
| 毛玻璃 backdrop 拷贝 | BUG-06 自检（包络解码） |
| QImage → bytes → 管道 write | 缺词 / 幻觉检查 |
| 编码器（ffmpeg 进程 CPU%） | 写回工程 |

**基线 = 现在 `b1c9003` 的墙钟**，两次取平均，贴表。之后每一步优化都贴同一张表。

### 2c. 自动字幕：方案（预期 ≥ 5×，不是 2×）

1. **复用拼接结果，不跑第二遍**：`timeline_stitch.project_from_placements` 把每段 `_asr_cache.json` 里的词级时间按 `start_t − in_t` 偏移写进 `task["segments"]`（带 `timing_tier`、role），工程落盘时字幕就在。拼接完成 = 字幕完成。
2. 时间线上的「自动字幕」按钮变成**「重新识别」**（用户明确要求才跑第二遍），并提示"拼接已带字幕"。
3. 真要跑第二遍时：模型一次加载全程复用（`engine._WHISPERX_MODEL` 已有缓存，确认三组之间没被 `unload` 清掉）；三组排队跑，不弹三次对话框。
4. 门禁：T023 三组，拼接结束到字幕出现在时间线 **≤ 5 s**（现在是三遍 ASR 的总时长，贴数）；字幕内容 == 拼接器 `_asr_cache` 的词序列（逐词相等）；BUG-06/07 的测试不变。

### 2d. 导出：方案（目标 ≥ 2×，按收益排序，量了再做）

1. **画布 = 源尺寸**（T21 补那条，现在必须做）：新建工程默认画布 = 首个素材尺寸（Luca 的都是 720×1280）；已有工程若所有源同尺寸且 ≠ 画布 → 提示一次「按源尺寸导出？」。单这一条对 Luca 的素材就是 2.25× 的像素量回来。
2. **合成并行、编码串行**：N 个工作进程各合成一段时间的帧（同一套 `frame_at`），按序送回主进程写进**同一个** ffmpeg 管道 → 输出**逐字节等于串行**（同一编码器、同一帧序）。这和 `render/parallel.py` 现有的"多任务并行"不同，是单视频内部并行。门禁：`workers=1` vs `workers=4` 输出 md5 相同（g16 那种 parallel==serial 锁，扩到 g08–g19b-2 全部）；golden 十二例哈希不变（默认 workers 由 CPU 核数定，但输出不变所以基线不动）。
3. **合成与编码流水线化**：即使 N=1，合成线程和管道写线程分开，8 帧队列。
4. **毛玻璃按帧判**：只有当前帧有玻璃字幕才拷 backdrop。
5. **零拷贝路径**：源帧已是画布尺寸且 fit=fill、无缩放旋转时，跳过 `QImage` 转换直接以 BGR 数组作底，字幕层用 ROI 叠上去（textfx 已有 ROI 缓存）。
6. 管道用 `bgr24`（不是 bgra，少 25% 字节），`stdin` 大缓冲。
7. 门禁：T023 导出墙钟 **≤ 现在的 1/2**；g08–g19b-2 十二例哈希不变；`workers=1/4` md5 相同；CPU 峰值不超过 80%（不许把机器卡死）。

### 2e. 不许做的

- 不许"快速模式"开关 —— Luca 删过一次。快就是默认。

## 5. T34 · 分屏系统

### 5a. 概念（按 Luca 的原话定死）
- **分屏是工程级的**，只有一份：`task["split"]`。任何轨道开启分屏 = 工程开启分屏，其他视频轨自动进入分屏模式，只能选「填到哪个格子」。
- **两个独立的东西**：① 分界线的位置 / 旋转 / 羽化 / 描边 —— 全局统一，在画面上拖或在属性页调；② 每个轨道在自己格子里的内容位置 / 缩放（T33 的轨道变换）—— 各自独立。分上屏后想把人往上挪，动的是②，不是①。

### 5b. 数据
```
task["split"] = {
  "enabled": true,
  "layout": "top_bottom" | "left_right" | "grid_2x2" | "grid_3x3" | "left1_right2" | "top1_bottom2" | "custom",
  "cells":    [{"id": "A", "rect": [0, 0, 1, 0.5]}, {"id": "B", "rect": [0, 0.5, 1, 0.5]}],   # 画布归一化
  "dividers": [{"id": "d1", "axis": "h", "pos": 0.5, "rotation_deg": 0.0, "feather_px": 24}],
  "border":   {"style": "none|solid|gradient|glass|shadow", "width_px": 6, "color": "#F2C14E",
               "color2": "#FFFFFF", "curve": "straight|wave|arc", "shadow_px": 12, "glass_sigma": 8}
}
track.split_cell = "A" | "B" | None     # 视频/图片轨；None = 不参与（全屏叠在最上，比如 logo）
```
`layout` 是预设：选一个 → 生成 `cells` + `dividers`；`custom` 允许在画面上拖出格子。改 `dividers[].pos` → 相邻 cells 的 rect 联动重算（`split_layout.recompute(split)`，纯函数，有单测）。

### 5c. 渲染（preview / export 同一函数 `render/split_screen.py`）
1. 对每个参与轨：以格子矩形为"画布"做 fill 适配 → 应用轨道变换 → 用格子 **mask**（羽化 = 高斯边缘 alpha，按 `feather_px`）裁切 → 叠到画布。
2. 所有格子叠完后画分界线描边：`solid` 直线/曲线路径描边；`gradient` 沿线渐变；`glass` 取分界带下的画面高斯模糊 + 高光边（复用 `glass_thick` 的采样）；`shadow` 两侧投影。`curve=wave/arc` 用同一条路径同时做 mask 边和描边，保证严丝合缝。
3. **缓存**：mask 与描边路径按 `(cells, dividers, border, canvas)` 哈希缓存，参数不变每帧零重算；羽化 mask 是一张 QImage alpha，逐帧只做 `drawImage` 带 mask —— 每帧开销 < 1 ms。
4. 不参与的轨（`split_cell=None`）照常全屏叠在最上面。

### 5d. UI
- 轨道属性页「分屏」段：开关 → 布局选择器（缩略图网格：上下 / 左右 / 2×2 / 3×3 / 左1右2 / 上1下2 / 自定义）→ 本轨格子选择（只列未被占用的格子，已占用的灰掉并写着占用它的轨名）→ 分界线组（位置 / 旋转 / 羽化）→ 描边组（样式 / 宽度 / 颜色 / 曲线 / 阴影）。分界线和描边是全局的，页面上标「全局」。
- 画面上：分屏开启时画分界线把手（圆点 + 线），拖 = 改 `pos`，`Alt+拖` = 旋转，双击回中；羽化在把手旁滚轮。
- 时间线：参与分屏的轨头带格子编号徽标（A / B / …）。

### 5e. 门禁
- `split_layout` 纯函数测试：每个预设 cells 面积和 = 1、互不重叠；拖 `d1.pos` 0.5→0.6 后 A 高 0.6、B 高 0.4；rotation 30° 时 mask 边与描边路径重合（采样 20 点距离 < 1 px）。
- 渲染：上下分屏两段 + feather 24 → 分界带 alpha 从 1 到 0 单调；glass 描边带内像素方差 > 0；导出帧 == 预览帧 MAD ≤ 0.015。
- 性能：分屏开启 vs 关闭，T023 导出墙钟差 < 5%。
- golden 新录 **g24_split_top_bottom**（两段、feather、glass 描边）；UI 基线 **u08** 分屏画面（含把手）、**u09** 轨道属性页分屏段。
