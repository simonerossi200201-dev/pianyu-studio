## 3.【第十例】素材丢了，CLI **一声不响**继续跑

```
CLI load_project_file：不抛。路径原样留下，duration 仍是 JSON 里的 20.0，无 offline 旗
GUI project.open：不崩。弹一次「文件缺失」。没有重链、没有离线斜纹
```

**这条是今天挖出来的第十例静默失败，也是后果最重的一例。**

为什么最重：**这个软件的定位就是「对一个文件夹的视频批量套用」。**
用户把素材文件夹改个名、挪个位置、或者清理了原始素材，然后挂一夜批量 ——
**CLI 不报错、不停、duration 还用的是 JSON 里的旧值**。

第二天早上他拿到的是什么？黑帧？中途崩掉的半截文件？还是一堆时长对不上的片子？
**我们现在答不上来** —— 而这正是最该答得上来的那种问题。

而且 `duration` 从 JSON 读、不重新探测，还带来第二个坑：
**素材被换成了另一个不同时长的文件**，时间线**静默错位**，连「文件缺失」都不会弹。

## T06 任务书 · 媒体库与工程可靠性

### T06a · 离线素材（第一块，其余都等它）

**1. 打开时就要知道谁不在**
- 载入工程时**逐个 `stat`** 素材路径，不存在 → 标 `offline=True`
- **重新 `ffprobe` 时长**，和 JSON 里的值不一致 → 标 `duration_mismatch`，**不要静默采信任何一方**
- CLI：`_log.error` 列出全部离线素材，**并且退出码非零**
- GUI：弹窗列出全部（不是「一次文件缺失」），时间线上离线片段画**斜纹 + 不可编辑**

**2. 导出前硬拦**
**有离线素材时 `export.run` / `export.batch` 直接拒绝**，抛 `CommandError` 列出缺哪些。
理由和 T05g 的锁定一样：**CLI / 配方 / MCP 都会绕过 UI 弹窗，拦必须拦在命令层。**
用户确实想跳过缺失素材 → 要一个显式参数（`allow_offline=True`），默认 `False`。

**3. 重链**
- `media.relink {source_id, new_path}` 单条
- `media.relink_folder {old_root, new_root}` —— **整批换根目录**，这才是常见场景
  （用户把 `D:\素材\2026` 挪到 `E:\素材\2026`，一条命令全好）
- 自动候选：在工程文件同目录、以及上次成功的根目录下**按文件名找**，找到就提示确认
- `portable=False`（含绝对路径）

**4. 测试**
- 缺素材打开 → 离线旗在、CLI 退出码非零
- 缺素材导出 → 抛错、**工程 JSON 逐字节不变**
- 时长不符 → `duration_mismatch` 旗在，两个值都留档
- `relink_folder` 一条命令修好整个工程

**门禁**：`pytest 0 failed` · **golden 十个全不变**（素材都在，这条不该被触发）

### T06b · 自动保存与崩溃恢复

摸底：`autosave.py` **不存在**。一个跑数小时批量的视频软件**没有自动保存**。

- 每 N 分钟（默认 3）+ 每次命令成功后**节流**写 `工程名.autosave.json` 到工程旁
- 正常保存 / 正常退出时删掉它
- **下次启动发现残留 → 提示「上次未正常退出，是否恢复」**，用户说了算，不自动覆盖
- 批量运行中也要写 —— 这是最需要它的场景
- `project.autosave.status` / `project.autosave.restore` 两条命令
- **测试**：模拟崩溃（残留文件存在）→ 启动能检出、能恢复、恢复后的工程 JSON == 崩溃前

### T06c · 工程打包（`project.pack`）

**这是离线问题的根治手段**：把工程用到的全部素材收集到一个目录，
重写路径为相对路径，产出一个可以整体搬走 / 归档 / 发给别人的工程。

- `project.pack {out_dir, copy|move}`，默认 `copy`
- 路径写成**相对工程文件**的形式 → 换机器也能开
- 报告：收了多少文件、多大、有没有收不到的
- `portable=False`
