## 0. 三句话概括现状

1. **只有一条成片流水线**，写死 `H.264 + AAC`，UI 连容器都写死 `mp4`。
   本机 NVENC 能 HEVC / AV1，FFmpeg 能 ProRes / WebM，**一条都没接**。
2. **没有导出预设对象**（无 `export_profile.py`），用户不能自建。
   —— 这和 T11 的「一一对应」是同一个病，只是搬到了导出侧。
3. **命令层有三处空转**：`profile` 空转、`export.batch` 的 `out_dir` 空转、
   `export.settings` 读错并行键（dump 已证实 `None`）。

第 3 条排最前面做。理由见下。

## T08a · 先把空转的命令堵上（第一块）

**「有命令、参数不落地」比「没有命令」危险得多。**
没有命令，调用方会报错；参数空转，调用方以为生效了，**配方和 MCP 会静默产出错的东西**。
这是静默失败目录的又一族。

- `export.run` / `export.batch` 的 `profile`：要么接上，要么**参数删掉**，不许留着空转
- `export.batch` 的 `out_dir`：接上（配方里 `{out_dir}` 占位就是给它用的）
- `export.settings`：读对并行键
- `honor_io`：命令有、UI `Ctrl+E` 不传 → UI 也传
- GPU 开关不落盘 → 落盘
- **`fast` 模式没有入口** → 要么给入口，要么删掉这个模式

**锁**：一条测试，遍历 `export.*` 的每个命令的每个参数，
**断言该参数确实影响了产出的 ffmpeg 命令行或输出路径**。
做不到的参数不许存在。这条是本切片的核心，不是附加分。

**门禁**：`pytest 0 failed` · golden 全不变

---

## T08b · 导出预设对象

- `export_profile`：名字 + 容器 + 视频编码 + 码率/质量 + 音频编码 + 分辨率/fps 策略
- 内置几档：**社交竖版（H.264/mp4/CQ18）· 高质量（HEVC）· 存档（ProRes 或高码率）· 音频版（m4a）**
- **用户可新建 / 另存为 / 删**，存用户目录 —— 和 T11 的预设体系**用同一套读写规矩**，
  不要再造一套（两套真相我们已经吃过两次亏了）
- 导出面板上选预设，不是散落的勾选框
- **命令** `export.profile.save / delete / list`，`export.run {profile}` 真正生效

**`original` 这个档要改名或改实现**：摸底说它「跟源的是宽高/fps/SAR/采样率，不是编码」，
`QP/CRF 0 + yuv420p ≠ 无损`，无音轨时还丢 `+faststart`。
**名不副实的档比没有这个档更坏。**

## T08c · 硬件编码探测

现状：`use_gpu` 绑的是 CUDA 勾选，**不是 NVENC 实测**；失败靠整段重渲。

- 首次运行做一次**真实探测**（摸底提到 `-t 0.1` 在本机 NVENC 是红的，**用更长片源**，比如 `-t 1`）
- 结果落盘缓存，不每次探
- 探测失败 → **导出开始前**就退回 `libx264` 并在 UI 说明，不是渲到一半炸了重来
- AMF / QSV：FFmpeg 二进制带了编码器，Python 从不选。
  **这一轮先不接**，但在探测框架里留位置，别写成 NVENC 专用
