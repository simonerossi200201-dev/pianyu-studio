## 提交 2：T12c 正题 —— 对齐模型表与回退（任务书 §2）

按 `T12_多语种自动字幕.md` §2 执行，另加四条：

- **只启用 `line_break == "space"` 的语言的对齐模型**（拉丁 / 西里尔 / 希腊 / 亚美尼亚 / 格鲁吉亚）。`fallback` 那 30 个语言一律走 `word_timestamps=True` 回退并标「近似词级」，**不为它们找对齐模型**。这与附录「范围缩小」一致。
- **逐条核对许可证**：`align_models.json` 每条记 `language / hf_repo / size / license / sha256`。非 MIT / Apache-2.0 / CC-BY 的**默认不启用**，并在报告里单独列表说明。**任何 gated 仓库一律不启用**（下载要 token 的东西不能进分发版）。
- 现有 en（`WAV2VEC2_ASR_LARGE_LV60K_960H`）与 it（`VOXPOPULI_ASR_BASE_10K_IT`）路径**原样保留**，golden 依赖它们，一个字不许改。
- **模型哈希由 Grok 自己固定，不要 Luca 手工下载。** 关键在于**哈希从哪里来**：如果只是"我们下了一份、记下它的哈希"，那这个哈希只证明"这是我们那天下到的东西"，证明不了它是发布方的原件。正确做法是**从 HuggingFace 自己的元数据取哈希**，再用它来验我们下到的文件：
  1. 新增 `tools/pin_model_hashes.py`。对 catalog 里每个模型，调 HF 官方 API `GET https://huggingface.co/api/models/{repo}/tree/{revision}?expand=1`（走 `net.py` 白名单），取每个文件的 `lfs.oid`——**那个 oid 就是该文件内容的 SHA256**，由发布方给出，不是我们自己算的。
  2. 同时取当前 `main` 的 **commit sha 作为 `revision` 钉死**。以后一律用 `https://huggingface.co/{repo}/resolve/{revision}/{file}` 下载，**不用 `main`**——这样上游改模型、强推分支都不会悄悄换掉用户拿到的东西。
  3. `models.json` 每个文件条目记：`repo / revision / filename / size / sha256 / source`（`source` 写 `hf-lfs-oid` 还是 `computed`）。小文件（`config.json`、`tokenizer.json`、`vocabulary.txt` 等）不是 LFS，API 给的是 git blob 的 SHA1 不是 SHA256——这类按 `revision` 下载后**自己算 SHA256 填进去**并标 `source: computed`；内容已被 revision 钉死，可以接受。
  4. **实机验证一次机器本身**：Grok 自己下载 `mobiuslabsgmbh/faster-whisper-large-v3-turbo` 全套文件（约 1.6 GB），逐个比对第 1 步取到的哈希，全部一致才提交 catalog。**其余模型不必真下**——哈希来自发布方元数据，下不下都一样可信；只需要证明"取哈希 → 下载 → 校验"这条链路能跑通。
  5. 运行时校验保持不变：用户点下载 → 按钉死的 `revision` 下 → 与钉死的 `sha256` 比对 → **不一致就拒绝安装并明确报错**，不静默重试、不降级放行。
  6. 把 `tools/pin_model_hashes.py` 提交进仓库，将来加模型时重跑一次即可，不要再有任何手工步骤。
