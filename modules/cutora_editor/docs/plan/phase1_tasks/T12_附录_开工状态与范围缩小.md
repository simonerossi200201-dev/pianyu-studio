## 1. 范围缩小（这是本附录最重要的部分）

Luca 已明确：**软件不面向中文与日文需求**。因此任务书 §4 里为 CJK / RTL / 泰文做的那一大块**全部砍掉**，本任务只做**拉丁字母与西里尔字母**这两类"有空格、从左到右"的文字。

**砍掉**：
- CJK 禁则处理（标点不在行首/行尾）、按字符断行；
- RTL（阿拉伯 / 希伯来 / 波斯 / 乌尔都）的行序、连写、逐字高亮方向；
- 泰文/高棉文/老挝文/缅甸文的无空格断行；
- 12 语种渲染验证集里的 CJK / RTL / 泰文样本；
- `languages.json` 里 `cjk` / `rtl` / `thai` 相关的渲染策略分支。

**保留**：
- ASR **开放全部语言**（faster-whisper 本来就支持，不额外花钱）——但**非拉丁/西里尔语言标为"实验性"**：能识别、能出字幕，断行走"按空格 + 最大字符数硬切"，不承诺排版质量，UI 里给一句提示。这样既不封死，也不为它花时间。
- 词级对齐模型：**只启用拉丁 + 西里尔语言的**（en/it/es/fr/de/pt/nl/ca/gl/da/no/nn/sv/fi/pl/cs/sk/sl/hr/hu/tr/ro/ru/uk/bg 等，以实际存在且许可证合规的为准），其余走 faster-whisper `word_timestamps=True` 回退并标"近似词级"。
- 自动检测语言、模型管理器、术语表、批量维度——**原样保留**，这几样对 Luca 立刻有用。
- 字体回退链保留但简化：Latin + Cyrillic + Greek 一条 Noto Sans 基本覆盖，只需保证选到的字体缺字形时能回退，不做多脚本字体矩阵。

**验收集相应缩小**：从 12 语种改成 **6 语种（en / it / es / fr / de / ru）各 3 句**，其中 ru 用来验证西里尔字母渲染与对齐回退。

## 2. 追加一件小事：意大利语的撇号匹配 bug（约二十行）

来源见 `docs/plan/04_竞品分析_VideoKit.md` §3.2。

现象：文案里写 `dell'anima`（直撇号 U+0027）而 ASR 输出 `dell'anima`（弯撇号 U+2019），或反过来——`script_stitcher.match_clip_global` 用 `difflib` 比对**按空格切分**的 token，这两个是不同的词，直接算未命中。同类问题还有连字符（`-` / `–` / `—`）和不间断空格。

修法：匹配前对**片段词表与文案 token 两边**统一做
1. `unicodedata.normalize("NFKC", s)`；
2. 把 `[’‘`´ʼ]` 统一成 `'`，把 `[‐‑‒–—―]` 统一成 `-`，把不间断空格统一成普通空格；
3. 其余逻辑一个字不改。

**注意**：这只用于**匹配比较**，写回字幕/工程的文本必须保持原样（Luca 的成片里撇号该是什么样还是什么样）。加测试：一条只在撇号形态上不同的文案与片段，改前不命中、改后命中。跑 `golden --all --repeat 3`，**g04 是真正走拼接的用例**，若它的文案里没有撇号则输出必须逐字节不变。

**不做**：按语言分词、ICU、任何针对中日泰的处理。
