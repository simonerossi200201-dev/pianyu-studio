## 1. 密钥与 AI 提供商：`cutora/core/secrets.py` + `cutora/ai/providers.py`

- `secrets.get(name) / set(name, value) / delete(name)`，后端 `keyring`（MIT；Windows 后端为 Credential Manager，服务名 `CUTORA`）。找不到 keyring 后端时**拒绝**保存并提示，不回退到明文。
- 迁移：启动时若 settings 里存在 `gemini_api_key` / `xai_api_key` 等非空字段 → 写入 keyring → 从 JSON 中删除字段 → 记录日志"已迁移密钥"。之后 `app.settings.*` 命令与设置文件永远不含 `*_key` / `*_token` / `*_secret`。
- `providers.py`：统一接口
  ```python
  class Provider(Protocol):
      id: str; name: str; supports_images: bool
      def chat(self, messages, images=None, model=None, timeout=60) -> str: ...
      def list_models(self) -> list[str]: ...
  ```
  实现：`openai`（`api.openai.com`）、`anthropic`（`api.anthropic.com`）、`gemini`（`generativelanguage.googleapis.com`）、`xai`（`api.x.ai`）、`ollama`（`127.0.0.1:11434`，用户可改端口但主机固定本机）。只用 `urllib`/`httpx`（BSD），不装各家 SDK。端点主机名硬编码白名单，**不允许用户填任意 URL**（防止被引到黑名单域名）。
- 现有 `sfx_ai.py` 改为调用 `providers`；行为不变。
- `设置 → AI 提供商`：每个提供商一行：状态（已保存密钥/未配置）、输入框（输入后立即存 keyring，界面只显示"••••已保存"）、模型下拉（`list_models` 或手填）、"测试连接"按钮；默认提供商选择；全局开关"允许 AI 功能联网"（默认关）。
- 网络层统一 `cutora/core/net.py::request(...)`：所有出站请求必须经过它；它检查主机名在白名单（通用规范 §2.2）内，否则抛异常并写日志。安全扫描脚本额外检查仓库里不允许出现 `urllib.request.urlopen(` / `requests.get(` / `httpx.` 在 `net.py` 之外。

## 3. 字体审计：`tools/font_audit.py` → `resources/fonts/FONTS_MANIFEST.json`
- 遍历 `core/fonts/`（迁到 `resources/fonts/`）每个文件：读取名称表（`fontTools`，MIT）里的 family、version、license URL/描述、版权行；与 `fonts/LICENSES` 目录对照；判定许可为 `OFL-1.1 / Apache-2.0 / UFL-1.0 / Bitstream-Vera / UNKNOWN`。

## 5. 代码安全加固（只改明确不安全的模式，不重构）
- 全仓库 `subprocess` 调用：确认无 `shell=True`；路径一律列表参数；`creationflags` 用 `CREATE_NO_WINDOW`。
- JSON 加载统一走 `cutora/core/safe_json.py`（大小限制、`object_pairs_hook` 拒绝重复键可选）。
- `--render-job` 的 job 文件：校验 schema 后再执行；子进程只接受来自父进程目录的路径。
- 日志脱敏：`log.py` 加过滤器，遇到 `Bearer `、`api_key=` 之类模式替换为 `***`。
- 崩溃日志不含环境变量全量转储。
