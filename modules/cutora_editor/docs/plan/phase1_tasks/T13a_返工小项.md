## 提交 2：`fix(ui): kill ghost "转场:" window; dark export monitor with stop button`

### 2a. 点画布上的文本会弹出一个只写着「转场:」的黑窗口
根因（已定位）：`cutora/ui/panels/property.py:337` `self.ov_transition_label = QLabel("转场:")` 创建后**从未加进任何布局**（339 行那一行用的是字符串标签 `bf.addRow("转场:", rt)`），所以它是个没有父对象的 QLabel；888 行 `self.ov_transition_label.setVisible(True)` 一执行，Qt 就把它当作顶层窗口显示出来——就是 Luca 看到的那个带「片语 Studio」标题、黑底、只有「转场:」两个字的窗口。
改法：`bf.addRow(self.ov_transition_label, rt)`（用这个 QLabel 做行标签），删掉字符串版本；`setVisible` 的两处（888、1028）保持，这样标签会随转场行一起显隐而不是弹窗。**全文件 grep 一遍**：凡是 `QLabel(...)` 创建后没有 `addRow/addWidget/setParent` 的，一并修（`671` 行的 `pf.addRow("转场:", vtr)` 附近也看一下）。加测试 `tests/test_property_panel_no_toplevel.py`：offscreen 选中一个文本覆层后，`QApplication.topLevelWidgets()` 里除主窗口外不允许出现 `QLabel`。

### 2b. 导出监视器改深色 + 「关闭」换成「停止导出」
`GuardWindow`（`cutora/render/export_guard.py:594`）是**独立进程**，拿不到主程序运行时生成的 QSS，所以现在是 Windows 默认的白底样式。
- 深色：进程启动时读 `resources/theme/theme_dark.qss`（文件版；T03c 已保证文件版与内存版同源），`app.setStyleSheet()`；窗口图标用 `resources/brand/assets/app.ico`；标题「片语 Studio · 导出中」。**只用 QSS，不引入 `cutora.ui`（那会把 PyQt6 之外的东西带进保活进程）。** 进度条、文字、按钮跟主程序一个味道即可，不需要主题跟随（监视器永远罗马金）。
- 「关闭」按钮改成「停止导出」（`err` 色描边）：点击 → 二次确认（"已完成的文件保留，正在写的这个会作废"）→ 在 `export_state.json` 同目录写 `export_stop.flag` → 对 state 里记录的渲染子进程 PID 逐个 `terminate`（父进程在写 state 时要把 `child_pids` 写进去——这是 `cutora/render/parallel.py` / `run_export_worker` 的一处小改动，只加字段不改输出）→ 按钮变灰、文字「已请求停止…」。父进程恢复响应后检查到 flag，走现有 `stop_export()` 清理，并删掉 flag。右上角的 ✕ 保持"只关监视器不影响导出"的语义。
- 之前那句「主界面暂时无响应属正常，请勿强关 ⓘ」保留在 tooltip。
- 验收：导出 3 个视频中途点「停止导出」→ 子进程退出（任务管理器/`nvidia-smi` 无残留）→ 主程序恢复后状态栏显示「导出已停止」→ 已完成的文件在、未完成的没有半截文件；`golden --all --repeat 3` PASS（正常导出路径没变）。截图一张深色监视器。
