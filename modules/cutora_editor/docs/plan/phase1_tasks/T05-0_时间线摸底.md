## 3. overshoot 钳制 —— 先把期望表钉死（吸取 T06-2 的教训）

上一轮我写「十个 case 全部不变」而其中一个是故意要改的，害你白跑一轮。
这次**改动前**就把话说清楚：

### 3a. 【核心规则】钳制是「越界检查」，不是「目标尺寸」

和安全区 cap 那次**完全同一个坑**：

```
if 变换后 bbox 仍在 SAFE_MARGIN 内:   → 什么都不做，原样返回（逐字节等于改动前）
else:                                 → 才把 overshoot 缩到边距允许的幅度
```

**没越界的动画一个像素都不许动。**

### 3b. 期望表（改动前就定）

| case | 期望 | 依据 |
|---|---|---|
| g01–g09 | **不变** | 不含 overshoot 动画 |
| **g10** | **不变** | c1 `SDK READY.` 56pt 的 stomp 峰值墨迹 x∈[120, 959]，安全区 [86.4, 993.6]，**左右余量约 34 px，没越界** → 按 3a 的短路，它不该被碰 |

**十个全不变。** 如果 g10 变了，说明短路没写对，**停，报我，不要重录。**

### 3c. 静帧要给的
- `stomp` 1.70× 峰值帧：**长行**（会越界的那种，自己造一条）钳制前 / 后
- `impact_pop` 1.30× 同上
- 每张附变换后 bbox 与 `SAFE_MARGIN` 的数值对比
- 外加一条**不该被钳的**短行对照，证明它逐字节没动

### 3d. 锁
`_edge_clear` 的 11 点扫描扩展：断言**变换后的 bbox 始终落在 `SAFE_MARGIN` 内**
（现在只检查 ROI 四边 alpha=0，管不到画布越界）。
