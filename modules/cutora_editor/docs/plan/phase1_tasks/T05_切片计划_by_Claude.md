## 3. T05 摸底读完了 —— 两个结论 + 切片计划

摸底表质量很高，尤其是「HistoryManager 是整份 tasks 快照，不是操作日志」
和「交互一半没走命令总线」这两条，直接决定了 T05 该怎么排。

### 3a. 【架构裁定】不重写成 QGraphicsScene，继续自绘

理由：
1. **专业 NLE 的时间线普遍是自绘的**（Resolve / Premiere 都是）。
   QGraphicsScene 在上千 item 时的 per-item 开销**比自绘更差**，不是更好。
2. 现有 widget 已经承载了大量行为（26 种转场、跨轨拖放、波形绘制），
   重写等于把这些全部重做一遍，风险极高、收益不明。
3. 真正的性能瓶颈是「全轨全片段每帧重绘」，**这个在 `paintEvent` 里就能解决**：
   脏矩形重绘 + 视口裁剪（只画可见时间范围内的片段）。

**所以：扩展现有自绘，补脏矩形 + 视口裁剪。不重写。**

### 3b. 【顺序裁定】命令总线补齐必须排第一

摸底说得很清楚：trim / 多选框 / 跨轨拖放 / 开场 ripple **全是 Widget 直接改 Clip，
松手整表快照**，不走总线。

总体计划里写死了：「T04–T08、T11 的每个新功能都必须注册为命令」。
**如果先做 snap / marker / ripple，它们会长在一个不合规的地基上，将来全要返工。**
这正是 Luca 最不想看到的「窝工返工」。

**所以 T05a 先做补齐，一天的投入换掉后面所有切片的返工风险。**

### 3c. 切片计划

| **T05a** | **命令总线补齐**：trim / 多选移动 / 跨轨拖放 / 开场 ripple 全部包成命令，正确可撤销、可录进 recipe。**无新功能。** 同时补脏矩形重绘 + 视口裁剪 | **十个全不变** |

**全局硬约束：T05 整个里程碑，golden 十个 case 哈希一个都不许动。**
时间线是**编辑期**交互，改的是工程数据，不该影响导出渲染。
**任何一个 case 变了，说明改到了渲染路径，停。**
—— 这是 T05 天然的安全网，比 T04 那些还干净。

### 3d. T05a 的具体要求

1. 每个操作一个命令：`timeline.trim_clip` / `timeline.move_clips` /
   `timeline.move_clip_to_track` / `timeline.ripple_intro`
2. **参数是 JSON-可序列化的**（片段 id + 数值），不是对象引用 —— 否则录不进 recipe
3. `undoable=True`，且撤销粒度 = 一次鼠标操作（拖动中间态不入栈）
4. **撤销测试**：每个命令执行 → 撤销 → 工程 JSON **逐字节等于执行前**
5. 脏矩形 + 视口裁剪：**1000 片段的工程，滚动/缩放时每帧重绘耗时 < 16 ms**
