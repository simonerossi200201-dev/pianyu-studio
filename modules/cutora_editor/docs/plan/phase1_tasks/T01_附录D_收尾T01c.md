## 一、核心问题：文件删了，形状没删

`AutoSub_debug.py` 已经不存在，但它的 **god-object 形状**还活着：

1. **`_t01_host()` 还留在 10 个模块里**（engine、align_worker、frame_renderer、render_worker、text_utils、canvas、main_window、timeline/{widget,header,container}、panels/subtitle_style）。这个函数去 `sys.modules` 找 `AutoSub_debug`，找不到就 `raise RuntimeError("T01: AutoSub_debug is not in sys.modules")`。**现在它永远不可能成功。** `_t01_attr()` 先查 `main_window.__dict__` 所以常用路径能走通，但凡是没被挂到 main_window 上的名字，运行时就会抛这个莫名其妙的异常——而且是 golden 覆盖不到的路径（golden 只验渲染）。这是定时炸弹，不是"注释残留"。
2. **`cli.py::host_module()` 在运行时往 `cutora.ui.main_window` 上猴子补丁 ~25 个属性**，让 main_window 冒充原来的巨石。等于 god object 换了个宿主继续活着。T03 要在这上面重做 UI，绝不能带着它进门。
3. `app.py` 顶部仍把 `core/` 插进 `sys.path`，docstring 还写着"must be defined before the monolith is imported"——已经过时。

**T01c 的目标：让 `cutora/` 里不存在任何运行时对巨石的引用，模块之间只靠显式 import 说话。**

## 二、做法（一个模块一个提交，每个提交后 `golden --all`）

按依赖顺序，与切片 A 相同的自底向上：`text_utils` → `engine` / `align_worker` → `frame_renderer` / `render_worker` → `timeline/*` → `canvas` → `panels/subtitle_style` → `main_window`。每个模块：

- 把该模块用到的、目前经 `_t01_host()` / `_t01_attr()` 拿的每个名字，改成**显式 import 真实来源模块**。顶层 import 会循环的，就在函数体内延迟 import，并在报告里列出（附录 B 的老规矩）。
- 删掉该模块的 `_t01_host()` / `_t01_attr()` 定义。
- **不许改任何函数签名、信号连接、构造参数**——这仍是搬迁，不是重构（T03 才重构）。

最后删掉 `cli.py::host_module()` 的全部猴子补丁；它的调用方改成直接 import。`app.py` 去掉 `core/` 的 `sys.path` 插入与过时 docstring。

**收尾判据**：`grep -rn "_t01_host\|_t01_attr\|host_module" cutora/` 为零（`__pycache__` 除外）。

## 三、资源搬出 `core/`，然后删掉 `core/`

附录 C 警告过 `__file__` 相对路径（`spatial.py` 那次七个 golden 哈希全变）。所以**每搬一类资源就跑一次 `golden --all`**，路径一律改走 `cutora.core.paths`，不要再让任何模块自己算 dirname。

搬完 `rmdir core/`，`CUTORA.bat` / `cli.py::prepare_runtime()` / `.gitignore` 里所有 `core/` 引用一并清掉。
