## 0. 先纠一句：那 22 个失败不是脚注

> 「pytest：477 passed / 22 failed……不是快进引入的。」

## 1. 而且你的解释如果成立，它指向一个**真的产品 bug**

> 「失败全是隔离 Qt 子进程把 `[Config] Blackwell…` 打进 stdout。」

如果真是这样，那问题不在测试，在**有人在 import / 启动阶段往 stdout `print()`**。

这条日志我在 golden 日志里也见过：

```
[Config] Blackwell 架构 (sm_120)，float16 模式 → device=cuda, compute_type=float16
```

**往 stdout 打字的启动日志会污染所有把 stdout 当协议通道的场景：**

| 场景 | 后果 |
|---|---|
| `--isolate` 的 `ISOLATE_CHILD <json>` 行 | 现在靠"按前缀反向扫描"侥幸躲过。协议是脆的。 |
| CLI（`g07_cli`）被管道/重定向 | 输出被污染 |
| **MCP stdio 服务器**（`tests/test_mcp_stdio.py`） | **JSON-RPC 分帧直接被打断。这是硬故障。** |
| 任何 `subprocess.run(capture_output=True)` 解析 | 全中 |

所以这不是"讨厌的测试噪音"，是 **stdout 卫生缺陷**，有真实的产品后果。

**修源头，不要修测试。**
