## 提交 3：`fix(stitcher): normalise apostrophes and hyphens before matching`
来源：`docs/plan/04_竞品分析_VideoKit.md` §3.2，T12c 审核已记。

现象：文案里写 `dell'anima`（直撇号 U+0027），ASR 输出 `dell'anima`（弯撇号 U+2019），`script_stitcher.match_clip_global` 用 `difflib` 比对按空格切分的 token，这两个是不同的词，直接算未命中。连字符（`-` `‐` `‑` `‒` `–` `—` `―`）和不间断空格同理。

修法：**匹配前**对片段词表与文案 token **两边**统一做
1. `unicodedata.normalize("NFKC", s)`；
2. `[’‘`´ʼ]` → `'`；`[‐‑‒–—―]` → `-`；不间断空格 → 普通空格；
3. 其余逻辑一个字不改。

**关键红线**：这只用于**匹配比较**。写回字幕、工程、导出的文本必须保持用户原样——**Luca 的成片里撇号该是什么样还是什么样**。加一条测试专门断言这一点（归一化前后的原文本一字不差）。

测试：一条只在撇号形态上不同的文案与片段，改前不命中、改后命中。跑 `golden --all --repeat 3`，**g04 是真正走拼接的用例**；若它的文案里没有这些字符，输出必须逐字节不变，变了就停下报告。

**不做**：按语言分词、ICU、任何针对中日泰的处理。
