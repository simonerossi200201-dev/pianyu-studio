## 0. 先更正一条许可认知 —— 这条很重要，别按错的做

Luca 说「不需要署名」。**严格讲，世界上不存在零义务的字体许可。**
但他真正关心的那件事，今天**已经满足**：

| | OFL-1.1 / Apache-2.0 |
|---|---|
| **导出的视频里要署名吗** | **不要。** 这是 Luca 关心的那条，已经满足。 |
| 软件包里要带许可原文和版权声明吗 | **要。** `THIRD_PARTY_LICENSES.md` + `resources/licenses/` 正是干这个的。 |
| 可以商用吗 | 可以。 |
| 可以改字体文件吗 | OFL 可以（改了要换 Reserved Font Name）。 |

真正"零义务"的只有公有领域 / CC0 字体，而那个池子里**没有**能覆盖 24 种文字的
优质字体。所以：

**策略不变 —— 继续只用 OFL-1.1 / Apache-2.0，继续在包里带全文。**
这已经完全满足「不涉及版权、具有商业许可、视频里不用署名」。

### 0a. 来源限定：**只从 Google Fonts 取，不去任何"免费字体"聚合站**

这一条我要比 Luca 的授权**更严**，理由是版权风险：

- 聚合站（dafont / fontsquirrel 之流）大量字体来源不明，"free for commercial use"
  经常是上传者自己写的，**其中相当比例是盗版或改名的商业字体**。
  对一个要分发的软件，那是真实的法律风险。
- Google Fonts 的每一个字体都有**可验证的 upstream 仓库、明确的 OFL/Apache 授权、
  版权行和版本号**。现有 215 个字体就是这么来的。
- **Noto 系列（Google，OFL-1.1）覆盖 `languages.json` 里全部 24 种文字**，
  一个来源就能把事办完。

**任何非 Google Fonts 来源的字体，先报给我，不要自行加入。**

### 3b. 每个新字体必须走完整管线 —— 一个都不能少

1. 文件**提交进 git**。
   **这是硬规则** —— `85825f00ff17` 那次幽灵就是 197 个从未入库的字体文件消失。
2. `FONTS_MANIFEST.json` 加条目：`file / family / version / license /
   license_url / copyright / sha256 / has_license_file`
3. `resources/licenses/` 放许可全文
4. `THIRD_PARTY_LICENSES.md` 加行
5. **新增一份 `resources/fonts/PROVENANCE.json`**：每个字体记
   **下载 URL + upstream 仓库 + release tag/版本 + 下载日期 + sha256**。
   以后任何人要审我们的字体来源，一份文件说清楚。

### 3c. 【关键门禁】加字体必须是**渲染中性**的

新增字体只能是**新文件**，不得替换现有文件，**不得与现有字族重名**。因此：

> **golden 的所有哈希必须一个不动。**
> 只有 `fonts_digest.txt` 的 `count` 和 digest 更新。

**任何一个 golden 哈希变了 → 停，报我，不要重录。**
那说明某个新字体的族名撞了现有族名，正在劫持字体解析 —— 和 `85825` 同一类事故。

`fonts_digest.txt` 更新时，在 `RERECORD_NOTES.md` 记一笔：新的 count、新 digest、
新增了哪些字体、以及**"所有 golden 哈希未变"这个事实**。

## 4. 切片 L3 —— 产品行为：绝不静默回退，绝不出豆腐块

这是 Luca 那句「保证准确的显示绝不出错，保证所显示出来的字体都是软件内的」的落地。

### 4a. 自有回退链（替代系统回退）

新增 `resources/data/script_fallback.json`：`script → 我们自己的默认字族`。

渲染时：所选显示体覆盖不了当前文本的字符 → **用映射表里我们自己的字体补**，
**绝不让 Qt 走到系统字体**。

> Qt 默认会为缺字形静默回退到系统字体。必须在渲染前**主动检查覆盖**并替换，
> 光靠 `QFont::setFamilies()` 不够 —— Qt 仍可能把系统字体当最后手段。

### 4b. 三层告知，一层都不能省

1. **字体下拉**：当前工程语言的 script 不被某字体覆盖 → 该项灰掉或标注
   （如「不支持西里尔」）。不要让用户一脚踩空。
2. **面板提示**：所选字体渲染不了当前字幕文本 → 走 2.1 已有的提示通道，
   明说「Anton 缺少西里尔字母，已用 Noto Sans 代替」。
3. **导出前**：`export_guard` 加一条 —— 有字符在所选字体里找不到时告警，
   并说明将用哪个自有字体代替。

### 4c. 两条硬测试（这是"承诺"的机械化）

**测试一 · 零豆腐**
遍历 `languages.json` 全部 100 个语种，各取一段该语种样本文本，
用该 script 的默认字体渲染，**断言输出里 `.notdef` 字形数为 0**。

**测试二 · 绝不碰系统字体**
用 Anton（零西里尔）渲染一段俄语，断言：
- 结果与用映射表里那个自有西里尔字体渲染**一致**；
- 实际解析到的字族**在我们的白名单内**；
- 无 `.notdef`。

这两条以后加语种、删字体都会红。**这才叫承诺。**

## 5. 切片 L4 —— 诚实分级（排版那一半）

字体解决了「显示不出错」，**排版**是另一回事：

| script | 排版现状 |
|---|---|
| latin / cyrillic / greek | 已完善（空格断行、安全区、27 个动画都基于此） |
| arabic / hebrew | **RTL 双向排版未做** |
| devanagari / bengali / tamil…（印度系） | HarfBuzz 能整形，但我们的**逐字符动画会打断连字整形** |
| han / kana / hangul | **无空格断行未做** |

`languages.json` 每行加 `subtitle_tier`：

- `"complete"` —— 字体 + 排版都完善
- `"font_only"` —— **字形保证正确、绝不回退系统字体**，但复杂排版（双向/断行/
  逐字动画）尚未完善

UI 上明示第二档。这不是退缩 —— 这是把「承诺」说到能兑现的精度。

**另外必须做的一条**：对需要上下文整形的 script（阿拉伯系、印度系），
**逐字符/逐词动画必须自动禁用**（否则连字被拆开，显示就是错的）。
加一条测试锁住。
