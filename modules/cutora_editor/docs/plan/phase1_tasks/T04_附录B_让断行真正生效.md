# T04 附录 B — 让 T04b 的断行真正生效（Luca 反馈：用起来感觉不到变化）

> 与 `T04_附录_开工状态与切片.md` 一起看。下一片开工前先做这一条，单独一次提交。

## 0. 问题

Luca 真机用完 T04c 的原话：**「没感觉到字幕有多大的功能更新」**。这个感受是准确的，原因在设计里：

golden 规则 B 要求"新功能关闭时逐字节一致"，于是 `break_lines()` 算出来的 `segment.lines` **只有在用户显式调用 `subtitle.relayout` 时才会写进工程**。他的工程里没有 `lines`，渲染器就走旧的自动换行——**所以他看到的画面和 T04b 之前一模一样**。

也就是说：**我们写了一套断行规则，但它默认不跑。** 这不是规则 B 的错，是我们只做了一半——规则 B 保的是"旧工程不变"，不是"新工程也不许用新功能"。

## 1. 改法：自动字幕跑完之后自动断行

- `subtitle.auto` 成功返回、写回 segments 之后，**自动对新产生的这批 segments 调一次 `break_lines()` 并写入 `lines`**。
- 只对**本次识别新产生的** segments 生效；已经存在的、以及 `locked=True` 的句子不动。
- 加设置项 `subtitle.auto_relayout`（默认**开**），位置在 设置 → 字幕；关掉就退回旧行为。
- 导入 SRT/VTT/ASS（`subtitle.import_file`）时**不自动断行**——那些文件里的换行是作者的意图，不要覆盖。只在"我们自己生成字幕"时才断行。

## 2. 为什么这样不会破坏 golden
golden 的七个 case 都是**已冻结 ASR 的旧工程**，跑对拍时不会重新识别，因此不会产生新的 segments，也就不会写 `lines`，渲染路径与现在完全一致。**`golden --all --repeat 3` 必须仍然逐字节 PASS**——如果变了，说明改动波及了旧路径，停下报告。

## 3. 还要让用户看得见这件事发生了
- 自动字幕完成的提示里加一句「已按排版规则断行」，或在字幕文本面板顶部给一个可关闭的一行提示。
- `字幕` 菜单里加 **`重新断行`**（对全部或选中句），这样用户改完文字之后能手动再排一次；对应命令 `subtitle.relayout` 已存在，只是没有菜单入口。
- 字幕文本面板的卡片上，鼠标悬停时用浅色显示这句将被断成几行、每行多少字（不常驻，避免噪音）。

## 4. 验收
- [ ] 新导入一条素材跑自动字幕 → 工程里这批 segments 都有 `lines`，且断行位置符合 `docs/linebreak.md` 的优先级
- [ ] 同一工程里已有的旧句子、以及 `locked` 的句子**没有**被写入 `lines`
- [ ] 导入 SRT 不产生 `lines`
