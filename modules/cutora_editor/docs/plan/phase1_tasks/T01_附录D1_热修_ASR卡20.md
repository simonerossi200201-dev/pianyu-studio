# T01 附录 D-1 — 热修：自动字幕卡在 20%（T01c 的第 0 步）

> 与附录 D 一起贴。**先做本附录，单独提交，再开始附录 D §二。**

## 现象
Luca 在真桌面上跑自动字幕，进度条到 20% 停住，没有任何报错弹窗。

## 根因（Claude 已在代码里定位，不用再猜）
`cutora/asr/align_worker.py`：
```
372:    self.progress.emit(20)
373:    os.environ["HF_HOME"] = resource_path("models")     # ← 这里
```
第 373 行的 `resource_path` 是本文件第 102 行的**本地垫片**：`return _t01_host().resource_path(*a, **k)`。`_t01_host()` 去 `sys.modules` 找 `AutoSub_debug`，找不到就 `raise RuntimeError`——巨石已删，所以它**每次必抛**。异常被第 421 行 `except Exception as e: self.error.emit(str(e))` 吃掉；主窗口没有把这个 `error` 信号接到任何提示上，于是界面就停在 20%，什么都不说。

`cutora/asr/engine.py` 更糟：第 65、101 行也调用 `resource_path(...)`，但这个文件里**既没有定义也没有 import** 它——真走到那里是 `NameError`。

这就是附录 D §一 说的定时炸弹，第一颗已经炸了。golden 抓不到它，因为 golden 的 ASR 是冻结的。

## 修法（两个文件，不改任何逻辑）
1. `align_worker.py`：删掉本地的 `_t01_host()` 与 `resource_path()` 垫片，改为 `from cutora.core.paths import resource_path`。
2. `engine.py`：删掉 `_t01_host()`，加 `from cutora.core.paths import resource_path`。
3. `cutora.core.paths.resource_path` 以 `CORE_DIR` 为基，所以 `resource_path("models")` 仍是 `core/models`——里面只有 `model_paths.json`，它指向 `runtime/models` 的绝对路径。这与 B2 之前的行为一致（T00 报告"AlignmentWorker 仍把 HF_HOME 指到 core/models"），**本热修不改这个**；附录 D §三 搬资源时再统一到 `paths.MODELS`。
4. 查一下巨石里 `AlignmentWorker.error` 原来有没有接到提示（`git show T01b1-done:core/AutoSub_debug.py | grep -n "error.connect"`）。**原来有、拆包时丢了 → 恢复；原来就没有 → 不加，写进报告建议栏留给 T03。**
