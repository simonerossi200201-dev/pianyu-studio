# T04L 语种 × 字体覆盖审计

**发出** Claude · 2026-09-14
**起因** Luca 问：换成葡语/西语/法语/俄语，字体和字母都能正常显示吗？
**我的结论** **拉丁语系没问题；俄语（西里尔）有真问题；另有 44 个语种基本没有字体支持。**

---

## 1. 我实测了什么

抽取 **18 个**代表性字体（默认字体、风格包主力、最常见的显示体、手写体、
花体），用 `fontTools` 读 `cmap`，逐字检查各语种必需字符。**这是抽样，不是全量。**

### 结果

| 字符集 | 18 个字体里通过的 |
|---|---|
| 基础拉丁 `ABCabc0123.,!?` | **18 / 18** ✅ |
| **葡语** `ãõáéíóúâêôàçÃÕ…`（24 字） | **18 / 18** ✅ |
| **西语** `ñáéíóúü¿¡ÑÁ…`（16 字） | **18 / 18** ✅ |
| **法语** `àâäçéèêëîïôùûüÿ«»…`（32 字） | **18 / 18** ✅ |
| **法语连字** `œŒæÆ` | **18 / 18** ✅ |
| 德语 `äöüßÄÖÜ` | 18 / 18 ✅ |
| 波兰语 `ąćęłńóśźż…` | 17 / 18 ⚠️ |
| 土耳其语 `çğıöşüÇĞİÖŞÜ` | 16 / 18 ⚠️ |
| **俄语（西里尔，66 字）** | **8 / 18** ❌ |

### 俄语这条，点名

**有西里尔（8）**：Arimo、Caveat、Fira Sans、Lobster、Open Sans、Oswald、Roboto、SN Pro

**零西里尔（10）**：**Anton**、Archivo Black、Bangers、**Bebas Neue**、
Dancing Script、Permanent Marker、Poetsen One、Rowdies、Shrikhand、Titan One

`0/66` —— 一个西里尔字母都没有。

**Anton 和 Bebas Neue 恰恰是做字幕最常被选的两个显示体。**

### 两个拉丁小缺口

- **Permanent Marker**：波兰语 3/17、土耳其语 7/12
- **Titan One**：土耳其语 11/12

---

## 2. 这意味着什么（产品行为）

用户选俄语转写 → 字幕是西里尔 → 选了 Anton → 该字体没有这些字形，于是：

1. Qt **静默回退到系统字体**（画面上字体突然变了，风格预设失效），或
2. 渲染成 **豆腐块 `□□□`**

**两种都很糟，而第 1 种还额外是个许可问题** ——
回退到的系统字体**不在**我们的白名单，也不在 `THIRD_PARTY_LICENSES.md` 里。
对一个要分发的软件，成片里出现未登记来源的字体是不可接受的。

这和 `85825f00ff17` 是同一个病：**静默回退**。我们已经为字体**名称**找不到的情况
加了大声报错，但**字形**找不到的情况还没有任何防护。

## 3. 更大的缺口：44 个语种压根没有字体

`resources/data/languages.json` 声明 **100 个语种 / 24 种文字**：

```
latin 56 | cyrillic 11 | arabic 5 | devanagari 4 | bengali 2 | hebrew 2 | han 2
ethiopic/tibetan/greek/gujarati/armenian/kana/georgian/khmer/kannada/hangul/
lao/malayalam/myanmar/gurmukhi/sinhala/tamil/telugu/thai 各 1
```

**215 个内置字体全部是拉丁向的**（少数带西里尔/希腊）。
阿拉伯语、印地语、日语、韩语、泰语……**一个能渲染的字体都没有。**

ASR 能听懂 100 种语言，字幕只能显示其中约 56 种 + 部分西里尔。
`languages.py` 里已经有 `EXPERIMENTAL_HINT = "能识别，排版质量不承诺。"` ——
说明断行这一层已经想到了，但**字体这一层还没有**。

## 4. 要做的

### 4a. 全量覆盖矩阵（先做，只出数据）

对 **全部 215 个字体** × **各 script 的必需字符集**跑一次 `cmap` 覆盖扫描，产出
`resources/data/font_script_coverage.json`：

```
{ "<字体族>": { "latin_basic": true, "latin_ext": true, "cyrillic": false, "greek": false, ... } }
```

字符集定义要写进仓库（不能散在脚本里），每个 script 至少覆盖该 script 下
所有已声明语种的必需字符。**我要这份数据，然后定策略。**

同时报三张小表：
1. 有西里尔的字体有几个、是哪些
2. 有希腊字母的有几个
3. 连**拉丁**都不全的有哪些（目前已知 Permanent Marker、Titan One）

### 4b. 产品行为：字形缺失必须大声

**绝不许静默回退。** 至少三层：

1. **字体下拉**：当前工程语言的 script 不被某字体覆盖时，
   该项**灰掉或标记**（"不支持俄语"），不要让用户一脚踩空。
2. **面板提示**：选中的字体渲染不了当前字幕文本时，
   走 2.1 那条已有的提示通道，明确说"XX 字体缺少西里尔字母"。
3. **导出前拦截**：`export_guard` 加一条 —— 有字幕文本的字符在所选字体里
   找不到时，导出前告警（不一定阻断，但必须让用户知道）。

### 4c. 策略决定（这条要 Luca 拍板，先给他选项）

- **方案 A**：补进几个覆盖西里尔+希腊的 OFL 字体（Noto Sans / Noto Serif 全欧版），
  作为这些语种的默认；显示体缺字形时提示用户换字体。
- **方案 B**：把 `languages.json` 分级 —— "字幕完整支持"（拉丁 + 有覆盖的西里尔）
  vs "仅识别，字幕不承诺"。UI 上明示。
- **方案 C**：A + B。

**我推荐 C。** 但 A 会增加包体积和许可条目，B 是零成本的诚实声明。

### 4d. 锁

加一条测试：`languages.json` 里每个标为"字幕完整支持"的语种，
**至少有一个内置字体完整覆盖它的 script**。以后加语种或删字体时会红。
