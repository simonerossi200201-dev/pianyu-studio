## 0. 先说清楚这一轮为什么返工

T03c §六之二 写的是"时间线画布高度 = 轨道实际总高，不要向下无限延伸出空洞"。这句话**表述不严谨，责任在任务书**：它的本意是"轨道下面不要出现一片死黑"，而不是"把画布钉死在内容高度"。9efa8f5 按字面做成了 `setMaximumHeight(hug)`，结果是：Dock 可以被拉高，但画布不跟着长，多出来的部分是一个纯黑的占位控件——**黑洞不但没消失，反而变成了拉得越高洞越大**。

正确目标只有一句：**时间线画布永远填满 Dock；轨道不够高时，剩余部分画 `bg1` 并可点击取消选择；轨道超出时纵向滚动。** 横向滚动条与「总时长」固定贴在 Dock 最底部（Premiere / Resolve 都是这样，不需要"紧贴最后一条轨道"——那条要求作废）。

下面三条根因我已经在仓库里逐行确认过，按行号改。

## A. 时间线：三处根因，全部修掉

### A1. `cutora/ui/timeline/container.py:129–131` —— 画布被钉死在内容高度
```python
content_h = self.timeline.get_content_height()
hug = max(int(content_h), self.timeline.RULER_H + 48)
self.timeline.setMaximumHeight(hug)          # ← 删除这三行里的 hug/setMaximumHeight
```
改法：
- 删除 `hug` 与 `setMaximumHeight`。`TimelineWidget` 的 size policy 设为 `(Expanding, Expanding)`；`widget.py:88` 的 `setMinimumHeight(80)` 保留。
- 删除 `container.py:59` 的 `self._filler`（`addWidget(self._filler, 1)`）及其 `_on_filler_press`——它的职责（点空白取消选择）画布本身已经有了（`widget.py:1197` 起 `y > content_h` 的分支）。删掉之后 `row`（轨头 + 画布 + 纵向滚动条）是唯一的 stretch=1 项，横向滚动条那一行 stretch=0 固定在底部。
- `widget.py:1076–1080` 已经把 `content_h` 以下画成 `bg1`——保留，这就是"没有黑洞"的实现。
- 纵向滚动范围沿用 `available_h = height − RULER_H − TOP_PAD − BOTTOM_PAD`，现在 `height()` 会随 Dock 变化，`resizeEvent` 里要调一次 `update_scroll_range()`（现在只在缩放/内容变化时调）。
- 标尺（`_draw_ruler`）固定在画布顶部，不随纵向滚动；轨头 `TrackHeaderPanel` 的纵向偏移与画布同步（已有 `set_scroll_y`，只需确认拉高后仍对齐）。

### A2. `cutora/ui/main_window.py:2480–2485` —— 快速模式把 Dock 钉在 96px
```python
if quick:
    self.dock_timeline.setMaximumHeight(96)     # ← 这就是"快速模式拉不开"的原因
else:
    self.dock_timeline.setMaximumHeight(16777215)
    self.timeline_container.setMinimumHeight(120)
```
改法：
- 两种模式都**不设上限**。快速模式只是"默认更矮"，不是"不许拉高"。
- 用 `self.resizeDocks([self.dock_timeline], [h], Qt.Orientation.Vertical)` 给默认高度：快速 140、专业 240。**只在用户没有手动拖过时才应用默认值**——记一个 `self._timeline_h_user_set: bool`，在 Dock 的 `resizeEvent`（用户拖动）里置 True；切模式时若已置 True 就不动它。
- 高度持久化：写进 `app_settings["layout"]["timeline_h"]`（与 §五 右侧面板宽度用同一个 `layout` 字典），启动时恢复。T06 的布局持久化以后会接管这个字典，字段名先定下来：`layout.timeline_h` / `layout.inspector_w` / `layout.bin_w`。
- `timeline_container.setMinimumHeight(80)`（1983 行）保留作为下限。

### A3. Dock 边缘只有中间小点能拖
现状：`_DockEdgeHandle`（1583 行）是 `setTitleBarWidget` 装上去的**标题栏**，它负责的是"拖出去浮动"，不负责改高度；真正改高度的是 `QMainWindow::separator`。QSS 里 separator 已是 6px，但颜色 `{{ line }}` 与周围几乎同色，用户看不见、也就只找到了那三个点。
改法：
- `QMainWindow::separator` 改 **8px**，常态就用 `{{ line }}` 且比 `bg0` 明显（如果 `line` 太暗就在 token 里给 separator 单独一个值 `sep = line 提亮 12%`，写进 `tokens.py` + `build_qss.py`，不要在 QSS 里写死 hex）；hover 变 `{{ accent }}`。
- `_DockEdgeHandle` 高度降到 **4px**，三个点保留在正中作为"可浮动"提示；它**不需要**承担 resize。
- 新增离屏测试 `tests/test_dock_resize.py`：起 MainWindow（offscreen）→ `show_editor()` → 分别在专业/快速模式下，找到中央区底边与 `dock_timeline` 顶边之间的 separator 矩形，在 **x = 10% / 50% / 90%** 三个位置用 `QTest.mousePress / mouseMove(−120px) / mouseRelease` 拖动，断言 `dock_timeline.height()` 增加 ≥ 100 **且** `timeline_container.timeline.height()` 同步增加 ≥ 100（这一条同时锁死 A1）。左右两个 Dock 也各测一次（横向 −120px / +120px）。**这个测试先写、先红，改完变绿。**

### A4. 标尺右端 / 「总时长」重叠
截图里标尺最右端的结束标记与右下角「总时长 03:47.21」挤在一起。改法：`total_label` 设 `setMinimumWidth(fontMetrics.horizontalAdvance("总时长 00:00:00.00") + 16)`、左侧 8px 内边距；横向滚动条的 `setRange` 已含 `+500` 余量，确认 `_draw_ruler` 的结束标记不再画到画布可见区之外（标记 x 超过 `width() + scroll_x − 8` 时不画文字，只画刻度线）。

## B. 顶部布局重排（去掉按钮之后要把空间还给编辑区）

现状（已核对）：
- `pro_toolbar`（1778–1782）里现在只剩一个 spacer + `btn_export_settings` + `btn_batch_export`（1829–1831）——**整整一行工具栏，只放了两个右对齐的按钮**，而这两个功能 `导出` 菜单里已经有了（`act_bexp` 2277、`导出设置` 2281）。
- `quick_toolbar`（2382）前面 `addToolBarBreak()`（2385），所以它永远占第二行。
- `progress_toolbar`（2399–2403）是第三行，而且**空闲时也显示**（截图里一直挂着"正在识别… 100%"）。
- 结果：菜单栏 + 三行工具栏，编辑区被压掉约 110px，这正是 Luca 说的"按钮去掉了但没有重新设计空间"。

改法：
1. **删除 `pro_toolbar` 整行**及 `btn_export_settings` / `btn_batch_export` 两个控件。`toggle_batch_export` 在 5087 / 7798–7802 行会改按钮文字（"停止批量导出" / "导出全部" / "导出选中项 (n)"）——把这些 `setText` 改到 `act_bexp.setText(...)` 上，菜单项文字同样动态变化；2725 行的按钮列表相应去掉 `btn_batch_export`。`_set_ui_mode` 里 2467–2468 / 2518–2519 对 `pro_toolbar` 的引用一并删除。
2. **`quick_toolbar` 去掉 `addToolBarBreak()`**，它成为菜单栏下方唯一的一行工具栏；专业模式下这一行隐藏（现状就是快速模式专属，保持）。专业模式 = 菜单栏 + 编辑区，中间没有任何工具栏行。
3. **`progress_toolbar` 删除**，`prog_frame` 改挂到 **状态栏左侧**（`statusBar().addWidget(self.prog_frame, 1)`），高度不超过状态栏：进度条 6px + 文字同一行。行为：
   - 任务开始（`set_progress_mode` / `update_progress_value(0)`）→ `prog_frame.show()`；
   - 到 100% → 文字改"完成"，**1.5 s 后 `hide()`**（`QTimer.singleShot`）；
   - 出错 → 文字变 `err` 色留在状态栏，用户点一下或下一次任务开始时隐藏；
   - 应用启动 / 切模式 / 回欢迎页时 → 隐藏。2469–2470 与 2520–2521 两处对 `progress_toolbar` 的显隐逻辑改到 `prog_frame` 上。
   - 快速模式 §三 要求的"自动字幕要有进度条"仍然满足——同一个 `prog_frame`，状态栏在两种模式下都可见。
4. 状态栏原有的 `_status_gpu / _status_task / _status_save` 靠右保留。
5. **验收截图**：快速、专业各一张，与 T03c 上一轮同尺寸（1600×900 offscreen），要能看出菜单栏下方只剩 0 行（专业）或 1 行（快速）工具栏。
