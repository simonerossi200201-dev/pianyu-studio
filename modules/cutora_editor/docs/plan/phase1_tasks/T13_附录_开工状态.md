## D1. 一个注册表，两种执行环境

- `CommandSpec` 加两个字段：`headless: bool`（能在无 GUI 的 CLI 进程里跑）与 `async_job: bool`（耗时长，执行即返回 `job_id`）。
- 现有 15 个 CLI 动作**原样包成命令**：命名空间 `batch.*`（如 `batch.stitch`、`batch.queue_run`、`batch.auto_subtitle`），`headless=True`，`run` 直接调用 `cli.py` 里现有的函数，参数 schema 由现有 `--describe` 的小 schema **机械翻译**成 JSON Schema（`path`→`string`，`path|list`→`oneOf`，`int|null`→`["integer","null"]`），写个 `tools/describe_to_jsonschema.py` 做这件事，别手抄。
- `Context.window` 为 `None` 时，`headless=False` 的命令抛 `NeedsGui`，API/CLI 返回 400 与清晰中文提示。

## D2. 命令体不弹窗——把 `MainWindow` 的入口方法切成两半

规则：**命令体里不得出现 `QFileDialog` / `QMessageBox` / `QInputDialog` / `exec()`**。现有 `import_media()`（弹文件框 → `on_drop(paths)`）这类方法拆成：
- `import_media()`：只负责弹框拿到 `paths`，然后 `self.bus.execute("media.import", {"paths": paths}, source="ui")`；
- 命令体 `_cmd_media_import(ctx, params)`：调 `on_drop(paths)` 并返回 `{media_ids: [...]}`。

§1.1 列出的每个命令都照此拆；报告里给一张表：命令 → 原方法 → 拆出来的命令体。`tests/test_commands_no_dialog.py`：用 AST 扫描所有注册的 `run` 函数体，出现上述四个名字即失败。

## D3. 线程模型（这是最容易出崩溃的地方）

- aiohttp 服务器跑在自己的线程；**所有命令执行必须回到 Qt 主线程**：`CommandBus` 是 `QObject`，API 线程通过 `QMetaObject.invokeMethod(bus, "execute_blocking", Qt.ConnectionType.BlockingQueuedConnection, ...)` 提交，超时 30 s 返回 504。
- `async_job=True` 的命令（`subtitle.auto`、`export.run`、`export.batch`、`batch.*` 里耗时的）：主线程只负责启动 worker 并登记到 `USER_DATA/jobs/<id>.json`，立即返回 `{job_id}`；进度由现有 `progress` 信号写进作业文件并推到 SSE。
- 无头 CLI 进程里没有 Qt 事件循环：`headless=True` 的命令直接同步跑（现状），不走 invokeMethod。
- 测试 `tests/test_api_thread_safety.py`：offscreen 起主窗口 + API，另一线程连发 200 次 `app.version` 与 20 次 `timeline.set_playhead`，进程不崩、结果正确。

## D4. MCP：不引入 `mcp` SDK，手写 stdio 服务器

理由：pypi 的 `mcp` 会拖进 `starlette / uvicorn / pydantic / sse-starlette / httpx-sse` 等十余个包——正是任务书 §3 说的"不要全家桶"，也扩大了 pip_audit 面。stdio 版 MCP 就是 JSON-RPC 2.0 over stdin/stdout，需要实现的只有：`initialize`（协议版本用 `2025-06-18`，能力声明 `tools` + `resources`）、`notifications/initialized`、`ping`、`tools/list`、`tools/call`、`resources/list`、`resources/read`。预计 300–400 行，放 `cutora/api/mcp_server.py`，**零新依赖**。
- 校验方式：官方 `mcp` SDK 只作为**开发依赖**放 `requirements-dev.lock`（`CUTORA_Install.bat` 不装它），`tests/test_mcp_stdio.py` 用它的客户端跑 initialize → tools/list → tools/call(`app_version`)。
- 如果手写过程中发现协议细节吃不准，**停下写进报告**，不要偷偷把 SDK 加进正式锁文件。

## D6. API 安全（在任务书 §3 之上再加三条）

1. 只绑 `127.0.0.1`（不是 `localhost`，避免解析到 `::1` 之外的东西）；`tests/test_api_server.py` 里断言 `0.0.0.0` / 本机局域网 IP 连不上。
2. **校验 `Host` 头**只能是 `127.0.0.1:<port>` / `localhost:<port>`，否则 421——防 DNS rebinding；**带 `Origin` 头的请求一律 403**——浏览器页面不得调用本地 API；不发任何 CORS 头。
3. `tools/security_scan.ps1` 加规则：业务代码里出现 `0.0.0.0` 或 `bind(("",` 即命中。
默认关闭；`设置 → 代理接口` 打开；关闭时端口不监听（测试断言）。
