## 1. T06-1 · 文本预设 + 批量自动署名（P1-B，从 beta4 砍下来的）

规格见 `OPS-01_内测冲刺_打包脚本与预设编辑.md` 第 4 节，这里只补三条当时没写死的：

### 1a. 相对定位的精确定义（必须写死，否则横竖版对不上）
```
anchor: 九宫格之一（top_left … bottom_right）
margin_x / margin_y: 相对**画布短边**的比例，不是各自的宽高
```
**用短边**，这样 1080×1920 和 1920×1080 上署名离边缘的**物理距离感**一致 ——
用各自宽高的话，竖版的左右边距会比横版窄一半，看起来就不是同一个设计。
字号同理：`size_pct` 相对短边。

### 1b. 和「文本层」的关系要讲清
文本预设 = 一个**可复用的文本层模板**。应用 = 新建一个文本层并套用模板。
不是"修改现有文本层"。所以：
- 应用两次 = 两个文本层（但自动署名那条路径要按预设 id 幂等，见 4b）
- 预设里存的是模板，改预设**不会**回溯改已经应用出去的层（和风格包一致）

### 1c. 自动署名的幂等键
`element.source_preset_id == preset.id` 作为唯一键。批量重复跑不叠加。
**测试**：同一工程连跑 3 次自动署名，断言署名元素恰好 1 个，且属性与单跑一致。

## 2. T06-2 · max_lines=2 末行堆叠（T04h）

### 2a. 现在的毛病
`effective_max_lines == 2` 有一条例外分支（`T04f-6a_g09_ruling` 里记的）。
去掉它会进入**非收敛循环**：字都堆到末行 → 只缩不重排 → 一路缩到 53%（行高 40→22）。

### 2b. 要的行为
**超出行数上限时，先在词边界重新分行，再考虑缩放。** 顺序不能反。
- 重新分行用现有 `break_lines` 的词边界逻辑，不要新写一套
- 只有**重新分行之后仍然超行**，才允许缩放，且缩放有下限（比如 ≤ 15%），
  到底了就截断 + 省略号，而不是无限缩
- 循环必须**可证明收敛**：每一轮要么行数减少要么字号减少，且有硬迭代上限

### 2c. 【重要】这会改 g09 的基线
换行逻辑变了 → `g09_linebreak_latin` 的哈希**必然**变。这是**故意的基线变更**，
走完整重录程序，不是"顺手重录"：

1. 先给我**修复前 / 修复后的 g09 静帧对照**（六段各一张）+ 每段的行数、字号、
   行宽、是否触边。我要看到"末行不再堆叠、字号不再暴缩"。
2. 我签字后才重录，`RERECORD_NOTES.md` 写清原因和新旧哈希。
3. **其余九个 case 的哈希必须一个不动。** 动了说明改到了不该改的地方，停。

### 2d. 锁
- 给定一段必然超两行的文本 + `max_lines=2`，断言：行数 == 2、**末行词数与首行词数
  差值 ≤ 某个阈值**（不允许"首行两个词、末行十个词"）、字号 ≥ 原始字号 × 0.85
- 迭代次数有上限的断言（防止将来有人再引入非收敛循环）
