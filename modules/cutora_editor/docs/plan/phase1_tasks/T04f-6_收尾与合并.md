### 1.3 v1 宽度回退的 `max_lines == 2` 例外

`frame_renderer.py` 里那条 `effective_max_lines(s) != 2` 的例外，当初是为了不碰冻结的 g09 才留的。现在 g09 的行为已经充分理解，去掉这个例外，让 `max_lines == 2` 也享受宽度保护。

**这会改变 g09 吗？** 先只改代码、跑 `golden --case g09`，把结果报我：
- 不变 → 直接过。
- 变了 → **停下**，附前后对比图。这是"新输出可能反而更正确"的典型情形，由我看着像素决定是修代码还是重录 g09。

**裁决（已执行，见 `T04f-6a_g09_ruling_by_Claude.md`）：** 哈希变了（got 曾为 `3b1481511150` / `30e2f5621522`，exp `4fbf421f08b6`）。**不重录 g09。** 新输出把 t=11500ms 缩到 53%（行高 40/42 → 22/22，左边距 92 → 11）却仍然顶在 x=1079；t=1000ms 反而略变大。根因是末行堆积 + 宽度回退只缩字号，不收敛。例外已恢复，注释写了这张表与根因。真正的 bug 立成 **T04h**，放在 T04f 合并之后。6b 录 g08/g10 时**不要再动这条例外**。
