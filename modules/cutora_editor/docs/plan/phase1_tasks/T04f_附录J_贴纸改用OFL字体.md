# T04f 附录 J — 贴纸素材源改为 OFL 授权的彩色 emoji 字体

> **为什么改**：Twemoji 是 CC-BY 4.0，署名义务跟着**成片**走——Luca 每导出一条带贴纸的视频，都要在简介里挂一句署名。Luca 决定不要这个义务。
> **改成什么**：**SIL OFL 1.1 授权的彩色 emoji 字体**（首选 Noto Color Emoji）。OFL 明确不限制"用该字体制作的文档"，所以渲染进视频的成品**不带任何署名义务**。
> **注意区分**：分发**字体文件本身**仍需随附 OFL 版权声明与许可证——这和仓库里已有的 412 个内嵌字体是同一套机制，走现成流程即可。**成片**无义务，**字体文件**有义务，两者不要混。

## 0. 先验可行性，不通过就停下报我

**这是这一片唯一的技术风险，必须最先排除，在动任何现有代码之前。**

Noto Color Emoji 有两种构建：
- **CBDT/CBLC 位图版**（传统，字形 136×128 px 位图，文件约 10 MB）
- **COLRv1 矢量版**（较新，矢量，文件约 1.5–2 MB）

Qt 对彩色字体的支持在不同平台/版本上并不一致。所以第一步只做一件事：

1. 写一个最小脚本：加载字体 → 用 `QPainter` 把若干 emoji（含多色的，如 🎉 🔥 ❤️ 👍 🌈）渲染到 QImage → 存 PNG。
2. **在 128 / 256 / 512 三个尺寸各出一张**，发我看。
3. 判据：
   - **必须是彩色**。渲染成方框、豆腐块或单色 → 这条路在当前 Qt 上走不通，**停下报我**，我们再选方案。
   - **512 px 那张不能糊**。COLRv1 矢量版应当锐利；CBDT 位图版放大到 512 会软——如果只有位图版能渲染，把 512 那张的实际观感报给我，由我判断是否可接受、或是否把贴纸的最大尺寸做限制。
4. 两种构建都试，报告哪一种能用、哪一种更清晰。**优先选能正常渲染的矢量版。**

**这一步通过之前，不要删任何 Twemoji 文件、不要改贴纸的任何现有代码。**

## 1. 素材与授权

- 字体文件放 `resources/fonts/`（和现有 412 个内嵌字体同一处，走同一套加载与授权流程），**不要**放回 `resources/stickers/svg/`。
- OFL 全文原样复制进 `resources/licenses/`，`THIRD_PARTY_LICENSES.md` 的 **Fonts** 一节加条目：名称、来源仓库、**具体 release tag 或 commit**、SIL OFL 1.1。**以你实际下载到的那份 LICENSE 文件为准，不要凭记忆写。**
- **只取字体**。`googlefonts/noto-emoji` 仓库里的 SVG/PNG 图像资产历史上是 Apache-2.0，与字体的 OFL 不是一回事——**不要用那些图像**，否则又回到"成片要不要署名"的老问题上。
- 完全离线，运行时零网络请求。

## 2. 删除 Twemoji

可行性验证通过、新管线跑通之后：

- 删 `resources/stickers/svg/`（220 个 SVG）、`LICENSE-twemoji.txt`、`LICENSE-twemoji-MIT.txt`。
- 删 `THIRD_PARTY_LICENSES.md` 的 **Stickers (Twemoji)** 一节。
- `resources/licenses/` 里 Twemoji 相关条目一并清理，索引表同步。
- **不要保留"以防万一"的副本。** 留着未用的 CC-BY 素材在分发包里，等于把刚甩掉的义务又背回来。

## 3. 渲染管线

- `sticker_id` **保持 Unicode codepoint 不变**——这样 T04f-5 期间建的工程还能对上（贴纸是新功能，实际受影响的工程几乎没有，但保持标识稳定总是对的）。
- 渲染：按当前显示尺寸用字体栅格化成 QImage，缓存键 = `sticker_id` + 整数像素尺寸（沿用现有缓存结构，不要新建一层）。
- 其余一律不动：贴纸仍然是图片元素，走 `draw_image_element` 的 `kind == "image"`，位置/缩放/旋转/不透明度/混合模式/四方向渐隐全部照旧继承。
- **确定性**：同一 `sticker_id` + 同一尺寸，两次渲染必须逐字节相同（字体栅格化本身是确定的，但要确认没有引入随机或时间相关的东西）。

## 4. 目录（catalog）

- 现有 `catalog.json` 的搜索关键字可以留用，但要**扩到字体实际支持的范围**——换成字体之后没有理由再限制在 220 个，全部可用 emoji 都可以出现在面板里。
- emoji 的名称/关键字若来自 Unicode CLDR，在 `THIRD_PARTY_LICENSES.md` 里记一条（Unicode License，宽松），注明来源与版本。
- 面板加分类与搜索，数量变大之后这两样更重要。

## 5. 不做

- 不做导出时的署名提示（换成 OFL 之后不需要了）。
- 不动渲染逻辑、不动 golden、不加新依赖（字体栅格化用 Qt 自带能力）。
- 不做 CJK/RTL。

## 6. 验收

1. **§0 的三张尺寸样图**（128 / 256 / 512），我看过并确认之后才继续往下做。
2. Twemoji 痕迹归零：全仓库 grep `twemoji`（不区分大小写）只应命中历史报告文档，`resources/`、`cutora/`、`THIRD_PARTY_LICENSES.md` 里一处不剩。
3. 授权：OFL 全文在位、Fonts 一节有条目并写明 tag/commit、`resources/licenses/` 索引同步、`security_scan HITS_CODE=0`。
4. 面板：能搜索、能分类、能插入；插入后缩放/旋转/不透明度/四方向渐隐全部正常。
5. 同一 emoji 同一尺寸两次渲染逐字节相同。
6. **规则 A**：`golden --all --repeat 3` PASS 带指纹头 `source_dirty=no`；所有现有像素锁不变。
7. bench 三遍 `dropped=0`；插 10 个贴纸播放 p50 增量 ≤ 1 ms。
8. pytest 0 failed；无新增依赖。
9. 静帧：面板一张、画面上多个不同 emoji 一张（含开了渐隐的）。

## 7. 一句话

这一片换掉的不是画质，是义务。换完之后 Luca 导出的每一条视频都不再欠任何人一句话——这比贴纸本身好不好看重要得多。
