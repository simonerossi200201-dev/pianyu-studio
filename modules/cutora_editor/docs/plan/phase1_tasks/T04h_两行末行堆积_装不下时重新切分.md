## 0. 为什么单独立这一片

T04f-6a 试过去掉 `frame_renderer._fit_v1_overwide_lines` 里 `effective_max_lines(s) != 2` 的例外，指望宽度回退把 g09 那条溢出的第二行缩进安全宽。**量过像素之后否掉了，不重录 g09，例外已恢复。** 基线保持 `4fbf421f08b6`。

`t=11500ms`（1080×1920，白色字身）：

| | expected（现基线） | got（去掉例外后） |
|---|---|---|
| 行高 | 40 / 42 px | **22 / 22 px** |
| 第 1 行 x | 98–984（宽 887） | 298–780（宽 483） |
| 第 2 行 x | 92–1079（宽 988） | **11–1079（宽 1069）** |
| 触到右边缘 1079 | **是** | **是** |
| 左边距 | 92 px | **11 px** |

字缩到 53% 仍顶在右边缘，第二行连安全边距都吃光。对照 `t=1000ms`：expected 行高 40/32，got 43/34，两边都没碰边缘——那里反而略微变大。同一改动一处变大一处剧烈变小，不是方向一致的改进。

**根因：** `max_lines==2` 这条路上多出来的词是**堆到最后一行**的（g09 当年冻结的正是这个行为），而宽度回退只会**缩字号**。两者叠加成不收敛的循环：

> 缩小 → 每行能塞更多词 → "堆到末行"规则继续把剩余词全倒进第二行 → 又超宽 → 再缩

缩到 53% 仍然溢出，正是这个循环。所以这不是"新输出可能反而更正确"，而是暴露了宽度回退与 `max_lines==2` 断行规则的真实冲突。

`frame_renderer.py` 里那条例外现在有了真正的理由，注释里写了这张表。**不要再把它当历史包袱去掉。** 移除此例外前必须先解决末行堆积。

已知用户可见情形（给 Luca 的实话，已写在裁决 §4）：很长的句子 + 排版设成两行 + 走 v1 旧路径时，第二行可能跑出画面右边被裁掉。v2 新路径有硬行数约束和重新切分，不受影响。

## 1. 正确修法（附录 C §3，不许另发明）

装不下时的处理顺序：

1. **在词边界重新切分成多条字幕**，让每条都能在规定行数内、以当前字号放下。时间按词时间切分；没有词时间时按字符比例。新字幕的时间区间必须首尾相接、不重叠、总时长不变。
2. 仍然装不下（**单个词本身**就比一行还宽，例如超长专有名词）→ **只对这一个词**按比例缩字号，并在 Transcript 那一条上标提示。缩放只作为最后手段。
3. **任何情况下都不允许输出超过 `字幕行数` 设定的行数。**

**禁止：** 把剩余词堆到末行，再对整块做 `fit_lines_to_width` 整体缩小。那正是 6a 量过的不收敛循环。

现成入口：`relayout_task` / `subtitle.relayout`（附录 C §3.3）。自动重排与手动「重新断句」共用同一实现，不要写两套。本片要做的是让 `max_lines==2` 在装不下时走这条切分，而不是 `_greedy_pack` 把 leftover 追加到最后一行。

`layout.py` 模块头里「After `max_lines` is full, leftover tokens are appended to the last line … Frozen by g09 seg3. **Do not change this `max_lines == 2` path.**」这一段，本片改完之后必须改成新政策，并指向本任务。

`_fit_v1_overwide_lines` 的 `!= 2` 例外：**只有在末行堆积已经改成重新切分之后**才可以移除。移除时先跑 `golden --case g09`，变了就停下附对比图，由 Claude 看着像素决定是否重录。不许在堆积还在的时候先拿掉例外。
