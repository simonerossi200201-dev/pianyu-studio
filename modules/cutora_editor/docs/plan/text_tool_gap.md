# 文本工具：和 Canva 差在哪，怎么补

写这份东西之前我把我们这边的文本这条链路从头读了一遍：
`cutora/subtitle/text_layer.py`（overlay → style）、
`cutora/render/text_layer_paint.py`（排版 + 放进框里）、
`cutora/render/textfx/layout.py`（折行 / 度量）、
`cutora/ui/canvas.py`（画布上的选中 / 拖动 / 缩放 / 双击编辑）、
`cutora/ui/panels/property.py`（右侧属性面板）。下面每一条都指得到具体位置。

## 先说结论

**不是引擎差，是「文本框」这个东西在我们这儿是假的。**

论渲染，我们比 Canva 强的地方不少：逐词动画、重点词自动识别、玻璃质感背景、
竖排 / 字符朝向、关键帧、四边渐隐。这些 Canva 没有。

但 Canva 的文本好用，靠的不是渲染，是**编辑模型**：一个文本框就是一个
有边界、会自己贴合内容、能被直觉操作的对象。我们这边这四件事全都不成立：

1. 新建的文本框**就是整块画布**，框和文字没有任何关系；
2. 垂直方向**只有顶对齐**，没有居中和底对齐；
3. 拖角柄 / 拖边柄的含义**和所有人的肌肉记忆相反**；
4. 框**不会跟着文字长**，也不会跟着文字缩。

所以你看到的是：选中一条文本，八个手柄挂在画面四角，拖哪儿都不对，
想让两行字居中在某个位置只能靠手动算 Y —— 这就是「无法正常排版」。

---

## 一条一条对

### 1. 文本框天生就是整块画布 ← 最要命的一条

**现状**：所有新建文本的地方都把框写成画布大小。

- `cutora/batch/batch_load.py` → `make_text_overlay()`：`"x": 0, "y": 0, "w": tw, "h": th`
- `cutora/ui/main_window.py` → `_drop_text_file()` / 文本轨「+」：同样是整画布
- `cutora/batch/text_batch.py` → `build_overlay()`：同样（这是我写的，一起改）

**后果**：
- 选中框永远是整个画面，看不出文字占多大地方（你截图里就是这样）；
- 折行宽度 = 画布宽度的 100%（`overlay_to_style()` 里
  `wrap_pct = w / video_w * 100`），所以一行能顶到边；
- 顶对齐 + 整画布框 = 文字永远贴在画面最上沿，想往下挪只能改 Y。

**Canva**：点一下画布出一个**贴着文字的框**，框宽默认是画布的一半左右，
框高自动等于文字高度。框在哪，文字就在哪。

**怎么改**：新建文本时框宽默认取画布的 70%~80%、框高按文字实际高度算一次，
居中摆放。这一条改完，后面几条才有意义。

---

### 2. 垂直方向只有顶对齐

**现状**：`text_layer_paint.py` → `_place_in_box()`：

```python
dy = (y + top) - layout.text_y     # 永远是顶
```

水平方向有 左 / 中 / 右 / 两端对齐，垂直方向一个都没有。

**Canva**：垂直三档（上 / 中 / 下），和水平对齐并排放在工具条上。

**怎么改**：`text_layout` 里加 `valign`（top/middle/bottom），
`_place_in_box` 按它算 `dy`。属性面板「对齐」那一行改成两组按钮。
这是半小时的事，但它决定了你能不能把一段字「居中在下三分之一」。

---

### 3. 手柄的含义是反的

**现状**：`canvas.py` → `_apply_resize()`，文本走 `overlay` 分支：

```python
ov['w'] = float(new_rect.width())
ov['h'] = float(new_rect.height())
```

八个手柄**都只改框的大小**，字号一动不动。更别扭的是
`lock_aspect` 默认是 True（`project_schema.lock_aspect_of`：没写就是锁），
所以拖右边那个手柄，高度会跟着一起变 —— 你只想把行变窄一点，结果框整个缩了。

**Canva**（所有排版软件都是这个约定）：
- **角柄** = 等比缩放整段文字（字号跟着变），
- **边柄** = 只改框宽，字号不变，文字重新折行，
- 按住 Shift 才反过来。

**怎么改**：`_apply_resize` 里给 `overlay` 且是文本的分支单独一套：
角柄算缩放比例乘到 `fontsize` 上（框跟着等比走），边柄只动 `w`（或 `h`），
并且**文本默认不锁比例**。

---

### 4. 框不会贴合文字

**现状**：`fit_mode` 有三档 —— `none`（默认）、`shrink`（文字缩到框里）、
`grow_box`（框涨大）。`grow_box` 只涨不缩（`text_layer_paint.py` 里
`if need_w > w: ov["w"] = need_w`），删掉几个字框不会收回来。

**Canva**：默认就是「宽度你定，高度自动」。打字打到第三行，框自己长高；
删回两行，框自己变矮。你永远不用管高度。

**怎么改**：加一档 `auto_height`（并设为文本的默认）：
`h` 每次排版后等于文字高度 + 上下边距，双向跟随。
`shrink` 保留给「必须塞进这块地方」的场景。

---

### 5. 编辑的时候看到的不是最终效果

**现状**：双击进 `InlineTextEdit`（`canvas.py` 792 行附近），
那是一个盖在画布上的 `QTextEdit`，能大致套字体和颜色，
但描边、背景色块、渐隐、逐词效果全都不显示 —— 编辑时
`_inline_editing` 一置位，`paint_text_overlay` 直接 return，真正的渲染是停掉的。

**Canva**：输入光标就在最终画面里，边打边看到最终效果。

**怎么改**：两条路。省事的一条是编辑期间仍然渲染真正的文本层，
把 QTextEdit 设成全透明只留光标和选区（文字用渲染层显示）。
这条能做到八成像，工作量可控。彻底的一条是自己画光标 + 选区，
不要 QTextEdit —— 那是另一个量级，先不碰。

---

### 6. 改一个字号要跑到屏幕另一头

**现状**：所有文本参数都在右侧属性面板，分在「基础 / 文字 / 效果」几个折叠段里。
改字号 → 鼠标从画面中间移到右边栏 → 找到「大小」→ 改 → 再看画面。

**Canva**：选中文本，**就地浮出一条工具条**：字体、字号、颜色、粗斜体、
对齐、行距、效果。两三个最常用的动作永远在手边。

**怎么改**：在画布上方（或选中框上方）加一条上下文工具条，只放
字体 / 字号 / 颜色 / B I U / 对齐（横+竖）/ 行距 这几样，
其余留在属性面板。工具条和面板读写同一份数据，不许各存一套。

---

### 7. 几个小的，但每天都会碰到

| 问题 | 现状 | 怎么改 |
|---|---|---|
| 字距调不了 | `ov_letter_spacing` 控件建了但 `.hide()` 了（property.py 671–674） | 放出来，和行距并排 |
| 没有文本样式画廊 | 只有一个下拉列表，看不见长什么样 | 做成缩略图画廊，和字幕风格包那套一样 |
| 多个文本框不能一起对齐 | 画布只能单选 | 框选多个 + 左/中/右/顶/中/底对齐、等距分布 |
| 复制样式 | 没有 | 「复制样式 / 粘贴样式」（Canva 的刷子） |
| 段落间距 / 首行缩进 | 有，但埋在面板深处 | 保持，不动 |

## 怎么做：五批，每批都能单独验收

排序原则是「先让框成为框」，因为 2/3/4 全都依赖第 1 条。

### 第一批：让文本框成为真正的框（改完你就能正常排版了）

1. 新建文本的三个入口统一改成：框宽 = 画布 78%，框高 = 文字实际高度，
   水平居中、垂直放在画面下三分之一（可配）。
2. `text_layout` 加 `valign`，`_place_in_box` 支持上 / 中 / 下。
3. `fit_mode` 加 `auto_height` 并设为文本默认，框高双向跟随文字。
4. 文本默认**不锁比例**。

验收：新建一条文本，框贴着文字；改文字内容框自动长高变矮；
垂直三档都对；整个过程不用碰 X/Y 数字。

### 第二批：手柄按所有人的习惯来

5. 角柄 = 等比缩字号，边柄 = 只改折行宽，Shift 反转。
6. 拖动时显示实时提示：当前字号 / 框宽占画布百分比。
7. 吸附沿用画布现有的那套（`_calc_snap`：画布中线 + 四边 + 分屏格子边），
   文本框之间也要能互相吸。

验收：拖右边手柄，字号不变、文字重新折行、框高自动跟随；
拖角，字号跟着变；两条文本能吸到同一条中线上。

### 第三批：就地工具条

8. 选中文本 → 上方浮出工具条（字体 / 字号 / 颜色 / B I U / 横竖对齐 / 行距）。
9. 字距控件放出来。
10. 工具条和属性面板共用一份读写逻辑，改任何一边另一边立刻跟着变。

验收：全程不碰右侧面板就能把一段字排好。

### 第四批：所见即所得的编辑

11. 编辑期间不再停渲染：QTextEdit 透明化，只留光标和选区，
    文字由真正的渲染层画。
12. 回车换行、退格删行时框高实时跟随（接第 3 条）。

验收：打字过程中描边、背景色块、渐隐都在，和最终成片一致。

### 第五批：批量和复用

13. 多选 + 对齐 / 等距分布。
14. 复制样式 / 粘贴样式。
15. 文本样式做成缩略图画廊；「存为模板」从画布上的当前文本直接存
    （和 Q121 那条并起来做）。

验收：五条文本一次对齐；一条调好的样式一键刷到其余四条。

---

## 不要做的

- 不要为了像 Canva 去动渲染引擎。逐词动画、重点词、玻璃背景这些是我们的长处，
  动它们只会把已经稳定的东西弄坏。这份清单里没有一条需要碰 `textfx/`。
- 不要重录 golden。第一批会改「新建文本的默认框」，这只影响**新建**，
  已有工程里的 overlay 的 x/y/w/h 原样读取，老片子重开必须一模一样 ——
  这是这一整轮的红线。
- 不要把工具条做成第二套数据。Canva 好用的一半原因是「哪里改都一样」。
