## 1.【发布阻断】FFmpeg 是 GPL 版本

T10 摸底最后一行：

> FFmpeg：gyan **GPL full_build**，THIRD_PARTY 未列

**这条比十九个需求加起来都急。**

gyan 的 `full_build` 是 **GPL** 授权的，里面带 `libx264`（GPL）等组件。
**把 GPL 的 FFmpeg 打进一个闭源软件一起分发 = 整个软件必须以 GPL 发布**，否则就是违反许可。
Luca 的硬约束是「友好分发、不侵权」—— **现在这个包不满足**。

三条路，需要 Luca 拍板：
1. **换 LGPL 构建**（gyan 有 `essentials` / 其他源有 LGPL build）：**丢掉 `libx264`**，
   H.264 只能走 NVENC / `openh264`。用户没 N 卡时软件端 H.264 编码就没了 —— 得想清楚
2. **保留 GPL FFmpeg，但以独立进程调用 + 不静态链接 + 提供获取方式**：法律上有争议，
   业界有人这么做，但「友好分发」这条就不干净了
3. **软件本身开源 GPL**：最干净，但那是产品决定

**这条不解决，T10 做出来的安装包也不能对外发。** 内测（几个熟人）风险低，正式发不行。
我在下面第 6 节单独问 Luca。

## 2. 阻断内测的 bug（BUG-01 … 05）

**编号规矩补一层**：里程碑 `Tnn` / 切片 `Tnn-x` / 运维 `OPS-nn` / **缺陷 `BUG-nn`**。

### BUG-01 · #4 启动后命令行无限刷 `[PaintError] The truth value of an array … is ambiguous`

这是 numpy 的报错：某处对一个**数组**做了 `if arr:` 或 `arr == x` 当布尔用。
**「无限重复」意味着它在每一帧的绘制路径上**，而且**被 `except` 接住、打印、继续** ——
所以画面可能根本没画出来（这就是 #13 的候选原因之一）。

**要求**：
- **`--tb=long` 完整 traceback**，不要 `--tb=line`（老规矩：line 输出不能当根因）
- **bisect** 到引入它的提交。昨天动过绘制路径的点：
  `9afa64c`（T11g-B PATH-only）· `8fe125b`（bullet_reveal）· `bc780ac`（T07b）· `be000e5`（T08b）
- 我的怀疑：**整数合成那批新代码**（`mul_premul_alpha` / `tint_run_solid` / `warp_layer_xf`）
  或 `resolve_paint_style` 里对含数组的 dict 做了 `==` 比较。**但这是怀疑，以 bisect 为准。**

**为什么 golden 没抓到**：golden 走的是导出路径（离屏）。这个报错很可能只在**预览** canvas 上触发。
修完要补一条**预览路径**的测试：离屏起一个 canvas，画一帧，**断言零 `PaintError` 日志**。

### BUG-02 · #13 点任何风格包都不起作用，字幕样式面板完全无法控制

Luca 说这是「最致命的问题」。我同意，而且**我认为这多半是我们昨天改出来的**。

**候选根因（按可能性排）**：
1. **2a 的副作用**：昨天为了修「导出读错层」，我们把绘制改成
   「`role=default` 带 `fx` → 画 `roles.default.style`」。
   **但字幕样式面板和风格画廊很可能还在写 `task.style`。**
   → 用户改的那份和画面读的那份**不是同一个对象**。
   这正是我们修 2a 时**没有反向验证**的地方：验了「预览 == 导出」，**没验「面板写的 == 画面读的」**。
2. BUG-01 的绘制异常把每一帧都吞了，所以画面停在某个旧状态，看起来「改什么都不生效」。
3. `apply_pack_to_task` 现在写 166 键全集，某处签名或信号没跟上。

**要求**：先修 BUG-01，再看 #13 是否还在。还在 → 按 1 查：
**面板 `on_change` 写到哪个 dict、`resolve_paint_style` 读哪个 dict，两个 `id()` 打出来。**
不相等就是根因。

**补的锁**：一条测试 —— **通过命令总线改一个样式键 → 断言下一帧 `resolve_paint_style` 返回的值已更新。**
这条锁昨天就该有。

## 4. Phase 2 里程碑（T20 … T27）

**编号从 T20 起**，和 Phase 1 的 T00–T13 不会混。

### T20 · 时间线拼接 + 转场库 —— **Phase 2 主线（#19）**

Luca 的原话：**「这是整个要求里面最最重要的一条」**。我同意，而且理由比他说的还多一条：
**现在的拼接是「软件外生成一个长 mp4 再导进来」，那个 mp4 一旦生成，所有片段信息就丢了。**
这和我们昨天杀掉的「两条路径」是同一个病 —— 拼接走的是软件外的一条岔路。

**目标**：点「开始拼接」→ **产出一个时间线工程**，N 个片段按顺序放在同一视频轨（音频链接轨跟着），
每个片段是**独立的 clip**（`source_id` 指向各自文件、`in_t/out_t` 来自拼接决策），
片段之间默认硬切、可加转场。**软件外不再产生任何中间视频。**

**切片**：
- **T20a 拼接器改产出时间线**：`stitch → List[ClipPlacement]` 而不是 `stitch → mp4`；
  一条 `stitch.to_timeline` 命令；媒体库显示**一个工程**，片段住在时间线里
- **T20b ASR 跨片段**：自动字幕把整条轨当一个视频 —— 把时间线音频**渲成一条临时 wav**跑一次 ASR，
  段落时间即时间线时间。**这里会撞上 `seg.id` 是下标的架构债** —— 多片段时间线上下标寻址更脆，
  **T20b 之前先还这笔债**（`seg.id = uuid`，一直挂着的 Phase 2 项）
- **T20c 转场库**：`TransitionItem` 模型 T05e 已有，**先盘渲染器现在到底画不画它**；
  然后做一套专业转场：交叉溶解 / 黑场·白场 / 推 / 擦 / 缩放 / 模糊溶解，各带时长和缓动。
  转场是**独立实体**（T05e 的语义：接缝在就平移，接缝没了就删，永不缩短）
- **T20d 二次编辑验证**：单片段调色、裁短、复原、关键帧 —— 这些 T05 已经有底子，
  T20d 就是**逐项实测**它们在拼接出来的工程上真的能用
- **golden**：新增 `g19_stitch_timeline`，拼接结果走时间线渲出的成片，**和旧路径拼出的成片观感对照**

**前置**：T21（画布尺寸）—— 拼进来的片段要铺满项目画布，尺寸标准先立起来。

### T21 · 画布尺寸标准（#1）

现在「新建项目 1080×1920」是**摆设**，不约束任何东西。
- 新建项目的尺寸 = **真正的画布**，导出尺寸 = 画布尺寸，**没有例外**
- 预设：1080×1920 / 1920×1080 / **720×1280 / 1280×720**（AI 素材多是这个）
- 导入的任何素材（拖入 / 拼接 / 批量）默认 **填满（cover）** 画布；右键菜单可改「完整适配（contain）」
- 右键菜单可对单个片段改「按项目尺寸 / 按源尺寸」，默认按项目
- **锁**：导出成片的宽高 == 画布宽高，一条测试，四种预设各一次
- **golden**：现有 case 的画布不变，所以哈希不动；新增一条 `720×1280` 的 case

### T22 · 时间线工具（#15 + #6 缩略图）

- **切刀**：对**所有选中片段**生效 —— 视频 / 文本 / 图片 / 音频 / 字幕，不只视频
- **磁铁开关**：T05c 的磁吸已有，缺一个工具栏开关（`Alt` 抑制保留）
- **变速工具**：变速**只能**通过它做
- **边缘修剪**：拖片段两边 = **修剪**，不是变速（现在是变速，Luca 说得对，这不该是默认）；
  悬停时**边缘高亮**
- **轨道缩略图**：视频轨显示帧缩略图、图片轨显示预览、文本轨完整显示文本 —— 缩略图走 T05f 波形那套缓存机制（key 含 mtime，512 MB 上限）
- **锁**：切刀对五种片段各一条；边缘拖拽后 `speed` 不变、`out_t` 变

### T23 · 批量加载（#10，重做「批量插图」）

- **删掉「开场素材」的两个功能**（插入缩略图 / 插入开场视频）—— 被时间范围取代

### #9 的查证结果：**Grok 生成的媒体资产不能打进包**

xAI 现行条款（2026-09-11 生效）原文：

> "When using Output or SpaceXAI's name, logos, trademarks, or other brand elements,
> **you are required to obtain our permission and attribute your generation of the Output to the Service**"

> "Due to the nature of artificial intelligence, **Outputs may not be unique**, and different users may receive similar Output"

两条撞上我们两个硬约束：
- **要署名** → 出货物里就会出现第三方产品名 —— 违反「第三方产品名不得出现在出货物里」
