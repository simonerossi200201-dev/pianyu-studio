# Q172 · 中央监视器不分屏时拖的是「点中的那一层」+ 同一批同步（2026-10-06）

## Luca 报的两件事

1. 在中央监视器里，不分屏、勾了「同步编辑选中的视频」，拖一条外部加载的绿幕视频：其他视频不动，连这条自己也不动；缩放、移动都没效果。
2. 回到主窗口，在画布上把外部绿幕视频缩小，露出来的媒体库视频是黑的，但声音正常，时间线上也有视频条。

## 根因（同一个）

`monitor_model.content_target` 在不分屏时一律返回「媒体库主视频」那条轨。

- 外部绿幕视频铺满整个画面，压在主视频上面。所以拖动和 Ctrl 缩放改的其实是被盖住的主视频：看不见任何变化，外部视频本身也不动。
- 主视频却被悄悄挪走或缩小了。勾了同步时，选中的每一条都一样。
- 回主窗口把外部视频缩小，才露出主视频的位置：主视频已经被挪出画面，看起来就是「黑的」。声音和时间线都正常，因为片段本身还在。

## 修了什么

- 点到哪一层就拖哪一层。从最上面往下找，取第一个满足以下条件的视频轨，作为拖动、Ctrl 拖、Ctrl+滚轮、双击重置、键盘微移的对象：
  - 看得见、没锁定；
  - 这个时刻有画面；
  - 画面框盖住鼠标所在的点。

  外部视频缩小后，点到露出来的角落就是主视频。
- 「同一批」身份（`layer_slot`）。媒体库主视频对应主视频；第 N 条外部视频轨对应别的视频里的第 N 条外部视频轨。批量加载外部视频时，每条视频都是按同样的顺序加轨的，所以第 N 条就是同一批，也就是同一个图层位置。勾了同步，选中的每条里同一批的这一层一起挪、一起缩，主视频不受影响。
- 鼠标悬停时状态栏写明要拖的是哪一层，比如「【外部视频 T0124-s001-p01.mp4】」，同步时还会注明「选中的每条里同一批的这一层」。
- 顺带修了日志里看到的卡顿：打开「批量」对话框时要校验模型权重的 sha256，以前每次开软件都要重算几个 GB，界面线程卡 14 秒。现在结果记在磁盘缓存里，文件不变就不再重算。

## 测试

`tests/test_q172_monitor_layer_drag.py`（6 项）：
- 点中的是最上面那一层，缩小后露出的角落是主视频，锁定或隐藏的层会落到下面；
- 同一批身份的对应关系；
- 拖动和 Ctrl 缩放时，三条的外部视频一起动、主视频不动，撤销能还原；
- 不勾同步只动这一条，悬停提示写明是哪一层；
- 双击重置的是同一层；
- sha256 磁盘缓存在重开软件后仍然有效。
