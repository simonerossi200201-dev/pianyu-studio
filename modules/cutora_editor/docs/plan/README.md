## Luca 的操作流程（每个任务一轮）

1. **投喂 Grok**。打开 PowerShell 里的 Grok 4.6 Heavy（或 Grok Bot），先贴 `01_GROK_通用规范.md` 全文，再贴对应的 `phase1_tasks/Txx_*.md` 全文，最后一句话：
   > 请按任务书执行，工作目录 D:\0_Dev\CUTORA，结束时按规范 §5 写报告到 docs\plan\reports\Txx_report.md。
   Grok 是独立会话，不会记得上一个任务，所以每次都要贴规范。
2. **Grok 干活**。中途它问问题就按任务书"最保守解释先做"回答；它想扩范围就说"写进报告建议栏"。
3. **交给 Claude 审**。把 `Txx_report.md`（和它提到的截图/录屏）丢给 Claude，或者让 Claude 直接读 `D:\0_Dev\CUTORA`（需要在桌面端给 Claude 这个文件夹的权限）。Claude 回复"通过"或一份短返工单；返工单同样整篇贴给 Grok。
4. **通过后**才开始下一个任务。顺序：
   **T00 → T01 → T09 → T02 → T03 → T13 → T12 → T04 → T05 → T06 → T07 → T08 → T11 → T10**
   （T04–T08、T11 之间可以按心情穿插，T10 必须最后。）

## 三条最重要的规矩

- **golden 对拍不过，任务就没完成。** 这是防止 Grok "改着改着把拼接算法改坏"的唯一保险。
- **安全红线不谈判。** 任何中国大陆的域名/镜像/SDK/模型源、任何明文密钥、任何静默联网，一票否决。
- **Grok 只做任务书里的事。** 它发现的好点子，写进报告"建议"栏，由 Claude 决定放进哪个任务。

## 预期节奏（供参考，不是承诺）

T00–T01 是重体力活但机械（1–2 个 Grok 会话）；T02–T03 是视觉活，Luca 需要看图做决定；T13 是架构活；T04/T05/T11 内容最多。整个 Phase 1 完成后，片语 Studio 已经是一个能替代"Premiere 做字幕短视频 + Canva 做封面"的完整产品；Phase 2 起才开始拉开与其他软件的差距。
